## 1. Annex B — FEC 如何套到突发场上

### 1.1 总顺序（B.0 + B.3.12）

对**一条要上突发的信息块**，规范隐含的处理链是：

1. **组 PDU**（LC / CSBK / Data Header / 用户数据块等，clause 7–9）。  
2. **算校验**（若 Table B.1 该行有 Checksum）：CRC / RS / 5-bit CS 等，作用在**信息多项式**上。  
3. **Data Type CRC Mask**（B.3.12）：对「整段 CRC 场」做 XOR；**发**：CRC 算完、**FEC 编码前**；**收**：FEC 解完、**CRC 校验前**。末块/中间续块/Idle 等按原文 note **不套掩码**。掩码取值表 **不抄**。  
4. **块 FEC**（BPTC / Trellis / Rate 1 或场内短码）。  
5. **交织**后写入突发 Info / 嵌入 / CACH 场。  
6. 中心场另加 **Slot Type / EMB / SYNC 或 RC**（各自短码，见 §1.4）。  
7. Annex **E** 把各场拆成 dibit，clause **10.2** 调 4FSK。

Table **B.1** 是「场 → FEC 码 → 校验」总表。学习只需记住：**控制/头/Idle/½ 数据走 BPTC(196,96)；¾ 数据走 Trellis；Rate 1 几乎不编；嵌入/CACH/RC 走变长 BPTC；中心短场走 Golay / QR / Hamming。**

### 1.2 BPTC(196,96)（B.1.1）——多数控制与 ½ 数据

- **信息**：96 bit `I(0)…I(95)` 排成 **9 行 × 11 列**；再补 **3 bit 保留 `R(0…2)=0`**，凑 99。  
- **行码**：每行 Hamming **(15,11,3)** → `H_Rx`。  
- **列码**：每列 Hamming **(13,9,3)** → `H_Cx`。  
- 为凑满 **196** 再加 **`R(3)=0`**（交织下标 0）。  
- **交织原则**（式 **B.1**）：编码阵按左→右、上→下编号，  
  `Interleave Index = Index × 181  mod 196`，  
  得到 `TX(195)…TX(0)` 填入通用数据突发左右 Info（各 98 bit）。  
- **不抄**：Fig B.1 阵面、Table B.2/B.3 下标全表。

适用（B.0）：PI / Voice LC Header / Terminator+LC / CSBK / Idle / Data Header / Rate ½ 续块与末块 / Response / MBC / UDT / USBD 等。  
**Idle 无 CRC**；确认数据另加 CRC-9 / 末块 32-bit CRC（仍先校验、后 BPTC）。

### 1.3 变长 BPTC（B.2）——嵌入、单突发、CACH

共同直觉：**行 Hamming + 列偶/奇校验 → 再按列读出写入发送阵**；消息变长就加行。

| 子款 | 用在哪 | 行码 / 列校验 | 如何进突发 |
|------|--------|---------------|------------|
| **B.2.1** | 语音超帧嵌入 Full LC | Hamming **(16,11,4)**；列 **偶校验** `PC` | 列自上而下读出 → **4 行 × 32 bit**，按超帧 **B–E** 依次放入嵌入场 |
| **B.2.2.1** | 非 RC 单突发嵌入（11 info） | 同形阵；首行 Hamming **(16,11,4)**；列偶校验（此时 PC 行=信息行） | `Index × 17 mod 32`（式 **B.2**）→ 32-bit 嵌入场 |
| **B.2.2.2** | Reverse Channel | 同上，但列 **奇校验**（PC 与信息行相反） | 同样单突发交织；RC 信息另带 **7-bit CRC**（B.3.13） |
| **B.2.3** | CACH 上 Short LC | 行 Hamming **(17,12,3)**；列偶校验 | 列读出 → **4 个 CACH** 各 17-bit 载荷；TACT 再按 **B.4.1** 与载荷交错 |

嵌入 Full LC：72-bit LC + **5-bit CS**（B.3.11）入阵；PC 使每列「1」的个数为偶。  
CACH Short LC：28-bit 信息 + **8-bit CRC**（B.3.7）再 BPTC。  
**不抄**：Fig B.2–B.6、Table B.4/B.5。

### 1.4 中心短场（B.0 / B.3.1–B.3.5）

这些**不走** 196-bit BPTC，直接护突发中心小场：

| 场 | 码 | 原则 |
|----|-----|------|
| EMB | QR **(16,7,6)** | 7 信息 + 9 校验；无额外 checksum |
| Slot Type | Golay **(20,8)** | Colour Code + Data Type 等 8 信息 + 12 校验 |
| CACH TACT | Hamming **(7,4)** | AT+TC+LCSS 共 4 + 3 校验 |

生成矩阵/多项式 → **SKIP**（B.3.1–B.3.5）。实现查 PDF。

### 1.5 Rate ¾ Trellis 与 Rate 1（B.2.4 / B.2.5）

- **¾**：144 信息 bit 串成 **48 个 tribit**（MSB 在左），送 **8 态 FSM**（初态 0；「当前输入 = 下一状态」），末尾再灌 **flush tribit `000`**，输出 **98 dibit**（码 **(196,144)**）。dibit 映到 ±1/±3 后按 Table B.9 **交织**，用以打散瑞利块差错。状态转移表 / 星座表 / 交织表 **不抄**。  
- **Rate 1**：**无块 FEC**；192 用户 bit + **4 个填 0 的 pad** 凑 196，再按 Table B.10B 的发射位序入突发（表 **不抄**）。确认路径仍可带 CRC-9 / 末块 CRC-32。

### 1.6 CRC 族怎么挂（B.3.6–B.3.13）——只讲挂法

| 名称 | 典型挂点 | 原则（系数回 PDF） |
|------|----------|-------------------|
| RS **(12,9)** | Voice LC Header / Terminator 的 Full LC | GF(2⁸) 上缩短 RS；9 八位组 → 3 校验八位组 |
| 5-bit CS | 嵌入 Full LC | 短校验，与 BPTC 同行 |
| 8-bit CRC | CACH Short LC；Act_Updt Hash | 信息多项式 × x⁸ 后对生成多项式取余 |
| CRC-CCITT（16） | CSBK、Data/MBC/UDT/USBD/PI Header 等 | 先 CRC，再 Mask，再 BPTC |
| CRC-9 | 确认数据块（DBSN+User） | 续块/末块按 B.0；仅当突发内存在 CRC-9 时才套 9-bit Mask |
| 32-bit CRC | 确认/非确认**末块**、Response data | 跨块载荷的消息 CRC；**Last Block 不套 Data Type Mask** |
| 7-bit CRC | RC Info | 与 RC 单突发 BPTC 叠用 |
| Data Type CRC Mask | 见 §1.1 | 按 Data Type 选掩码；收发同一掩码才能通过 CRC |

**禁止事项**：不写 G(x) 系数、不写生成矩阵、不写 Table B.21/B.22 十六进制掩码表。

### 1.7 CACH 帧交织（B.4.1）

24-bit CACH 上：**AT / TC / LCSS 及其 3-bit Hamming** 被**拆开散布**在整段突发里抗衰落；17-bit 载荷 `P(16)…P(0)` 填空档。Fig B.9 位图 **不抄**——记住「控制比特散开、载荷顺序填缝」。

## 2. Annex D — Idle / Null 突发原则（不 dump 比特）

### 2.1 Null 嵌入（D.1）

- 嵌入 Null 的 **11 个信息位全 0**。  
- BPTC 线性 → **校验/PC 亦全 0** → 发送的 **32-bit 嵌入场全 0**（对应 B.2.1 的 Transmit Matrix）。  
- 用途：语音超帧里**无有效嵌入信令**时的占位（与 EMB / LCSS 配合，clause 7/9）。  
- Table D.1 逐位全 0 **不必抄**。

### 2.2 Idle 消息（D.2 + B.0）

- Idle **不是**全 0：规范规定一组固定 **96-bit 伪随机信息位**（Table D.2），再走 **BPTC(196,96) + 通用数据突发交织**（同 B.1.1）。  
- Table B.1：**Idle 无 checksum、无 CRC Mask**。  
- Data Type = Idle 的通用数据突发，用来**占空 / 保活 / 填无业务时隙**，接收机按 BPTC 解出后应识别为 Idle，而不是用户数据。  
- **不抄**：Table D.2 96 位、Fig D.1 编码阵、Table D.3 编码后逐位。

与 Null 对照：Null = **嵌入场**的「空」；Idle = **整突发 Info** 的「规定图案空闲数据」。

## 3. Annex E — 发射比特/符号序 + 4FSK（原则）

### 3.1 调制侧（clause 10.2，Annex E 前置）

- 符号率 **4800 symb/s**，每符号 **2 bit（dibit）**。  
- 4FSK 恒包络；偏差指数 **h = 0,27**。Table **10.3** 映射原则（只记四档，不展开 SYNC）：

| Bit1 Bit0 | 符号 | 中心偏差（约） |
|-----------|------|----------------|
| 0 1 | +3 | +1,944 kHz |
| 0 0 | +1 | +0,648 kHz |
| 1 0 | −1 | −0,648 kHz |
| 1 1 | −3 | −1,944 kHz |

调制器：dibit → 根升余弦 → 调频（Fig 10.1）。Annex **E** 只解决「突发里哪个 dibit 先送」，不定义波形滤波器。

### 3.2 突发上的符号扫描（Annex E 开篇）

- 正常突发 **132 符号**：中心左右各 **66**。  
- **先发 L66 → … → L1，再 R1 → … → R66**。「第一个发出的符号是 L66」。  
- RC 突发更短（中心左右各 24 符号，clause 10 时序图）；独立 RC 见表 E.12。  
- 每个符号的 Bit1/Bit0 对应上一小节的 4FSK 档。

### 3.3 场内编号习惯

- 任一信息场：LSB **恒为下标 0**；图上 LSB 在**最右**；**通常最后发送**。  
- 校验场用**码名**当场名：如 EMB 的 `qr(x)`（x 从高到 0）、Slot Type 的 `Golay(x)`、BPTC 的 `H_Cx` / `H_Rx`。  
- 例：`H_C11(3)` = 第 11 列 Hamming 的 bit 3。

### 3.4 表 E.1–E.12 是什么（只列用途，不抄表）

| 表 | 突发类型 |
|----|----------|
| E.1 | BPTC 通用数据 + SYNC |
| E.2 | BPTC 通用数据 + RC（中心换 RC/EMB） |
| E.3 | Rate ¾ + SYNC |
| E.4 | Rate ¾ + RC |
| E.5 | 语音 + SYNC（超帧 A） |
| E.6–E.9 | 语音 + 嵌入分片 1…4 |
| E.10 | 语音 + 嵌入 RC |
| E.11 | 语音 + Null 嵌入 |
| E.12 | 独立 RC 突发 |

实现：按突发种类查对应表，把 Info / Slot Type / SYNC 或嵌入场的已编号比特填进 L/R 符号。  
**完整 L/R 映射 → SKIP。**
