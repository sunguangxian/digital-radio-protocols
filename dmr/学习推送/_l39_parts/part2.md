## 6. UDT：跑在控制信道上的「小货车」

### 6.1 为什么需要它（6.5.0）

规范开门见山：Tier III 支持的业务很多，**搬数据**是普遍需求；UDT 短数据是一种主要的数据业务，但还有很多场合是「为了支撑别的业务而搬数据」——原文举的例子正是第 38 课那件事：**手台拨 PABX / PSTN 时，要把拨的号码上传给 TSCC**。为了降低复杂度，**所有经由 TSCC 的数据搬运共用一种方法——统一数据传输机制（Unified Data Transport，UDT）**。

6.5.0 把 UDT 的用途分成三大类，原文逐条列出：

| 大类 | 原文列出的用途（意译） | UDT 头里的 SF |
|---|---|---|
| **a) 补充数据传输服务**（Supplementary Data Transfer） | 上传经网关接通的目的地址；上传 PSTN/PABX 拨号数字；上传 IPv4/IPv6 地址；上传 NMEA 位置；下传远端地址；**下传 PABX/PSTN 来电号码（CLI）**；下传 IP 地址；下传 NMEA 位置；**作为其他业务一部分的补充用户数据**；呼叫改向的地址/数字；组订阅/附着的组地址上传 | **SF = 1** |
| **b) UDT 短数据投递服务** | NMEA 位置；LIP 位置；**UDT 短信**；**DGNA 的组地址** | **SF = 0** |
| **c) UDT 短数据轮询服务** | （网络向手台要数据） | **SF = 0** |

一句话：**SF = 1 表示「我是给别的业务打下手的」，SF = 0 表示「我自己就是这次业务的主角」。**短信和 DGNA 都是 SF = 0；拨外线时交号码、打电话时顺带传 GPS，是 SF = 1。

### 6.2 一辆货车的结构：1 个车头 + 最多 4 节车厢

```text
  ┌──────────── UDT 头（1 块，10 字节）────────────┐ ┌附加块 1┐ ┌附加块 2┐ ┌附加块 3┐ ┌附加块 4┐
  │ 谁发给谁、装的是什么格式、后面挂几节、填了多少空 │ │ 数据   │ │ 数据   │ │ 数据   │ │ 数据   │
  └───────────────────────────────────────────────┘ └────────┘ └────────┘ └────────┘ └────────┘
       ↑ 车头：C_UDTHD（下行）/ C_UDTHU（上行）         ↑ 1~4 节，「必须连续发送」（6.5.0）
         DGNA 专用：C_DGNAHD / C_DGNAHU
```

UDT 头的十个字节（Figure 6.42，Table 7.24 / 7.28）：

```text
          7    6    5        4         3 2 1 0
Octet 0 │G/I │ A  │ Emerg/ │ Option/ │ Data Packet Format(4) = 0000 │
        │    │    │ Rsvd   │ UDT_DIV │                              │
Octet 1 │ SAP(4) = 0000（UDT）       │ UDT_Format(4)  ← 装的是什么    │
Octet 2–4 │ Target 或网关（24）                                       │
Octet 5–7 │ Source 或网关（24）                                       │
Octet 8 │ Pad Nibble(5)  ← 填了几个 F  │ 0 │ UAB(2) ← 挂几节（值+1）    │
Octet 9 │ SF │ PF │ Opcode(6)                                       │
```

逐个字段说人话：

| 字段 | 位 | 意思 |
|---|---|---|
| **G/I** | 1 | 0 = 发给个人；1 = 发给组（**组不回应答**） |
| **A** | 1 | 1 = 要求
