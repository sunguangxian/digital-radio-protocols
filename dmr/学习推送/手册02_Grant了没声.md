## 1. 为什么要写这篇手册（动机 + 现场对话）

第 40 课收官把「Grant 无声」钉在呼叫故事的第 [5] 步：房卡已发，人却听不见。手册 01 专治「登不上」；本篇专治另一句更高频的值班口头禅：

> 「有 Grant 啊……怎么没声？」

现场你一定听过这些对话：

- 调度：「网管显示呼叫已分配信道，用户说听不见。」——你问「空口上是哪条 Grant？CHAN 多少？时隙几？」对方回「就显示已接通啊。」——中文「已接通」是线索，**不是空口证据**。  
- 监听员：「我看见 Grant 了！」——仔细一问，其实看见的是 **登记 ACK（`0x62 Reg_Accepted`）**，或把确认族误叫成 Grant（手册 01 第二问的口误，在本篇会再次咬人）。  
- 写频同事：「控制信道一切正常，一进业务信道就静，过几秒自己掉回 TSCC。」——十有八九是 **门牌表缺行 / 固定计划参数错 / CC 不对**（第 36 课现场分诊），不是功放坏了。  
- 分析仪新人：「业务信道上有能量，怎么还说没声？」——能量 ≠ 本系统话务。**SYNC 对上了也可能 CC 不对**（第 20 课）；时隙听错了等于坐错半边座位（第 33 课 Logical Channel Number）。  
- 网优：「新加了一台载频 CHAN=23，老批次手台一被分到就失败。」——灵活计划**漏行**的经典指纹（第 36 课例「新载频，老手台」）。  
- 运维夜班：「主叫有声、被叫无声」——可能一边跟对了 Payload，另一边仍守在 TSCC 听「前台广播」；或一边时隙位读反。  
- 测试：「信道号每次呼叫都在变？」——字段边界读错：把地址低字节当成 CHAN（GopherTrunk 社区坑；第 36 课 §4.2）。**先怀疑读法，再怀疑网络疯了。**

培训台如果只背「Grant 就是分配信道」八个字，值班会卡在同一处：

> **会背「有 Grant」≠ 会分诊无声。**  
> 分诊 = 每次工单强制四问：  
> **① 空口真的收到 Channel Grant 了吗？**（不是把登记 ACK / 别的确认族误叫成 Grant）  
> **② Grant 里的 CHAN / 时隙 / 物理信道身份对了吗？**（对照写频 Frequency Plan / Annex C 门牌表；0 / 1…4094 / 4095）  
> **③ 业务信道上的同步 / CC（Colour Code）/ 时隙身份对了吗？**  
> **④ 仍无声才查射频 / 功放 / 静噪 / 音频路径——先信令后射频。**  
> 四问答不清，不许升级为「射频坏了」或「换天线试试」。

本篇目标：能画出「C_RAND(业务) → Channel Grant → 改频进 Payload → 同步/CC/时隙对齐 → 才说话」总图，并与「失败走 NACK+Reason」「登记走 ACK+Reason」对照；会用四问 +「日志三联单（Grant 版）」接单；会精读 CHAN 三段取值、时隙 1 bit、CC 身份（不是把第 33 课 Grant 地图再 dump 一遍）；会区分「守着 TSCC 听 Grant」与「已在 Payload 说话」；能填完《本网 Grant 无声分诊卡》；自测过关后，回库翻第 31/33/36/20/40 课与 `鉴权与AnnexC频率.md` 把本网门牌检查项补进分诊卡。

**本篇硬禁令（写进脑子）**：不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/ReasonCode与Grant变体.md`、`鉴权与AnnexC频率.md`、`集群协议字段速览.md`、`总索引.md` 集群关键词、第 20/31/33/36/40 课已有编号为准）；**不重 dump Grant 全变体地图**（第 33 课；本篇只认「成功路径是 Grant、Grant 无 Reason」+ CHAN/时隙两字段）；**不发明 Reason 码**（失败路径只对照「NACK+Reason」，细节回手册 01 / 第 34 课）；**不讲鉴权算法 / RC4**；**不写攻击面 Stun/Kill 内容**；不把厂商中文提示当成 ETSI 正式名；**不写真实批复频点 / 站点号进公开仓库**；本篇不写下一篇手册正文。

## 2. 总图 / 故事：房卡发了，客房为什么还静？

### 2.1 一句话：Grant 是「房卡」，有卡 ≠ 已经在房间里说话

继续旅馆比喻（第 31–36、40 课 + 手册 01）：

| 旅馆 | 空口 | 「没声」时常卡在哪 |
|------|------|-------------------|
| 前台 | **TSCC** | 人其实还在前台，分析仪却当他已进客房 |
| 点餐按铃 | **C_RAND**（语音/数据类 Service_Kind） | 根本没按铃，却抱怨「Grant 了没声」 |
| 拒绝/排队条 | **NACK/QACK/WACK + Reason** | 把失败条误叫成「有 Grant」 |
| **房卡小票** | **Channel Grant**（PV/TV/…） | **Grant 本身不带 Reason**；常重复发送 |
| 房号 | **Logical Physical Channel Number（CHAN，12 bit）** | 房号不是 MHz；表缺行 → 进不去 |
| 座位 | **Logical Channel Number（1 bit 时隙）** | 坐错半边 = 听错时隙 |
| 客房油漆色 | **Colour Code** | 同频不同色 → 有能量没本系统声 |
| 客房里说话 | **Payload 超帧 / 数据** | 身份对了才谈射频与音频 |

口诀：**先确认真的拿到房卡 → 再核房号与座位 → 再核客房油漆色与同步 → 最后才拧天线。**  
把「登记成功 ACK」说成「收到 Grant」，或把「还守在 TSCC」说成「已经在通话」，是本篇最常见的两大口误。

### 2.2 大图：Grant 成功路径（本篇主线）

### 2.3 对照图：三种「像成功其实不是」

```text
  A. 登记成功（手册01主线）
     C_RAND(登记) → C_ACKD + Reason 0x62/0x65
     ※ 不是 Channel Grant；此时还没派客房

  B. 呼叫失败
     C_RAND(语音) → C_NACKD + Reason
     ※ 没有 Grant；别写「Grant无声」工单

  C. 真 Grant 后掉回 TSCC（本篇主线）
     C_RAND(语音) → Grant(CHAN=N) → 手台查表失败/CC错/时隙错
     → 听不见同步 → 几秒后回控制信道
     ※ 网管可能仍显示「已分配」——空口身份才是证据
```

对照口诀：

| 你想确认的事 | 成功长什么样 | 失败 / 假成功长什么样 |
|--------------|--------------|------------------------|
| **登记办成了吗？** | 确认族 **ACK** + `0x62`/`0x65`… | NACK + `0x2A`/`0x2B`…（手册01） |
| **房间派出去了吗？** | **Channel Grant**（无 Reason） | **NACK** + 呼叫类 Reason |
| **进得了客房吗？** | Payload 上 SYNC/CC/时隙对齐 | 掉回 TSCC；或有能量无本系统声 |
| **只是让你等？** | WACK/QACK | 后面还有最终条；别当「已 Grant」 |

## 3. Grant 无声四问 + 「日志三联单（Grant 版）」

### 3.1 四问工作流（每次工单照念）

把下面四行贴在网管 / 分析仪值班屏边上（第 40 课 §4.5「Grant 无声」加厚）：

```text
① 空口真的收到 Channel Grant 了吗？
   → 是 Grant 票样（学习口径：PV/TV/BTV/PD/TD/DX 等族），还是把 ACK/NACK/登记回条误叫成 Grant？
   → 没有 Grant：先走「呼叫被拒 / 登记未成 / 还在排队」剧本，不要开「无声」单
   → 有 Grant：进入第 ② 问；记下 CSBKO/票样名、时间戳、是否重复下发

② Grant 里的 CHAN / 时隙 / 物理信道身份对了吗？
   → 读 Logical Physical Channel Number（12 bit）：0 / 1…4094 / 4095
   → 读 Logical Channel Number（1 bit）：TDMA ch1 还是 ch2
   → 对照本机写频 Frequency Plan（固定公式 或 灵活逐行）；缺行/错行/SEP 错 → 典型「掉回 TSCC」
   → CHAN=4095：去找 CG_AP 续块，别当坏值
   → CHAN=0（在 Grant 里）：当无效，先查解码——勿与 P_CLEAR 的 0（回 TSCC）搞混

③ 业务信道上的同步 / CC / 时隙身份对了吗？
   → 分析仪是否已经跟到 Payload 频点？（别只守 TSCC 骂「没超帧」）
   → 有无本系统 SYNC？Colour Code 是否与门牌/CG_AP/写频一致？
   → 时隙是否坐对半边？组呼 Late_Entry 等指针回第33课，本篇只提醒「别漏时隙位」

④ 仍无声才查射频 / 功放 / 静噪 / 音频
   → 前三问都有证据且身份对齐后，才升级：驻波、功率、静噪/数字静噪、耳麦路由、加密开关等
   → 口诀：**先信令后射频**
```

**结束条件**：四问都有证据（空口或可靠解码日志 + 写频门牌核对）写入工单，才能谈「换天线 / 送修」。只有中文「已分配信道但无声」= 线索不足。

## 4. 深挖：CHAN / 时隙 / CC / SYNC 身份（不是 Grant 地图重播）

### 4.1 Grant 成功路径无 Reason——再钉一次

来自 `ReasonCode与Grant变体.md` 与第 33 课口径：

- **Channel Grant 不要求确认**，故常重复发送。  
- **成功路径是 Grant**；**失败路径是 NACK + Reason**。  
- 不要在 Grant 比特里找「失败原因码」——找不到是正常的。  
- 本篇**不**展开 PV/TV/BTV/PD/TD/DX 逐字段地图；需要票样差异回第 33 课。

### 4.2 CHAN 三段取值（所有带信道号的 Tier III PDU 共用）

| 值 | 含义 | 值班一句话 |
|----|------|------------|
| **0** | Grant 语境下：**无效** | 先查解码；别硬映射频率 |
| **1…4094** | 逻辑 CHAN → 查手台门牌表 | 「房号」；单块 CSBK 常见 |
| **4095（0xFFF）** | 绝对频率在续块 **CG_AP** | 别当坏值；去找附页 |

**例外提醒（避免串戏）**：在 **P_CLEAR** 里，0 = **回到上次确认的控制信道**（第 36 课 §4.3）。本篇工单若看到「清场后回 TSCC」，可能是预期行为，不是「Grant 无声」。

### 4.3 两个「Logical Channel」——一字之差

| 字段 | 宽度 | 是什么 | 错了会怎样 |
|------|------|--------|------------|
| **Logical Physical Channel Number** | 12 bit | 哪一对频率（CHAN） | 进错房 / 查表失败掉回 TSCC |
| **Logical Channel Number** | 1 bit | 哪个时隙（ch1/ch2） | 坐错半边：有能量或邻时隙话务，本侧静 |

口诀：**12 bit 是房号，1 bit 是座位号。**

### 4.4 门牌表三来源（Annex C 直觉）

| 来源 | 手台里有什么 | 典型故障指纹 |
|------|--------------|--------------|
| **固定计划** | fbase / 间隔(SEP) / 双工分裂 / Tx 高低 | 高号系统性跑偏；SEP 写错误差随 CHAN 放大 |
| **灵活计划** | 每个 CHAN 一行 Tx/Rx/CC | **漏行**→ 只有某几个 CHAN 失败；新载频老手台 |
| **绝对频率** | 当场 CG_AP（或 Chan_Freq 广播） | 只发单块逻辑号、老表无行 → 仍失败；应 4095+续块 |

**社区观察（非标准强制）**：某些机型在「固定计划猎站」设定下对绝对 Grant 不友好（第 36 课引用开源控制器说明）。上线绝对频率前用目标机型实测——**规范允许 ≠ 每台手台都实现了**。

### 4.5 灵活计划缺 CHAN → Grant 后掉回控制信道

这是本篇要练到肌肉里的现场指纹：

```text
  网络：TV_GRANT CHAN=23（单块，逻辑号）
  新手台：门牌有 23 → 进 Payload → 正常
  老手台：门牌无 23 → 无法映射频率 → 听不见业务同步
           → 呼叫失败感 / 数秒后回到 TSCC
  网管：可能仍显示「已 Grant」——空口与写频才是判据
```

处理优先级（学习口径）：

1. **长期**：老手台补写频（补行）。  
2. **临时**：该业务信道改发 **4095 + CG_AP**（或 Chan_Freq 广播让大家更新门牌）。  
3. **别先做**：换功放、换天线、重装系统码（除非①②已排除）。

### 4.6 Colour Code：有能量 ≠ 有本系统声

第 20 课钉子搬过来：

- CC 是 **4 bit** 系统色标（CC0–CC15），住在 Slot Type / EMB，**不是** SYNC 图案本身。  
- **SYNC 成功 ≠ CC 匹配**。  
- 同频两网：能量很饱满，色不对则拒收 / 不开本系统静噪。  
- Grant / 门牌 / CG_AP 三处 CC 要对齐；频率核对无误仍无声时，**先核色码**（第 36 课分诊表）。

### 4.7 分析仪纪律：跟人走，不要只守一个频点

第 31 课开场警告在本篇变成检查项：

1. 人在 TSCC 等 Grant 时，你不该用「Voice LC Header 去哪了」骂射频。  
2. Grant 之后，分析仪应跟到 **Payload 频点 + 正确时隙**。  
3. Payload 上再看见「Grant 样 Opcode」——先问是否 **P_GRANT**（CSBKO 沿用原 Grant；第 33 课 §8），别喊「又回到控制信道建链」。

### 4.8 和「呼叫类拒绝」划界

| 现象 | 更像 | 去哪 |
|------|------|------|
| 无 Grant，有 NACK+Reason | 呼叫被拒 | 第 34 / 手册01 若 Reason=`0x2D` 先登记 |
| 有 Grant，进 Payload 失败 | **本篇四问** | CHAN/CC/时隙/射频顺序 |
| 有 ACK `0x62`，用户说「通了但没声」 | 登记成功、呼叫未成或未跟频 | 先分清阶段，再开单 |



### 4.9 「门牌三件套」对齐检查（可复印）

第 36 课把「信道号 ↔ 频率 ↔ 色码」称为三件套。本篇把它写成值班勾选：

```text
□ 空口 Grant 里的 CHAN（或 4095→CG_AP 宣告的逻辑号）是多少？
□ 手台写频门牌：该号是否存在？计划类型是否与网络一致？
□ 由门牌算出（或读出）的 Tx/Rx 是否与网络业务载频一致？（内部核，勿外泄）
□ 门牌行 / CG_AP / 写频格里的 Colour Code 是否同一值？
□ Logical Channel Number（时隙）与监听配置是否同一边？
```

五勾全过，仍无声 → 才郑重打开第④问。缺一勾就宣称「射频故障」，叫**跳步**。

### 4.10 固定计划「高号更惨」指纹（对照漏行）

| 指纹 | 更像 | 为什么 |
|------|------|--------|
| 只有 CHAN 17、23 失败，5、6 正常 | **灵活漏行/错行** | 逐行表只坏那几行 |
| CHAN 越小越正常，越大越偏/全军覆没 | **固定 SEP 或 fbase 错** | 误差 ≈ (CHAN−1)×间隔误差，随号放大 |
| 手台发射频点「看起来对」，完全收不到下行 | **TXRX_SPLIT 反了或分裂值错** | 公式先算手台发；分裂只扳收 | 
| 新旧批次对同一 CHAN 一个行一个不行 | **灵活：老机无行** | 例1 经典 |

把这张表和四问②绑在一起：先分类指纹，再决定是「补一行」还是「改四个参数」。

### 4.11 和手册 01 的「接口课」——两张贴纸并排贴

```text
  手册01贴纸（登记）          手册02贴纸（Grant无声）
  ① 有登记RAND？              ① 真是Channel Grant？
  ② 确认族还是误说Grant？     ② CHAN/时隙/门牌？
  ③ Reason码值？              ③ Payload SYNC/CC/时隙？
                              ④ 射频/静噪/音频
```

接口规则：

- 若①发现其实是登记 ACK → **整单移交手册01 语境**，不要在本篇硬找 CHAN。  
- 若①发现是 NACK+`0x2D` → 根因常是「还没登记」，**回跳手册01 三问**，不要在 Grant 地图里找 0x2D。  
- 若①确认是 Grant，再跑本篇②③④——两手册不互相替代，是**串联**。

## 6. 工作实例（厚例）

### 例 1 · 灵活计划漏行：Grant 了，几秒掉回 TSCC

**症状**：新站加业务载频，逻辑号教学记为 CHAN=17。新写频批次正常；老批次用户投诉「有时能叫通、一分配到新信道就静，过几秒自己回来」。

**四问记录（合格）**：

1. 空口：重复 **TV_GRANT**，CHAN=17，slot=0 ——①通过。  
2. 老手台读频：灵活计划表 **无 CHAN=17 行**；新手台有 ——②失败点锁定。  
3. 老手台未稳定出现在 Payload 同步 ——③不必先抱怨射频。  
4. 射频指标抽测正常 ——④排除。

**处理**：老批次补行；窗口期对 CHAN=17 改发 4095+CG_AP 作临时措施。  
**教训**：网管「已 Grant」+ 用户「掉回控制信道」≈ **先查门牌**。

### 例 2 · 把登记 ACK 误叫成 Grant

**症状**：用户开机后说「都 Grant 了怎么还是没人和我讲话」。

**空口**：可见 `C_ACKD` + Reason=`0x62`，**没有**业务 C_RAND，也**没有** Channel Grant。

**分诊**：①失败——这不是 Grant 无声单，是「入住成功、尚未点餐」。  
**处理**：教用户 / 调度先发起呼叫；若发起后被拒，按 Reason 剧本（手册01 / 第34）。  
**教训**：手册01 第二问与本篇第一问是同一块肌肉的两面。

### 例 3 · 频率对了，色码错了

**症状**：频谱仪在业务频点见能量；用户「完全静」。

**四问**：① Grant CHAN=9 有；② 固定计划正算与网络下行一致；③ Payload 上 SYNC 偶发可见，但 **CC 与写频不一致**（教学记：网侧 CC=5，机侧 CC=1）；④ 未先动功放。

**处理**：统一色码；同频邻网排查。  
**教训**：**有能量没声，先问 CC，再问功放。**

### 例 4 ·（加分）时隙坐错半边

**症状**：组呼部分人正常；某一台「有数字灯、无语音」。

**空口**：Grant 时隙位 =1（ch2）；该机监听配置死守 ch1。  
**处理**：纠正时隙配置 / 读法。  
**教训**：12 bit 房号对了，1 bit 座位错了，照样「Grant 了没声」。

### 例 5 ·（干净对照）成功路径短例

```text
18:10:01  C_RAND  Service_Kind=组呼语音
18:10:02  TV_GRANT × 3   CHAN=5  slot=0   （无 Reason）
18:10:02  双方离开 TSCC → 门牌 CHAN=5 有行、CC 一致
18:10:03  Payload：本系统 SYNC + 超帧 → 有声
```

用这条校准耳朵：成功时你应同时看到 **Grant 证据** 与 **Payload 身份对齐**，而不是只看到网管绿勾。

---



### 例 6 · 固定计划 SEP 写错：高号「全军偏航」

**症状**：一批从其它项目调来的手台，小号业务信道偶发可用，一分配到较大逻辑号就「完全静、掉回」。控制信道正常。

**四问**：① Grant 票样与 CHAN 清晰；② 读出写频 SEP 与本网不一致（教学叙述：机内按更宽间隔步进）；高号偏差随 (CHAN−1) 放大；③ Payload 频点根本不对，谈不上 CC；④ 射频正常。

**处理**：统一固定计划四参数（与网络规划一致），不要逐个 CHAN「盲补灵活行」。  
**教训**：指纹先分类——高号系统性 ≠ 漏行。

### 例 7 · 主叫有声、被叫无声

**症状**：调度听得到外勤；外勤说「调度没声」。网管显示双方「在同一呼叫」。

**分诊**：

| 侧 | ① Grant？ | ② 门牌/时隙 | ③ Payload 身份 |
|----|-----------|-------------|----------------|
| 主叫 | 有 | 有行、slot 一致 | SYNC/CC 齐 → 有声 |
| 被叫 | 空口偶发漏收重复 Grant | 有行 | 仍长时间守 TSCC |

**处理**：查被叫侧覆盖/漏听（Grant 本就靠重复）；确认被叫写频 CC；必要时做可达性/场强，而不是先换主叫功放。  
**教训**：双端分别跑四问；「同一呼叫」绿勾不能代替被叫跟频证据。

### 例 8 · 在 TSCC 上骂「没有超帧」

**症状**：测试同事按第 30 课清单找 Voice LC Header，十分钟找不到，申告「集群语音坏了」。

**现场**：分析仪中心频率仍停在 **TSCC**；屏上反复刷新 Aloha 与 Grant。

**处理**：Grant 出现后把分析仪切到业务载频与正确时隙；超帧在客房里。  
**教训**：第 31 课「跟人走」是测试岗位的第一纪律，也是本篇③的设备版。

### 参考答案

1. **不是第 41 课。** 接在手册 01（登记失败三问）之后；核心是 **Grant 无声四问**。  
2. ①真 Grant？②CHAN/时隙/门牌？③Payload 同步/CC/时隙？④射频/静噪/音频。——前三问未清时动射频，会掩盖门牌/色码根因，浪费时间且误判设备。  
3. **不带 Reason**；失败看 **NACK+Reason**。  
4. Grant：0=无效；17=逻辑房号查表；4095=看 CG_AP。P_CLEAR 的 0=回上次确认的 TSCC。  
5. 12 bit=频率房号；1 bit=时隙座位。房号错→进错房/掉回；座位错→听错半边。  
6. Grant 后进不去 / 数秒掉回 TSCC；长期补写频，临时 4095+CG_AP 或 Chan_Freq。  
7. 人可能已进 Payload；分析仪应**跟人走**到业务频点与时隙。  
8. **先 CC**（及身份）；依据第 20 课 + 第 36 课分诊：「频率无误仍无声→色码」。  
9. **不应**开 Grant 无声单；那是登记成功——回手册01形态，再视是否发起业务 RAND。  
10. 空口/信令、终端/写频、网络/载频。无 CHAN/票样/门牌证据则无法执行分诊卡。  
11. 「信道号每次呼叫都变」的假象（地址在变）；先查解码字段边界。  
12. 先问是否已在业务信道上的 **P_GRANT**（CSBKO 沿用），别立刻报「又回 TSCC 建链」。

## 11.6 和弱项加餐的衔接（仍非主线）

若你读到「没声」仍第一反应是「是不是 4FSK 解不出」：

1. 先问：TSCC 上能否稳定看见 Aloha/Grant？能看见前台小票，通常说明**解调链路活着**。  
2. 再跑四问——多数票落在门牌、色码、时隙、跟频。  
3. 只有身份都解不出、或 Payload 能量与解码长期对不上时，才把射频提到前面。  
4. 四句话随时回：`学习推送/加餐_频率带宽与调制解调.md`。

记住：**Grant 是控制面房卡；无声首先是身份与跟频问题，不是频谱仪心情。**

## 11.7 常见问法速查（FAQ 式）

**Q1：网管绿勾，用户无声，以谁为准？**  
A：以空口 Grant + Payload 身份为准。绿勾只是线索。

**Q2：固定计划网也会「缺行」吗？**  
A：固定计划不靠逐行；更常见是 SEP/fbase/分裂参数错导致**系统性**跑偏。指纹不同：灵活是「某几个号」，固定是「高号更惨」。

**Q3：绝对 Grant 是否万能？**  
A：规范允许，但机型/猎站设定可能限制（社区观察）。目标机型实测；长期仍建议门牌一致。

**Q4：要把 Stun 写进 Grant 无声卡吗？**  
A：**本篇不写。** 管理类异常见第39课与下一候选「Week‑2 话术」。

**Q5：分诊卡能否写真实频点方便夜班？**  
A：**不能写进学习推送/公开仓。** 真实频点只存在你们受控参数库；卡片只留逻辑号与问题。

**Q6：主叫有声被叫无声，还用四问吗？**  
A：用。两边分别跑①②③——常见是被叫未跟频、时隙/CC 不一致，或根本没收到同一张 Grant。
