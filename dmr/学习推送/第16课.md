# 第 16 课 · 突发 264 bit 与 108+48+108

> DMR 深入学习 · **阶段 C 空口深入第 2 课**  
> 适合：已吃透第 15 课「时隙 30 ms / TDMA frame 60 ms」，但看到「264」「中间 48」「两侧 108」仍像一串数字、写频/抓包时分不清「这是语音突发还是数据突发」的人  
> 阅读量：约 **30–40 分钟** · 几乎不推公式 · 要把「**Traffic burst = 264 bit ≈ 27.5 ms = 108 + 48 + 108；中间是 SYNC 或嵌入；两侧合计 216 bit 够装约 60 ms 压缩话**」钉死  
> **频谱 / 调制提醒（一小段，不是本课主线）**：RF 仍是整条 **12.5 kHz** 上路；调制仍是 **4FSK**，符号率约 **4800 baud**，总比特率约 **9.6 kbps**（每符号 2 bit）。本课数字账会用到：264 bit ÷ 27.5 ms ≈ 9600 bit/s。频率/带宽/调制四句话见 `学习推送/加餐_频率带宽与调制解调.md`；本课主线是**货箱内部布局**。

## 1. 为什么本课重要（动机）

第 15 课站住了时间轴：绿灯 30 ms、一对时隙拼成 60 ms 的 TDMA frame、约 2.5 ms 缝留给 Guard 或 CACH。同事若只问「时隙对不对」，你已经能答。下一步问题更「贴铁皮」：

- 抓包 / 协议分析仪：屏幕上蹦出一个 **burst**。它不是「一整秒的音频文件」，而是一个约 **27.5 ms** 的货箱，里面整整 **264 bit**。  
- 说明书或白皮书写「108 + 48 + 108」：中间那块有时是 **SYNC**（同步字），有时是 **嵌入信令**（EMB + 碎片），有时数据突发还要再「抠」出 **Slot Type**。搞不清这三种读法，就会把语音当数据、把色码当业务类型。  
- 现场听感谜题：时隙只有 30 ms，人为什么听不到「咯噔咯噔」？答案就在本课账本——**两侧 payload 合计 216 bit，可承载约 60 ms 压缩语音**；时间窗短，听感窗长。  
- 迟后进入（Late Entry）：语音超帧里 **Burst A** 中间放 Voice SYNC，后面 B–F 中间常放嵌入。本课先把「中间 48 位是什么座位」认清；第 17 课再专讲 A–F。  
- 排障口语：「同步不上」「Slot Type 不对」「没有 Voice LC Header」——这些话最终都落在**同一个 264 bit 货箱的不同读法**上。

若只背「突发有 264 比特」七个字，后面会卡在同一处：

> **264 不是一坨糊涂肉。它是左右两块货（各 108）夹着中间一块导航/信令（48）。语音读法与数据读法共享同一外壳，中间座位的用法不同。**

本课目标是让你能自己讲清十件事：

1. **为什么**要用「左右货仓 + 中间驾驶舱」记 108+48+108；  
2. 一张总图：Traffic burst 264 = 108 | 48 | 108，嵌在 30 ms 时隙的 27.5 ms 内容窗里；  
3. 白话术语：Burst、Payload、SYNC、嵌入信令、EMB、Slot Type、Data Type、Vocoder socket、dibit；  
4. 语音突发 vs 数据/控制突发的两种读法；  
5. 现场岗位：抓包认中心场、写频/监听「有声无地址」、迟后进入与 SYNC 疏密脸熟；  
6. 完整例子：从 Voice LC Header → 超帧 A（SYNC）→ B（嵌入）跟一次；  
7. 数字账本：264 / 216 / 48 / 20 / 196 / 72×3 / 4800 / 9.6k；  
8. 常见误区 + 自测；  
9. 资料库加深路径；  
10. 核验过的外链（Part1 原文 + 协会导读 + 信号笔记 + 解码深潜文）。

## 2. 总图 / 故事：左右货仓 + 中间驾驶舱

先把整课装进一个故事，再落到 Part1 clause **4.2.2** figure 4.3 与资料库 `01-空中接口/帧结构与字段定义.md` §3。精神与 `00-入门/DMR术语与帧结构速查卡.md` §A 一致。

### 2.1 货箱长什么样

第 15 课把时隙比作 30 ms 绿灯。绿灯亮着时，真正「装比特出门」的货箱大约只有 **27.5 ms** 长，里面码放 **264 bit**：

```text
一个 Timeslot = 30.0 ms
├── 内容窗 ≈ 27.5 ms · Traffic burst = 264 bit
│         ┌──────────┬──────────┬──────────┐
│         │ 108 bit  │  48 bit  │ 108 bit  │
│         │ Payload  │ SYNC/嵌入│ Payload  │
│         │ （左货仓）│ （驾驶舱）│ （右货仓）│
│         └──────────┴──────────┴──────────┘
└── 缝 ≈ 2.5 ms · 入站 Guard / 出站 CACH（第 15、18 课）
```

口诀：

- **左右货仓**：各 **108 bit**，合起来 **216 bit** → 语音时够装约 **60 ms** 压缩话。  
- **中间驾驶舱**：**48 bit** → 要么贴一张「我是谁/我在哪」的 **SYNC 标签**，要么塞一小卷 **嵌入信令**。  
- **货箱总重**：108+48+108 = **264**。少一块都不叫标准 Traffic burst。

### 2.2 为什么中间要夹在正中？

规范把中心场放在突发正中，接收机好办两件事：

1. **找中心**：用 SYNC 图案做相关（matched filter），对准符号节拍与频偏；  
2. **换读法**：同一次突发，中心可以是 SYNC，也可以是嵌入；后续突发不必每帧都贴完整 SYNC，也能用嵌入继续带地址/控制信息。

可以想成火车：车厢（payload）在两侧，车头标志灯（SYNC）或随车调度单（嵌入）夹在中间——车长固定，你先摸到中间，就知道整列车从哪切到哪。

### 2.3 两种读法：语音壳 vs 数据壳

**同一外壳 264 bit**，业务不同时，左右货仓的「刻度」会微调：

| 读法 | 左右怎么切 | 中间 48 | 还多什么 |
|------|------------|---------|----------|
| **语音突发**（Vocoder socket） | 108 + 108 = **216** 语音载荷 | Voice SYNC **或** EMB+嵌入 | 无 Slot Type |
| **数据/控制突发** | 左右各拿出 10 bit → 信息区变成 **98+98=196** | Data SYNC 或 RC 等 | **Slot Type 20 bit**（10+10 夹在中心两侧） |

数据突发的「刻度图」更细一点：

```text
数据/控制突发（仍是 264 bit 总长）：
  Info(98) | SlotType(10) | SYNC或嵌入(48) | SlotType(10) | Info(98)
             └──────── SLOT PDU 共 20 bit ────────┘
```

- **Slot Type** 里带着 **Colour Code（色码）** 与 **Data Type（数据类型）**——告诉你这 196 bit 信息是 CSBK、Voice LC Header、Idle，还是分组数据块……  
- 语音突发**没有**这 20 bit Slot Type；它用「中心是 Voice SYNC 还是嵌入」+ 超帧位置来叙事。细节字段第 19–21 课还会再拆。

### 2.4 216 bit 与「约 60 ms 话」怎么对账

这是第 15 课埋下的钩子，本课结账：

| 说法 | 数字 | 含义 |
|------|------|------|
| 时隙绿灯 | 30 ms | 时间车道长度 |
| 内容窗 | ≈ 27.5 ms | 264 bit 真正占用的发送时间 |
| 语音载荷 | 216 bit | 两个 108 |
| 听感窗口 | ≈ **60 ms** 压缩语音 | 一突发装进去的话音时长（含 FEC 后的声码帧） |
| 常见切法 | 3 × 72 bit | 例如 20 ms 声码帧时，三帧 + 中心 48 = 264 |

反直觉但正确：**30 ms 窗口里发出去的货，耳朵可以听成约 60 ms 的话。** 因为数字压缩 + 双时隙时间复用：你不是在「实时模拟波形占满 30 ms」，而是在「短窗里塞进压缩后的语音比特」。

### 2.5 和第 15 课、第 17 课的接口

| 课 | 你已经会 / 即将会 |
|----|-------------------|
| 第 15 | 时隙 30 ms、frame 60 ms、Guard/CACH 缝、264 只是脸熟 |
| **本课** | 264 内部 108+48+108；语音/数据两种读法；216↔60 ms |
| 第 17 | 六个突发 A–F = 360 ms 语音超帧；A 放 SYNC、B–E 拼 Full LC |

本课对超帧只要求：知道 **Burst A 的中心常常是 Voice SYNC**，B–F 中心常常是嵌入——别和「每个突发中间永远是 SYNC」搞混。

### 2.6 调制账本钩子（巩固弱项，不重开加餐）

加餐四句话在本课落成一行算术：

1. **频率**：载波仍停在你写频的那个 MHz 刻度上。  
2. **带宽**：地皮仍约 **12.5 kHz** 宽。  
3. **调制**：信息被装进 **4FSK**（四个频偏电平 ↔ 四个 dibit）。  
4. **解调**：对方从电平序列卸下 dibit，再拼回 264 bit 货箱。

符号率约 **4800 符号/秒** × 2 bit/符号 ≈ **9600 bit/s**。  
验算：264 bit / 0.0275 s ≈ **9600 bit/s**——和总比特率同量级。若有人用 264/0.030 去除，会算「偏慢」，那是把约 2.5 ms 缝也当成业务比特窗了（第 15 课题 7 已练过）。

## 3. 白话术语表

| 术语 | 一句话 | 别和谁混 |
|------|--------|----------|
| **Burst（突发）** | 一次时隙绿灯里发出的那一箱比特 | 不是「整通通话」，也不是「整个超帧」 |
| **Traffic burst** | 业务突发，内容 **264 bit / ≈27.5 ms** | 另有 CACH 24 bit、独立 RC 96 bit 等短突发 |
| **Payload** | 左右货仓里的业务比特 | 语音时是声码载荷；数据时是 Info |
| **108+48+108** | 通用突发外壳布局 | 数据读法会从左右再抠 Slot Type |
| **SYNC** | 48 bit 同步图案，标突发中心、区分语音/数据/方向等 | 不是色码，也不是 Talkgroup |
| **嵌入信令** | 中心 48 不用 SYNC 图案时，改塞 EMB+信令碎片 | 第 21–22 课再拆 EMB/Full LC |
| **EMB** | 嵌入信令外框的一小段头（语音突发中心场的一部分） | 别把整个 48 bit 都叫 EMB |
| **Slot Type（SLOT）** | 数据/控制突发上的 20 bit：色码 + Data Type + 校验 | **语音突发没有** |
| **Data Type** | Slot Type 里的类型码：CSBK、Voice LC Header、Idle… | 决定 196 bit 怎么解 |
| **Vocoder socket** | 「声码器插座」：规范为语音载荷留的固定比特位 | 声码器算法本身可选供应商 |
| **Dibit** | 4FSK 一个符号携带的 2 bit | 264 bit = **132 dibit** |
| **Voice superframe** | 连续 6 个业务突发 A–F = **360 ms** | ≠ TDMA frame（60 ms） |
| **Colour Code** | 同频系统区分用的色码 | 常出现在嵌入/数据突发相关场 |

## 4. 现场对照：这些数字落在岗位上

### 4.1 写频与监听

- 用户只关心「能不能通话」；你要关心「空口上到底是语音突发还是控制突发在飞」。  
- 中继一路 Slot1 在开会（一串语音突发 + 偶发 Terminator），Slot2 可能在飞 CSBK/数据——**同一 12.5 kHz，不同逻辑车道，货箱外壳相同、读法不同**。

### 4.2 抓包 / 仪表

典型认图顺序（直觉版）：

1. 先锁定时隙与突发边界（第 15 课）。  
2. 看中心 **48**：像不像已知 SYNC 图案？像 → 语音 SYNC 或数据 SYNC（图案不同）。  
3. 若是数据壳：解 **Slot Type** → 读 Data Type → 再解 196 bit。  
4. 若是语音壳：看超帧位置——A 常 SYNC；B–E 常嵌入碎片。

### 4.3 「有载波、听不清话 / 无声」

可能栈：

| 现象 | 优先怀疑 | 和本课关系 |
|------|----------|------------|
| 完全无声，RSSI 好 | 错槽、错色码、错组 | 第 15 课 + 色码课 |
| 偶发同步失败 | SYNC 图案/极性/信噪 | 本课中心场 |
| 头一秒无声后突然进会 | 迟后进入，在等 Burst A 的 Voice SYNC | 本课钩子 → 第 17 课 |
| 控制台显示 CSBK 刷屏无语音 | 你在看数据壳，不是语音壳 | 本课两种读法 |

### 4.4 电池与占空（复习挂钩）

MS 在某一逻辑信道上发射时，大约只占 **50%** 时间（双时隙里的一槽）。货箱是 27.5 ms 满载比特，但整机发射节奏仍按 30 ms 车道走——省电故事的根仍在 TDMA，不在「264 变少」。

### 4.5 直通 vs 中继

- **中继出站**：业务突发之间常夹 **CACH**（24 bit），不是 264 的一部分。  
- **入站**：264 后面常接 **Guard**。  
- **直通**：同样有 Traffic burst 外壳；SYNC 图案会用直通专用系列（规范有多套图案）。本课先记「外壳一样，标签图案可能不同」。

### 4.6 培训台上怎么讲给新人听（30 秒版）

你可以这样说，不必报条款号：

> 「DMR 每次轮到你的时隙，就扔出一个固定大小的包裹，里面 264 个比特。包裹两边是货物，中间是标签或小便签。打电话时两边装压缩声音；发控制命令时两边装信令，并且会从两边各撕一条边下来写『这是哪种命令、什么色码』。标签不是每包都一样：有的包贴同步大标签，有的包改贴小便签拼地址。」

若新人追问「那 30 ms 和 60 ms 话怎么同时成立？」——指向本节 2.4 与题 2。

### 4.7 和岗位文档的映射

| 你司/项目里可能出现的词 | 映射到本课 |
|--------------------------|------------|
| 时隙帧 / TDMA 帧 | 第 15 课 60 ms；本课不重讲 |
| 突发 / burst / 时隙脉冲 | **264 bit Traffic burst** |
| 同步字 / sync word | 中心 **48** 的 SYNC 读法 |
| 嵌入 LC / embedded LC | 中心 **48** 的嵌入读法 |
| 时隙类型 / slot type | 数据壳 **20 bit SLOT** |
| 声码帧 / AMBE 帧（厂商口语） | 落在 216 bit 语音载荷里（算法细节非本课） |

## 5. 完整例子：跟一次「开始说话」的货箱

场景：Tier II 中继，某组呼在 **Slot1** 发起语音。时间数字取常见教学量级；实现细节以 Part1 为准。

### 5.1 开场：数据壳先报门牌

通话真正「进超帧哼歌」之前，空口上常先出现**数据/控制形态**的突发，例如 **Voice LC Header**（语音链路控制头）：

```text
数据壳 264 bit：
  Info 98 | SLOT 10 | Data SYNC 48 | SLOT 10 | Info 98
                 └─ Slot Type：CC + Data Type=Voice LC Header …
  196 bit Info（经 FEC）里带着：谁呼谁、FLCO、地址…
```

现场翻译：先贴一张工卡（地址/业务），再允许进会议室连续发言。

### 5.2 进入语音超帧：Burst A 中间是 Voice SYNC

```text
语音壳 264 bit（Burst A）：
  Voice 108 | Voice SYNC 48 | Voice 108
              └─ 超帧边界；迟后进入的人靠它「跳进会场」
```

左右 216 bit ≈ 装进约 60 ms 压缩话。听感上会议开始有声。

### 5.3 Burst B（以及常见的 C–E）：中间改嵌入

```text
语音壳 264 bit（Burst B 典型）：
  Voice 108 | EMB(8)+嵌入(32)+EMB(8) 共 48 | Voice 108
```

- 语音继续从左右货仓流出去；  
- 中间改塞 **嵌入碎片**，多帧拼回一条 **Full LC**（完整链路控制）——第 17、22 课展开；  
- 本课只要建立肌肉记忆：**不是每个语音突发中间都是 SYNC**。

### 5.4 结束：Terminator with LC（又是数据壳）

语音尾常跟 **Terminator with LC**：再次用数据壳 + Data SYNC，宣告「散会」，并可再带一次 LC。现场语感：话停了，空口上还可能闪一下控制型突发。

### 5.5 一张对照表（本课要求能背结构，不要求背比特图案）

| 阶段 | 外壳 | 中心 48 常见 | 左右 |
|------|------|--------------|------|
| Voice LC Header | 数据壳 | Data SYNC | 196 Info + Slot Type |
| Voice Burst A | 语音壳 | Voice SYNC | 216 语音 |
| Voice Burst B–E | 语音壳 | 嵌入（EMB+碎片） | 216 语音 |
| Terminator with LC | 数据壳 | Data SYNC | 196 Info + Slot Type |

### 5.6 双时隙旁边在干什么？（同一条 12.5 kHz）

假设 Slot1 在跑上面的组呼，Slot2 同时有个呼或数据：

```text
时间 →（示意，非严格波形）
Slot1:  …[语音A][语音B][语音C]…     ← 语音壳为主
Slot2:  …[CSBK ][Idle ][数据头]…     ← 数据壳为主
物理：同一 RF 载波，时间上轮流亮绿灯（第 15 课）
```

岗位翻译：网管「一路语音一路信令」并不神秘——**两个逻辑车道各自装填自己的 264 bit 货箱**；你用抓包过滤时隙后，再套本课的语音壳/数据壳读法。

### 5.7 迟后进入：为什么中途开机还能进会？

用户中途开机、拧到正确组与时隙：

1. 耳朵要等下一次 **Voice SYNC**（常见在 Burst **A**）；  
2. 同时靠嵌入碎片拼地址（B–E），确认「这通是不是我的组」；  
3. 所以迟后进入的体验是「略顿一下再有声」，不是永远听不到。

本课贡献：你知道去空口上找的是**中心场的 SYNC/嵌入节奏**，而不是幻想「每个 30 ms 都有完整门牌」。拼 LC 的细节留给第 17、22 课。

### 5.8 和「独立 RC 突发 / CACH」划界（防膨胀）

| 东西 | 长度 | 是不是本课的 264 货箱？ |
|------|------|------------------------|
| Traffic burst | 264 bit | **是**（主线） |
| CACH | 24 bit | 否；夹在出站缝里（第 18 课） |
| Standalone RC | 96 bit | 否；另一类短突发（脸熟即可） |
| 嵌入在中心 48 里的 RC 碎片 | 占中心场 | 仍在 264 外壳内，但读法特殊（以后课） |

口诀：**先认 264 大货箱，再认缝里的小信封。**

| Slot Type | **20 bit** | 10+10 |
| CACH | **24 bit** | 仅出站缝里 |
| Standalone RC | **96 bit** | 另一类短突发；本课脸熟 |
| Voice superframe | **360 ms** | 6 × 30 ms，A–F |
| 符号率 | **≈ 4800 baud** | 4FSK |
| 比特率 | **≈ 9.6 kbps** | 2 bit/符号 |
| 验算 | 264 / 0.0275 ≈ **9600** | 用内容窗，不用 30 ms |

口算口诀：**三十窗、二七五货、二六四粒、两旁一零八、当中四八、语音二一六对六十毫秒话。**

## 7. 常见误区

1. **「264 bit 平均摊在 30 ms 里。」**  
   错。业务比特主要在 **≈27.5 ms**；约 2.5 ms 是缝。

2. **「每个突发中间永远是 SYNC。」**  
   错。语音超帧里往往 **A 为 Voice SYNC，B–F 多为嵌入**；数据突发中心是 Data SYNC 或 RC 等。

3. **「语音突发也有 Slot Type。」**  
   错。Slot Type 是**数据/控制壳**上的 20 bit；语音壳是干净的 108+48+108。

4. **「216 bit 只能装 27.5 ms 的话，所以一定卡顿。」**  
   错。216 bit 对应约 **60 ms** 压缩语音；再加接收端平滑，听感连续。

5. **「108+48+108 和 98+10+48+10+98 是两种完全不同的物理长度。」**  
   错。都是 **264 bit** 外壳；第二种是从左右货仓各挪 10 bit 给 Slot Type 的读法。

6. **「dibit 就是 bit。」**  
   错。一个 4FSK 符号 = **2 bit** = 1 dibit；264 bit = 132 dibit。

7. **「中间 48 bit 就是 Colour Code。」**  
   错。色码另有位置（如 Slot Type、嵌入相关场）。48 是 SYNC 或嵌入窗口。

8. **「Burst = Superframe。」**  
   错。Burst 是一箱；Superframe 是六箱连拍。

9. **「CACH 的 24 bit 也算在 264 里面。」**  
   错。CACH 在出站 **约 2.5 ms 缝**里，与 Traffic burst 首尾相接，但**不是** 108+48+108 的一部分。

10. **「看到 9.6 kbps 就以为单时隙用户独占全部比特率。」**  
    错。约 9.6 kbps 是载波上的总空口比特率量级；双时隙时间复用后，单逻辑信道的「业务节拍」要按自己的 30 ms 车道理解（第 15 课 + 本课货箱）。

## 8. 自测（请先自己答，再展开）

**题 1.** Traffic burst 总比特多少？通用外壳如何拆成三段？内容窗大约多长？

<details><summary>简答</summary>

**264** bit；**108 + 48 + 108**；内容窗约 **27.5 ms**（外加约 2.5 ms 缝才凑满 30 ms 时隙）。

</details>

**题 2.** 语音突发两侧合计多少 bit？它和「约 60 ms 压缩语音」如何对账？为什么听感不是 30 ms 卡一下？

<details><summary>简答</summary>

两侧合计 **216 bit**，规范描述为足以携带约 **60 ms** 压缩语音；短时间窗里塞的是压缩后的声码比特，接收端再播放平滑，故听感连续。

</details>

**题 3.** 数据/控制突发相对语音壳，左右货仓发生了什么变化？多出来的 20 bit 叫什么、主要带什么信息？

<details><summary>简答</summary>

左右各拿出 10 bit，信息区变为 **98+98=196**；多出的 **Slot Type（20 bit）** 主要带 **Colour Code** 与 **Data Type**（外加校验）。

</details>

**题 4.** 同事说：「语音通话时每个 30 ms 突发中间都是 Voice SYNC。」请纠正，并指出正确的疏密直觉。

<details><summary>简答</summary>

纠正：语音超帧里通常 **Burst A** 中心为 Voice SYNC，**B–F** 中心多为嵌入信令。SYNC 机会大约每逻辑信道 **360 ms** 量级（超帧级），不是每 30 ms 都贴 Voice SYNC。

</details>

**题 5.** 口算：为什么用「264 bit ÷ 30 ms」会对不齐约 9.6 kbps？正确分母应取多少？

<details><summary>简答</summary>

30 ms 含约 2.5 ms 非业务比特缝；应用 **≈27.5 ms**：264 / 0.0275 ≈ 9600 bit/s。

</details>

**题 6.** 抓包看到 Data Type = CSBK。这更可能是语音壳还是数据壳？中心 48 更可能是 Voice SYNC 还是 Data SYNC？

<details><summary>简答</summary>

**数据壳**；中心更可能是 **Data SYNC**（或规范允许的嵌入/RC 情形），不是 Voice SYNC。CSBK 落在 196 Info + Slot Type 叙事里。

</details>

**题 7.** 132 dibit 等于多少 bit？它和 4FSK、4800 baud 有何关系？（巩固调制弱项）

<details><summary>简答</summary>

132 × 2 = **264 bit**。4FSK 每符号 2 bit；约 4800 符号/s → 约 9.6 kbps，与单突发内容窗账本一致。

</details>

**题 8.** CACH 24 bit 是否包含在 Traffic burst 的 264 bit 内？它出现在入站还是出站缝里？

<details><summary>简答</summary>

**不包含**在 264 内。CACH 出现在**出站**约 2.5 ms 缝；入站同位置通常是 Guard。

</details>
