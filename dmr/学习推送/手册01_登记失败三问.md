## 1. 为什么要写这篇手册（动机 + 现场对话）

第 40 课收官时，运维路线的 **第 1 周** 写得很清楚：

> Reason 高频码 + **登记失败三问** → 交付《本网 10 个 Reason 剧本》草稿。

课程编号停在第 40 课。从今天起，同一套材料按**症状 / 岗位**继续推——这是手册模式的第一篇，专门把 Week‑1 那一行展开成可值班用的厚文。

现场你一定听过这些对话：

- 调度：「他开机了，网管显示『注册失败』。」——你问「Reason 码值？」对方回「就写着失败啊。」——中文提示是线索，**不是证据**。  
- 写频同事：「系统码、CC、频率都对，怎么还登不上？」——可能空口身份对了，但 **C_RAND(登记) 根本没发出去**；也可能发出去了，回的是 `0x2B Reg_Denied`。三问没问完就改写频，等于在猜。  
- 新站开通当天：「一半手台登不上。」——日志里 `0x2A` 和 `0x2B` 混着出现。一个是 **Reg_Refused（可换站再试）**，一个是 **Reg_Denied（被本 TSCC 否决、进 Denied Registration List）**，处理剧本完全不同（第 34 课钉子；本篇 §4、§6 再钉）。  
- 用户：「手台一直转圈，说排队。」——有人当「登记失败」开单，其实看见的是 **`0xE0 Wait`（WACK，中间态）**，后面还应有最终 ACK/NACK；别把「稍等」当成终局拒绝。  
- 监听员：「我看见 Grant 了啊！」——登记成功路径**不是**语音 Channel Grant；登记成功常见是 **`C_ACKD` + Reason=`0x62 Reg_Accepted`（或 `0x65` 登记+组订阅）**。把登记回条跟语音小票搞混，三问第二问就答错。  
- 分析仪新人：「字节里明明有个 `2A`……」——直接念 `0x2A Reg_Refused`，结果真正 Reason 可能是跨字节拼出来的别的码（第 34 课 §3.3 阴坑；本篇 §4.4 提醒）。

培训台如果只背「集群要先登记」六个字，值班会卡在同一处：

> **会背「要登记」≠ 会分诊。**  
> 分诊 = 每次工单强制三问：  
> **① C_RAND 发出去了吗？（有没有按铃 / Service_Kind=登记类）**  
> **② 回来的是 Grant 还是哪条确认族 ACK？**（登记成功走 ACK Reason，不是语音 Grant）  
> **③ Reason 码值是多少？**（整 8 位；重点 `0x62 / 0x2A / 0x2B / 0x2D / 0xE0` 与鉴权相关名字指针）  
> 三问答不清，不许升级为「设备故障」或「射频坏了」。

本篇目标：能画出「守 TSCC → 读 Aloha → C_RAND(登记) →（可选 WACK）→ ACK(Reg_Accepted) / NACK(Reg_Refused|Reg_Denied|…)」总图，并与语音 Grant 路径对照；会用三问 +「日志三联单」接单；会精读登记相关 Reason（不是把第 34 课全表再 dump 一遍）；会区分写频/CC/Hunt 问题与真登记拒绝的先后顺序；能填完《本网 10 个 Reason 剧本》模板；自测过关后，回库翻 `ReasonCode与Grant变体.md` 把本网真实高频码补进剧本。

**本篇硬禁令（写进脑子）**：不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/ReasonCode与Grant变体.md`、`集群协议字段速览.md`、`总索引.md` 集群关键词、第 32/34/35/40 课已有编号为准）；**不重 dump Grant 全变体地图**（第 33 课）；**不重 dump Hunt 状态机**（第 37 课）；**不讲鉴权算法 / RC4 细节**（第 35 课；本篇只认鉴权相关 Reason **名字**当指针）；**不写攻击面 Stun/Kill 内容**（若提及仅保留第 39 课网络管理口径）；不把厂商中文提示当成 ETSI 正式名；本篇不写下一篇手册正文。

## 2. 总图 / 故事：登记回条 vs 语音 Grant

### 2.1 一句话：登记是「入住」，Grant 是「房卡」

继续旅馆比喻（第 31–34、40 课）：

| 旅馆 | 空口 | 成功长什么样 |
|------|------|--------------|
| 前台告示牌 | **C_ALOHA**（Reg / Mask / Backoff…） | 能读懂「要不要先登记」 |
| 入住按铃 | **C_RAND**，Service_Kind=登记类（学习口径 `1110₂`） | 分析仪上**看见这台机的登记按铃** |
| 入住回条 | **确认族** C_ACKD / C_NACKD / C_WACKD… + **Reason** | 成功常见 `0x62 Reg_Accepted`；失败 `0x2A/0x2B`…；中间 `0xE0 Wait` |
| 点餐要房 | 再发 **C_RAND**（语音/数据类） | 与登记按铃 **Service_Kind 不同** |
| 房卡小票 | **Channel Grant**（PV/TV/…） | **Grant 本身不带 Reason**；失败才走 NACK |

口诀：**先读告示 → 再办入住（登记 RAND + ACK Reason）→ 再点餐要房（语音 RAND + Grant）→ 最后进客房说话。**  
把「登记成功」说成「收到 Grant」，是本篇最常见的口误。

### 2.2 大图：登记路径（本篇主线）

```text
  ┌─────────────────────────────────────────────────────────┐
  │  MS 守在 TSCC（控制前台）                                 │
  │  听 C_ALOHA：Reg / Mask / Backoff / NRand_Wait / SF …   │
  └───────────────────────────┬─────────────────────────────┘
                              │
              Reg=1（须登记后才活跃）时
                              ▼
  ┌─────────────────────────────────────────────────────────┐
  │  ① 按铃：C_RAND（Service_Kind = 登记类 `1110₂`）          │
  │     ← 三问第 1 问：这枪发出去了吗？                        │
  └───────────────────────────┬─────────────────────────────┘
                              │
          （可选）网络忙着办手续
                              ▼
  ┌─────────────────────────────────────────────────────────┐
  │  C_WACKD · Reason = Wait `0xE0`                         │
  │     ← 中间态：已收下，后面还有信令；≠ 登记成功；≠ 登记失败 │
  └───────────────────────────┬─────────────────────────────┘
                              │
              最终回条（确认族，看 Reason 的 tt）
                              ▼
        ┌─────────────────────┴─────────────────────┐
        │                                           │
        ▼                                           ▼
  C_ACKD（tt=ACK）                            C_NACKD（tt=NACK）
  · Reg_Accepted `0x62`                       · Reg_Refused `0x2A`
  · Reg_Subscription… `0x65`（登记+组附着）    · Reg_Denied  `0x2B`
  · （鉴权相关名字 → 第 35 课指针）            · （其它网络拒因，见第 34）
        │                                           │
        ▼                                           ▼
  入住办成 → 可再发语音/数据 C_RAND            按码值选剧本：
                                               2A→可换站再试
                                               2B→本站否决/Denied List
                                               …
  三问第 2 问：回来的是确认族 ACK/NACK，
               不是语音 Channel Grant！
  三问第 3 问：Reason 整 8 位码值是多少？
```

旁路指针（本篇认形状，不展开）：

- **C_AHOY 点名**也可驱动登记后续（第 32 课路径 B）——仍要落到确认族 Reason，不是 Grant。  
- **MassReg**（大规模重登记）会让控制面「挤」——先查是不是策略性重登记窗，别先换机柜（第 32 课）。  
- 未登记却直接发**语音** C_RAND → 常见 `0x2D MS_Not_Registered`（这是「业务被拒」，根因仍是没办成入住）。

### 2.3 对照图：语音呼叫成功路径（只为对比，不 dump Grant 地图）

```text
  （已登记）MS --C_RAND(语音类)--> TSCC
       │
       ├─ 成功 → Channel Grant（重复发送常见）→ 双方进 Payload 说话
       │         ※ Grant 无 Reason
       │
       └─ 失败 → C_NACKD + Reason（权限/对方不在/拥塞/…）
                 ※ 这里的 Reason 是「呼叫被拒」，不是「登记被拒」
                 ※ 若 Reason=`0x2D`：先回去办登记，别在 Grant 变体里找原因
```

对照口诀：

| 你想确认的事 | 成功长什么样 | 失败长什么样 |
|--------------|--------------|--------------|
| **登记办成了吗？** | 确认族 **ACK** + `0x62`/`0x65`… | 确认族 **NACK** + `0x2A`/`0x2B`… |
| **房间派出去了吗？** | **Channel Grant** | **NACK** + 呼叫类 Reason |
| **只是让你等？** | **WACK** `0xE0` 或 **QACK** `0xA0`/`0xA1` | 后面还有最终条；别当终局 |

## 3. 登记失败三问 + 「日志三联单」

### 3.1 三问工作流（每次工单照念）

把下面三行贴在网管值班屏边上（第 40 课 §5.2 原文加厚）：

```text
① C_RAND 发出去了吗？
   → 有没有「按铃」？Service_Kind 是不是登记类？
   → 没有 RAND：先查终端是否在发、Aloha Mask/Backoff、写频系统身份、射频能否守住 TSCC
   → 有 RAND：进入第 ② 问

② 回来的是 Grant 还是哪条确认族 ACK？
   → 登记场景：期望看见 C_ACKD / C_NACKD / C_WACKD（同一 Opcode 壳，靠 Reason 的 tt 区分）
   → 若同事说「看见 Grant 了」：先确认是不是把登记回条误叫成 Grant；
     登记成功通常是 ACK+Reg_Accepted，不是语音小票
   → 若只有 WACK/QACK：记「中间态」，等最终条再结案

③ Reason 码值是多少？（整 8 位十六进制）
   → 优先记码值，再对 ETSI/笔记名字；厂商中文提示只做线索
   → 登记高频：0x62 / 0x65 / 0x2A / 0x2B / 0x2D / 0xE0
   → 鉴权味道的名字 → 指针第 35 课，本篇不展开算法
```

**结束条件**：三问都有证据（空口或可靠解码日志）写入工单，才能谈「下一步动作」。只有中文「注册失败」四个字 = 线索不足。

### 3.2 决策树（口述版）

```text
工单：登不上 / 注册失败 / 开机无网
        │
        ▼
  先问①：看见本机 C_RAND(登记) 了吗？
        │
   没有 ─┬─► 空口身份（SYNC/CC/是否在正确 TSCC）→ 写频系统码/频率计划
        │    → Aloha Reg/Mask/Backoff → 终端是否禁用开机登记
        │    → 仍无 RAND 再怀疑射频/天线（最后一刀）
        │
   有了 ──► 问②：回条是确认族还是（误认的）Grant？
                │
           只有 WACK 0xE0 ──► 等最终 ACK/NACK；勿结「失败」单
                │
           ACK 0x62/0x65 ──► 登记其实成功；投诉可能在「下一步语音」
                │
           NACK ──────────► 问③：码值？
                              0x2A Reg_Refused → 可换站/查本站策略
                              0x2B Reg_Denied  → 本站否决/Denied List/号段授权
                              0x2D （若出现在语音 RAND 后）→ 回去办登记
                              鉴权相关名字 → 第 35 课 / 钥匙与挑战
                              其它 → 回第 34 课全表与 ReasonCode 笔记
```

### 3.3 日志三联单（强制三栏）

第 40 课 §5.2b 建议网管工单强制三栏。本篇把它写成可复制模板：

| 栏 | 必填 | 合格例子（教学虚构） | 不合格例子 |
|----|------|----------------------|------------|
| **空口 / 信令** | 有无登记类 C_RAND；回条族（ACK/NACK/WACK）；**Reason 十六进制**；时间戳 | 「10:02:11 C_RAND SK=登记；10:02:12 C_NACKD Reason=0x2B」 | 「网管显示注册失败」 |
| **终端侧** | 型号/写频版本；个号（可脱敏）；是否刚换站/换写频；开机登记开关 | 「机型X，写频包 2026-09；个号末四 …1234；今早改过邻站表」 | 「用户说机子坏了」 |
| **网络侧** | 站点/TSCC 标识（脱敏）；时间窗；本站是否开鉴权；近期 MassReg/改授权 | 「站B TSCC；鉴权开；今日 09:30 有 MassReg 窗」 | 「系统有问题」 |

规则：**三联单填齐之前，不升级为「设备故障」。**  
三联单填齐且三问指向同一结论之后，才进入 §5 的分诊顺序（先空口身份，再信令，再写频/Hunt，最后射频）。

### 3.4 「中文提示 → 先问码值」对照心态

| 网管 / 终端常见中文（厂商各异） | 你开口第一句 | 可能落到的码（举例，以空口为准） |
|--------------------------------|--------------|----------------------------------|
| 注册失败 / 登记拒绝 | 「Reason 十六进制是多少？0x2A 还是 0x2B？」 | `0x2A` / `0x2B` / 其它 |
| 未注册 / 请先登记 | 「是业务 RAND 被 0x2D 打回，还是根本没发登记 RAND？」 | 常 `0x2D` 或「无登记 RAND」 |
| 排队中 / 请稍候 | 「是 WACK 0xE0 还是 QACK 0xA0？最终条来了吗？」 | `0xE0` / `0xA0`… |
| 鉴权失败 | 「空口是哪条鉴权相关 Reason 名？钥匙批次对过吗？」 | 名字指针 → 第 35 课 |
| 注册成功但仍无法呼叫 | 「登记 ACK 是 0x62 吗？语音 RAND 的 Reason/Grant 呢？」 | 登记已过，问题在呼叫链 |

**永远：中文是线索，码值与空口字节是证据。**（第 40 课分诊口诀）

## 4. 登记相关 Reason 深挖（不是第 34 课全表重播）

第 34 课教你**怎么读**任意 Reason（载体 → tt/d/aaaaa → 最终/中间 → 网络/对方 → 对表 → Response_Info）。  
本篇只把**登记值班最常用的一把码**钉进肌肉，并提醒跨字节阴坑。全表仍回：

- `学习推送/第34课.md`
- `04-集群协议/ReasonCode与Grant变体.md`（§1–§4 编码骨架与表）

### 4.1 编码骨架速记（够用版）

Reason **8 bit** 位布局（学习口径，与笔记一致）：

```text
  bit7 bit6 | bit5 | bit4 … bit0
    t    t  |  d   |  a  a  a  a  a
   ACK类型  | 方向 |   原因码
```

| 场 | 含义（值班口语） |
|----|------------------|
| **tt** | `00` NACK 拒绝；`01` ACK 接受；`10` QACK 排队；`11` WACK 请稍等 |
| **d** | `1` 网络（TS→MS）意见；`0` 手台（MS→TS）意见或镜像 |
| **aaaaa** | 具体原因——**必须连同 tt 一起查**，别只背后 5 位 |

同一 Opcode 外壳（出站确认族 CSBKO 学习口径 `100000₂`）靠 **Reason 的 tt** 区分 ACK/NACK/QACK/WACK 别名。  
**C_ALOHA / C_AHOY / C_RAND / Channel Grant 都不带 Reason。**

### 4.2 本篇必背：登记相关码一览

| Hex | 二进制味道（tt d aaaaa） | 族 | 名字 | 值班一句话 | 下一检查点 |
|-----|--------------------------|----|------|------------|------------|
| **0x62** | `01 1 00010` | ACK | **Reg_Accepted** | 登记请求被接受——入住办成 | 若仍不能呼叫：查下一步语音 RAND/Grant，不是重开「登记失败」单 |
| **0x65** | `01 1 00101` | ACK | **Reg_Subscription/Attachment service** | 登记 + 组订阅/附着一并接受；Response_Info=Index pattern | 组列表是否如预期；`0000000₂` 味道=登记可接受但本批组全被拒（第 34 课钉子） |
| **0x2A** | `00 1 01010` | NACK | **Reg_Refused** | 登记被**拒绝**——**可以去别的站再试** | 本站策略/负荷/允许集合；配合 Hunt 换站（第 37，不展开状态机） |
| **0x2B** | `00 1 01011` | NACK | **Reg_Denied** | 登记被**否决**——优先用于把 MS 从**该 TSCC 赶走**；记入 **Denied Registration List** | 号段/站点授权、黑白名单、本站是否故意驱离；别跟 2A 同一剧本 |
| **0x2D** | `00 1 01101` | NACK | **MS_Not_Registered** | 系统要求先登记（常见 Aloha Reg=1），MS **未登记却来办业务** | 先完成登记路径；查为何跳过入住（开机登记关？登记失败未处理？） |
| **0xE0** | `11 1 00000` | WACK | **Wait** | 已接受，**后续还有信令**——登记/呼叫建立常见中间态 | **不要结失败单**；盯最终 ACK/NACK；超时无最终条再另查 |

**Refused vs Denied 对照（钉死）**

| | `0x2A Reg_Refused` | `0x2B Reg_Denied` |
|--|--------------------|-------------------|
| 味道 | 拒绝 | 否决 |
| MS 侧直觉 | 换个站也许行 | 别死磕**这个** TSCC；进 Denied List 并老化 |
| 运维第一刀 | 本站是否临时不可登记、是否应引导换站 | 本站授权/否决策略、该号是否不该出现在本站 |
| 常见误判 | 把所有「注册失败」都当成 2A | 把 2B 当「再试一次就好」 |

### 4.3 鉴权相关：只留名字指针（不讲算法）

登记过程中可能穿插鉴权挑战响应（第 35 课）。本篇**禁止**展开 RC4 / 密钥推导。值班只需：

| 你在日志里看到的名字（举例） | 做法 |
|------------------------------|------|
| Authentication Response（网络侧 / 手台侧各有码点，见第 34/35） | **记名字 + 时间顺序**，转第 35 课与 `鉴权与AnnexC频率.md` |
| 「鉴权失败」类中文提示 | 三联单网络栏勾「本站鉴权开启？」；对钥匙批次/挑战是否匹配——**不在本篇默写算法** |
| 反复重试登记且夹杂鉴权 PDU | 先分清「登记 NACK」与「鉴权路径未完成」，避免两张工单互相覆盖 |

边界口诀：**本篇认门牌，第 35 课进门。**

### 4.4 跨字节阴坑提醒（Oct2 / Oct3）

确认 PDU 里 Reason **不是**「Octet3 整字节 = Reason」。布局学习口径（与 `ReasonCode与Grant变体.md` §5、第 34 课 §3.3 一致）：

```text
Octet2: Response_Info(7) | Reason[7]
Octet3: Reason[6:0]     | Reserved(1)=0
```

拼接：

```text
Reason = ((Oct2 & 0x01) << 7) | (Oct3 >> 1)
```

**例（教学用，来自第 34 课）**：原始 `Oct2=0x2A, Oct3=0x4E`

- 错念：看见 `0x2A` → 喊 Reg_Refused。  
- 正解：`(0x2A&1)<<7 = 0`，`0x4E>>1 = 0x27` → Reason = **`0x27 SYSbusy_Refused`（网络过载）**。  

**例**：`Oct2=0x0B, Oct3=0xC0` → Reason = **`0xE0 Wait`**（中间态），不是「已经 Message_Accepted」。

值班规则：

1. 软件/解码器若已给出拼好的 Reason，直接用码值。  
2. 只有原始十六进制时，**先拼再查表**。  
3. 剧本与工单里写 **`Reason=0x..`**，不要写「字节里出现过 2A」。

### 4.5 Response_Info 一句（登记成功时）

| Reason | Response_Info 常见装法（第 34 课口径） |
|--------|----------------------------------------|
| `0x62` Reg_Accepted | **PowerSave_Offset**（省电偏移）——别按 G/I+校验去解 |
| `0x65` 登记+附着 | **Index pattern**（组列表位图味道） |

口诀：**先看 Reason，再决定角落备注怎么解。**

### 4.6 和「呼叫类拒绝」划界（避免剧本串台）

下列码**不是**本篇精读对象，但容易混进「登不上」工单——见到先问：是登记 RAND 之后还是语音 RAND 之后？

| Hex | 名字 | 常见误用 |
|-----|------|----------|
| 0x24 | NoregMSaway_Refused | 「对方没登记」——是**被叫**状态，不是你本机登记失败 |
| 0x25 | MSaway_Refused | 被叫已登记但无线检查无响应 |
| 0x27 | SYSbusy_Refused | 过载——可能出现在多种业务，不单登记 |
| 0xA0 / 0xA1 | QACK 排队 | 呼叫排队；与登记 WACK 不同族语义 |

本篇剧本模板（§7）以**登记相关**为主；其它高频码可另页追加，仍写码值不写含糊中文。

## 5. 现场映射：中文提示、Denied/Refused、分诊顺序

### 5.1 网管中文 → 先问码值（可复印）

| 步骤 | 动作 | 禁止 |
|------|------|------|
| 1 | 让对方报 **Reason 十六进制**（或导出含 Reason 的解码行） | 只转发截图上的中文 |
| 2 | 对照本篇 §4.2 六码 + 第 34 课全表 | 用厂商词直接当 ETSI 名写进制度文档 |
| 3 | 按 2A/2B/2D/E0/62 选剧本 | 「再试一次」无假设地重试轰炸 |
| 4 | 三联单三栏补齐后指派下一检查点 | 直接开「换机 / 换天线」 |

### 5.2 Denied List vs Refused「换站再试」

```text
收到 0x2A Reg_Refused
  → 剧本：本站拒绝，但允许 MS 寻找其它站
  → 运维：查本站是否过载/维护/策略关闭登记；引导用户侧允许 Hunt（第 37）
  → 不要：把该站写进「永久禁止」运维备注（那是 2B 味道）

收到 0x2B Reg_Denied
  → 剧本：本 TSCC 否决；MS 记入 Denied Registration List（有老化，非口头「永久黑名单」口号）
  → 运维：查号段是否授权到本站、是否故意驱离、白名单/区域限制
  → 不要：让用户「在本站多试几次」——越试越像在打Denied钉子
```

现场对话示范：

- 差：「注册失败，你再开关机试试。」  
- 好：「空口是 `0x2B`。这是本站否决，不是普通拒绝。我们先核你的号是否授权在站 B；同时别在站 B 死磕重试。」

### 5.3 写频 / CC / Hunt vs 真登记拒绝——分诊顺序

第 40 课口诀：**先空口身份（SYNC/CC），再集群信令（RAND/Grant/Reason），再频率表（CHAN），最后才怪射频硬件。**  
落到「登不上」工单：

```text
第 0 刀 · 空口身份
  是否稳定解到正确系统的 TSCC？SYNC / CC / 系统身份是否对得上写频？
  身份都错 → 先别谈 Reason（你可能在听隔壁旅馆的告示牌）

第 1 刀 · 有没有登记按铃（三问①）
  无 C_RAND(登记) → Aloha Reg/Mask/Backoff、终端开机登记开关、是否 Reg=0 站却被人工催登记
  有 C_RAND → 第 2 刀

第 2 刀 · 回条族与码值（三问②③）
  WACK → 等最终条
  ACK 0x62/0x65 → 登记成功，转查呼叫链
  NACK 0x2A/0x2B → 真·登记拒绝/否决剧本
  鉴权名字 → 第 35

第 3 刀 · 写频与邻站/Hunt（仍无解时）
  邻站表、Denied List 残留、固定/灵活频率计划是否与网络一致（第 36/37 指针）
  ※ 不在本篇展开 Hunt 状态机 / CHAN 公式

第 4 刀 · 射频硬件
  天线、驻波、功放——仅当身份与信令链已排除
```

**常见误序**：一上来拧天线 → 改 CC → 最后才发现 Reason=`0x2B` 本站未授权。正确顺序能省掉大半无效动作。

### 5.4 和「语音失败 0x2D」的衔接

用户投诉「按了 PTT 嘟一声」：

1. 抓的是**语音类** C_RAND 之后的 NACK 吗？  
2. Reason 是否 = **`0x2D MS_Not_Registered`**？  
3. 若是：工单标题不要写「呼叫授权失败」——根因是**还没办成入住**；回到三问走登记链。  
4. 若登记也曾 NACK：先修登记，再测 PTT。

## 6. 工作实例（2–3 个厚例）

### 例 1 · 新站开通日：`0x2A` 与 `0x2B` 混杂

**现象**：站 B 割接次日，约一半手台「注册失败」。网管中文同一句，解码却有的 `0x2A`、有的 `0x2B`。

**三问记录（教学虚构时间戳）**

| 问 | 证据 |
|----|------|
| ① C_RAND？ | 两批都能看见登记类 C_RAND |
| ② 回条族？ | 均为 C_NACKD（确认族），未见 Channel Grant（正确——本来也不是 Grant 场景） |
| ③ 码值？ | 批 A：`0x2A`；批 B：`0x2B` |

**分诊**

- 批 A（Refused）：允许换站；查站 B 是否仍在维护窗、登记负荷、是否应引导回站 A。  
- 批 B（Denied）：核号段是否写入站 B 授权；是否误把测试号段否决策略带到生产；提醒用户侧勿在站 B 狂重试。  

**错误动作**：对所有人统一「清写频重写系统码」——身份本就正确的终端会被无效折腾。  
**交付**：把 2A/2B 两条写进《本网 Reason 剧本》第 1、2 行（§7）。

### 例 2 · 「一直排队」其实是 Wait/WACK，不是登记失败

**现象**：用户：「转了两分钟还在转圈，是不是注册失败？」值班初判开了「登记失败」单。

**三问**

| 问 | 证据 |
|----|------|
| ① | 有登记类 C_RAND |
| ② | 先见 **C_WACKD**，尚未见最终 ACK/NACK；同事曾误报「有个 E0 错误码」 |
| ③ | Reason = **`0xE0 Wait`** |

**分诊**

- `0xE0` = 中间态：「收下了，后面还有信令」。  
- 动作：延长观察最终条；查网络侧是否卡在鉴权/资源；**撤销「登记失败」标签**。  
- 若长时间只有 WACK 无最终条：另开「最终确认超时」检查，仍不是「按 2A/2B 剧本」。  

**对照**：若最终来的是 `0x62`，向用户解释「刚才是办理中」；若最终 `0x2B`，再切 Denied 剧本。

### 例 3 · 语音失败 `0x2D`：不是 Grant 坏了，是还没登记

**现象**：「一按 PTT 就被拒」；有人已经开始翻第 33 课 Grant 变体。

**三问（注意：这枪是语音 RAND）**

| 问 | 证据 |
|----|------|
| ① | **语音类** C_RAND 有；**登记类** C_RAND 在当日开机后**未见** |
| ② | 回条是 C_NACKD，不是 Grant |
| ③ | Reason = **`0x2D MS_Not_Registered`** |

**分诊**

- Aloha Reg=1 站，跳过入住直接点餐 → 前台用 `0x2D` 挡回来（第 32/34 钉子）。  
- 先查：开机登记是否被关、早先登记是否已 NACK 未处理、是否 Denied List 导致一直登不上。  
- **不要**在 Grant 地图里找「哪种 Grant 会变成 0x2D」——Grant 成功路径根本还没走到。  

**收工标准**：补完登记三问并见到 `0x62`（或合法 `0x65`）后，再测 PTT；此时若仍失败，才进入呼叫类 Reason / Grant 链。

### 例 4 ·（加分）跨字节误读差点开错单

监听导出原始 `Oct2=0x2A Oct3=0x4E`，新人写「Reason=0x2A Reg_Refused」。  
按 §4.4 拼接得 `0x27 SYSbusy_Refused`。  
剧本从「换站/拒登」改为「控制面过载/拥塞」——MassReg 窗或突发登记风暴优先（第 32 课指针）。  
**教训**：剧本键是**拼好的码值**，不是字节里碰巧出现的 `2A`。

## 5.5 值班对话脚本（可直接照着说）

把「会」变成「嘴里说得出来」。下面三组对话按三问推进；括号内是你心里的检查点。

### 对话 A · 只有中文「注册失败」

- 对方：「网管上写注册失败，你给看看。」  
- 你：「好。**Reason 十六进制码值是多少？** 是 `0x2A`、`0x2B`，还是别的？」（三问③先要码）  
- 对方：「没有码，就四个字。」  
- 你：「那我们先补证据。空口或解码日志里：**这台机有没有发出登记类 C_RAND？** 回来的是确认族 ACK/NACK，还是有人说成 Grant？」（三问①②）  
- 对方：「……我去导日志。」  
- 你：「三联单三栏：空口、终端、网络。填齐之前先不升级成设备故障。」

### 对话 B · 听见「有 Grant」但主题是登记

- 对方：「监听员说看见 Grant 了，应该登记成功了吧？」  
- 你：「登记成功通常不是 Grant。Grant 是语音/数据的**房卡**。登记成功请找确认族里的 **`0x62 Reg_Accepted`**（或 `0x65`）。他看到的 PDU 名字和 Reason 码值分别是什么？」  
- 对方：「哦，其实是 ACK，Reason 显示 62。」  
- 你：「那入住办成了。若用户仍叫不通，新工单标题应改成呼叫链，从语音 C_RAND / Grant / 业务信道身份查，别再开登记失败单。」

### 对话 C · 2A/2B 混单

- 对方：「都是失败，统一让他们清写频。」  
- 你：「先分码。`0x2A Reg_Refused` 可以换站再试；`0x2B Reg_Denied` 是本站否决，狂重试没帮助。两批号段授权一样吗？站 B 是否对某批号开了否决？」  
- 对方：「批 B 本来就不该上站 B。」  
- 你：「那批 B 走 2B 剧本：核授权；批 A 走 2A：看是否维护窗/引导回原站。写频系统码对的人不要清。」

### 对话 D · 「排队」焦虑

- 对方：「转圈两分钟了，按失败处理？」  
- 你：「先看是不是 **`0xE0 Wait`**。那是中间态，不是终局。最终 ACK/NACK 来了吗？若只有 WACK，我们盯超时与鉴权是否卡住，而不是结登记失败。」

把这四段练顺，班会上就能带新人；比再讲一遍 Part4 目录有用。

```text
  ③ Reason：0x2B

【下一检查】号段是否授权本站；是否维护驱离；对照批A的0x2A是否混单
【对用户说】「这是本站否决，不是普通拒绝；请勿在本站反复重试，我们先核授权。」
【禁止】清写频碰运气；与0x2A混用同一处理单
【关联课】L32 / L34 / 本手册 §4–§5
【脱敏】无真实频率、无完整个号
```

**题 5.** 用户一直转圈，解码 Reason=`0xE0`。应结「登记失败」单吗？下一步盯什么？

**题 6.** 语音 C_RAND 后收到 `0x2D`。根因更靠近「Grant 变体配错」还是「还没登记」？三问应如何回跳？

**题 7.** 原始字节 `Oct2=0x2A, Oct3=0x4E`。Reason 是多少？为什么不是 `0x2A`？

**题 8.** 日志三联单三栏各是什么？为什么「只有网管中文」不合格？

**题 10.** `0x62` 与 `0x65` 都是登记成功味道时，Response_Info 各自常见装什么？鉴权算法细节应翻哪一课？

**题 11.（加分）** 新站一半 `0x2A`、一半 `0x2B`，统一「重写系统码」为什么可能错？

**题 12.（加分）** Aloha 带不带 Reason？登记拒绝有没有单独一张「Reg Reject PDU」？

### 参考答案

1. **不是第 41 课。** 手册模式接第 40 课收官；本篇服务运维/网管 **Week‑1**：Reason 高频码 + 登记失败三问 →《本网 10 个 Reason 剧本》。  
2. ①C_RAND发出去了吗？②回来的是Grant还是哪条确认族ACK？③Reason码值是多少？——登记成功常见是 **ACK+Reg_Accepted**，不是语音 **Channel Grant**；Grant 是「房卡」，登记是「入住回条」。  
3. 登记成功：确认族 ACK + `0x62`/`0x65`…；语音成功：Channel Grant（无 Reason）。失败两边都可能是 NACK+Reason，但 Service_Kind 与剧本不同。  
4. Reg_Refused；Reg_Denied；**换站再试更贴 0x2A**。  
5. **不应**结失败单；`0xE0` 是 WACK 中间态；盯**最终** ACK/NACK，并查是否超时卡在鉴权/资源。  
6. 更靠近**还没登记**；回跳登记三问，先追求 `0x62`/`0x65`，再测 PTT；别在 Grant 地图里找 0x2D。  
7. Reason=`0x27`（SYSbusy_Refused）。因为 Reason 跨字节：`(Oct2&1)<<7 | (Oct3>>1)`；Oct2 高 7 位是 Response_Info。  
8. 空口/信令、终端侧、网络侧。只有中文则没有码值与 RAND/回条证据，无法执行剧本。  
9. 推荐：空口身份(SYNC/CC) → 有无登记RAND → 回条族与Reason码值 → 写频/Hunt指针 → **最后**射频天线。  
10. `0x62`→PowerSave_Offset；`0x65`→Index pattern。鉴权算法→**第 35 课**（本篇只留名字）。  
11. 两批码值剧本不同：2A可换站/查本站策略，2B查授权否决；身份正确的终端会被无效重写。  
12. Aloha **不带** Reason；登记拒绝走 C_NACK 的 `Reg_Refused`/`Reg_Denied` 等，**没有**单独一张 Reg Reject 表（ReasonCode笔记口径）。

## 11.7 常见问法速查（FAQ 式）

**Q1：Reg=0 的站，用户还投诉「要登记」？**  
A：速览/第32课口径——Reg=0 时 MS **不应主动寻求登记**。先核对 Aloha/CACH/BCAST 的 Reg 是否真为 0，再查是否人为流程要求「强制登记」。别用 2B 剧本硬套。

**Q2：登记 ACK 是 0x65，但组不对？**  
A：看 Response_Info 的 Index pattern；可能登记接受但组附着位图不理想。回第34课 0x65 钉子与组规划，不重开「登记失败」。

**Q3：只有终端 UI「失败」，空口什么都没有？**  
A：三问①失败——先查是否根本没在正确 TSCC上、是否发射被禁、Mask 未轮到、Backoff 等待。无空口证据时，优先终端与身份，而不是 Reason 表。

**Q4：MassReg 期间大量「失败」？**  
A：先看是否时间窗内的重登记风暴 + 过载类 Reason（如 0x27）；用 Window/Mask 摊峰视角，避免误判成单站永久否决。

**Q5：要把 Stun/Kill 写进登记剧本吗？**  
A：**本篇不写攻击面内容。** 网络管理类异常另见第39课与后续手册候选「Week‑2 话术」；登记三问仍只服务登记/Reason。

**Q6：剧本里能否写真实频点方便夜班？**  
A：**不能。** 第40课已强调卡片只留问题与码值；真实频点走你们受控的参数库，不进学习推送与公开仓库。
