## 6. 现场对照与分诊

| 现象 | 先怀疑哪一层 / 哪几课 | 第一刀检查 |
|------|------------------------|------------|
| 开机后一直搜网、发不出去 | Hunt / 写频表 / CC（L37、L36、L20） | TSCC 频率与猎站列表是否一致；能否解码 SYScode |
| 能听控制信道广播，登记总失败 | 登记 / Aloha / 鉴权（L32、L35） | 是否回了 NACK；Reason；钥匙是否匹配 |
| 一按 PTT 立刻被拒 | Reason / 权限 / 拥塞（L33、L34） | 抓 ACK 码值；是拒绝还是排队 |
| Grant 了但进客房没声 | CHAN↔频率 / CC / 时隙（L36、L20、L31） | 手台是否有该 CHAN；CC 是否一致；是否听错时隙 |
| 语音一会儿就断、对方迟后进不来 | 超帧 / 嵌入 LC / 覆盖（L17、L25、L26） | 场强与误码；是否仅主叫侧问题 |
| 短信「已送达」对方说没有 | UDT 组呼语义（L39） | 个呼还是组呼；组呼只有网络接受义 |
| 动态组「旧组丢了」 | DGNA 整表替换（L39） | 最近一次 Address 模式清单是否漏带旧组 |
| 远程禁用后仍见登记/定位 | Stun 设计如此（L39） | 是否误期待成 Kill；业务是否已停 |
| 同频两网互扰 | CC / 系统码（L20、L37） | Colour Code 与系统识别是否分离 |
| 「数字机坏了」但模拟同站正常 | 调制/时隙/同步（L4、L15、L19） | 是否真在解 DMR SYNC；别只看 RSSI |
| 外线/PSTN 拨不通 | 拨号映射 / UDT 外线号码（L38、L39） | Target 是否 PSTNI；UDT 是否交完 |
| 新开载频，老终端一派就掉线 | 灵活计划缺行 / SEP 不一致（L36） | 老终端写频是否含该 CHAN |

**分诊口诀**：

> **先空口身份（SYNC/CC），再集群信令（RAND/Grant/Reason），再频率表（CHAN），最后才怪射频硬件。**

再补一句给值班长：

> **网管中文提示是线索，Reason 码值与空口字节才是证据。**

### 6.1 两个完整分诊例子（把表用起来）

**例子 A · 「新载波开通，老批次手台一被派到新信道就掉线」**

1. 分诊表落到：Grant 无声 / 新开载频（L36）。  
2. 打开第 36 课钉子：CHAN 是房号；灵活计划缺行会掉回 TSCC。  
3. 查 `鉴权与AnnexC频率.md`：确认本网是固定还是灵活计划。  
4. 第一刀：抽 2 台老手台读写频，看新 CHAN 是否存在、SEP/CC 是否一致。  
5. 只有写频无误仍失败时，才上频谱/功放硬件。

**例子 B · 「网管点了远程禁用，用户投诉还能看到位置」**

1. 分诊表落到：Stun 后仍见登记/定位（L39）。  
2. 回忆网络管理口径：Stun **保留**定位与登记，停的是用户业务。  
3. 验证标准：该机能否发起/接收语音或短信业务，而不是「网管地图上有没有点」。  
4. 若业务仍能通，再查 C_AHOY 是否真正下发、手台是否回了 MS_Accepted / 不支持类 Reason。  
5. 不要把 Stun 与 Kill 混用；Kill 有反向鉴权与不可恢复语义，权限与流程按运营制度。

### 自测答案

> 答题时尽量写出「课号 + 库文件」——收官考的是检索，不是死背。

1. **12.5 kHz** 是 RF 车道宽；**4FSK** 在车道里用四种偏移装符号；每符号 2 bit、4800 符号/s → **9600 bit/s**；时间上切成 **30 ms** 时隙，使两路 TDMA 共享同一车道。  
2. Tier III 至少多：**守 TSCC、登记（常+鉴权）、C_RAND、等 Grant、再进业务信道**；Tier II 中继通常直接在已知信道上呼叫。  
3. 开机→**Hunt(L37)**→**登记+鉴权(L32/35)**→拨号(L38)→C_RAND→**Grant(L33/34)**→CHAN 调频(L36)→**超帧(L17/25/30)**→Hang→回 TSCC(L31)。  
4. 0：无效/无信道（P_CLEAR 等场景下常表示「回上次 TSCC」类语义，细节以第 36 课为准）；300：逻辑号，查本地计划得 Tx/Rx/CC；4095：不查表，读绝对频率续块。  
5. Grant 只保证「协议上派了房号」；房号→MHz 与 CC 不对，射频再好也解调不到自己的业务。  
6. Reason 在 ACK/NACK/QACK/WACK 等确认族；**Grant 本身不带 Reason**，失败走 NACK 路径。  
7. **不能**。组呼短数据网络侧「接受/已发给组」≠个体送达（第 39 课）。  
8. **不一定失败**——Stun 设计为停用户业务但保留登记/漫游/定位等。Kill 经反向鉴权后永久失去 DMR 功能，空口不可恢复；Stun 可用 Revive（同网关 Flag=1）恢复（第 39 课网络管理口径）。  
9. `鉴权与AnnexC频率.md` 与 `AnnexD猎站Hunt.md`；现场先查老终端写频是否含新 CHAN、CC 是否一致。  
10. SYNC → 突发/数据类型 → Colour Code → CSBK/LC 外壳（再看地址与 Service_Kind）。  
11. **Annex E informative（拨号计划建议）**；**Annex G normative（原生编址能力边界）**。  
12. 总索引当搜索框，学习推送当口语说明书，速览+PDF 当证据。短信投诉例：总索引搜「短数据/UDT」→ 第 39 课 §8 语义 → `Stun_DGNA_UDT与定时器.md` → 需要时回 Part 4 PDF 6.6.4；同时问清个呼还是组呼。

## 8.5 弱项加餐：频率 · 带宽 · 调制（收官必回）

你的进度文件里长期标记了弱项：**频率与带宽、调制与解调**。收官不假装它们已经自动变强——请用 15 分钟走完下面这张小图：

```text
频率 = 抖多快（位置）
带宽 = 占多宽（车道宽度）     ← DMR 车道 12.5 kHz
调制 = 把比特装进高频         ← DMR 用 4FSK
解调 = 卸下来变成比特
         │
         ▼
符号率 4800 符号/s × 2 bit = 9600 bit/s
         │
         ▼
时间切开：30 ms 一格 → 两格共享一条车道（TDMA）
```

**自检三问**（不会就打开加餐课正文，不要硬撑）：

1. 邻居信道 `460.125` 与 `460.1375` 的间隔是多少？这和「占用带宽」是不是一回事？  
2. 为什么说「6.25 kHz 等效」却仍然在 12.5 kHz 信道里发射？  
3. 若符号率不变，把 4FSK 错记成「1 符号 1 bit」，算出的比特率会错成多少？

答案要点：1）12.5 kHz 间隔；间隔≠占用带宽。2）等效指两时隙带来的容量口径。3）会错成 4800 bit/s，整课空口账对不上。
