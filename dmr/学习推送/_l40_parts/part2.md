## 4. 一条呼叫：从开机到挂断（课号钉在每一步）

下面用**教学虚构**的手台 M（用户拨号 `40125312` → 空口示例 `0x348E1D`，网号口径沿用第 38 课示例网 NP=401）打一通过程组呼。旁支给出短信与 Stun。

### 4.1 主路径（语音组呼）

```text
[1] 开机 / 掉网恢复
      │  Hunt：上次 TSCC → 受令信道 → 短列表 → 综合扫描
      │  验证 SYScode / CACH → 确认后才允许在该 TSCC 上发射   ← 第37课
      ▼
[2] 守在 TSCC（前台一直在播 Aloha / 广播）              ← 第31、32课
      │  登记（C_RAND 登记类）→ 可能鉴权（C_AHOY RAND ←→ 响应） ← 第32、35课
      ▼
[3] 用户拨号 / 选组 → 映射成 24-bit Target + Service_Options ← 第38课
      │  例：组 40125934 → 0x348217；修饰符进 Service_Options
      ▼
[4] 随机接入：C_RAND（Service_Kind=语音组呼等）         ← 第32、33课
      │  TSCC 可能先 C_AHOY 探可达 / 排队
      │  失败：C_NACKD + Reason（读第34课）
      │  成功：C_GRANT（含 CHAN / 时隙等）反复下发
      ▼
[5] 双方改到业务信道频率
      │  CHAN 1…4094 查本地计划；CHAN=4095 读绝对频率续块   ← 第36课
      │  Colour Code 必须对齐                             ← 第20课
      ▼
[6] 客房里跑语音
      │  Voice Header → 超帧 A–F（嵌入 LC）→ Terminator     ← 第17、25、30课
      │  迟后进入窗口给后来者                              ← 第26课
      ▼
[7] Hangtime 结束 / 网络回收 → 手台回到原 TSCC           ← 第31、25课
```

### 4.2 旁支 · 短信（全程前台，不进客房）← 第 39 课

```text
C_RAND(Target=对方, SK=短数据, 预告块数)
  → C_AHOY(Src=SDMI FFFEC5)「请交货」
  → UDT 上传（C_UDTHU + 1~4 附加块）   # 载荷 80/176/272/368 bit
  → TSCC store-and-forward
  → UDT 下载（C_UDTHD + 块）
  → 个呼回 ACK 并镜像；组呼网络回 Message_Accepted（不保证某人收到）
```

### 4.3 旁支 · 网管远程禁用（Stun）← 第 39 课（网络管理口径）

```text
TSCC 以 STUNI(FFFECC) 发 C_AHOY，Service_Kind=1101，Flag=0
  → 手台停用户业务，仍可登记/漫游/被定位/再收 Revive
Revive：同一套 C_AHOY，Flag=1
Kill：KILLI(FFFECF)，必须先反向鉴权通过；空口不可恢复
```

### 4.4 把故事钉在「你的工位」

建议你真的做两件事（30 分钟就能完成）：

1. 把 §4.1 主路径抄成一页纸，四个关键课号（37 / 32·35 / 33·34 / 17·25）用荧光笔标出。  
2. 在旁边留三行空白：「本网 TSCC 怎么认」「本网 Reason 高频三个码」「本网 CHAN 计划类型（固定/灵活）」——这三行只能由你的现场参数填写，课程不会也不应替你填真实频率。

以后任何新字段，先问「它出现在第几步」。

### 4.5 同一条故事的「失败剧本」练习

把成功路径背熟还不够。值班时你遇到的多半是失败。用下面四个剧本各讲一遍（对着 §4.1 图指）：

| 剧本 | 卡在哪一步 | 你开口第一句该问什么 |
|------|------------|----------------------|
| 搜网死循环 | [1] Hunt | 「手台写频里的 TSCC / 猎站列表和站点实际是否一致？CC 呢？」 |
| 登记被拒 | [2] | 「NACK 的 Reason 码值是多少？要不要先怀疑鉴权钥匙？」 |
| 一键即拒 | [4] | 「是拒绝还是排队？Service_Kind / 权限 / 拥塞哪个更像？」 |
| Grant 无声 | [5] | 「派的 CHAN 在这台手台写频里有没有？CC、时隙对了吗？」 |

**加分项**：把四个剧本写成你们班组的值班卡片；卡片上只留问题，不留可能泄密的真实频点。

### 4.6 短信旁支为什么要单独记

很多人学完集群仍下意识认为「有业务就要进客房」。第 39 课钉死的例外是：

- **短数据 UDT、DGNA、Stun/Revive/Kill**：默认舞台是 **TSCC**。  
- 代价是控制信道容量宝贵 → UDT **最多 4 个附加块**（80/176/272/368 bit 档）。  
- 所以调度规划里，「什么走语音、什么走短信、什么必须上业务信道数据」是容量问题，不是喜好问题。

### 5.1b 网优工具箱心态（不绑定具体品牌）

路测与频谱工作不必等「买齐仪器」才开始学习，先建立判断顺序：

```text
1. 控制信道能不能稳定解码？（身份问题）
2. 业务信道能量与解码是否同时成立？（表 vs 射频）
3. 邻站/同频是否在抢同一油漆色 CC？
4. 终端侧写频与网络侧计划是否同一套故事？
```

把这四步写进网优工单模板，比先争论「要不要换天线」更能节省一周。

### 5.2b 运维「日志三联单」

建议网管工单强制三栏（可复制到你们的工单系统）：

| 栏 | 填什么 | 为什么 |
|----|--------|--------|
| 空口/信令 | RAND 有无、Grant 还是 ACK、Reason 码值 | 避免只贴中文提示 |
| 终端侧 | 型号、写频版本、是否刚 Stun/DGNA | 分清机与网 |
| 网络侧 | 站点、TSCC、时间窗、是否鉴权开启 | 复现边界 |

三联单填齐之前，不升级为「设备故障」。

### 5.3b 测试实验室最小集

即使没有黄金仪表，最小闭环也可以是：

1. 一台已知良好的终端（金机）+ 一台待测机；  
2. 可录音/可抓突发的接收手段（以你们现有工具为准）；  
3. 固定剧本：登记成功、组呼成功、登记鉴权失败、Grant 后故意写错 CC 的对照。  

剧本比设备贵——没有剧本，再贵的仪表也只是看热闹。

### 5.4b 开发互操作「红线清单」示例

在代码评审里固定问：

- 这个功能走标准 FID 还是 MFID？  
- 失败态有没有 Reason / 超时 / 重试上限？  
- CHAN=4095 续块解析了吗？  
- UDT 块数是否拒绝 >4？  
- 有没有把 Annex E 拨号算法写死成唯一入口，导致原生地址呼叫失败？  

红线清单比「再读一遍规范」更能防止回归。

### 5.7 资料库「三层用法」——收官后怎么翻


遇到症状时的推荐顺序（比「打开 PDF 第一页」快得多）：

1. §6 本课分诊表 → 锁定课号与层。  
2. 打开对应 `第N课.md` 的「现场对照 / 钉子」段落。  
3. 打开对应速览文核对字段名与码值。  
4. 仍争议时，回 PDF 原文（版本以库内文件名为准）。  
5. 若是频率/调制发糊，**插队**打开加餐课，再回来。

### 5.8 跨岗位 FAQ（收官高频）

**Q1：我不是开发，还要看 PDF 吗？**  
A：要会「打开到条款核对码值」，不必会实现状态机。速览文够用 80% 场景；争议时才下 PDF。

**Q2：协会 IOP 证书和 ETSI 文本什么关系？**  
A：ETSI 定协议；协会 IOP 测「厂商之间按测试套件互操作」。运营采购常看 IOP，排障仍要回到空口与 Reason。

**Q3：厂商私有功能在课里为什么讲得少？**  
A：因为私有功能靠 MFID，一换厂家就变。标准路径先通，私有能力对照厂商手册，并在分诊时明确「这是标准还是私有」。

**Q4：加餐课和正式课冲突怎么办？**  
A：加餐只加固频率/带宽/调制直觉，不改 ETSI 字段。数字以正式课与 PDF 为准；直觉发糊时回加餐。

**Q5：40 课以后还要「打卡」吗？**  
A：不需要按 9:52/18:52 推送节奏。改用 §10 保养计划：每周症状驱动 30 分钟，每季度返修半天。
