# 第 38 课 · 拨号与本地编址

> DMR 深入学习 · **阶段 E · 集群 Tier III 第 8 课（约 10 课之八）**（接第 37 课「猎站 Hunt」）  
> 适合：已经能让手台找到控制信道、登记成功，也知道 C_RAND 里有 Target 和 Source 两个 24 位地址，但一被问到「**键盘上按的 `40125312` 和空口上跑的那个 24 位地址是什么关系？**」「**同事说他的号是 318，为什么解码器上看到的是 3444259？**」「**拨 `*9*934#` 和直接拨 `934`，C_RAND 里到底哪几个比特不一样？**」「**手台拨外线电话，那串电话号码是怎么送上去的？**」「**两家厂商的手台进同一个集群网，个呼为什么一边打得通一边打不通？**」就答不上来——说不出**用户看到的号码只是『翻译前』的样子，空口永远只认 24 位二进制；翻译规则写在哪、谁必须遵守、谁可以不遵守**——的人  
> 阅读量：约 **30–40 分钟** · **只讲映射规则和比特落点，不贴 FEC、不画完整 MSC** · 要把「**拨号 = 把人看的十进制串，按一套可逆算法翻成 24 位地址 + 几个业务比特；Annex E 是『建议的翻译表』（informative，厂商可以不用），Annex G 是『最低能力要求』（normative，必须能直接编到 1…16 776 415 里任何一个号）；号码长度和号段决定它是个号、组号还是调度台；`*` 开头的修饰符变成 C_RAND 的 Service_Options 比特；`01` / `02` 开头的外线号码不进地址字段，而是把 Target 设成 PSTNI / PABXI，号码本身用 BCD 装进 UDT 另外上传**」钉牢  
> **频谱 / 调制提醒**：RF 仍是 **12.5 kHz** 一条车道，调制仍是 **4FSK**（一个符号 2 bit，**4800 符号/秒 = 9600 bit/s**），时隙 **30 ms**。本课的「地址」在物理上就是 **24 个比特 = 12 个 4FSK 符号 ≈ 2.5 ms 的空口时间**（未计纠错编码）。号码再长、拨号串再花哨，**上了天线都要先变成这 24 个比特**——用户域多几位数字，不会多占一点带宽；真正多占空口的是外线号码那种「额外要上传的数据」（§10）。四句话原文见 `学习推送/加餐_频率带宽与调制解调.md`。

## 1. 为什么本课重要（动机）

第 37 课结尾我们说：**找到网之后，键盘上按的号码怎么变成地址。**前面 37 课里，你见过无数次「Target_address 24 bit」「Source_address 24 bit」，也在第 7 课学过「个呼 / 组呼」。但现场人手里拿的是**手台键盘和写频软件**，嘴上说的是「打 318」「切到 934 组」「按 `*9` 紧急」，没人会说「Target = 0x348E23」。这中间隔着一层**翻译**，而这层翻译恰恰是现场扯皮最多的地方：

- 用户：「我拨同事的号 `318`，手台说『号码无效』。」——多半是**短拨号依赖的『本车队号』没写进手台**，或者这个号在**号段规则外**（比如 IN 写成了 `150`，而合法 IN 从 `200` 开始），手台按规范**不许发起有歧义的呼叫**（§8）。  
- 网管：「解码器上看见 Source = 3444259，用户坚持说自己是 318 号。」——**两个都对**。`318` 是用户域的缩短拨号，`40125318` 是完整车队号，`3444259`（`0x348E23`）是空口地址。三者用一个公式互换（§5）。  
- 集成商：「A 厂手台进 B 厂集群，组呼正常，个呼一半打不到。」——一边按 **Annex E 车队号**换算，一边**直接用空口 ID**；两边对同一串数字的理解不一样（§11）。  
- 调度：「我按 `*1967` 想全呼，旁边站的手台没响。」——`*196x` 是**本站全呼 ALLMSIDL**，只到发起者所在站；要全网得拨 `*198x`（ALLMSID）（§9.4）。  
- 用户：「拨外线手机号，转了半天提示失败。」——外线号码不是一次发完的：先发一个 **Target = PSTNI** 的 C_RAND，网络回 **C_AHOY** 来「要号码」，手台再用 **UDT** 把 BCD 号码交上去；中间任何一步没过，网络回 **C_NACKD**（§10）。  
- 写频：「组号和某个人的个号都是 1001，软件报重复，是不是空口会冲突？」——**空口不冲突**：个号和组号是两套独立的地址空间，靠 Service_Kind（个呼 / 组呼）区分；报重复是**写频软件自己的限制**（§3.2）。

培训台如果只背「手台有个 ID，组有个组号」，后面排障会一直卡住：

> **号码有三副面孔：键盘上按的（拨号串）、屏幕上显示的（用户号码）、空口上发的（24 位地址）。**  
> 翻译规则：**Annex E**（建议性的车队编号与拨号计划，可逆算法）。  
> 底线要求：**Annex G**（强制：能把自己设成、也能呼叫 1…16 776 415 里任何合法地址）。  
> 用户说「打不通 / 号不对 / 显示怪」时，先问：**他按的是哪副面孔？手台用的是哪套翻译？对端用的又是哪套？**

本课目标：画出「用户域 ↔ 空口域」总图；复习 24 位地址空间里哪些号是谁的；拆开 **NAI 9 bit ‖ SSI / SGI 15 bit**，讲清 **NP = NAI + 296**；**手算**个号、组号、调度台号的换算（含反向）；用「位数 + 号段」判断一串数字是什么；把 `*9*` `*8*` `*11*` 等修饰符**落到 C_RAND 的 Service_Options 比特**并手拼几条 C_RAND；讲清外线拨号的 **PSTNI / PABXI + C_AHOY + BCD UDT** 流程和「20 位 / 44 位」两个门槛；讲清 Annex G 为什么是互通的底线；能做现场分诊；为第 39 课「Stun / DGNA / UDT」留好边界。

**本课硬禁令（写进脑子）**：不 dump FEC/CRC/BPTC、不贴完整 MSC/SDL、不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/AnnexE拨号.md` **§0–§9**、`AnnexG本地编址.md` **§0–§5**、`Stun_DGNA_UDT与定时器.md`、`集群协议字段速览.md`、`总索引.md` **集群 / Tier III** 已有编号为准；本课新引用的条款——E.1–E.3.7、G.1、4.3.1、6.6.1.7、6.6.2.1.2、Table 6.40、7.2.9 Table 7.46、7.2.13.1 Table 7.52、B.3.3 Table B.3、Table 7.25——都已在 PDF `TS102361-4_V1.12.1.pdf` 原文里逐条核对过）。**Annex E 是 informative**：本课讲的拨号串是「标准建议的写法」，**具体手台的按键和菜单以厂商说明书为准**。

## 2. 总图：同一个号码的三副面孔

先把整件事画成一张图。左边是人，右边是空口，中间是手台里的一段「翻译程序」（规范叫 MS Application，Figure E.2 叫它 **Bi-Directional Algorithm**，双向算法）：

```text
          用户域（User Interface domain）                     空口域（Air Interface domain）
   ┌──────────────────────────────────────┐            ┌──────────────────────────────────┐
   │ 变长 · 十进制 · CCITT 键盘 0–9 * #      │            │ 定长 · 二进制                       │
   │                                      │   双向算法   │                                  │
   │  318            （3 位短号）           │ ─────────► │  Target_address  24 bit           │
   │  25318          （5 位短号）           │            │  Source_address  24 bit           │
   │  40125318       （8 位完整车队号）      │ ◄───────── │  Service_Kind    4 bit（个/组）    │
   │  *9*934#        （修饰符 + 组号）       │            │  Service_Options 7 bit（紧急/广播/ │
   │  *1987          （全网全呼）           │            │                  优先级…）         │
   │  0113800138000  （外线电话）           │            │  Proxy Flag      1 bit            │
   │  通讯录「老王」   （别名，本质也是号码）  │            │  + 需要时：UDT 里的 BCD 号码        │
   └──────────────────────────────────────┘            └──────────────────────────────────┘
        ↑ 人看、人按、人记                                     ↑ 只认比特，不认「位数」
```

三条要记死的规则：

1. **空口只有 24 位。**不管用户按了 3 位、5 位还是 8 位，C_RAND / C_AHOY / Grant 里的地址字段永远是 24 bit。所以「号码多长」是**用户域**的事，「号码合不合法、属于谁」是**空口域**的事。  
2. **翻译必须可逆。**E.3.0 原文：映射用的是 *a number of reversible coding algorithms*。你按 `40125318` 能算出 `0x348E23`；手台收到来电 Source = `0x348E23`，也要能算回 `40125318`（或在同车队时显示 `318`）。来电显示就是反向翻译。  
3. **翻不出来就不许打。**E.1：如果用户按了一串**不属于任何拨号算法**的数字，手台**不应尝试建立呼叫**，要给用户提示（「号码无效」「业务不可用」之类）。原因很朴素：一串乱号在空口上可能恰好落在某个网关地址或保留地址上，会造成**不确定的呼叫建立**。

再把「两个附件」的分工钉牢——这是本课最容易混的地方：

| | **Annex E** 车队编号与拨号计划 | **Annex G** 原生编址（MS Native Addressing Plan） |
|---|---|---|
| 性质 | **informative**（信息性、建议） | **normative**（规范性、必须） |
| 管什么 | 用户按什么 ↔ 空口发什么（翻译表） | 手台**至少**要能直接编到哪些空口地址 |
| 内容 | NAI/SSI/SGI、NP、FIN/IN、FGN/GN、调度台、全呼串、修饰符、外线前缀 | 三条：本机地址可设在 1…16 776 415；被叫可编到 1…16 776 415；若支持全呼，能编 ALLMSIDL/Z/ID |
| 厂商能不能不照做 | **能**（E.1 明说尊重厂商设计独立性） | **不能** |
| 篇幅 | 约 10 页 | 约 1 页（只有 G.1） |

一句话：**Annex E 告诉你「推荐这样翻」，Annex G 告诉你「不管你怎么翻，空口上这些号都得够得着」。**

把它放回前几课的总图里，拨号发生在「守 TSCC → 登记」之后、「发 C_RAND」之前：

```text
开机 → 猎站（第37课）→ 验证+确认 → 登记（第32课）
     → 用户按键：拨号串 ──[本课：双向算法]──► Target(24) + Service_Kind + Service_Options (+Proxy)
     → C_RAND 随机接入（第32课 Aloha）
     → TSCC：C_WACKD / C_QACKD / C_NACKD（第34课 Reason）
             C_AHOY（查被叫 / 要外线号码 / 鉴权，第35课）
     → Grant（第33课）→ 业务信道频率 CHAN（第36课）→ 通话
```

## 3. 先复习：24 位地址空间里，哪些号是谁的

### 3.1 24 位有多大

24 bit 一共 \(2^{24} = 16\,777\,216\) 个值，十六进制 `000000`…`FFFFFF`，十进制 `0`…`16 777 215`。这些值**不是**全都能给手台用，规范把它切成了几块：

```text
十六进制          十进制              给谁用（Part 4 视角）
000000            0                  ADRNULL：空地址，不属于任何实体（列表空位、填充）
000001 … 0FFFFF   1 … 1 048 575       个号：Annex E 说保留给 MPT1327 迁移（E.3.1.1）
100000 … FFFCDF   1 048 576 … 16 776 415   DMR 个号 / 组号的主力区（Annex E 车队号都落在这里）
FFFCE0 … FFFEBF   …                  保留等（Part 1 Annex A 分区）
FFFEC0 … FFFED7   16 776 896 …        Tier III 网关 / 服务标识（Part 4 Table A.8）：PSTNI、PABXI、REGI、AUTHI、STUNI…
FFFED8 … FFFFFC   …                  保留 / 其他分区（Part 1 Annex A 还细分了系统网关、自定义、全呼等小区段，本课不展开）
FFFFFD            16 777 213         ALLMSIDL：本站全呼
FFFFFE            16 777 214         ALLMSIDZ：部分站点全呼
FFFFFF            16 777 215         ALLMSID：全网全呼
```

注意 Annex G 的上界 **16 776 415 = `FFFCDF`**，正好是「普通用户号」的最后一个值；再往上就进了保留区和网关区。**普通个号、组号都不该编到 `FFFCE0` 以上**——那一带的值在 Tier III 里有特殊意义（第 35 课鉴权用的 AUTHI 等服务 / 网关标识都在那里）。

> 小插曲：Annex E 说 `1…0FFFFF` 「保留给 MPT1327 迁移」，Annex G 却要求 `1…16 776 415` 全都能编。两句话不矛盾：E 说的是「**按我这套车队计划**，DMR 号从 `100000` 起编」；G 说的是「**手台能力上**，这些低号你也得能直接填进去」。现场很多常规网（Tier II）和业余网的号就是 `1001`、`3108128` 这种低于 `100000` 或者落在任意位置的号——Annex G 保证这些号在集群手台上也能用（§11）。

### 3.2 个号和组号是两套平行空间

clause **4.3.1** 的 NOTE 说得很清楚：**个体地址和 talkgroup 地址分属独立的地址空间**；数值可以相同，PDU 里用**个呼 / 组呼业务类型**区分，没有歧义。

```text
个号空间：  000001 ……… 3444259 ……… FFFCDF
组号空间：  000001 ……… 3444259 ……… FFFCDF
            ↑ 同一个数值，在两套空间里是两个不同的东西
区分靠：C_RAND 的 Service_Kind（IND_V_SRV = 0000 / GRP_V_SRV = 0001）
        Grant 的类型（第33课：PV_GRANT 个呼 / TV_GRANT 组呼 …）
```

所以「组号 1001 和张三的个号 1001 冲突吗？」——**空口不冲突**。写频软件拒绝重复，是软件为了防止用户在通讯录里选错，不是协议限制。Puget Sound DMR Coalition 的入门文章也特意提醒过：Private ID 和 Talkgroup ID 数值可以一样，但很多手台的写频软件**不接受**重复（见文末外链 4）。

### 3.3 地址在空口上是怎么「长」的

24 bit 在 PDU 里就是**连续 3 个字节，高位在前**（Big-endian）。比如 `0x348E23`：

```text
十六进制：  34        8E        23
二进制：    0011 0100 1000 1110 0010 0011
            └───────── 24 bit ─────────┘
十进制：    3×16^5+4×16^4+8×16^3+14×16^2+2×16+3 = 3 444 259
```

C_RAND 里 Target 在 **Octet 4–6**，Source 在 **Octet 7–9**（第 32 课登记时见过 C_RAND，本课 §9.3 会把它逐字节手拼出来）。

## 4. Annex E 的骨架：NAI ‖ SSI / SGI，以及 NP = NAI + 296

### 4.1 24 位地址的两段切法

E.3.1.1 规定：按车队计划编号时，24 位地址切成两段——

| 段 | 名称 | 比特 | 范围 | 白话 |
|---|---|---|---|---|
| 高 9 位 | **NAI**（Network Area Identity，网络区域标识） | 9 | DMR 用 **32…511**（0…31 留给 MPT1327 迁移） | 「区号」 |
| 低 15 位 | **SSI**（Short Subscriber Identity，短个体标识）或 **SGI**（Short Group Identity，短组标识） | 15 | 1…32 767（**0 无效**） | 「区内号」 |

```text
bit 23                 bit 15 bit 14                                   bit 0
 ┌──────────────────────────┬─────────────────────────────────────────────┐
 │      NAI（9 bit）          │          SSI 或 SGI（15 bit）                 │
 └──────────────────────────┴─────────────────────────────────────────────┘
 公式：AI 地址 = NAI × 2^15 + SSI = NAI × 0x8000 + SSI = (NAI << 15) | SSI
```

为什么是 9 + 15？因为 \(2^{15} = 32\,768\)，正好是一个「区」里能放的号数；\(2^9 = 512\) 个区。NAI 从 32 起，所以 DMR 号最小是 \(32 × 32768 = 1\,048\,576 = \texttt{0x100000}\)——这就是 E.3.1.1 说「DMR 个号从 `100000` 开始」的来历。**这不是巧合，是同一件事的两种说法。**

### 4.2 SSI 和 SGI 里的号段

| 值 | SSI（个号空间） | SGI（组号空间） |
|---|---|---|
| 0 | NULL，无效 | 保留 |
| 1 … 7 000 | 普通个号 | **组号**（每个 NP 最多 7000 个车队组号） |
| 7 001 … 32 200 | 普通个号 | 保留 |
| 32 201 … 32 767 | **特殊个号**（调度台就落在这里，§7） | 32 767 = **车队全呼**；其余保留 |

个号空间里 1…32 200 是给普通手台的（32 200 这个数怎么来的，§5.3 会算给你看）。

### 4.3 NP：给人看的「三位区号」

NAI 是二进制里的 9 位，人不好记。Annex E 给它配了一个**三位十进制的前缀 NP**（Network Prefix，网络前缀）：

$$
NP = NAI + 296
$$

- NAI 32 → NP **328**；NAI 510 → NP **806**。许可的 NP 是 **328…806，共 479 个**（E.3.1.2）。  
- **NAI = 511**（对应 NP 807）不给普通手台，**留给特殊网关**。  
- NP **200…327** 保留给 **MPT1327 迁移**。

为什么偏偏加 296？看一眼它的「祖宗」就明白了。英国 MPT1327 集群的编号标准叫 **MPT1343**，它的车队前缀（Fleet Prefix）范围恰好是 **200…327**（RadioReference 的 MPT-1327 词条写得很清楚，见文末外链 3）。DMR 把 **328 起**的前缀接着往后排，前面 200…327 原样留给老 MPT 网迁移过来的用户——**新老两套号码在用户眼里永远不会撞车**。296 就是为了让 NAI = 32 刚好对上 NP = 328 而凑出来的偏移量。

| 你看到的 | 它是什么 | 换算 |
|---|---|---|
| NP = 401 | 用户域三位前缀 | NAI = 401 − 296 = **105** |
| NAI = 105 | 地址高 9 位 | 105 × 0x8000 = **0x348000**（这个区的起点） |
| 这个区的号 | `0x348001` … `0x34FFFF` | 低 15 位就是 SSI / SGI |

后面所有例子都用 **NP = 401**（NAI = 105）这个**示例网络**，你会发现所有地址都以 `0x34…` 开头——因为它们都在同一个「区」里。

### 4.4 Annex E 的号码家族一览

先给全貌，后面三节一个个拆：

```text
                       ┌─ 个号（Individual）：NP ‖ FIN ‖ IN      8 位，例 401 25 312
                       │      FIN 20–41（大车队，每队 700 人）/ 42–89（小车队，每队 350 人）
用户号码（十进制）  ────┼─ 组号（Group）     ：NP ‖ FGN ‖ GN      8 位，例 401 25 934
                       │      FGN 20–89，GN 900–999（每队 100 个组）
                       ├─ 调度台（Dispatcher）：NP ‖ 10n         6 位，例 401 105
                       ├─ 全呼（All Call）  ：*196x / *197x / *198x
                       └─ 外线（Line）       ：01… PSTN / 02… PABX
缩短拨号：本网 NP 已预置 → 5 位（FIN‖IN / FGN‖GN）；本车队也预置 → 3 位（IN / GN / 10n）
```

**FIN**（Fleet Individual Number）= 车队号（个体用），**IN**（Individual Number）= 车队内个号；**FGN**（Fleet Group Number）= 车队号（组用），**GN**（Group Number）= 车队内组号。FIN 和 FGN 取同一个范围 20…89，规范说「每个 NP 有 70 个组车队，**与 FIN 对应**」——也就是说，**25 车队的人（FIN 25）一般就用 25 车队的组（FGN 25）**。
