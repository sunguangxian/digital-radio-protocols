# 第 12 课 · 协议分层 L1 / L2 / L3

> DMR 深入学习 · 阶段 B 全貌（协议栈分层专课）  
> 适合：已能分清 TR 与 Part1–4 书架，但一听到「物理层 / 数据链路 / 呼叫控制」「U-plane / C-plane」就懵——分不清该怪哪一层、该翻哪本书的人

## 1. 为什么本课重要（动机）

第 11 课钉死了文档地图：TR 是导读，Part1–4 分管空口 / 语音 / 数据 / 集群，冲突时 **TS > TR > 手册**。下一关不是再背一本 PDF 名字，而是学会**把问题钉到层上**：

- 同事说「协议栈出了问题」，你却分不清是调制解调坏了，还是校验/成帧坏了，还是呼叫建立逻辑坏了——三个人各查各的，浪费半天。  
- 语音「听得到但破音严重」，有人去改 Part2 个呼组呼配置；其实更像 L1 射频/同步或 L2 突发保护出了问题。  
- 组呼根本起不来，有人只拧天线（L1），从不看有没有 Voice LC Header、地址对不对（L2/L3）。  
- 听到「OSI 七层」就硬套：试图在 DMR 空口里找「完整第七层应用层条款」——DMR **只规范到三层空口栈**，灵感来自 OSI，但不是把七层全搬进来。  
- 看到字段文写「CCL / C-plane」，以为语音载荷也要走呼叫控制层——其实语音主载荷走 **U-plane**，呼叫控制主要在 **C-plane**。

若只背「DMR 有三层」五个字，后面会卡在同一处：

> **L1 管比特怎么在电波里飞；L2 管比特怎么成帧、保护、寻址与信道管理；L3（CCL）只管控制面上的呼叫建立/维持/释放与固有业务。排障先分层，再选书。**

本课目标是让你能自己讲清十件事：

1. **为什么**要分层（电梯楼层 / 快递分拣：各层只干自己的活）；  
2. 一张总图：L1 / L2 / L3 + U-plane / C-plane；  
3. 白话术语：Physical / Data Link / CCL、突发、FEC、MAC、声码器接口等；  
4. 现场岗位与故障如何映射到「该怪哪一层」；  
5. 三层各自**管什么、不管什么**（含关键数字：30 ms、60 ms、264 bit、12.5 kHz、4FSK）；  
6. 书架怎么叠：**Part1 ≈ L1+L2**；**Part2 ≈ L3 语音/通用**；**Part3 数据呼叫控制**；**Part4 集群高层仍叠在同一空口栈上**；  
7. 三到四个正反完整例子；  
8. 常见误区清单；  
9. 自测能闭卷答「该怪哪一层」；  
10. 为第 13 课「业务全景：语音 / 数据 / 补充业务」准备好「层之上还有业务种类」的直觉。

## 2. 总图 / 故事：三层电梯 + 两条通道

先把整课装进「电梯楼层」故事，再落到规范里的真实机制。精神与 `01-空中接口/帧结构与字段定义.md` §1（TS 102 361-1 **clause 4.1**）一致。

### 2.1 电梯楼层故事（直觉）

想象一栋三层小楼，对讲机每次「说话」都要从顶层意图走到地面电波：

```text
楼层 3（L3 · 呼叫控制 CCL）
  「谁跟谁说？建呼？保持？释放？紧急插话？」
  —— 只在控制通道（C-plane）上忙活

楼层 2（L2 · 数据链路）
  「打包、贴地址、加校验、排时隙、告诉声码器往哪插」
  —— 既服务语音用户面，也服务信令/数据控制面

楼层 1（L1 · 物理层）
  「把比特变成 4FSK 波形发出去；收端再变回比特」
  —— 12.5 kHz 格子、收发切换、同步、RF 性能都在这
```

类比要落地到机制：

| 电梯说法 | 真实机制（请用这句对外讲） |
|----------|----------------------------|
| 「三楼决定去哪」 | L3 决定呼叫建立/维持/释放、个呼/组呼、目的地址、固有业务（紧急、抢占、迟后进入等） |
| 「二楼打包贴单」 | L2 做 FEC/CRC、交织、ACK/重传原则、MAC/信道管理、帧与超帧、突发参数、寻址、声码器接口、与 CCL 交换信令/用户数据 |
| 「一楼变成电波」 | L1 做 4FSK 调制解调、收发切换、RF、比特/符号、频率与符号同步、突发组装 |

### 2.2 规范栈图（请在脑子里贴墙上）

```text
┌──────────────────────────────────────────────────────────┐
│  AI Layer 3 — Call Control Layer (CCL)                   │
│  仅 C-plane：BS 激活/去激活；呼叫建立/维持/释放；         │
│  个呼/组呼；目的寻址；固有业务；数据呼叫控制；公告信令   │
│  （细节主战场：Part 2；数据细节：Part 3；集群高层：Part 4）│
├──────────────────────────────────────────────────────────┤
│  AI Layer 2 — Data Link Layer                            │
│  FEC/CRC、交织、ACK/重传、MAC/信道管理、帧/超帧与同步、   │
│  突发参数、寻址、声码器接口、数据承载、与 CCL 交换        │
│  （U-plane 语音载荷 + C-plane 信令/数据 都经过这里）       │
├──────────────────────────────────────────────────────────┤
│  AI Layer 1 — Physical Layer                             │
│  4FSK 调制解调、收发切换、RF 性能、比特/符号、             │
│  频率与符号同步、突发组装（30 ms 时隙舞台）                │
└──────────────────────────────────────────────────────────┘
```

关键数字（阶段 C 还会深挖，本课先钉进肌肉记忆）：

| 项 | 值 | 落在哪一层直觉 |
|----|-----|----------------|
| 信道间隔 | **12.5 kHz** | L1 的「地皮宽度」 |
| 调制 | **4FSK** | L1 |
| 时隙 Timeslot | **30 ms** | L1 时间格子；L2 在上面排业务 |
| TDMA frame | **60 ms**（2×30 ms） | L1/L2 共同舞台 |
| Traffic burst | **264 bit ≈ 27.5 ms** | L1 组装；L2 定义里面装什么 |
| Guard / CACH | **约 2.5 ms** | 入站 guard；出站 CACH（L1/L2 边界常聊） |

### 2.3 两条通道：U-plane vs C-plane

DMR 不只「上下三层」，还有「左右两条通道」的说法——这是排障时最容易漏掉的一张图：

```text
                    控制面 C-plane                用户面 U-plane
                    （信令 / 数据呼叫控制等）      （语音主载荷）
                            │                           │
            ┌───────────────┴───────────────┐           │
            │  L3 CCL（只在 C-plane）        │           │
            └───────────────┬───────────────┘           │
                            │                           │
            ┌───────────────┴───────────────────────────┴───────────────┐
            │              L2 Data Link（两边都服务）                      │
            │   C-plane：带寻址的信令/数据 PDU                            │
            │   U-plane：语音载荷（该平面本身不靠「呼叫地址字段」走路）    │
            └───────────────────────────────┬─────────────────────────────┘
                                            │
                            ┌───────────────┴───────────────┐
                            │           L1 Physical         │
                            └───────────────────────────────┘
```

白话钉死三条：

1. **L3 只出现在 C-plane**——它不直接「搬语音波形」。  
2. **语音主载荷走 U-plane**，经 L2 的声码器接口落到突发里；**呼叫是谁、建没建起来**，要看 C-plane 上的 L3 + L2 信令（如 Voice LC Header 等）。  
3. **L1 对两条通道一视同仁**：到了物理层，都是要飞出去的比特与符号。

口诀：**上三层管意图与打包；左右两道分「控制」与「语音载荷」；地面 L1 只负责把比特变成电波。**

## 3. 白话术语表

| 术语 | 白话 | 现场你会碰到 |
|------|------|----------------|
| **协议栈 / Layer** | 把通信问题拆成几层，每层只干一类活 | 「这是底层问题还是呼叫控制问题」 |
| **L1 Physical Layer** | 物理层：调制解调、RF、同步、突发比特怎么飞 | 4FSK、12.5 kHz、收发切换、同步不上 |
| **L2 Data Link Layer** | 数据链路层：成帧、保护、接入、寻址、信道管理 | FEC/CRC、LC/CSBK、超帧、ACK |
| **L3 / CCL** | Call Control Layer：呼叫控制层 | 建呼、释呼、个呼/组呼、紧急、迟后进入 |
| **OSI 灵感** | 分层思想来自 OSI，但 DMR **空口只规范三层**，不是七层全文搬迁 | 「别在 DMR 里硬找完整 L7 条款」 |
| **U-plane（用户面）** | 主要扛语音载荷的那条逻辑通道 | 「话音破、有噪声」常先怀疑 U-plane/L1/L2 |
| **C-plane（控制面）** | 信令与呼叫控制、带寻址的数据控制 | 「根本打不通、登记/建呼失败」 |
| **Burst（突发）** | 一次发送的物理单元；业务突发常见 **264 bit** | 「看一下突发类型 / SYNC」 |
| **FEC / CRC** | 前向纠错 / 校验：让空中误码可查、部分可纠 | L2 主场；本课不贴矩阵 |
| **交织（Interleaving）** | 把比特打散再发送，减轻突发误码「连片打死」 | L2；与 FEC 搭配出现 |
| **MAC / 信道管理** | 谁可以占用时隙、如何礼貌接入等链路侧规则 | 「接入冲突、礼貌等待」 |
| **帧 / 超帧** | 时隙之上的时间结构；语音超帧 A–F 共 **360 ms** | 「超帧没对齐」 |
| **声码器接口（Vocoder socket）** | L2 提供的「语音比特往突发里插」的插口；声码器实现可由厂商选 | 「声码器不匹配」≠ 一定是 L3 |
| **寻址（Addressing）** | 个呼/组呼等身份；在 C-plane / L2 信令里携带 | 色码对了但地址错了 |
| **BS activate/deactivate** | 基站侧业务信道激活/去激活一类控制 | 中继/基站资源何时起来 |
| **固有业务（intrinsic services）** | 紧急、抢占（pre-emption）、迟后进入（late entry）等 | 「迟后进入为何无效」 |
| **Part1 ≈ L1+L2** | 空口规范同时定义物理与数据链路 | 排障空口先翻 Part1 |
| **Part2 ≈ L3 语音与通用** | 呼叫控制细节主战场 | 业务语义先翻 Part2 |
| **冲突裁决** | **TS > TR > 手册笔记** | 与第 11 课同一口诀 |

口诀：**L1 电波，L2 打包，L3 呼叫；U 走语音载荷，C 走信令控制。**

## 4. 现场对照（岗位 / 故障 → 该怪哪一层）

| 现场角色 / 卡点 | 先怀疑哪一层 | 该翻的书/笔记 | 别一上来就 |
|-----------------|--------------|---------------|------------|
| 射频 / 覆盖：收不到、解调花、灵敏度差 | **L1** | Part1；`帧结构与字段定义.md` 时序；加餐文巩固 4FSK/12.5 | 改 Part2 联系人 |
| 写频：色码、时隙、频率格子设错 | **L1 为主，常连带 L2 同步/色码场** | Part1；速查卡 | 直接上 Part4 Reason |
| 「有噪声但偶能听懂」vs「完全无声」 | 前者偏 **L1/L2 保护**；后者还要查 **是否根本没建呼（L3/C-plane）** | Part1 → Part2 | 只拧功率或只改显示名 |
| 组呼列表对，但空中根本没有建呼信令 | **L3 / C-plane + L2 信令** | Part2 + Part1 LC/CSBK | 只查天线 |
| 迟后进入、紧急、抢占行为不符合预期 | **L3 固有业务**（仍要 L2 把信令送出去） | Part2；必要时回 Part1 嵌入/LC | 当纯射频问题 |
| 短信/短数据确认失败、重传怪 | **L2 数据承载 + Part3 数据呼叫控制（叠在栈上）** | Part3 + Part1 | 只骂手机 App |
| 集群登不上、无 Grant | **Part4 高层信令**，但仍经同一 **L1/L2 空口** | Part4 + Part1 | 「分层与集群无关」——有关，栈是同一个 |
| 产品经理讲「系统分层」给客户听 | 本课总图 + TR 导读 | TR；本课；手册 | 甩 FEC 矩阵吓客户 |

对照口诀：

> **电波/同步/调制 → L1；成帧/校验/时隙占用/地址壳 → L2；建呼释呼/个组呼意图/固有业务 → L3。先分层，再开书。**

## 5. 各层深挖：管什么、不管什么

权威锚点：ETSI **TS 102 361-1 V2.7.1** **clause 4.1**；本库中文入口：`01-空中接口/帧结构与字段定义.md` §1。版本冲突时仍遵守：**TS > TR > 手册**。

### 5.1 L1 Physical Layer —— 比特如何变成电波

**管什么（请用完整句子记）：**

1. **调制与解调**：DMR 空口用 **4FSK**，把比特流变成可在 **12.5 kHz** 信道里飞的波形，收端再变回比特。  
2. **收发切换**：半双工世界里，何时发、何时收，物理上要切得干净。  
3. **RF 性能相关要求**：发射/接收是否「够格」——覆盖、干扰、灵敏度讨论的主场在这一层的物理现实。  
4. **比特与符号**：符号怎么对应比特、频率与符号如何同步，让双方「踩在同一个节拍上」。  
5. **突发组装**：把要发送的比特流按突发时间窗口送出去——业务突发常见 **264 bit ≈ 27.5 ms**，再加约 **2.5 ms** 的 guard（入站）或 CACH（出站），凑满 **30 ms** 时隙。

**不管什么：**

- 不管「这个呼叫是个呼还是组呼、要不要紧急插话」——那是 **L3**；  
- 不管「PDU 里地址字段怎么编、CRC 多项式怎么选」——那是 **L2**（及上层规范）；  
- 不管「短数据确认重传策略的业务语义」——那是 **Part3 / 数据呼叫控制**；  
- **但**：上层全对、L1 不同步或射频崩了，整机仍会表现为「什么都不通」。

**现场口播：**

> 「频率格子、4FSK、30 ms 时隙节拍——出问题先当 L1 查；频率概念糊，就会在 L1 症状上反复摔跤。」

### 5.2 L2 Data Link Layer —— 打包、保护、信道与插口

**管什么：**

1. **FEC / CRC 与交织**：减轻空中误码；让接收方知道「这包能不能信」。  
2. **ACK / 重传相关机制（原则级）**：需要确认的数据路径上，链路侧如何应答与再送（细节随业务进 Part3 等）。  
3. **MAC 与信道管理**：谁占用哪个时隙、如何接入、如何与基站协调资源。  
4. **帧 / 超帧与同步图案使用**：例如语音超帧 **A–F（360 ms）**、语音/数据不同 SYNC——让接收机知道「现在听到的是哪一类东西」。  
5. **突发参数与 PDU 壳**：264 bit 里面 108+48+108 如何切、中间放 SYNC 还是嵌入信令、数据突发如何露出 Slot Type 等（阶段 C 细拆）。  
6. **寻址**：把「打给谁」放进合适的信令/数据 PDU（C-plane 侧尤其明显）。  
7. **声码器接口**：给语音比特一个标准「插座」，方便 U-plane 载荷进入突发。  
8. **数据承载**：短数据/分组数据等如何在链路上搬。  
9. **与 CCL（L3）交换**：把上层的呼叫控制意图变成可在空口走的信令，把收到的信令/用户数据交回上层。

**U-plane vs C-plane 在 L2 的差别（再钉一次）：**

- **U-plane**：主要搬语音载荷；该平面本身不以「呼叫地址字段」为走路方式——地址与呼叫控制在 C-plane 完成。  
- **C-plane**：信令与数据控制，**带寻址**；L3 的命令经这里上下。

**不管什么：**

- 不管 4FSK 星座怎么映射到射频前端电路——那是 **L1 / 实现**；  
- 不管「业务上什么叫一次完整组呼流程、补充业务名单」的完整语义——主战场在 **Part2 / L3**；  
- 不管集群控制器里 Aloha 参数表、Reason Code 全文——那是 **Part4**；  
- **但**：没有 L2，L3 的意图出不了门，L1 也只是在飞「无结构的噪声级比特」。

**现场口播：**

> 「能同步但一讲话就CRC炸、时隙抢不上、地址壳错——偏 L2。」

### 5.3 L3 Call Control Layer（CCL）—— 只在控制面上管呼叫

**管什么（摘要自 clause 4.1.3 一类表述 + Part2/3/4 分工）：**

1. **仅在 C-plane 上工作**——这是最重要的边界。  
2. **BS 激活 / 去激活**：基站侧资源何时为业务起来或收起。  
3. **呼叫建立 / 维持 / 释放**：一次呼叫的生命周期。  
4. **个呼 / 组呼**：谁跟谁说的业务类型决策。  
5. **目的寻址**：呼叫要打到哪里（与 L2 携带地址配合）。  
6. **固有业务**：紧急、抢占、迟后进入等。  
7. **数据呼叫控制**：数据会话如何建立与管理（细则见 **Part3**）。  
8. **公告信令（announcement signalling）** 等控制类通告。

**细节落在哪本书：**

| 内容 | 主规范 |
|------|--------|
| 语音与通用呼叫控制细节 | **Part 2**（TS 102 361-2 V2.5.1） |
| 数据呼叫控制 / PDP 等 | **Part 3**（TS 102 361-3 V1.3.1） |
| 集群登记、派信道、Grant/Reason 等高层 | **Part 4**（TS 102 361-4 V1.12.1）——**仍叠在同一 L1/L2/L3 空口思想上** |
| 空口三层定义与 L1/L2 条文 | **Part 1**（TS 102 361-1 V2.7.1）clause 4.1 等 |

**不管什么：**

- 不管把语音样点变成 4FSK 符号——**L1**；  
- 不管 FEC 矩阵怎么乘——**L2 / 附录级实现细节**（本课程阶段 C 只讲原则）；  
- 不管「天线驻波比好不好」——射频工程，常归到 L1 现场症状；  
- **不管 OSI 第 5–7 层的互联网应用协议全文**——DMR 空口标准不在这里扩成完整七层百科。

**现场口播：**

> 「列表、权限、建呼释呼、紧急与迟后进入——先当 L3/C-plane；但信令仍要 L2 送、L1 飞。」

### 5.4 和「OSI 七层」怎么相处（避免玄学）

- DMR 空口栈是 **OSI 启发下的三层模型**，不是「实现时必须画满七层盒子」。  
- 你在 IT 课学的传输层/应用层，**不等于** DMR 的 L3。DMR 的 L3 名字就叫 **Call Control Layer**，职责写在 Part1 clause 4.1 与 Part2/3/4。  
- 对外沟通建议：说「DMR 空口三层：物理、数据链路、呼叫控制」，需要类比时再说「类似把网络问题分层，但空口规范只钉到三层」。

     │                 （数据/集群仍要回空口）

## 7. 完整例子（正反共四则）

### 例子 A · 正例：破音严重，却先分层再动手

- **场景**：Tier II 中继，组呼能通，但多人反馈「沙沙声、字丢」。调度台业务名、组号看起来都对。  
- **分层思路**：  
  1. 能通 → 不太像「完全没建呼」的纯 L3 失踪；  
  2. 先查 L1：场强、干扰、频率/色码是否擦边、天线与驻波；  
  3. 再查 L2：是否大量 CRC 失败、时隙是否被挤、同步是否不稳；  
  4. Part2 业务选项最后再核对（迟后进入等），避免一上来改联系人。  
- **结果**：发现邻频干扰 + 一台终端频率微调偏了——典型 **L1 症状**。  
- **一句话**：**「能建呼但不好听」优先 L1/L2，而不是先改 L3 业务名单。**

### 例子 B · 正例：组呼列表对，空中却没有呼叫

- **场景**：写频软件里组号正确，屏幕也能选组，按 PTT 对方完全无反应；仪表看空口几乎看不到应有的语音建立相关信令。  
- **分层思路**：  
  1. 先确认 L1 是否在发射（功率、信道、时隙是否真的在占用）；  
  2. 若 L1 在飞，查 L2 是否带出 Voice LC Header / 地址壳、色码是否一致；  
  3. 再查 L3/C-plane：权限、禁发、业务是否允许该组呼、基站是否激活相应资源。  
- **结果**：终端被误设成错误色码 + 某呼叫权限关闭——**L2 寻址壳与 L3 权限**叠加，不是天线坏了。  
- **一句话**：**「界面有组」≠「C-plane 已建呼」；要分层看信令是否出门。**

### 例子 C · 正例：数据确认失败，不骂应用层了事

- **场景**：短数据/状态消息「发送失败」，IT 同事说 App 有 bug。  
- **分层思路**：  
  1. App 之上先问：空口是否处于可传数据的信道与时隙（L1/L2）；  
  2. 打开 Part3 视角：确认/非确认、重传与呼叫控制是否按规范；  
  3. 回 Part1 看数据突发类型、SYNC、FEC 是否大量失败。  
- **结果**：确认链路在弱覆盖下连续 CRC 失败触发放弃——**L1 条件差 + L2 保护撑不住**，不是单纯 App 逻辑错误。  
- **一句话**：**数据问题常常是「Part3 控制 + Part1/L2 承载」合奏，不能只骂应用。**

### 例子 D · 反例：把 OSI 七层硬套进空口争论

- **错误做法**：联调争议时说「这是表现层/会话层的问题」，要求对方拿出 DMR「第 6 层条款」；同时忽略 Part1 clause 4.1 已写明的三层与 U/C-plane。  
- **后果**：会议变成计算机网络课复读机，现场故障多拖一天。  
- **纠正**：承认 OSI 是教学类比；**DMR 空口规范锚点是 L1/L2/L3（CCL）**；业务细节回 Part2/3/4。  
- **教训**：**类比可以上桌，条款必须回 ETSI 三层定义。**

## 8. 常见误区（请逐条用自己的话复述）

1. **「分层就是 OSI 七层，DMR 也该有七层标准全文。」**  
   错。DMR 空口是 **三层**模型；Part1 clause 4.1 是锚点。

2. **「L3 也处理语音波形。」**  
   错。L3（CCL）在 **C-plane**；语音主载荷走 **U-plane**，经 L2 声码器接口进突发。

3. **「有破音一定是呼叫控制配错。」**  
   危险。更常见是 **L1 射频/同步** 或 **L2 保护/突发** 问题。

4. **「同步问题属于 L3。」**  
   错。频率/符号同步、突发组装偏 **L1**；帧/超帧与 SYNC 图案使用紧密连着 **L2**。

5. **「Part4 集群是另一套物理层。」**  
   错。集群高层信令仍叠在同一套空口思想与 L1/L2 管道上；只是控制过程更丰富。

6. **「Part1 只等于 L1。」**  
   不完整。Part1 **≈ L1+L2**，并定义整栈边界；L3 细节主要在 Part2（数据 Part3，集群 Part4）。

7. **「U-plane 语音突发里自己就带着个呼地址，所以不用 C-plane。」**  
   混淆。呼叫寻址与建立在控制相关信令路径上完成；U-plane 侧重载荷搬运。细节到阶段 C/D 再拆字段，本课先建立平面直觉。

8. **「12.5 kHz 和 4FSK 是 L3 业务参数。」**  
   错。它们是 **L1** 的舞台参数；业务在上面跑。

9. **「FEC 矩阵背出来才算懂 L2。」**  
   不必。先懂「L2 负责保护与成帧」；矩阵留给实现与后续原则课（第 24 课规划）。

10. **「中文科普文写的分层若与 ETSI 冲突，听科普。」**  
    错。冲突时 **TS > TR > 手册/中文旧文**；本课外链亦同。

11. **「分层学完就可以不记 30 ms / 264 bit。」**  
    不建议。这些数字是 L1/L2 共同语言，阶段 C 会反复用到。

12. **「频率不懂没关系，分层课不涉及。」**  
    半对。本课不重讲频谱，但频率混乱会表现为 **L1 症状**——加餐文仍要回看。

## 9. 自测（建议先闭卷写，再对答案）

1. **填空**：DMR 空口规范的三层是 ______、______、______（CCL）；L3 主要工作在 ______-plane。  
2. **选择**：组呼能通但严重破音，优先排查顺序更合理的是：  
   A. 只改 Part2 组显示名  
   B. L1 射频/同步 → L2 保护/突发 → 再核 L3 业务选项  
   C. 直接精读 Part4 Reason Code  
3. **判断**：Part1 只描述物理层，数据链路与呼叫控制都不在 Part1 出现。对 / 错？  
4. **连线**（写对应）：  
   - 4FSK / 12.5 kHz / 收发切换 → ?  
   - FEC、成帧、声码器接口、MAC → ?  
   - 建呼释呼、紧急、迟后进入 → ?  
   - 语音主载荷通道 → ?  
5. **数字填空**：时隙 ______ ms；TDMA 帧 ______ ms；业务突发约 ______ bit ≈ ______ ms；guard/CACH 约 ______ ms。  
6. **简答**：为什么说「Part4 集群仍叠在同一空口栈上」？请用两句话说明排障含义。

### 参考答案

1. **物理层 L1；数据链路层 L2；呼叫控制层 L3；C（控制面）。**  
2. **B。**  
3. **错。** Part1 定义整栈（clause 4.1），并详述 L1/L2；L3 细节主战场在 Part2 等。  
4. **L1；L2；L3；U-plane。**  
5. **30；60；264；27.5；2.5。**  
6. **集群的登记/派信道等是更高层过程（Part4），但比特仍要经 L2 成帧保护、经 L1 调制发出；所以集群故障也常要回查空口同步与链路质量，不能只盯 Reason Code 表。**
