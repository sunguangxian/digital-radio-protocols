# DMR 第 21 课：EMB / Slot Type

本课学习 Voice Embedded Signalling 中的 EMB 与 Data/Control Burst 中的 Slot Type。

## 核心结构

Voice B～F：`Voice(108) | EMB(8) | Embedded signalling(32) | EMB(8) | Voice(108)`。

General Data/Control：`Info(98) | Slot Type(10) | SYNC/Embedded(48) | Slot Type(10) | Info(98)`。

## EMB

EMB 的有效信息是 7 bit：Colour Code(4) + PI(1) + LCSS(2)，经 Quadratic Residue (16,7,6) 编码成 16 bit，再拆成左右各 8 bit。CC 用于系统筛选，LCSS 用于 Embedded LC 分片关系，PI 与 Privacy signalling 状态有关。

## Slot Type

Slot Type 的有效信息是 8 bit：Colour Code(4) + Data Type(4)，经 Golay(20,8) 编码成 20 bit，再拆成左右各 10 bit。Data Type 告诉接收机旁边 196 bit Info 应按哪种 PDU 解释，例如 Voice LC Header、CSBK、Data Header 或不同速率数据块等。

## 为什么两者都包含 CC？

CC 是 Voice 与 Data 两条路径都需要的公共筛选条件，但 EMB 的其它信息服务 Embedded Signalling，而 Slot Type 的 Data Type 用于选择 Data/Control Payload 的解释方式，所以不能把两者看成同一个字段。

## 为什么短字段还需要 FEC？

这些字段一旦误码，会让后续大块 Payload 按错误方式解释。ETSI 的 FEC 汇总中，EMB 使用 QR(16,7,6)，Slot Type 使用 Golay(20,8)，体现了关键元数据需要强保护的设计。

## 接收流程

`Voice B～F → EMB重组 → QR Decode → CC/PI/LCSS → Embedded Signalling → Embedded LC`

`Data/Control → SLOT重组 → Golay Decode → CC/Data Type → 按Data Type选择后续解码器`

## 今天记住这几点

1. EMB = CC + PI + LCSS，重点服务 Voice Embedded Signalling。
2. Slot Type = CC + Data Type，重点告诉接收端 196 bit Info 是什么。
3. 左右 EMB/SLOT 不是两份独立信息，而是同一个编码块拆成两半。
4. EMB 7 bit 经 QR 编码成 16 bit；Slot Type 8 bit 经 Golay 编码成 20 bit。
5. CC 相同不代表 EMB 与 Slot Type 职责相同。

## 自测题

1. Slot Type 已有 CC，为什么还需要 Data Type？——因为 CC 只判断系统，Data Type 决定 196 bit Info 的具体解释方式。
2. Voice C 的 CC 正确但 LCSS 错，声音一定坏吗？——不一定，可能声音正常但 Embedded LC 重组失败。
3. 为什么不裸传 EMB/SLOT？——关键类型字段误码会导致后续 Payload 整体误解，因此需要 FEC 保护。
