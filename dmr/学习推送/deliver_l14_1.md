# 第 14 课 · 互操作：SFID / MFID / FLCO

> DMR 深入学习 · 阶段 B 全貌（互操作收官课）  
> 适合：已能分清语音/数据/补充业务，但一听到「特性集」「SFID」「厂商私有 FID」「FLCO」就晕——分不清「同频同色码为啥还各说各话」、标准业务该挂哪个门牌的人  
> 阅读量：约 30–40 分钟 · 几乎不推公式 · 要把「FID = 特性集门牌、FLCO/CSBKO = 门牌下的功能码、标准业务必须走 SFID」钉死  
> 若频率/带宽/调制仍糊：只提醒一句——坏射频常**看起来像**「互操作失败」，其实是 L1 听不清；互操作真正卡在 **FID + Opcode**。频谱加餐见 `学习推送/加餐_频率带宽与调制解调.md`。本课主线是**特性互操作**，不重讲频谱。

## 1. 为什么本课重要（动机）

第 13 课钉死了业务全景：Bearer / Tele-service / Supplementary；语音主战场在 Part2，数据在 Part3，集群控制信道短数据还要看 Part4。下一关不是再背菜单，而是学会**把「用户要的能力」钉到空口门牌上**：

- 采购说「两家 DMR 都符合标准，应该能互通」，联调时 A 厂组呼正常、B 厂「特色导航语音」对端完全听不见——不是天线坏了，而是 **MFID 私有特性**对端不认。  
- 抓包看到 Full LC 的 `FID=0x00`、`FLCO=000000`，同事问「这是什么」——这是标准组呼语音信道用户 LC；若 `FID` 落在厂商区，同一 `FLCO` 数值**含义可能完全不同**。  
- 产品经理要求「把标准个呼做成我们自己的 Opcode，好防拷贝」——这会直接破坏互操作：规范要求**已标准化的特性只能经 SFID + 对应 FLCO 暴露**。  
- 对端回了一条「Feature Not Supported（FNS）」类信令——不是骂你，是礼貌地说「你用 SFID 叫了一个我不支持的标准 Opcode」。  
- 产业侧还有 **DMR Association IOP 认证**：测的是标准特性清单能否互通；私有特性本来就不在「必通」名单里。

若只背「DMR 能互通」五个字，后面会卡在同一处：

> **互操作不是「都写着 DMR 就能说话」。空口上先看 FID（哪一套特性集），再看 FLCO/CSBKO（这套里的哪一个功能）。标准业务挂 SFID；厂商私活挂 MFID。门牌挂错，同频同色码也会各说各话。**

本课目标是让你能自己讲清十件事：

1. **为什么**要用「商场门牌 + 楼层功能码」来记 SFID/MFID/FLCO；  
2. 一张总图：FID 分区（Table H.1）+ Full LC / CSBK 外壳里的位置；  
3. 白话术语：FID、SFID、MFID、FLCO、CSBKO、FNS、IOP；  
4. 现场岗位与故障如何映射到「查 FID 还是查射频」；  
5. SFID 下常见 FLCO / CSBKO 地图（与第 13 课业务对照）；  
6. 完整例子：标准组呼 vs 厂商私有 LC vs FNS；  
7. 数据侧 Part3 的互操作提醒（第二数据头 / MFID）；  
8. 常见误区 + 自测；  
9. 资料库加深阅读路径；  
10. 为阶段 C「时隙 30 ms」留下钩子（本课收官阶段 B）。

## 2. 总图 / 故事：商场门牌 + 楼层功能码

先把整课装进「商场导航」故事，再落到 Part1 Annex H 与 Part2 clause 4.3。精神与 `DMR整合学习手册.md` §5.1、`AnnexA编址与AnnexH_FID.md` 一致。

### 2.1 商场门牌故事（直觉）

想象空口上每个「控制/链路控制」消息都要先报门牌，再报楼层服务：

```text
┌─────────────────────────────────────────────────────────────┐
│  FID（8 bit）= 商场门牌 / 特性集                              │
│     0x00 = SFID「标准馆」——Part2/Part3 写明的默认特性集        │
│     厂商区 = MFID「某某品牌私密馆」——对端未必有钥匙             │
│                                                             │
│  FLCO（6 bit，在 Full LC 里）= 该馆内的空中功能码              │
│     例：标准馆里 000000 = 组呼语音信道用户                      │
│                                                             │
│  CSBKO（6 bit，在 CSBK 里）= 控制信令块上的功能码              │
│     例：标准馆里 000100 = 个呼语音业务请求                      │
└─────────────────────────────────────────────────────────────┘
```

类比要落地到机制：

| 商场说法 | 真实机制（请用这句对外讲） |
|----------|----------------------------|
| 「门牌」 | **FID**：标识用的是哪一套特性集 |
| 「标准馆」 | **SFID** = `00000000`（0x00）：TS 102 361-2 默认特性集 |
| 「品牌私密馆」 | **MFID**：厂商向 ETSI 申请的特性集；对端不懂就不处理 |
| 「馆内服务码」 | **FLCO**（Full LC）或 **CSBKO**（CSBK）：该 FID 下的空中功能 |
| 「对不起，本店不提供」 | **FNS**（Feature Not Supported）：被个呼到、但不支持该 SFID+Opcode |

口诀：**先看门牌（FID），再看服务码（FLCO/CSBKO）。标准业务只能开在标准馆。**

### 2.2 为什么「同频同色码」还不够

同频、同 **12.5 kHz** 信道间隔、同 Colour Code、甚至同个呼/组呼号码，只保证「听得到比特、不会误入别的系统」。**听懂业务意图**还要门牌一致：

```text
射频层 OK（12.5 kHz · 4FSK · 30 ms 时隙）
        │
        ▼
   L2 解出 Full LC / CSBK 外壳
        │
        ├── FID == 0x00 且 FLCO/CSBKO 是标准表里的？
        │         → 按 Part2/Part3 解释（可互通）
        │
        └── FID 落在 MFID 区？
                  → 只有支持该厂商特性集的设备才「懂」
                  → 其他厂设备通常静默忽略（不是天线坏了）
```

### 2.3 规范总图（请在脑子里贴墙上）

```text
                    ┌──────────────────────────────┐
                    │  用户要的能力：组呼 / 个呼 / 别名 / 私有导航… │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │  是否已在 Part2（或 Part3）标准化？ │
                    └──────┬─────────────────┬─────┘
                           │是               │否
                           ▼                 ▼
                    必须用 SFID          只能用 MFID
                    + 标准 FLCO/CSBKO    + 厂商自定 Opcode
                           │                 │
                           └────────┬────────┘
                                    ▼
                         Full LC / CSBK 外壳里写出
                         Octet0: … Opcode(6)
                         Octet1: FID(8)
```

Annex H 分区摘要（学习用；冲突以 PDF 为准）：

| FID 值（二进制直觉） | 含义 |
|----------------------|------|
| `00000000` | **SFID** — TS 102 361-2 标准业务 |
| `00000001`…`00000011` | 保留，未来标准化 |
| `00000100`…`01111111` | **MFID** 厂商区 |
| `1xxxxxxx` | 保留，未来 MFID 扩展 |

要点：一家厂商可持有多个 MFID；多家也可共用同一 MFID（厂商策略）。MFID **向 ETSI 申请**（见 Part1 Annex H.2）。

贯穿数字（舞台仍是空口，阶段 C 会拆时隙）：

| 项 | 值 | 互操作直觉 |
|----|-----|------------|
| 信道间隔 | **12.5 kHz** | 「地皮」一样，不保证「店规」一样 |
| 时隙 | **30 ms** | 比特按时到达，不等于 Opcode 同义 |
| FID | **8 bit** | 门牌 |
| FLCO / CSBKO | **各 6 bit** | 门牌下的功能码 |
| SFID | **0x00** | 标准馆唯一默认门牌 |

## 3. 白话术语表

| 术语 | 白话 | 现场一句话 |
|------|------|------------|
| **FID** | Feature set ID，特性集标识 | 「这套信令挂在哪家门牌下」 |
| **SFID** | Standards FID，标准默认特性集 | 「ETSI 标准馆，门牌 0x00」 |
| **MFID** | Manufacturer's FID，厂商特性集 | 「品牌私密馆；没钥匙就别指望懂」 |
| **FLCO** | Full Link Control Opcode | 「Full LC 里的 6 bit 功能码」 |
| **CSBKO** | CSBK Opcode | 「控制信令块里的 6 bit 功能码」 |
| **Full LC** | 全链路控制 | 语音头/终止/嵌入里带地址与业务类型的那块 |
| **CSBK** | Control Signalling Block | 控制信令块（请求、应答、激活、前导等） |
| **FNS** | Feature Not Supported | 「你用标准门牌叫了一个我不支持的功能」 |
| **IOP** | Interoperability（产业认证语境） | 「协会测过的标准特性清单能否互通」 |
| **私有特性** | 规范未标准化、走 MFID 的能力 | 「增值功能，不承诺跨厂」 |

对照记忆（避免混）：

- **FID ≠ 地址**：地址是 24 bit 源/目的；FID 是特性集。  
- **FLCO ≠ CSBKO**：一个在 Full LC，一个在 CSBK；都是 6 bit，但表不同。  
- **SFID 下的 FLCO 数值** 与 **某 MFID 下的同数值** **不能**当成同一个功能。

## 4. 现场对照：谁会用到这一课

| 岗位 / 场景 | 你会碰到什么 | 本课怎么用 |
|-------------|--------------|------------|
| 协议/栈开发 | 实现组呼 LC、个呼 CSBK、Talker Alias | 标准路径固定写 **FID=0x00** + 表内 Opcode |
| 联调 / 互通测试 | A/B 厂组呼通、某「彩蛋功能」不通 | 先抓 **FID**；MFID 不通是预期，不是射频锅 |
| 产品 / 方案 | 「要不要把标准功能改成私有 Opcode」 | **不要**；规范禁止用 MFID「重包装」已标准化特性 |
| 测试 / 抓包 | 看 Voice LC Header / CSBK | 读 Octet0 的 Opcode、Octet1 的 FID |
| 售前 / 招投标 | 客户要「多厂家互通」 | 对齐 **标准特性 + IOP 证书范围**；私有特性单列 |
| 运维排障 | 「有时能通有时不能」 | 区分：射频/色码问题 vs FID/Opcode 不认 |

排障口诀：

1. 先确认频率、Colour Code、时隙、ID 是否匹配（L1/寻址）；  
2. 再看 Full LC/CSBK 的 **FID**；  
3. `0x00` → 查标准 Opcode 表；非 `0x00` → 问「是不是某厂私有特性」。
