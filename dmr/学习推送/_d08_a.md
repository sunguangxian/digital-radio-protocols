# 第 8 课 · 从模拟到 DMR：为什么要标准化

> DMR 深入学习 · 阶段 A 通信地基（收官）  
> 适合：已懂「频率 / 时隙 / 中继 / 个呼组呼」，但还不清楚「为什么必须有一份 ETSI 公开标准、不同牌子能不能通、Tier 和厂商私有功能差在哪」的人  
> 阅读量：约 30–40 分钟 · 几乎不推公式 · 要把「公开标准 vs 私有协议」「频谱规划兼容」「互操作边界（SFID / MFID）」钉死  
> 本课会复习加餐四句话，并用**新例子**巩固「频率 / 带宽 / 调制 / 解调」

---

## 0. 开课前：加餐四句话复习（带新例子）

若你已读过 `学习推送/加餐_频率带宽与调制解调.md`，下面四句应能脱口而出。本课**不照抄加餐与第 2–7 课**，换成「单位要从模拟网迁到数字、还想不同厂商设备能互通」的场景再钉一遍：

| # | 一句话 | 本课用的新例子 |
|---|--------|----------------|
| 1 | **频率** = 信号抖得有多快 | 标准化的第一刀，往往不是「换一个好听的数字协议名」，而是：**还在不在你执照上的那对频点上工作**。DMR 刻意对齐现有陆地移动频段规划，让你尽量**不必为了数字化去改信道表上的中心频率** |
| 2 | **带宽** = 频谱尺子上占多宽的一条带子 | 监管与规划里常见 **12.5 kHz** 信道间隔。DMR 的目标之一，是在这条**已有宽度**里做数字双时隙，并达到约 **6.25 kHz 等效**效率——而不是另发明一套「占 25 kHz 才能数字」的规矩，把执照与邻道规划推倒重来 |
| 3 | **调制** = 把信息装进适合发射的高频波 | 模拟常是连续语音直接 FM；DMR 约定用 **4FSK** 把比特装进载波。若每家厂商私定一套调制与符号率，空中就像「同频点却听不懂对方的方言」——**标准就是强制大家说同一种装车方式** |
| 4 | **解调** = 从收到的高频波把信息卸下来 | 对方电台只有按同一套空口规则解调，才能还原你的声码器比特与链路控制。标准保证的是「能卸下来并认出信封」；**加密密钥、厂商扩展菜单、Tier 是否同层**不在「解调成功」这一句里自动解决 |

再补一句和本课主线钉死的对照：

- **物理与频谱规划**回答：「我们还能不能用原来的 12.5 kHz 车道？」  
- **公开空口标准**回答：「不同牌子按同一份规范写软件，能不能互通基本语音？」  
- **特性集边界（SFID / MFID）**回答：「哪些功能保证互通，哪些只是某家私货？」

若这四句仍糊：先打开加餐文，再回本课。本课主线是：**为什么要从模拟走到公开数字标准、标准解决什么 / 不解决什么、现场怎么判断「通 / 不通」**。

## 1. 为什么本课重要（动机）

现场与招标材料里你会反复撞到这些说法：

- 「我们要上 DMR / 数字对讲。」  
- 「必须符合 ETSI 标准 / TS 102 361。」  
- 「不同品牌能不能互通？」  
- 「模拟兼容 / 模数双模 / 平滑迁移。」  
- 「Tier II 常规」和「Tier III 集群」差在哪？  
- 「这是标准功能还是厂商私有功能？」  
- 文档与抓包里：**SFID、MFID、FLCO、IOP（互操作测试）**

若只背「数字比模拟好听、抗干扰强」两句空话，后面会卡在同一处：

> **数字化本身不等于互通。只有公开、被多方实现并验证的空口规则，才能让「换一个牌子的终端」仍有机会打通基本业务；厂商私有扩展可以很强，但默认不能指望跨厂互通。**

本课目标是让你能自己讲清八件事（仍不推公式）：

1. 模拟对讲的「隐式约定」是什么，为什么业务一复杂就不够用；  
2. 为什么「每家私定数字协议」比模拟更糟（方言分裂）；  
3. ETSI DMR 标准化想解决的三件大事：**频谱兼容、基本业务互通、可演进的分层（Tier）**；  
4. 「数字优势」里哪些来自数字化本身，哪些来自**标准选中的 TDMA / 4FSK / 纠错**；  
5. 迁移现场常见路径：双模终端、分批换中继、网关；  
6. **Tier I / II / III** 各解决谁的问题，以及「跨层不互通」这句硬话；  
7. **SFID vs MFID**：标准特性集与厂商特性集的分界；  
8. 常见误区：以为贴了「DMR」标就一定互通、以为标准化等于没有厂商差异、以为数字永远比模拟听得远。

第 9 课才会专讲「DMR 是什么 + Tier 全貌与文档地图入口」；本课到「为什么要标准化、边界在哪」为止。

## 2. 总图 / 故事：从「同频就能喊」到「同标准才能通」

先把整课装进一张故事图。

```text
【阶段 0 · 模拟】
  约定：同一频点（+ 亚音/DCS 等选呼）≈ 能对话
  优点：简单、设备便宜、历史存量大
  痛点：频谱效率低、边缘区噪声渐重、数据/调度能力弱、管控难

【阶段 1 · 若无标准、各厂私有数字】
  A 厂：自有调制 + 自有帧格式 + 自有组号语义
  B 厂：另一套
  结果：同频点也「听不见」——比模拟还难混用
  采购：被单一供应商锁死；应急联动跨单位几乎无解

【阶段 2 · 公开标准（ETSI DMR）】
  大家书面约定：
    · 仍落在现有 12.5 kHz 规划里（尽量不改执照结构）
    · 同一套空口：4FSK、2 时隙 TDMA（常规/集群主路径）、帧与业务过程
    · 基本语音/数据/补充业务写在 Part 2/3…；集群在 Part 4
    · 标准功能走 SFID；厂商扩展走 MFID（明确「可不互通」）

【阶段 3 · 你现场真正要问的】
  ① 执照与信道规划是否仍匹配？（频率 / 12.5 kHz）
  ② 双方是否同一 Tier 产品形态？（跨层标准上不保证互通）
  ③ 要通的是标准业务，还是某家私有菜单？
  ④ 是否做过 IOP / 同系统联调？密钥与编号规划是否一致？
```

三句话记牢：

| 层 | 回答的问题 | 典型落点 |
|----|------------|----------|
| **频谱与监管** | 数字化还能否塞进现有信道规划？ | 12.5 kHz、执照、邻道干扰预期 |
| **公开空口标准** | 不同实现能否互通「标准业务」？ | ETSI TS 102 361 系列、SFID + FLCO |
| **产品与工程** | 这批货、这个系统、这场应急，实际通不通？ | Tier、厂商扩展、IOP、写频与编号 |

模拟时代「拧到同一频点」常常就够了；数字时代「拧到同一频点」只是门票，**标准与配置才是门票上的条码**。

## 3. 白话术语表

| 术语 | 白话 | 现场你会碰到 |
|------|------|----------------|
| **模拟对讲 / Analog FM** | 语音连续波形直接调到载波上（常见窄带 FM） | 「老模拟机」「亚音 CTCSS」「模拟中继」 |
| **数字化** | 先把语音变成比特，再按规则装进载波 | 声码器、FEC、数字静噪、「断崖式」无声 |
| **公开标准 Open standard** | 规范公开，多家可按同一份文档实现 | 「符合 ETSI」「TS 102 361」 |
| **私有 / 专有协议 Proprietary** | 一家说了算，跨厂默认不通 | 「只能配我们家调度」「私有加密套件」 |
| **ETSI** | 欧洲电信标准化协会；DMR 规范的发布方 | 招标书「ETSI DMR」 |
| **TS 102 361** | DMR 技术规范系列（空口 / 语音 / 数据 / 集群等分册） | Part 1–4；资料库 PDF |
| **TR 102 398** | 系统设计总览类技术报告（帮助理解「为什么这样设计」） | `00-入门/TR102398_*.pdf` |
| **互操作 Interoperability (IOP)** | 不同厂商实现能否互通约定业务 | IOP 认证、联调报告、「跨厂组呼」 |
| **Tier I / II / III** | 标准里划分的三类产品形态（免执照直通 / 执照常规 / 执照集群） | 标书「Tier II」「数字集群 Tier III」 |
| **常规 Conventional** | 信道固定分配，用户选信道/组；无「自动派信道」的集群控制器 | 多数中小专网、业余中继模型 |
| **集群 Trunking** | 控制器动态分配业务信道 | 大容量、多组、自动漫游等 |
| **SFID** | Standards Feature ID：标准默认特性集（FID=`00000000`） | 标准组呼/个呼等走这里才谈互通 |
| **MFID** | Manufacturer Feature ID：厂商特性集 | 私有功能、扩展信令 |
| **FLCO** | 给定 FID 下的功能码 | 区分组语音 LC / 个语音 LC 等 |
| **6.25 kHz 等效** | 在 12.5 kHz 载波上用 2 时隙，达到「每路约半条 12.5」的效率说法 | 频谱效率宣传、窄带政策对照 |
| **双模 / 多模** | 同一台机能跑模拟与 DMR（有的还能跑其他制式） | 迁移期「先换终端再换基站」 |
| **模数网关** | 在模拟网与数字网之间做桥接 | 分批割接、跨系统临时互通 |

## 4. 模拟世界：其实也有「标准」，只是薄

很多人以为模拟「没有标准」。更准确的说法是：

> 模拟对讲的「互通」主要靠**射频层的宽松约定**（频段、信道间隔、FM 调制习惯、亚音等），而不是靠一份厚厚的「呼叫过程 + 帧格式 + 数据业务」空口白皮书。

### 4.1 模拟为什么曾经够用

- **同频 + 够大的场强** → 喇叭里就能听到人声。  
- **亚音 / DCS** 提供粗粒度的「别听闲杂」——类似极简版选呼，但不是 DMR 那种 24 bit 寻址信封。  
- 设备简单，培训成本低，存量巨大。

### 4.2 模拟在现代专网里的痛点（动机清单）

用「现场对照」写，方便你对领导/客户复述：

| 痛点 | 现场样子 | 数字化后通常怎么缓解（仍依赖标准落地） |
|------|----------|------------------------------------------|
| 频谱效率 | 一条 12.5 kHz 常常只撑一路话 | 2 时隙 TDMA → 同载波两路（中继协调下） |
| 边缘音质 | 越远越沙、噪声渐起 | 纠错 + 数字重建 → 可用区内更「稳」；越出门限则可能突然无声 |
| 业务单一 | 主要靠语音；短信/定位/遥测弱 | 标准数据与补充业务、IP 数据等 |
| 管控弱 | 难精细审计、难优先级/遥晕等 | 信令丰富（仍须按法规与单位制度用） |
| 干扰观感 | 噪声「糊」进语音 | 数字在弱干扰下可纠错；强干扰下可能整帧失败 |

注意：上表是**动机**，不是保证书。覆盖、天线、功率、中继布局、干扰环境，永远比口号重要。

## 5. 若没有公开标准：数字化的「方言灾难」

假设监管只说「你们数字化吧」，却没有公开空口：

1. A 厂用自有调制与帧；B 厂用另一套。  
2. 两边都「数字、清晰、有 GPS」，但**同频点也无法通话**。  
3. 客户被锁死在单一供应链；应急时跨部门借机几乎不可能。  
4. 测试与合规成本上升：每对组合都要私测。

所以标准化要回答的核心问题是：

> **在不大改现有频谱规划的前提下，让多家厂商能实现同一套空口与基本业务，从而使竞争、替换与协作成为可能。**

DMR 的设计意图（结合 TR / 协会材料的常见表述）可以记成四根柱子：

1. **频谱柱**：落在现有陆地移动频段与 **12.5 kHz** 习惯上；追求 **6.25 kHz 等效**效率。  
2. **技术柱**：常规/集群主路径用 **2 时隙 TDMA + 4FSK**（约 4800 符号/秒、9.6 kbit/s 量级——细节第 4、10、15 课再钉）。  
3. **业务柱**：语音、数据、补充业务、集群过程写进公开分册。  
4. **边界柱**：标准特性与厂商特性分开（SFID / MFID），避免「私货冒充标准互通」。

## 6. 「标准化」具体标准化了什么？

用一张「菜单」看，避免把标准想成一本魔法书。

### 6.1 标准主要钉死的

| 类别 | 例子 | 你得到什么 |
|------|------|------------|
| 空口物理与帧直觉 | 12.5 kHz 载波、时隙约 **30 ms**、突发结构等 | 不同实现能「对上拍」 |
| 调制与比特装载 | 4FSK 等 | 解调器知道怎么卸 |
| 寻址与呼叫类型 | 24 bit 地址、组呼/个呼等 | 第 7 课的「信封」有统一写法 |
| 标准语音/通用业务 | Part 2 过程 | 跨厂组呼/个呼等有共同剧本 |
| 数据协议 | Part 3 | 短数据等有共同剧本 |
| 集群协议 | Part 4 | Tier III 有共同剧本 |
| 特性集规则 | Annex H：SFID / MFID | 区分「该互通」与「可不互通」 |

### 6.2 标准并不自动保证的

| 类别 | 例子 | 现场含义 |
|------|------|----------|
| 跨 Tier 互通 | Tier II 终端 ↔ Tier III 系统 | 规范写明三层产品**独立工作、跨层不保证互通** |
| 厂商私有功能 | 某家独有菜单、私有加密方案、私有调度特性 | 看 MFID / 产品说明书；别写进「必须跨厂」的标书却不验收 |
| 编号与系统规划 | 组号、色码、时隙、频率、漫游策略 | 标准不管你单位怎么编号；规划错了照样不通 |
| 射频工程 | 站址、合路、干扰协调 | 标准再完美也救不了坏工程 |
| 「一定比模拟听得更远」 | 覆盖对比依赖环境与指标定义 | 常见是边缘音质更稳；不是无条件距离翻倍 |

### 6.3 一句现场口诀

> **标准 = 共同语言的词典与语法；工程配置 = 你们约好说哪几个词；私有功能 = 某家方言俚语。**

## 7. 现场对照：标准化落到你桌上的六张表

### 7.1 招标 / 选型

| 你会看到的词 | 建议你追问 |
|--------------|------------|
| 「支持 DMR」 | 哪一 **Tier**？常规还是集群？声称符合哪几册 TS？ |
| 「完全兼容某某品牌」 | 兼容的是**标准业务**还是**私有扩展**？有无 IOP / 联调报告？ |
| 「模拟兼容」 | 双模终端？信道级模数可配？还是仅网关？迁移窗口怎么切？ |
| 「加密」 | 标准可选能力 vs 厂商方案？密钥管理是否跨厂？法规是否允许？ |

### 7.2 写频与系统参数

标准化让「参数名」开始像同一种语言：色码、时隙、Radio ID、Talkgroup、联系人类型……  
但**填什么数字**仍是你们的规划。标准不会替你生成频率表。

### 7.3 排障口令升级

| 旧口令（模拟思维） | 新口令（标准思维） |
|--------------------|--------------------|
| 「频点对了吗？」 | 「频点、色码、时隙、Tier/模式、呼叫类型、SFID 业务还是私有功能？」 |
| 「换台机试试」 | 「是同标准实现吗？还是私有功能依赖？」 |
| 「数字抗干扰强所以不该断」 | 「是弱信号纠错区，还是已经低于可解调门限的断崖？」 |

### 7.4 跨单位联动

公开标准是**必要条件**，不是充分条件。还要：同一套编号约定或网关翻译、允许的业务集合、可能的密钥策略、训练与纪律。

### 7.5 迁移项目经理视角

常见平滑路径（厂商文档里反复出现的思路）：

1. **先发双模终端**：日常仍走模拟信道，数字信道试点；  
2. **站点分批数字中继**：覆盖与容量先在试点区翻倍（两时隙）；  
3. **网关维持过渡期话音桥**；  
4. **再关模拟**，必要时再升 Tier III。

标准的价值在这里很具体：**终端与基础设施可以来自不同供应商候选清单**，而不必从第一天起绑死一家。

### 7.6 和「其他数字制式」的边界

世界上还有 TETRA、P25、NXDN、dPMR、国内 PDT 等。它们**互不兼容**。  
「都是数字」≠「能通话」。标准化是**在某一种制式内部**解决互通；制式之间仍要网关或根本不通。本课聚焦 DMR 这一支。
