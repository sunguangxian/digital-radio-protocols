# DMR 第 20 课：Colour Code——为什么 DMR 还需要一个“数字色码”？

今天接着第 19 课的 SYNC 往下走。SYNC 解决的是：

> “我在哪里？这个 Burst 大概是什么类型？”

但找到一个合法 DMR Burst 后，还有一个问题：

> “这个 DMR 信号是不是我这个系统的？”

这就是 **Colour Code（CC）** 要解决的问题。

## 1. Colour Code 是什么

Colour Code 是 DMR 中的 4 bit 系统识别字段，因此取值范围为：

[
0 sim 15
]

也就是：

```text
0000 → CC0
0001 → CC1
0010 → CC2
...
1111 → CC15
```

它的主要作用，是帮助接收机区分同频或覆盖重叠的 DMR 系统。

例如：

```text
系统 A
452.500 MHz
CC = 1

系统 B
452.500 MHz
CC = 5
```

仅仅知道频率并不足以区分系统，因此接收端还需要检查 Colour Code。

## 2. CC、TS、TG 分别解决什么问题

可以把接收过程理解为：

```text
RF Frequency
     ↓
4FSK Demod
     ↓
SYNC
     ↓
“这是一个合法 DMR Burst”
     ↓
Colour Code
     ↓
“是不是我的系统？”
     ↓
TS1 / TS2
     ↓
LC / Destination ID
     ↓
“这次业务是不是给我的？”
```

例如：

```text
Frequency = 452.500 MHz
CC = 1

TS1 → TG100
TS2 → TG200
```

这里分别回答：

```text
452.500 MHz → 哪个射频信道？
CC1         → 哪个同频系统？
TS1         → 哪个 TDMA 逻辑信道？
TG100       → 业务发给谁？
```

所以：

> **CC 不是 Talk Group，也不是 Radio ID，更不是时隙号。**

## 3. 为什么很多人把 CC 类比成“数字亚音”

因为它和模拟 CTCSS 在使用体验上有些相似：

```text
模拟：
频率正确
   +
CTCSS正确
   ↓
打开静噪
```

DMR 中则类似：

```text
频率正确
   +
Colour Code正确
   ↓
继续接受这个系统的业务
```

但物理实现完全不同。

CTCSS 是叠加在模拟语音中的低频音调，而 Colour Code 是 DMR Burst 中真实编码进去的数字协议字段。

因此：

```text
CTCSS ≠ Colour Code
```

只是用途上有一定相似性。

## 4. Data Burst 中 CC 放在哪里

对于一般 Data/Signalling Burst，可以看到这样的中心结构：

```text
98 bit       10 bit      48 bit      10 bit       98 bit
 Data      Slot Type    Data SYNC   Slot Type      Data
```

前后两个 10 bit 合起来就是 20 bit Slot Type。

Slot Type 的原始信息包含：

```text
┌──────────────┬──────────────┐
│ Colour Code  │  Data Type   │
│    4 bit     │    4 bit     │
└──────────────┴──────────────┘
        8 bit
```

然后通过 Golay(20,8) 编码得到 20 bit，并拆成 10 bit + 10 bit 放在 SYNC 两侧。

因此接收链路更接近：

```text
264 bit Burst
      ↓
找到 Data SYNC
      ↓
取左右 Slot Type
      ↓
10 bit + 10 bit
      ↓
Golay Decode
      ↓
8 bit 信息
      ↓
CC + Data Type
```

## 5. Voice Burst 中 CC 又在哪里

Voice A 的中央主要用于 Voice SYNC：

```text
108 bit Voice
      +
48 bit Voice SYNC
      +
108 bit Voice
```

而 Voice B～F 的中央位置用于 Embedded Signalling。

其中 EMB 会携带 Colour Code 等控制信息，因此持续语音期间也可以获得 CC。

可以这样记：

```text
Data Burst
    ↓
Slot Type
    ↓
Colour Code


Voice B~F
    ↓
EMB
    ↓
Colour Code
```

## 6. CC 和 LCSS 不要混

Voice EMB 中 CC 与 LCSS 靠得很近，但职责完全不同：

```text
CC
↓
“是不是我的系统？”


LCSS
↓
“这一片 Embedded LC
 是 First / Continue / Last？”
```

例如收到 Voice C：

```text
EMB
│
├── CC = 1
│
└── LCSS = Continue
```

含义是：

> 这是 CC1 系统的语音 Burst，同时这里携带的是某条 Embedded LC 的中间分片。

## 7. CC 和 TS1/TS2 没有绑定关系

典型中继：

```text
           Repeater
       452.500 MHz
           CC = 1
             │
       ┌─────┴─────┐
       ↓           ↓
      TS1         TS2
       │           │
     TG100       TG200
```

通常两个时隙属于同一个系统，因此使用同一个 Colour Code。

## 8. 为什么 Colour Code 只有 4 bit

4 bit 只有：

[
2^4 = 16
]

显然不可能唯一标识全球所有 DMR 系统。

因为它的目标从来不是全球唯一标识，而是：

> **帮助区分局部射频环境中可能互相影响的同频系统。**

真正用于识别用户、组和业务对象的，仍然是：

```text
Source ID
Destination ID
LC
CSBK
...
```

## 9. CC 能不能消除同频干扰

不能。

假设：

```text
站 A：
452.500 MHz
CC1

站 B：
452.500 MHz
CC5
```

如果两个信号同时到达接收机：

```text
4FSK(A)
   +
4FSK(B)
   ↓
RF 同频碰撞
```

可能导致：

```text
Symbol Error
↓
SYNC失败
↓
Slot Type失败
↓
Golay无法纠正
↓
连CC都解不出来
```

Colour Code 无法把两个已经叠加的 RF 信号分离。

它只能在信号已经能正确解调以后，帮助协议层判断：

```text
RX CC != 配置 CC
        ↓
      DROP
```

## 10. 为什么 RSSI 很强却仍然不开音

例如：

```text
RSSI = -65 dBm
4FSK Demod OK
SYNC OK
RX CC = 5

但：
CFG CC = 1
```

那么接收机仍可能直接丢弃业务。

所以现场完全可能出现：

```text
RSSI：满格
SYNC：正常
Audio：不开
```

此时应该检查：

```text
RX SYNC : BS_VOICE
RX CC   : 5
CFG CC  : 1

DROP: CC mismatch
```

而不是第一时间怀疑 AMBE、DAC 或 Audio PA。

## 11. 嵌入式接收代码思路

Data Burst：

```c
bool dmr_process_data_burst(const uint8_t *burst)
{
    dmr_slot_type_t slot_type;

    if (!dmr_check_data_sync(burst))
        return false;

    if (!dmr_decode_slot_type(burst, &slot_type))
        return false;

    if (slot_type.colour_code != g_channel.colour_code)
        return false;

    return dmr_decode_data_by_type(
        burst,
        slot_type.data_type);
}
```

逻辑顺序：

```text
SYNC
 ↓
Slot Type FEC
 ↓
Colour Code
 ↓
Data Type
 ↓
对应业务解码
```

Voice B～F：

```text
EMB Decode
 ↓
Colour Code
 ↓
LCSS
 ↓
Embedded LC Fragment
```

建议日志：

```text
[DMR RX]
SYNC = BS_DATA
CC   = 1
DT   = DATA_HEADER
```

或者：

```text
[DMR RX]
VOICE = C
CC    = 1
LCSS  = CONTINUE
```

## 今天记住这几点

1. Colour Code 是 4 bit，范围 0～15。
2. CC 主要用于区分同频或覆盖重叠的 DMR 系统。
3. CC 在使用体验上类似模拟 CTCSS，但本质上是数字协议字段。
4. 对 Data Burst，CC 位于 Slot Type；对 Voice B～F，可从 EMB 获得 CC。
5. 不要混淆：

```text
CC → 哪个系统
TS → 哪个时隙
TG → 发给谁
```

6. CC 不能消除 RF 同频碰撞，只能在成功解调后帮助协议层筛选。

## 自测题

### 1. 两个中继都是 452.500 MHz，一个 CC1，一个 CC5，同时发射时，接收机能不能靠 CC 把两个 RF 信号无损分离？

不能。两个信号如果已经在 RF 层发生严重同频碰撞，可能连 SYNC 和 CC 都无法正确解出来。

### 2. CC1、TS1、TG100 分别表示什么？

```text
CC1   → 同频系统识别
TS1   → TDMA 逻辑信道
TG100 → 组呼目标
```

### 3. 为什么 RSSI 很强，却仍然可能不开音？

因为 RSSI 只表示 RF 能量。后续仍可能出现：

```text
CC mismatch
TS mismatch
TG mismatch
LC错误
```

其中任何一个条件都可能使业务被丢弃。
