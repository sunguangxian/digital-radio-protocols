## 5. 外壳长什么样：Full LC 与 CSBK 里的门牌

引用资料库：`01-空中接口/CSBK与LC字段详表.md`、`02-语音业务/语音业务字段速览.md`。学习摘要，冲突以 ETSI 原文为准。

### 5.1 Full LC 外壳（语音头 / 终止 / 嵌入路径）

```text
Octet0:  PF(1) | Reserved(1) | FLCO(6)
Octet1:  FID(8)          ← 门牌在这里
Octet2–8: Full LC Data   ← 地址、Service Options 等（随 FLCO 变）
+ CRC（头/终止路径与嵌入路径长度不同，阶段 C 再拆）
```

标准语音业务公共前缀直觉：

> **PF=0，Reserved=0，FLCO=表内值，FID=`00000000`（SFID）。**

### 5.2 CSBK 外壳

```text
Octet0:  LB(1) | PF(1) | CSBKO(6)
Octet1:  FID(8)          ← 门牌同样在这里
Octet2–9: CSBK Data (64)
+ CRC-16
```

单块 CSBK 时 LB 通常为 `1`。标准控制信令同样默认 **FID=SFID**。

### 5.3 规范硬规则（请背下来）

来自 Part2 **clause 4.3 Feature interoperability**（精神一致，措辞以 PDF 为准）：

1. **FID** 标识特性集；**FLCO** 标识该集内的空中功能。  
2. 为确保空口互操作：**本文件已标准化且设备已提供的特性，只能通过默认 SFID + 对应 FLCO 访问**。  
3. **未**在本文件标准化的特性，只能通过 **MFID** 提供。  
4. 被**个呼**到却不支持某标准 Opcode 时，应使用 **FNS** 类信令礼貌拒绝（所有 MS 都应实现 FNS 相关能力；细节见 Part2）。

用大白话再说一遍：

> **标准功能不许偷偷换门牌；私有功能不许冒充标准门牌。**

## 6. SFID 下的功能码地图（与业务对照）

下面只列**标准馆（SFID）**里最常用的码，方便和第 13 课菜单对上。完整表见 `语音业务字段速览.md`。

### 6.1 常见 FLCO（Table B.1 学习摘要）

| FLCO | 别名 | 你在业务里认识它为 |
|------|------|-------------------|
| `000000` | Grp_V_Ch_Usr | 组呼（及全呼/广播等用组地址+Service Options 表达的形态） |
| `000011` | UU_V_Ch_Usr | 个呼语音信道用户 |
| `000100`…`000111` | Talker Alias 头/块 | 主叫别名（补充能力，嵌入超帧） |
| `001000` | GPS_Info | 嵌入 GPS 信息 |
| `110000` | TD_LC | **Part3** 数据终止 LC（别和语音 Terminator 混淆） |

### 6.2 常见 CSBKO（Table B.2 学习摘要）

| CSBKO | 别名 | 场景 |
|-------|------|------|
| `000100` | UU_V_Req | 个呼语音业务请求（OACSU 存在性检查） |
| `000101` | UU_Ans_Rsp | 个呼应答 |
| `100110` | NACK_Rsp | 否定应答（也可承载 FNS 等场景） |
| `111000` | BS_Dwn_Act | 唤醒/激活基站出站 |
| `111101` | Pre_CSBK | 前导（扫描/节电相关） |

### 6.3 和「业务种类」怎么叠

| 用户要的 | 空口门牌直觉 |
|----------|--------------|
| 标准组呼说话 | SFID + FLCO=`000000` + 组地址 |
| 标准个呼说话 | SFID + FLCO=`000011`；OACSU 时先 CSBKO=`000100/000101` |
| 标准主叫别名 | SFID + Talker Alias 系列 FLCO |
| 厂商「一键巡更语音」 | **MFID** + 厂商自定 Opcode（对端无该 MFID 则不通） |
| 标准短数据/PDP | Part3：标准化数据走规定头；非标准化走第二数据头里的 **MFID** 路径 |

Part3 提醒（本课不展开字段）：数据互操作同样有「标准路径 vs MFID」二分；标准化分组数据不得靠私有 FID「另起炉灶」来冒充标准。

## 7. 完整例子（请跟着走一遍）

### 例子 A · 标准组呼（应互通）

场景：台 A 向组 `000001` 发起组呼；台 B、C 同组。

1. 空口 Voice LC Header / 嵌入 LC：`FID=0x00`，`FLCO=000000`（Grp_V_Ch_Usr）。  
2. Service Options + Group address + Source address。  
3. 任意遵守 Part2 的他厂终端：认 SFID + 该 FLCO → 进组听。  
4. **结论**：这是 IOP 意义上「该通」的典型路径。

### 例子 B · 厂商私有特性（不通是预期）

场景：A 厂终端在语音中嵌入「私有导航提示 LC」。

1. 抓包见 `FID=0x10`（示例，落在 MFID 区；真实值以厂商申请为准），FLCO 某值。  
2. B 厂终端无此 MFID 解释逻辑 → **忽略**该 LC。  
3. 组呼语音本身若仍用 SFID+`000000`，语音可能仍通；**只有私有附加功能丢了**。  
4. **结论**：不要把「私有功能丢了」写成「DMR 不互通」；要写成「私有特性未纳入互操作范围」。

### 例子 C · 错误示范：标准个呼挂 MFID（破坏互操作）

场景：研发把 UU_V_Ch_Usr 改成 `FID=自家MFID`，FLCO 仍写 `000011`，「觉得更安全」。

1. 对端按规范只在 **SFID** 下认个呼 → 不认你的门牌。  
2. 联调失败；IOP 也过不了。  
3. **结论**：标准化特性**必须**留在 SFID；安全/差异化应走真正的私有特性或上层策略，而不是挪用标准 Opcode 换门牌。

### 例子 D · FNS（标准门牌，但不支持该功能）

场景：台 A 用 SFID + 某标准 CSBKO 个呼台 B；B 未实现该可选标准特性。

1. B 识别门牌是 SFID，但 Opcode 自己不做。  
2. B 回 FNS / 相关 NACK 类信令（礼貌拒绝）。  
3. **结论**：这是「标准馆里缺货」，不是「进错商场」。排障应查能力清单/选配，而不是先拧天线。

### 例子 E · 射频伪装成互操作故障（对照弱项）

场景：FID/FLCO 全对，但场强极差、误码高。

1. 终端表现：时通时断、头 LC 解不出 → 有人误判「厂家不互通」。  
2. 真因可能在 L1：频率偏移、天线、干扰、越区。  
3. **结论**：互操作课也要会分流——**先证明比特稳定，再吵门牌**。频谱直觉见加餐文。
