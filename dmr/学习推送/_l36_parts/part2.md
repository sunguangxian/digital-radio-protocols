## 5. 固定计划：一条公式算到底（Annex C.1.1.2）

### 5.1 公式原样（只有加减乘除）

规范 Annex C.1.1.2 给的定义（Annex C 是**资料性附录**，但它就是 CHAN 换算的唯一出处）：

```text
fMS_Tx = fbase + ((CHAN − 1) × (fseparation / 1 000))      [MHz]
fMS_Rx = fMS_Tx ± fduplexsplit                              [MHz]
fduplexsplit = 0 MHz … 50 MHz，步长 2,5 kHz
```

| 符号 | 白话 | 单位 | 由哪张表定 |
|------|------|------|-----------|
| `fMS_Tx` | 手台发射频率 | MHz | 算出来 |
| `fMS_Rx` | 手台接收频率 | MHz | 算出来 |
| `fbase` | 这个频段里 **CHAN = 1** 对应的最低频率 | MHz | Table C.4（BAND） |
| `fseparation` | 相邻信道间隔 | **kHz**（所以公式里要 ÷1 000 变成 MHz） | Table C.1（SEP） |
| `fduplexsplit` | **MS 发 − MS 收**（可正可负） | MHz | Table C.3（DUPLEX_SPLIT）定大小，Table C.2（TXRX_SPLIT）定正负 |
| `CHAN` | 逻辑信道号 1…4094 | — | Grant 里带来 |

**三个最常错的地方**：

1. **`(CHAN − 1)`**：CHAN 1 就是 fbase 本身。忘了减 1，所有频点整体偏一个间隔。  
2. **`fseparation / 1 000`**：间隔表里是 kHz，公式里是 MHz。12,5 kHz 要写成 0.0125 MHz。  
3. **`±`**：双工分裂的正负不是随便选的，由 TXRX_SPLIT 那 1 bit 决定（§5.2）。

> 规范里的小数点用逗号（欧洲写法）：`6,25` 就是 6.25，`2,5 kHz` 就是 2.5 kHz。读 PDF 时别被吓到。

### 5.2 四张参数表

**Table C.1 — 信道间隔 SEP（4 bit）**

| SEP | 间隔 | 白话 |
|-----|------|------|
| `0000₂` | 5 kHz | |
| `0001₂` | 6,25 kHz | 极窄车道 |
| `0010₂` | 10 kHz | |
| `0011₂` | **12,5 kHz** | **DMR 最常见** |
| `0100₂` | 15 kHz | |
| `0101₂` | 20 kHz | |
| `0110₂` | 25 kHz | 老宽带模拟常见 |
| `0111₂` | 30 kHz | |
| `1xxx₂` | 保留 | |

为什么 DMR 要支持这么多种间隔？Annex C 开头说得很直白：**DMR 支持把现有模拟信道改造（re-farm）过来用**，老频点是什么间隔就得能描述什么间隔。注意：**SEP 只决定「号码怎么排」**，DMR 信号本身仍然是 12.5 kHz 车道里的 4FSK（第 10 课：6.25 kHz 等效靠的是 TDMA 双时隙，不是把车道切窄）。

**Table C.2 — 收发高低 TXRX_SPLIT（1 bit）**

| TXRX_SPLIT | 含义 | 于是 |
|------------|------|------|
| `0₂` | 手台发 **高于** 手台收 | `fMS_Rx = fMS_Tx − 分裂` |
| `1₂` | 手台发 **低于** 手台收 | `fMS_Rx = fMS_Tx + 分裂` |

**Table C.3 — 双工分裂 DUPLEX_SPLIT（15 bit）**

规则：**分裂（kHz）= 这个 15 bit 无符号数 × 2,5**。规范只列了几个代表点，中间用省略号——我们用规则反推核对了一遍（全部吻合）：

| DUPLEX_SPLIT | 十进制 | × 2,5 kHz | 分裂 |
|--------------|--------|-----------|------|
| `000 0000 0000 0000₂` | 0 | 0 | 0（同频，单频中继/直通类场景） |
| `000 0000 0000 0001₂` | 1 | 2,5 kHz | 最小步 |
| `000 0111 0011 0000₂` | 1 840 | 4 600 kHz | **4,6 MHz** |
| `000 1100 1000 0000₂` | 3 200 | 8 000 kHz | **8 MHz** |
| `000 1111 1010 0000₂` | 4 000 | 10 000 kHz | **10 MHz** |
| `100 0110 0101 0000₂` | 18 000 | 45 000 kHz | **45 MHz** |

15 bit 最大能写 32 767 × 2,5 = 81 917,5 kHz，但正文限定分裂只用 **0…50 MHz**，也就是这个数最大到 20 000。

**Table C.4 — 频段 BAND → fbase（7 bit）**

规律：**fbase（MHz）= BAND × 10**。规范代表点：

| BAND | 十进制 | fbase |
|------|--------|-------|
| `000 0011₂` | 3 | 30 MHz |
| `000 0101₂` | 5 | 50 MHz |
| `010 1101₂` | 45 | **450 MHz** |
| `101 0000₂` | 80 | 800 MHz |
| `110 0100₂` | 100 | 1 000 MHz |

另外 Annex C.1.1.1 说 DMR 标称载波可以落在 **50 MHz … 999 MHz** 的任何频段里，国家主管部门还可以对具体频点加限制（比如功率）。

### 5.3 这些参数住在哪？——不在空口上

这是固定计划最关键、也最反直觉的一点：

> **SEP、TXRX_SPLIT、DUPLEX_SPLIT、BAND 这四个参数，Grant 里一个都不带。**它们是物理层参数，**在个性化（写频）或出厂时**写进设备。空口上永远只跑 12 bit 的 CHAN。

所以「固定计划」的意思是：**手台和网络事先约定好了同一组 (fbase, 间隔, 分裂, 高低)**，之后只报号码。约定不一致，空口上的号码没错，手台算出来的频率却错了——**而且分析仪上什么异常都看不出来**，因为分析仪看到的也只是号码。

### 5.4 算三笔账（教学虚构参数，不对应任何真实网络）

**参数**：BAND = 45（fbase = 450.000 MHz），SEP = `0011₂`（12,5 kHz），DUPLEX_SPLIT = `000 1111 1010 0000₂`（10 MHz），TXRX_SPLIT = `1₂`（手台发低于收）。

**账 1：Grant 说 CHAN = 161，手台去哪？**

```text
fMS_Tx = 450.000 + (161 − 1) × 0.0125
       = 450.000 + 160 × 0.0125
       = 450.000 + 2.000
       = 452.000 MHz
TXRX_SPLIT = 1 → 手台发低于收 → fMS_Rx = 452.000 + 10 = 462.000 MHz
```

手台：**发 452.000、收 462.000**。基站反过来：**收 452.000、发 462.000**。

**账 2：倒着算——频点表里有一对 452.3375 / 462.3375，它是几号？**

```text
CHAN = (452.3375 − 450.000) / 0.0125 + 1
     = 2.3375 / 0.0125 + 1
     = 187 + 1
     = 188
```

如果除出来**不是整数**（比如 452.3400），说明这个频点**不在这个固定计划的网格上**——固定计划描述不了它，要么换灵活计划，要么用绝对频率（§6、§7）。

**账 3：间隔写错会怎样？**

假设手台被误写成 SEP = `0001₂`（6,25 kHz），网络仍按 12,5 kHz。同样 CHAN = 161：

```text
手台算：450.000 + 160 × 0.00625 = 451.000 MHz
网络算：452.000 MHz
相差  ：1.000 MHz
```

CHAN = 2 时只差 6.25 kHz（可能还勉强能收到一点），CHAN = 161 时差 1 MHz（完全不在一条车道上）。**误差 = (CHAN − 1) × 间隔之差，号码越大偏得越远**。现场症状就是：「**低号信道偶尔还行，高号信道一个都不通**」——这是固定计划参数错的典型指纹。

### 5.5 4094 个号码能覆盖多宽？

```text
12,5 kHz 间隔：(4094 − 1) × 12.5 kHz = 51.1625 MHz
6,25 kHz 间隔：(4094 − 1) × 6.25 kHz = 25.58125 MHz
```

也就是说，一个固定计划最多能把 **约 51 MHz（12,5 kHz 间隔）**的频谱逐个编号。实际网络通常只用其中一小段：比如上面的例子，fbase = 450 时 CHAN 4094 会算到 501.1625 MHz——数学上合法，但真实网络根本不会用到那里。**号码空间够大，不代表每个号码都有频率可用**；哪些号码真的有载频，由网络规划决定。

## 6. 灵活计划：逐行写的门牌表（Annex C.1.1.3）

### 6.1 是什么

固定计划要求所有频点在**一条等距网格**上。现实中的频率批复往往不是这样：东一个 451.0125，西一个 456.3375，再来一个 458.7000……它们之间没有统一的 fbase 和间隔。

灵活计划就是：**每个 CHAN 单独写一行**。

| CHAN | SDU 编码 | 手台发 | 手台收 | Colour Code |
|------|----------|--------|--------|-------------|
| 1 | `0000 0000 0001₂` | （逐行填） | （逐行填） | 值（默认 `0000₂`） |
| … | … | … | … | … |
| 4094 | `1111 1111 1110₂` | （逐行填） | （逐行填） | 值 |

规范 Table C.6 就是这样一张**空白模板**——没有公式，内容全由网络规划和写频决定。

### 6.2 固定 vs 灵活：怎么选

| 维度 | 固定计划 | 灵活计划 |
|------|----------|----------|
| 手台里存什么 | 4 个参数（fbase / 间隔 / 分裂 / 高低） | 每个用到的 CHAN 一行 (Tx, Rx, CC) |
| 能描述的频点 | 只能是等距网格上的点 | 任意频点 |
| 加一台新载频 | 若新频点在网格上：**手台不用改** | **每台手台都要加一行**（或用绝对频率/广播绕过） |
| 写错的后果 | 高号信道整体偏移（§5.4 指纹） | 只有写错的那一行错 |
| 适合 | 大块连续频谱、新建网 | 零散批复、从模拟改造的网 |

**一句话**：固定计划「省写频、怕不规整」；灵活计划「能装任何频点、怕漏行」。

### 6.3 一个开源实现观察到的现象（社区观察，不是标准）

开源 Tier III 控制器 qradiolink/dmrtc 的说明文档列了它支持「固定和灵活两种猎站信道计划」和「绝对信道 Grant」，并记录了一个实测现象：**绝对信道 Grant 只在手台设成按灵活计划猎站时才可用；手台设成固定计划时，绝对 Grant 不工作**（作者自己也写了「可能是手台的限制」）。这**不是 ETSI 的规定**，只是某些机型的行为——但它提醒你：**「规范允许」不等于「每台手台都实现了」**。上线绝对频率前，先拿目标机型实测（§16 第 6 条链接）。

## 7. 绝对频率：4095 和那块「小票背面」

### 7.1 什么时候用

当网络想把手台派到一个**手台门牌表里没有**的频率上——新加的载频还没写进老手台、临时调来的频点、邻网借用的信道——就把信道号写成 **4095（0xFFF）**，再附上一块**续块**，里面直接写频率。

### 7.2 MBC 是怎么拼起来的（Part 1 的骨架，一段话）

普通 CSBK 是一块 96 bit（80 bit 信息 + 16 bit CRC）。装不下时用 **MBC（Multi Block Control，多块控制）**：一个**头块** + 0 到 2 个**中间块** + 一个**末块**，在同一个时隙里**连续发**。

| 块 | Slot Type 里的 Data Type | LB | CRC |
|----|--------------------------|-----|-----|
| 头块 | **MBC Header**（`0100₂`） | `0` | 只算头块自己 |
| 末块 | **MBC Continuation**（`0101₂`） | `1` | 算**除头块外**的所有块 |

普通单块 CSBK 的 Data Type 是 `0011₂`。所以分析仪上**单块 Grant 是 Data Type = CSBK、LB = 1**；**绝对 Grant 的头块是 Data Type = MBC Header、LB = 0，后面紧跟一块 MBC Continuation、LB = 1**。绝对频率的场景只用「头块 + 末块」两块。

### 7.3 续块长什么样：CG_AP（Table 7.16）

| 字段 | 位数 | 值 / 含义 |
|------|------|-----------|
| LB | 1 | `1`（它就是末块） |
| PF | 1 | 保护标志 |
| CSBKO | 6 | **与头块相同**（TV_GRANT 头块是 49，续块也写 49） |
| Reserved | 4 | `0000₂` |
| **Colour Code** | 4 | **目标信道用的色码** |
| **Cdeftype** | 4 | CdefParms 怎么解读；目前只定义了 `0000₂` |
| Reserved | 2 | `00₂` |
| **CdefParms** | 58 | 频率本体（下表） |
| 合计 | **80** | 正好一块的信息位 |

### 7.4 CdefParms（Cdeftype = `0000₂`，Table 7.103）

| 子字段 | 位数 | 别名 | 含义 |
|--------|------|------|------|
| Logical Physical Channel Number | 12 | **CHAN** | 同时宣告：这对频率对应的逻辑号 |
| 手台发 · 整数 MHz | 10 | **TXMHz** | 0…1023，有用的是 50…999 |
| 手台发 · 小数部分 | 13 | **TXKHz** | 以 **125 Hz** 为一步，0…7999 |
| 手台收 · 整数 MHz | 10 | **RXMHz** | 同上 |
| 手台收 · 小数部分 | 13 | **RXKHz** | 同上 |
| 合计 | **58** | | |

Cdeftype = `0001₂` 到 `1111₂`：58 bit 全部**保留**，目前没有定义。

> **读 PDF 时的一个小错别字**：Table 7.103 里 RXMHz 那一行的备注写成了「Absolute **transmitter** frequency - integer MHz」，这是规范自己的笔误。看**别名 RXMHz** 和左边的字段名「Absolute **receiver** frequency」，它是**接收**频率。

### 7.5 换算公式（Annex C.1.1.4 / Table C.7）

```text
手台发（MHz）= TXMHz + (TXKHz × 125) / 1 000 000
手台收（MHz）= RXMHz + (RXKHz × 125) / 1 000 000
```

白话：**整数部分直接写 MHz；小数部分数「有几个 125 Hz」**。

| 例 | 整数 MHz | 小数部分 | 小数 ÷ 125 Hz | 写成 |
|----|----------|----------|---------------|------|
| 50.000000 MHz | 50 | 0 Hz | 0 | TXMHz = 50，TXKHz = 0 |
| 451.0125 MHz | 451 | 12 500 Hz | 100 | 451，100 |
| 451.00625 MHz | 451 | 6 250 Hz | 50 | 451，50 |
| 352.5 MHz | 352 | 500 000 Hz | 4 000 | 352，4000 |
| 999.999875 MHz | 999 | 999 875 Hz | 7 999 | 999，7999（规范 Table C.7 的上限例） |

**为什么是 125 Hz？** 因为它能整除所有常见间隔和分裂步长：2,5 kHz ÷ 125 = 20，5 kHz ÷ 125 = 40，6,25 kHz ÷ 125 = 50，12,5 kHz ÷ 125 = 100。也就是说**任何 SEP 表里的网格点都能被绝对频率精确写出来**，不会有舍入误差。13 bit 最多 8191，用到 7999 正好覆盖「0 到不满 1 MHz」。

**再强调一次弱项**：125 Hz 是**刻度**（尺子最细能读到多细），不是带宽，也不是间隔。车道还是 12.5 kHz 宽。

### 7.6 四种续块，一个模子

| 续块 | 表 | 跟在谁后面 | 和 CG_AP 的区别 |
|------|-----|-----------|----------------|
| **CG_AP** | 7.16 | 各种 Grant（含 P_GRANT、P_CLEAR）信道号 = 4095 | — |
| **MV_AP** | 7.18 | **C_MOVE** 信道号 = 4095 | 格式相同 |
| **VN_AP** | 7.72 | C_BCAST **Vote_Now** 的 CH_VOTE = 4095 | 格式相同 |
| **BC_AP** | 7.21 | C_BCAST **Ann_WD_TSCC**（绝对形式）、**Chan_Freq**（必须） | 头部是 **8 bit Reserved**，**没有独立的 Colour Code 字段** |

**记忆法**：「AP」= Absolute Parameters（绝对参数）。前缀告诉你它是谁的背面：CG = Channel Grant，MV = Move，VN = Vote Now，BC = Broadcast。**CSBKO 永远抄头块**，所以看续块的 CSBKO 就知道它是哪张票的背面。

### 7.7 P_GRANT 换信道时：只换号码（和绝对频率）

第 33 课讲过业务信道上的 P_GRANT。规范对它有一句很实用的话：**为了把一个呼叫换到新业务信道而发的 P_GRANT，除了信道号（以及有续块时的绝对频率）以外，其他字段都必须保持 TSCC 上原 Grant 的值。**所以对比两条 Grant 时，只有频率那部分变了，就是「换信道」，不是「新呼叫」。

## 8. 手拆原始字节：一块 CG_AP

> 下面的字节是**按规范字段宽度自行编出来的教学样例**（只含 80 bit 信息位，不含 CRC 和 FEC），已用 Python 正向编码、反向解码各核一遍。

### 8.1 先看头块（TV_GRANT，LB = 0）

```text
31 00 FF F8 00 00 65 00 03 E9
```

| 字节 | 值 | 拆 |
|------|-----|-----|
| Oct0 | `0x31` | `0011 0001`：LB = 0（**MBC 头**），PF = 0，CSBKO = `11 0001₂` = 49 → **TV_GRANT** |
| Oct1 | `0x00` | FID = 0（标准） |
| Oct2–3 | `0xFF F8` | `1111 1111 1111 \| 1 \| 0 \| 0 \| 0`：信道号 = **0xFFF（4095）**，时隙位 = 1（**时隙 2**），Late_Entry = 0，Emergency = 0，Offset = 0 |
| Oct4–6 | `0x00 00 65` | 目标 = 101（组号） |
| Oct7–9 | `0x00 03 E9` | 源 = 1001（主叫） |

看见 Oct0 的最高位是 0、Oct2–3 开头是 `FFF`，就知道：**后面一定还有一块，频率在那里**。

对比：如果这是一张普通单块 TV_GRANT 去 CHAN 161、时隙 1：

```text
B1 00 0A 10 00 00 65 00 03 E9
```

Oct0 = `0xB1`（LB = 1，CSBKO = 49），Oct2–3 = `0x0A 10` → 信道号 `0x0A1` = 161，时隙位 0。**单块和头块的区别就在 Oct0 最高位和那 12 bit。**

### 8.2 再拆续块（CG_AP）

```text
B1 05 00 4B 1C 30 19 39 A0 32
```

**第一步：前两个字节是整字节对齐的，直接读。**

| 字节 | 值 | 拆 |
|------|-----|-----|
| Oct0 | `0xB1` | LB = 1（末块），PF = 0，CSBKO = 49 → 是 **TV_GRANT 的背面** |
| Oct1 | `0x05` | 高 4 位 Reserved = 0，低 4 位 **Colour Code = 5** |

**第二步：从 Oct2 开始字段跨字节，最稳的办法是把剩下 8 个字节展开成 64 bit 再切。**

```text
00       4B       1C       30       19       39       A0       32
00000000 01001011 00011100 00110000 00011001 00111001 10100000 00110010

按宽度切： 4 | 2 | 12 | 10 | 13 | 10 | 13   （共 64）
0000 | 00 | 0001 0010 1100 | 01 1100 0011 | 0 0000 0011 0010 | 01 1100 1101 | 0 0000 0011 0010
```

| 字段 | 二进制 | 十进制 | 意义 |
|------|--------|--------|------|
| Cdeftype | `0000` | 0 | 按 Table 7.103 的唯一定义解读 |
| Reserved | `00` | — | |
| CHAN | `0001 0010 1100` | **300** | 宣告：这对频率是 300 号 |
| TXMHz | `01 1100 0011` | **451** | |
| TXKHz | `0 0000 0011 0010` | **50** | 50 × 125 Hz = 6 250 Hz |
| RXMHz | `01 1100 1101` | **461** | |
| RXKHz | `0 0000 0011 0010` | **50** | 6 250 Hz |

**第三步：换算。**

```text
手台发 = 451 + 50 × 125 / 1 000 000 = 451.00625 MHz
手台收 = 461 + 50 × 125 / 1 000 000 = 461.00625 MHz
色码   = 5
```

**这一条 Grant 的完整意思**：「组 101 的呼叫（主叫 1001），去**手台发 451.00625 / 收 461.00625 MHz** 这对频率的**时隙 2**，那里的色码是 **5**；顺便记一下，这对频率在网络里叫 **300 号**。」

注意 451.00625 落在 **6,25 kHz 网格**上、不在 12,5 kHz 网格上——这正是一个「固定计划（12,5 kHz）描述不了、只能用绝对频率」的典型频点。

### 8.3 拆的时候的三条纪律

1. **先看 Oct0 最高位**：0 = 头块（后面还有），1 = 单块或末块。  
2. **续块 CSBKO 抄头块**：看见续块 CSBKO = 57，就是 C_MOVE 的 MV_AP，不是 Grant。  
3. **从 Oct2 起一律展开成二进制再切**。第 34 课 Reason 跨字节的坑、第 35 课「Oct3 = 0x90」的坑，这里更多：CHAN、TXMHz、TXKHz 全都跨字节。**不要试图「看十六进制猜十进制」**。

## 9. 广播：让大家一起更新门牌表

### 9.1 Chan_Freq：宣告「某号 ↔ 某频率」（6.7.1.6 / Table 7.78）

C_BCAST（CSBKO = 40）的 Announcement_type = `0 0101₂`（**Chan_Freq**）专门干这件事：**把一个逻辑号和一对物理收发频率的关系广播给所有手台**。

- 它**必须**用 MBC：头块 + **BC_AP** 续块。  
- 头块里：Parms1 全 0（保留）；Parms2 = 12 bit 保留 + 12 bit **CH_ADJ**（被宣告的信道号）。  
- 真正的频率在 BC_AP 的 CdefParms 里。

白话：**Grant 的绝对续块是「一次性告诉这一个呼叫」；Chan_Freq 广播是「告诉所有人，以后这个号就是这个频率」**。前者每次呼叫都要多发一块；后者让手台记住这层关系（多久广播一次由网络决定），之后 Grant 就有机会只发单块。

### 9.2 Ann_WD_TSCC：增删猎站列表里的控制信道（6.7.1.1 / Table 7.69）

Announcement_type = `0 0000₂`。用来**增加或撤销**一个广域系统里的 TSCC 频点，手台据此更新它的**短猎站列表**（第 37 课）。

- 逻辑号形式：单块，最多同时宣告 **两个**（BCAST_CH1 / CH2，各配一个色码，各有 1 bit 加/撤标志）；只宣告一个时，另一个写 CHNULL（0）。  
- 绝对形式：MBC + BC_AP，**一次只能宣告一个**。

### 9.3 Adjacent_Site 和 Vote_Now：告诉你邻居的控制信道在哪

- **Adjacent_Site**（`0 0110₂`）：广播邻站 TSCC 的 **CH_ADJ** 和系统识别码高 14 bit。规范说手台怎么用它「不作规定」，但建议：猎站时可以优先试这些号码。单块发。  
- **Vote_Now**（`0 0010₂`）：邀请手台去评估另一个 TSCC，信道号叫 **CH_VOTE**；写 4095 时跟 **VN_AP**。

**这两条加上 C_MOVE、Ann_WD_TSCC，全是「控制信道在几号」**——都要靠本课的门牌表才能变成频率。下一课的猎站，就是拿着这些号码一个个去试。
