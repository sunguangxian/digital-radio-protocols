## 1. 为什么本课重要（动机）

第 33 课我们把 Grant 比作旅馆前台开的**房间小票**：小票上写着「去 161 号房、2 号床（时隙 2）」。第 35 课解决了「前台凭什么信你」。今天解决最后一个看似简单、现场却最容易出事的问题：

> **161 号房，到底在哪一层、哪一间？**

小票上只有「161」这个数字。手台必须自己知道「161 号 = 发 452.000 MHz、收 462.000 MHz」，才能把射频调过去。**这张「房号 → 门牌」对照表不在 Grant 里，而是事先写在手台（和基站）里。**这就是本课的核心矛盾：

- **好处**：Grant 只要 12 bit 就能指一个信道，一个 CSBK 就装得下，控制信道省得很。  
- **代价**：网络和手台**必须用同一张表**。两边表不一致，网络说「去 161」，手台去了另一个频率，或者干脆不认识 161——呼叫就失败，而且**看起来像射频故障**。

现场你一定见过这些对话：

- 网管：「新加了一台载频，配置的是 CHAN 23。老批次手台一被分到 23 就听不到声音，过几秒自己回控制信道了。」——十有八九是**老手台的写频里没有 CHAN 23 这一行**（灵活计划），或者**固定计划参数和网络不一样**（§5、§6、§11）。  
- 写频员：「这批手台我写的是 6.25 kHz 间隔，结果 Grant 一来全跑偏。」——固定计划的公式里 **SEP（信道间隔）乘的是 (CHAN−1)**，间隔写错，CHAN 越大偏得越多（§5.4）。  
- 分析仪：「这条 TV_GRANT 的信道号是 4095，是不是解码错了？」——不是。**4095 = 0xFFF 是一个约定好的暗号**：「频率不查表，看下一块」（§4、§7）。新人常把它当成「坏值」或「最大信道号」。  
- 分析仪：「这个 Grant 是两块的，第二块全是看不懂的数。」——第二块是 **CG_AP**，里面装着**绝对频率**：整数 MHz 和以 **125 Hz** 为一步的小数部分（§7、§8）。  
- 优化：「手台发 452、收 462，那基站呢？」——基站反过来：**基站收 452、发 462**。规范里所有 Tx/Rx 都是**站在手台（MS）的角度**说的（§3.3）。  
- 维护：「P_CLEAR 里信道号写的 0，不是『无效』吗？手台怎么还走了？」——在 P_CLEAR 里，**0 有特殊含义：回到你上次确认过的控制信道**（§4.3）。同一个数字在不同 PDU 里意思不一样，这是本课第二个坑。

培训台若只背「CHAN 就是信道号」，后面会一直卡在同一处：

> **CHAN 是房号，不是频率。** 房号到频率要过一张表；表有三种来源：**① 写在手台里的公式（固定计划）；② 写在手台里的逐行对照（灵活计划）；③ 网络当场告诉你（绝对频率续块，或广播「这个号对应这个频率」）。**看见呼叫一到业务信道就失败、而控制信道一切正常时，先怀疑的是**这张表**，再怀疑射频。

本课目标：能说清 CHAN 的三段取值（0 / 1…4094 / 4095）及 P_CLEAR 的例外；会用固定计划公式 `fMS_Tx = fbase + (CHAN−1) × 间隔` **正着算、倒着算**；会读 SEP / TXRX_SPLIT / DUPLEX_SPLIT / BAND 四张参数表；会说清灵活计划和固定计划的取舍；会把绝对频率 `整数 MHz + 分数 × 125 Hz` 正算、反算；会**手拆一块 CG_AP 原始字节**；会认四种绝对续块（CG_AP / MV_AP / VN_AP / BC_AP）和 C_BCAST 的 Chan_Freq 广播；会把「信道号 ↔ 频率 ↔ 色码」三件套对齐；会做现场分诊；并为第 37 课「猎站 Hunt」留好边界——**猎站列表里存的也是 CHAN**。

**本课硬禁令（写进脑子）**：不 dump FEC/CRC/BPTC、不贴完整 SDL/MSC、不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/鉴权与AnnexC频率.md` **§7–§10**、`ReasonCode与Grant变体.md` Grant 一节、`总索引.md` **集群 / Tier III** 已有编号为准）；**不讲任何具体国家/单位的真实频率规划**（本课所有频点都是**教学虚构数字**，实际以无线电管理部门批复和本单位频率规划为准）；**不讲 Hunt 状态机**（第 37 课，本课只说「猎站列表存的是 CHAN」）；**不讲拨号、本地编址、Stun/DGNA**（第 38–39 课）；**不重 dump 第 33 课 Grant 变体全表**和**第 35 课鉴权字段**。本课只钉 **CHAN 号码与物理频率之间的换算关系**。

## 2. 总图 / 故事：「小票只写房号，门牌表在你兜里」

### 2.1 一句话故事

旅馆很大，房间按 **1 到 4094** 编号。前台开小票只写「**161 号房**」，不写「三楼东侧第五间」——因为**每个客人入住时都发了一本楼层图（门牌表）**，自己翻就知道 161 在哪。

但有两种情况楼层图不够用：

1. **新开的临时房间**，楼层图上没印。前台只好在小票上写「**特殊房间（4095），具体位置见背面**」，然后在**小票背面**把地址写全（这就是绝对频率续块）。  
2. **前台想让大家更新楼层图**，就在大厅广播：「**从今天起，300 号房在某某位置**」（这就是 C_BCAST 的 Chan_Freq 广播）。

楼层图本身有两种印法：

- **按规律印**：「1 号房在大门口，往后每间隔 12.5 步一间」——这就是**固定计划**，一个公式算到底。  
- **逐行印**：「1 号房在这里，2 号房在那里……」，每行单独写——这就是**灵活计划**，适合房间东一间西一间、不规整的旅馆（比如从老模拟频点改造来的网）。

### 2.2 总图：一个 Grant 从号码变成频率

```text
                     TSCC（控制信道，手台此刻正守着它）
                                 │
       Grant / C_MOVE / P_CLEAR / Vote_Now 等带一个 12 bit 信道号

           │                     │                          │
     信道号 = 0              1 … 4094（0x001…0xFFE）    4095（0xFFF）

                      手台查自己写频里的「门牌表」              ▼

                  │                                │     CHAN(12)
```

把这张图记住三件事：

1. **上层协议只认号码**。规范 Annex C 原话的意思是：上层只有一个逻辑 CHAN 来指物理频率；计划类型、收发间隔这些额外参数**只存在于物理层**，在**个性化（写频）或出厂时**就写进设备了。  
2. **4095 是「绕开门牌表」的唯一通道**。它让网络能把手台派到一个**手台表里根本没有**的频率上。  
3. **频率之外还有色码**。Annex C 的门牌表每行都带一个 Colour Code（默认 `0000₂`）；绝对续块 CG_AP 里也专门有 4 bit 的 Colour Code。**到了新信道，频率对、色码不对，照样听不到**（第 20 课；§10）。

## 3. 先把频率账本擦干净（巩固弱项，一节就够）

你最弱的是「频率与带宽」。本课到处是 MHz、kHz、Hz，所以先用五句话把账本擦干净，后面算数才不会乱。

### 3.1 五句话

1. **频率**是电波每秒振动的次数，单位 Hz。1 kHz = 1 000 Hz，1 MHz = 1 000 kHz = 1 000 000 Hz。写频软件里的 `452.0125` 单位是 **MHz**，等于 452 012 500 Hz。  
2. **信道间隔**是相邻两个信道**中心频率**之间的距离。DMR 常见 12.5 kHz：`452.0000`、`452.0125`、`452.0250`……每次加 0.0125 MHz。  
3. **占用带宽**是一条信号实际铺开的宽度，它**小于或约等于**信道间隔（留出护栏）。**间隔是「车道线画多宽」，带宽是「车本身多宽」**。本课的公式只管车道线（间隔），不管车宽。  
4. **双工分裂**是同一个信道里「发」和「收」两个频率之间的差，通常是 **MHz 级**（比如 5 MHz、10 MHz），比信道间隔（kHz 级）大好几百倍。**间隔是邻居之间的距离，分裂是自己左右手之间的距离**——两者别混。  
5. **步长 / 分辨率**是「最细能写到多细」。本课绝对频率的步长是 **125 Hz**，这只是**刻度有多细**，跟带宽、间隔都无关。

### 3.2 一条数轴把三个量放一起

```text
  （教学虚构频点，单位 MHz）

  手台发（上行）这一侧                                 手台收（下行）这一侧
  ├──┼──┼──┼──┼── … ──┤                    ├──┼──┼──┼──┼── … ──┤
 450.0000                                   460.0000
     450.0125                                   460.0125
        450.0250                                   460.0250
  │←→│ = 信道间隔 12.5 kHz（邻居之间）
  │←──────────────── 双工分裂 10 MHz（同一信道的发与收）──────────────→│

  一个信道 = 一对频率（发 450.0125 / 收 460.0125），共用一个 CHAN 号码
  每条车道里还能再切两个时隙（TDMA，第 15 课）——那是时间上的切，不是频率上的切
```

### 3.3 「Tx / Rx」站在谁的角度？——一律站在手台

这是本课最容易**算对却说反**的地方：

| 说法 | 站在手台（MS）角度 | 站在基站/中继（BS）角度 |
|------|-------------------|------------------------|
| 上行 | MS **发** | BS **收** |
| 下行 | MS **收** | BS **发** |
| 规范符号 | `fMS_Tx` / `fMS_Rx`；`TXMHz` / `RXMHz` | 规范 Annex C 不用这个角度写 |

Annex C 的公式写的是 `fMS_Tx`、`fMS_Rx`；绝对频率换算那一节的标题也是「MS 的发射和接收频率」。所以：

> **续块里的 TX = 手台发 = 基站收；RX = 手台收 = 基站发。**  
> 你在基站配置界面看到的「发射频率」，对应的是 CdefParms 里的 **RX**，不是 TX。

### 3.4 用第 2 课的老例子热身

第 2 课写频例子是 `460.125` 和邻居 `460.1375`。差多少？`460.1375 − 460.125 = 0.0125 MHz = 12.5 kHz`。对——它们是两条相邻车道。如果某个固定计划的 `fbase = 460.000`、间隔 12.5 kHz，那么：

- `460.125` 是第几号？`(460.125 − 460.000) / 0.0125 + 1 = 10 + 1 = 11` → **CHAN 11**  
- `460.1375` 是 **CHAN 12**

**倒推的公式就是：CHAN = (频率 − fbase) / 间隔 + 1。** 记住那个「+1」：因为 **CHAN 1 对应 fbase 本身**，不是 CHAN 0。

## 4. 12 bit 信道号：三段取值，外加一个例外

### 4.1 三段取值（所有带信道号的 Tier III PDU 共用）

12 bit 能表示 0…4095，共 4096 个值。规范把它切成三段：

| 值 | 二进制 | 含义 | 空口形态 | 白话 |
|----|--------|------|----------|------|
| **0** | `0000 0000 0000₂` | **CHNULL**：无效 / 未分配 | — | 「没有房间」 |
| **1 … 4094** | `0000 0000 0001₂` … `1111 1111 1110₂` | **逻辑信道号 CHAN**，对应一对预置的 Tx/Rx | **单块 CSBK** | 「查你兜里的门牌表」 |
| **4095** | `1111 1111 1111₂`（**0xFFF**） | 绝对频率写在**第二块** | **MBC：头块 + 续块** | 「别查表，看背面」 |

所以**真正能用的逻辑信道最多 4094 个**——规范 4.7.1 原话就是「最多 4 094 个逻辑/物理对应关系」。

规范在 Grant 族、C_MOVE、P_GRANT、Vote_Now 等每一个带信道号的 PDU 下面，几乎**一字不差**地重复这三条规则：0 无效；1…4094 逻辑号、单块发；4095 表示「另附一块写绝对收发频率」。你看见它重复，就知道这是**全局约定**，不是某个 PDU 的私有规矩。

### 4.2 「Logical Physical Channel Number」和「Logical Channel Number」——一字之差，天壤之别

Grant 头块里有两个名字很像的字段（第 33 课见过）：

| 字段 | 宽度 | 是什么 | 例 |
|------|------|--------|-----|
| **Logical Physical Channel Number** | 12 bit | **哪一对频率**（本课的 CHAN） | 161 |
| **Logical Channel Number** | 1 bit | **哪个时隙**：`0` = TDMA 信道 1，`1` = TDMA 信道 2 | 1（时隙 2） |

一个是**哪条车道**（频率），一个是**车道里的哪一半时间**（时隙）。名字里都有 Logical Channel，**看宽度就分得开：12 bit 的是频率号，1 bit 的是时隙号**。

开源扫描软件 GopherTrunk 就踩过一个相关的坑：早期把 Grant 最后一个字节当成「信道号」，结果那其实是 24 bit 主叫地址的低字节——于是「信道号每次呼叫都在变」，看起来像信道计划乱了，其实是**字段边界读错**（§16 第 5 条链接）。教训：**信道号在 Grant 载荷最前面的 12 bit，紧跟着 1 bit 时隙。**

### 4.3 例外：P_CLEAR 里的 0

P_CLEAR（CSBKO = `10 1110₂` = 46）是业务信道上的「清场」命令（第 33 课提过，第 39 课前还会再见）。它的信道号字段规则**和别人不一样**：

| P_CLEAR 信道号 | 含义 |
|----------------|------|
| **0** | 手台**回到它上次确认过的那个控制信道**（不是「无效」！） |
| 1 … 4094 | 去这个逻辑信道 |
| 4095 | 去续块里写的绝对频率 |

道理很朴素：清场以后，大多数情况就是「各回各的控制信道」，用 0 表示「回老地方」最省事。**所以「0 = 无效」这句话要加限定：「在 P_CLEAR 以外的 PDU 里」。**

### 4.4 谁会带信道号？一张总表

| PDU | CSBKO | 信道号字段叫什么 | 4095 时的续块 | 用途 |
|-----|-------|------------------|---------------|------|
| PV/TV/BTV/PD/TD/DX 等 Grant | 48–56 | Logical Physical Channel Number | **CG_AP** | 派去业务信道（第 33 课） |
| P_GRANT（业务信道上） | 同原 Grant | 同上 | **CG_AP** | 换信道/补发 Grant |
| **C_MOVE** | `11 1001₂` = 57 | Physical Channel Number | **MV_AP** | 命令手台「换到另一个 TSCC」 |
| **P_CLEAR** | `10 1110₂` = 46 | Logical Physical Channel Number | （续块格式沿用 Grant 那一节） | 清场；0 = 回上次的 TSCC |
| **C_BCAST / Vote_Now** | `10 1000₂` = 40 | **CH_VOTE** | **VN_AP** | 邀请手台去评估另一个 TSCC |
| **C_BCAST / Ann_WD_TSCC** | 40 | **BCAST_CH1 / CH2** | **BC_AP**（此时只能宣告一个） | 增删猎站列表里的 TSCC |
