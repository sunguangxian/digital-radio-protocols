# 第 20 课 · Colour Code 与同频系统

> DMR 深入学习 · **阶段 C 空口深入第 6 课**  
> 适合：已吃透第 16 课「突发 264」、第 17 课「语音超帧 A–F」、第 18 课「CACH 与 Guard」、第 19 课「SYNC 分壳」，但听到「色码不对」「同频两套系统」「分析仪有 SYNC 却没声」仍分不清「是壳对上了，还是色码没匹配」的人  
> 阅读量：约 **30–40 分钟** · 几乎不推公式 · 要把「**Colour Code = 4 bit 系统色标（CC0–CC15）；藏在 Slot Type / EMB 里；用来区分同频重叠站点、降低误听；SYNC 成功 ≠ CC 匹配；CC ≠ SYNC ≠ CACH；CC 不改 12.5 kHz / 4FSK；直通里 1111 = All site**」钉死  
> **频谱 / 调制提醒（一小段，不是本课主线）**：RF 仍是整条 **12.5 kHz** 上路；调制仍是 **4FSK**，符号率约 **4800 baud**，总比特率约 **9.6 kbps**。Colour Code **不换频、不改调制、不另开带宽**——它只是嵌在信令场里的 **4 bit 系统色标**。频率/带宽/调制四句话见 `学习推送/加餐_频率带宽与调制解调.md`；本课主线是**同频怎么不搅成一锅、写频与排障怎么对色码**。

## 1. 为什么本课重要（动机）

第 16 课把货箱钉死了：264 = 108+48+108。  
第 17 课把语音火车排齐了：A = Voice SYNC，B–F 多为嵌入。  
第 18 课把缝拆开了：出站 CACH（24 bit）、入站 Guard——**缝不在 264 里**。  
第 19 课把中心 48 的暗号字典拆开了：Voice / Data 分壳，BS / MS / DM 分册。

同事接下来会盯着写频软件和分析仪问：

- 同一频点、同一时隙上，两套公司各跑一套中继——为什么不会互相「当自己人」乱转、乱开静噪？  
- 写频里那一格 **Colour Code / 色码 / CC**，和 Talkgroup、时隙到底谁管什么？  
- 分析仪明明已经显示 **Voice SYNC / Data SYNC**，用户却说「有能量没声音」——是不是先改色码？  
- 直通（Direct Mode）里还有一个 **1111 = All site** 的特殊取值——和日常 CC1、CC7 有何不同？  
- 培训台上：若只背「色码像亚音」六个字，后面会卡在同一处：

> **Colour Code 不是调制，也不是 SYNC 图案，更不是 Talkgroup。它是嵌在 Slot Type（数据/控制突发）与 EMB（语音嵌入信令）里的 4 bit 系统色标：用来区分同频重叠站点、降低误听与误转。接收机可以「壳已同步」却仍因色码不匹配而拒收——SYNC 成功 ≠ CC 匹配。**

本课目标是让你能自己讲清十件事：

1. **为什么**同频系统必须认真对待 Colour Code（误听、误转、写频事故）；  
2. 一张总图：CC 住在 Slot Type / EMB，**不是**中心 48 的 SYNC 图案，也**不是**缝里的 CACH；  
3. 白话术语：CC、CC0–CC15、All site、同频干扰检测、礼貌接入里的「对本色码客气」；  
4. 机制：4 bit → 16 值；数据壳读 Slot Type；语音嵌入读 EMB；规范精神（Part1 4.2.1 / 9.3.1）；  
5. **SYNC ≠ CC ≠ CACH** 对照表，钉死「壳对上了色码仍可能错」；  
6. 现场岗位：写频、分析仪、同频两套系统、有能量没声、错色码像「错组」的错觉；  
7. 完整例子：医院同频两中继；写错 CC；分析仪读 CC；直通 All site；集群信道色码一眼带过；  
8. 数字账本：4 bit、16 码、Slot Type 20、EMB 16、与 48/24/264 分柜；  
9. 误区 + 自测 + 资料库路径 + 核验外链；  
10. 下一课预告：EMB / SLOT 字段整包拆开。

## 2. 总图 / 故事：同频两家「门牌色」

先把整课装进一个故事，再落到 Part1 clauses **4.2.1、9.1.2、9.1.3、9.3.1** 与资料库 `01-空中接口/帧结构与字段定义.md` **§3、§7、§8**。精神与 `00-入门/DMR术语与帧结构速查卡.md`「Colour Code」行一致。

### 2.1 一句话故事：同频不搅锅，靠「色标」

想象同一条 **12.5 kHz** 地皮上，两家公司各架一台中继，输出频率碰巧重叠（频谱紧张时很常见）。  
空口上的比特流会「叠」在一起——物理层能量谁也躲不开。  
但 DMR 给每个系统刷一层 **Colour Code（色码）**：

- 中继只愿意转发 **色码匹配** 的入站突发；  
- 终端只愿意对 **色码匹配** 的业务开静噪 / 当本系统话务；  
- 于是「同频」不等于「同系统」——色码不同，就尽量不当自己人。

规范原话精神（Part1 **4.2.1**）：Colour Code 出现在 **嵌入信令场** 与 **一般数据突发** 中，用来提供区分重叠站点的简单手段，以便检测同频干扰。  
规范还明确：**CC 不用来做个呼/组呼地址**（不是 Talkgroup，不是 Radio ID）。

### 2.2 总图：CC 住在哪儿？SYNC / CACH 住在哪儿？

```text
一个 Timeslot = 30.0 ms
├── 内容窗 ≈ 27.5 ms · Traffic burst = 264 bit
│
│   【语音突发 · 带嵌入时 · 第 17 课回忆】
│         Voice(108) | EMB(8) | 嵌入(32) | EMB(8) | Voice(108)
│                     └──── EMB PDU 共 16 bit ────┘
│                          其中有 Colour Code 4 bit  ← 本课
│         超帧 A：中心常是 Voice SYNC（48）——SYNC 本身不含 CC
│
│   【数据/控制突发 · 第 16/19 课回忆】
│         Info(98) | SlotType(10) | SYNC或嵌入(48) | SlotType(10) | Info(98)
│                    └────── SLOT PDU 共 20 bit ──────┘
│                         其中有 Colour Code 4 bit + Data Type 4 bit  ← 本课
│
└── 缝 ≈ 2.5 ms · 入站 Guard / 出站 CACH(24)（第 18 课）
         CACH/TACT 主场是 AT / TC / LCSS 等 —— 别把 CC 默认塞进缝里记
```

口诀：

| 东西 | 住哪 | 大约多长 | 本课角色 |
|------|------|----------|----------|
| **SYNC** | Traffic **中心** | 48 bit | 对暗号、认壳（第 19 课） |
| **EMB** | 语音嵌入时夹在中心两侧 | 16 bit 合计 | **携带 CC**（及 PI、LCSS…） |
| **Slot Type** | 数据壳中心两侧各撕 10 bit | 20 bit 合计 | **携带 CC + Data Type** |
| **CACH** | 出站 **缝** | 24 bit | 忙闲/槽号/短 LC（第 18 课） |
| **Colour Code** | 藏在 **EMB / Slot Type** 里 | **4 bit** | 同频系统色标（本课） |

```text
三件套对照（请背成条件反射）：

  SYNC 成功 ──→ 「壳对上了 / 找到中心了」
  CC 匹配   ──→ 「这是不是我这套系统的色」
  CACH 读到 ──→ 「出站缝里的忙闲/槽号小广播」（中继出站）

  可以：SYNC 成功，但 CC 不匹配 → 拒收 / 不当本系统
  可以：射频很吵，RSSI 高，但 CC 写错 → 有能量没合法话音
  不行：把 CC 当成 SYNC，或把 CACH 当成色码
```

### 2.3 和第 16–19 课怎么咬合？

| 课 | 你已经会 / 本课加上 |
|----|---------------------|
| 第 16 | 264 货箱；数据壳有 Slot Type；语音嵌入有 EMB |
| 第 17 | 语音火车；A = Voice SYNC；B–F 嵌入（EMB 出场） |
| 第 18 | 缝 = CACH/Guard；**不是** CC 主场 |
| 第 19 | 中心 48 = SYNC 图案字典；**SYNC ≠ CC** |
| **本课** | 把 **4 bit CC** 从 Slot Type / EMB 里拎出来，对准同频与写频 |

四句话串起来：

1. **货箱**是 264（第 16）；  
2. **语音火车**在嵌入窗挂 EMB（第 17）；  
3. **SYNC** 认壳（第 19）；**CACH** 管缝（第 18）；  
4. **Colour Code** 在 Slot Type / EMB 里刷系统色——同频不搅锅（本课）。

### 2.4 调制账本钩子（巩固弱项，不重开加餐）

加餐四句话在本课落成「CC 不改物理层」一句：

1. **频率**：载波仍停在写频的那个 MHz；改 CC **不会**把你搬到隔壁信道。  
2. **带宽**：地皮仍约 **12.5 kHz**；CC 只是比特场里的 4 bit，不另占地皮。  
3. **调制**：仍是 **4FSK**；CC 不是第三种调制，也不是「数字亚音波形」。  
4. **解调**：先对齐突发与中心（常靠 SYNC），再从 Slot Type / EMB 解出 CC 做匹配；匹配失败 ≠ 「没解调出比特」，而是「这比特不属于我这套色」。

口算复习：4 bit → \(2^4 = 16\) 种色码（CC0…CC15）。  
它和 9600 bit/s 水管是「水管里的一滴标签」，不是「另一根水管」。

## 3. 白话术语表

| 术语 | 一句话 | 别和谁混 |
|------|--------|----------|
| **Colour Code (CC) / 色码** | 4 bit 系统色标，区分同频重叠站点、降低误听/误转 | ≠ SYNC；≠ CACH；≠ Talkgroup；≠ Radio ID |
| **CC0 … CC15** | 十六种合法取值；写频软件里常显示 0–15 | 没有「官方规定 CC7=医院」这种全球硬规则 |
| **All site（直通）** | Direct Mode 中 **`1111`₂ = 15** 的特殊取值（资料库 / Part1 **9.3.1**） | ≠ 普通「第 15 号站点色」的日常语感；见 §4.4 |
| **Slot Type (SLOT)** | 数据/控制突发上的 20 bit：CC(4)+Data Type(4)+parity(12) | **语音壳不这么读**；别在 Voice SYNC 突发上硬找完整 Slot Type |
| **EMB** | 语音嵌入时的 16 bit：CC(4)+PI(1)+LCSS(2)+parity(9) | ≠ 整段 48 中心都叫 EMB；A 突发中心常是 SYNC |
| **Data Type** | Slot Type 里另 4 bit：CSBK / Header / Idle… | ≠ Colour Code；下一课会更深挖 |
| **同频干扰（co-channel）** | 两套系统共用/重叠同一 RF 频率 | CC **检测/拒收**帮助大；**消不掉**物理能量叠扰 |
| **误听 / 误转** | 终端开错静噪，或中继转发了别人的入站 | CC 匹配是第一道快门 |
| **CTCSS / DCS（模拟亚音）** | 模拟里区分同频用户组的老办法 | **类比可讲、细节勿硬套**；DMR 的 CC 是数字场，不是亚音频 |
| **礼貌对本色码（polite to own CC）** | 信道接入策略之一：对本色码的 DMR 活动客气 | ≠ 「CC 等于加密」；细节在接入条款，本课只建语感 |
| **SYNC 成功** | 中心 48 图案对上，壳边界清楚 | **不等于** CC 已匹配 |
| **Talkgroup / 组地址** | 谁跟谁说话的业务地址 | CC **不做**个呼/组呼寻址（Part1 明确） |

## 4. 机制细节：4 bit 色标怎么工作

### 4.1 规范钉死的两句

1. **出现位置**（Part1 **4.2.1**）：CC 出现在 **embedded signalling（嵌入信令）** 与 **general data burst（一般数据突发）**——学习映射即 **EMB** 与 **Slot Type**。  
2. **用途**：区分重叠站点，便于检测同频干扰；**不是**个呼/组呼地址。

资料库对照：`帧结构与字段定义.md` §7.1 EMB、§7.2 SLOT、§8 IE 表「CC | 4 | CC0…CC15；DM 中 `1111` = All site | 9.3.1」。

### 4.2 数据壳：从 Slot Type 读 CC

```text
数据/控制突发（学习视图）：

  Info(98) | ST(10) | 中心48(SYNC/嵌入) | ST(10) | Info(98)
             └──────── Slot Type 20 bit ────────┘

  Slot Type 信息场直觉（Table 9.4 精神）：
  ┌──────────┬───────────┬────────────────┐
  │ CC 4 bit │ Data Type │ Slot Type      │
  │          │ 4 bit     │ parity 12 bit  │
  └──────────┴───────────┴────────────────┘
       ▲
       │ 本课主读
```

校验：资料库记 Slot Type 用 **Golay (20,8)**（Annex B.3.1）——8 信息 + 12 校验。  
本课**不贴生成矩阵**；只要知道「CC 坐在受保护的 8 信息里」。

接收机路径（学习视图，非唯一实现）：

1. 靠 **Data SYNC**（等）认数据壳；  
2. 拼出 Slot Type 20 bit，过 Golay；  
3. 取出 CC，与本机写频/本系统配置比较；  
4. 不匹配 → 不当本系统数据/控制（仍可能受能量干扰）。

### 4.3 语音壳：从 EMB 读 CC

```text
语音突发 B–F（典型嵌入）：

  Voice(108) | EMB(8) | 嵌入信令(32) | EMB(8) | Voice(108)
               └─────── EMB 16 bit ───────┘

  EMB 信息场直觉（Table 9.3 精神）：
  ┌──────────┬────┬──────┬────────────┐
  │ CC 4 bit │ PI │ LCSS │ EMB parity │
  │          │ 1  │  2   │ 9 bit      │
  └──────────┴────┴──────┴────────────┘
       ▲
       │ 本课主读；PI/LCSS 留给第 21 课
```

校验：资料库记 EMB 用 **Quadratic Residue (16,7,6)**。  
超帧 **A** 中心常是 **Voice SYNC**：那 48 bit 是图案，**不是**「SYNC 里藏了 CC」。语音过程中的 CC，要到 **嵌入窗的 EMB**（以及前后数据壳单据，如 Header/Terminator 的 Slot Type）上去找。

### 4.4 十六色与 Direct Mode「All site」

| 二进制（示意） | 十进制 | 学习叫法 |
|----------------|--------|----------|
| 0000 … 1110 | 0 … 14 | 普通色码 CC0–CC14 |
| **1111** | **15** | 直通（DM）中规范记为 **All site** |

白话解释（请用「小心讲」而不是「吓自己」）：

- 日常中继/常规写频：你选一个 **0–15** 的色，全网约定一致即可。  
- **Direct Mode** 下，规范把 **`1111`₂** 标成 **All site**：它是 DM 场景里的特殊色标语义（「全站点/全站」类含义），**不要**把它和「随便挑一个常用色 CC1」混成同一种语感。  
- 写频或排障时：若同事在直通测试里看到 CC=15 / All site，先问「是不是 DM 特殊取值」，再问「是不是真要当普通第 15 号色去和中继对齐」。  
- **冲突规则**：具体枚举与约束以 **TS 102 361-1 V2.7.1 clause 9.3.1** PDF 为准；课文只建立位置与语感。

### 4.5 SYNC 成功 ≠ CC 匹配（本课最硬的钉子）

```text
排障决策树（学习视图）：

  射频有能量？
    ├─ 否 → 先查天线/频点/距离/中继是否激活（物理）
    └─ 是 → 找得到突发边界 / SYNC？
              ├─ 否 → 「同步不上」主线（第 19 课）：图案册、首 SYNC、射频干净度
              └─ 是 → CC 是否匹配？
                        ├─ 否 → 「壳对了、色不对」：改写频 CC / 确认是否同频邻系统
                        └─ 是 → 再查时隙、组地址、FID/业务、权限…
```

请把这句话练到能脱口而出：

> **分析仪显示 Voice SYNC，只说明中心 48 图案对上了语音壳；不保证 Colour Code 是你的。**

### 4.6 CC 与「礼貌接入」的语感（点到为止）

资料库与培训文常提到：终端可配置成对本色码活动客气（polite to own Colour Code）等。  
本课只要建立：

- CC 会进入**信道接入决策**的视野（「信道上是不是自己人的 DMR」）；  
- 它**不是加密**，也**不能**单靠 CC 当安全边界；  
- 细则在 Part1 信道接入条款与 Part2/产品实现——留给岗位手册，不在本课展开状态机。

## 5. 现场对照

| 现场现象 / 动作 | 先怎么想 | 别误判成 |
|-----------------|----------|----------|
| 写频软件一格 **Colour Code** | 系统色标 0–15；与中继/对端必须一致 | ≠ Talkgroup；≠ 时隙号 |
| 分析仪显示 **CC=7** | 当前解出的色码是 7 | ≠ 「一定是合法业务」——还要看组/时隙/权限 |
| 同频两套系统，CC 不同 | 设计意图：降低误听/误转 | ≠ 物理干扰消失；强信号仍可能抬噪底 |
| 同频两套系统，**CC 相同** | 危险：更容易互相当自己人 | 规划事故；优先改色或改频 |
| 「有 RSSI / 有能量，完全没声」 | 查 CC、时隙、组、数字监视模式 | 别只骂天线；也别只改 CC 一次碰运气 |
| 「能听到别的公司在讲话」 | 可能 CC 写得和对方一样，或开了宽收/数字监视 | 先对规划表，再查是否误开监视 |
| 中继「乱转」邻系统入站 | 入站 CC 与中继配置是否撞车 | 先别只加功放 |
| 口语「同步不上」 | 拆成：没 SYNC / 册错 / **CC 错** / 射频差 | 三件事不是一回事（接第 19 课） |
| 直通测试 CC=15 | 核对是否 **All site** 语义 | 勿盲目当成「普通 CC15 去对中继」 |
| 改 CC 后立刻通了 | 典型写频色码错误 | 通了仍要回头记进变更单，避免复发 |

岗位三问（建议贴显示器旁）：

1. **频点 / 时隙对了吗？**（物理与 TDMA）  
2. **Colour Code 与系统规划一致吗？**（本课）  
3. **组地址 / 业务门牌对了吗？**（Talkgroup、FID…——后面课）

## 6. 完整例子

### 例子 A · 同频两中继，靠 CC 分开

园区只有一对许可频率。安保中继与后勤中继**输出同频**，覆盖有重叠。

- 安保：CC=**3**，TS1 跑安保组；  
- 后勤：CC=**9**，TS1 跑后勤组。  

手台若误写成 CC=9 却想听安保：可能「有数字味道 / 分析仪能看到邻系统 SYNC」，但本机不当安保话务。  
若两人**都误写成同一个 CC=3**：同频叠扰 + 系统边界塌掉，现场会像「串台升级版」。

要点：**CC 是系统色，不是组名。** 组仍要另配 Talkgroup。

### 例子 B · 写频事故：SYNC 漂亮，CC 写错

用户投诉：「中继灯在闪，同事说听得到我，我听不到他们。」

分析仪对用户机旁接收：出站 **Voice SYNC** 稳定，Slot Type/EMB 解出 **CC=1**；  
用户写频却是 **CC=2**。

路径：

1. SYNC 成功 → 壳没问题；  
2. CC 不匹配 → 静噪/业务过滤把话挡在门外；  
3. 改回 CC=1 → 恢复。  

这就是「**壳对了、色不对**」的标准剧本。

### 例子 C · 分析仪读 CC，规划员对表

规划员用分析仪扫一段已知同频走廊：

- 频点 X 上交替出现 **CC=4** 与 **CC=11** 的突发；  
- 说明至少两套色在共用/挤占该频。  

动作：画覆盖与色码复用图；确认两套是否故意同频异色；检查是否有第三家误用了其中一色。

### 例子 D · 直通 All site（小心讲）

车队近距离切直通测试。某台显示色码 **15**，手册/规范语汇对应 DM **All site（`1111`）**。

讲解口径：

- 这是 **Direct Mode** 下的特殊取值语义；  
- 不要直接拿去「对齐园区中继的日常 CC」；  
- 测试记录写清「DM / All site」，避免运维同事当成中继色码事故。

### 例子 E · 「像错组」其实是错色

用户说：「怎么变成别的对讲组了？」  
实际：邻系统同频、用户 CC 误写成邻系统色，听到的是**邻系统当前话务**；Talkgroup 显示也可能让人产生「组乱了」的错觉。

分诊：先对 **CC 与系统名**，再对组列表——避免在错误系统里疯狂改组。

## 7. 数字账本

| 量 | 值 / 关系 | 别和谁混 |
|----|-----------|----------|
| **CC 位宽** | **4 bit** | ≠ 48 bit SYNC；≠ 24 bit CACH |
| **色码个数** | \(2^4=\)**16**（CC0–CC15） | 不是「无限系统 ID」 |
| **All site（DM）** | **`1111`₂ = 15** | 见 §4.4；以 9.3.1 为准 |
| **Slot Type** | **20 bit** = 8 信息 + 12 校验 | 信息里含 CC(4)+Data Type(4) |
| **EMB** | **16 bit** = 7 信息 + 9 校验 | 信息里含 CC(4)+PI+LCSS |
| **SYNC** | **48 bit** 中心图案 | **不含** CC 字段 |
| **CACH** | **24 bit** 缝 | 主场 AT/TC/LCSS；别默认当 CC 柜 |
| **Traffic** | **264 bit** | 货箱总长 |
| **带宽 / 调制** | **12.5 kHz** + **4FSK** | CC **不改变**二者 |
| **校验名（记名即可）** | Slot Type: Golay(20,8)；EMB: QR(16,7,6) | 不贴矩阵；实现以 PDF Annex B 为准 |

分柜口诀：

```text
264 货箱
 ├─ 中心 48 …… SYNC 或 嵌入窗
 │                ├─ SYNC …… 认壳（无 CC）
 │                └─ EMB+碎片 …… EMB 内有 CC
 ├─ 数据壳两侧 Slot Type …… 内有 CC + Data Type
 └─ 缝 24/Guard …… CACH 故事（第 18 课）
```

## 8. 常见误区（10 则）

1. **「Colour Code 就是 SYNC。」** → 否。SYNC 是中心 48 图案；CC 在 Slot Type / EMB。  
2. **「Colour Code 就是 CACH。」** → 否。CACH 在出站缝；CC 不在那条主故事里。  
3. **「Colour Code 就是 Talkgroup。」** → 否。规范写明 CC 不做个呼/组呼寻址。  
4. **「SYNC 成功 = 色码一定对。」** → 否。本课核心反例。  
5. **「改色码会换频率/换调制。」** → 否。仍是 12.5 kHz + 4FSK。  
6. **「CC 不同就完全没有射频干扰。」** → 否。拒收≠消能量；强邻频/同频仍可能抬噪、砸解调。  
7. **「CC 等于加密/保密。」** → 否。匹配只是系统色标过滤；明文话务仍可能被监视类接收机看到。  
8. **「十六个色码不够用就重复没关系。」** → 同频覆盖重叠时重复很危险；要靠规划复用距离。  
9. **「同步不上 = 先改 CC。」** → 顺序常反：先 SYNC/射频，再 CC，再组与业务。  
10. **「直通 CC=15 就当普通第 15 号色去对中继。」** → 先核对 DM **All site** 语义（9.3.1）。

## 9. 自测（8 题）

**题 1.** Colour Code 主要出现在哪些 PDU/场？它和 Traffic 中心 48 的 SYNC 图案是同一段吗？

<details><summary>简答</summary>

主要在 **Slot Type（数据/控制突发）** 与 **EMB（语音嵌入信令）**。SYNC 是中心 **48 bit 图案**，**不是** CC 字段本身。二者常「前后相关」，但不是同一段比特。

</details>

**题 2.** CC 有多少 bit？有多少种取值？Direct Mode 里 `1111` 叫什么？

<details><summary>简答</summary>

**4 bit** → **16** 种（CC0–CC15）。DM 中 **`1111` = All site**（资料库 / Part1 **9.3.1**）。讲解时要标明「直通特殊语义」，勿与日常中继色码口语混用。

</details>

**题 3.** 为什么说「SYNC 成功 ≠ CC 匹配」？举一个现场症状。

<details><summary>简答</summary>

SYNC 只说明中心图案/壳边界对上了；CC 是另一次系统色匹配。典型症状：分析仪有 Voice/Data SYNC，RSSI 不差，但本机无声或不当本系统——写频 CC 与空口 CC 不一致。

</details>

**题 4.** 同频两套系统应如何使用 Colour Code？若误用同一 CC 会怎样？

<details><summary>简答</summary>

应使用**不同 CC**，降低误听/误转、便于检测同频干扰。误用同一 CC：系统边界塌掉，更容易互相当自己人，叠加物理干扰，排障极难。

</details>

**题 5.** 用一张表对比 SYNC、Colour Code、CACH（位置 / 长度 / 干什么）。

<details><summary>简答</summary>

| | 位置 | 长度 | 干什么 |
|--|------|------|--------|
| SYNC | Traffic 中心 | 48 bit | 认壳、对齐、分语音/数据等 |
| CC | Slot Type / EMB 内 | 4 bit | 同频系统色标 |
| CACH | 出站缝 | 24 bit | 忙闲、槽号、短 LC 等 |

</details>

**题 6.** 用户说「有信号没声音」。你按什么顺序问三件事？

<details><summary>简答</summary>

建议序：① 频点/时隙/射频是否够；② **Colour Code** 是否与系统一致；③ 组地址/业务/是否误开监视。并提醒：有能量 ≠ 已 SYNC ≠ CC 已匹配。

</details>

**题 7.** Colour Code 会改变 12.5 kHz 或 4FSK 吗？它是不是 Talkgroup？

<details><summary>简答</summary>

**不会**改变带宽/调制。也**不是** Talkgroup——规范明确 CC 不做个呼/组呼寻址。

</details>

**题 8.** 数据壳里 Slot Type 除了 CC 还有什么？语音超帧 A 的中心通常是 CC 吗？

<details><summary>简答</summary>

Slot Type 还有 **Data Type**（及 parity）。超帧 **A** 中心通常是 **Voice SYNC 图案**，不是「SYNC 里直接等于 CC」；语音过程中的 CC 要到 **EMB**（及前后数据单据的 Slot Type）上读。

</details>
