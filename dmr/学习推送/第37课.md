# 第 37 课 · 猎站 Hunt

> DMR 深入学习 · **阶段 E · 集群 Tier III 第 7 课（约 10 课之七）**（接第 36 课「频率 CHAN / 绝对频率」）  
> 适合：已经会把 Grant 里的 CHAN 换算成 MHz、也会画「守 TSCC → 登记 → C_RAND → Grant → 进 Payload」总图，但一被问到「**手台开机后，屏幕上那句『搜索中』到底在搜什么？**」「**为什么从地下车库出来要等十几秒才有网？**」「**网管加了一个新控制信道，为什么一部分手台就是不去？**」「**登记被拒以后，手台为什么在两个站之间来回跳？**」就答不上来——说不出**手台手里有哪几张号码单、按什么顺序试、试到什么程度才算「找到了」、找到之前为什么一个字都不许发**——的人  
> 阅读量：约 **30–40 分钟** · **只讲流程和判据，不贴 FEC、不画完整 SDL/状态机** · 要把「**猎站 = 拿着号码单一个个调过去听；顺序是『回老地方 → 按命令去 → 扫短名单 → 扫全范围』；每听到一个，都要先过『验证』（C_SYScode 是不是我的网、我有没有资格）再过『确认』（信号质量够不够），两关都过之前绝不发射；过关以后再看要不要登记，登记失败就回到登记前那一段接着猎**」钉牢  
> **频谱 / 调制提醒**：RF 仍是 **12.5 kHz** 一条车道，调制仍是 **4FSK**，空口仍是 **2-slot TDMA**、时隙 **30 ms**、一个 TDMA 帧 = 两个时隙 = **60 ms**。本课的「猎」在物理上就是：**合成器跳到一个频率 → 接收机在 12.5 kHz 的窗里量一量电平 → 4FSK 解调出比特 → 找同步、读 CACH 和 CSBK**。所以本课会顺手把「**电平（听得见）和误码（听得清）是两回事**」讲透（§3），这正好补你「调制与解调」的弱项；四句话原文见 `学习推送/加餐_频率带宽与调制解调.md`。

## 1. 为什么本课重要（动机）

第 36 课结尾我们说：**猎站列表里存的也是 CHAN。**上一课解决了「号码 → 频率」，今天解决的是它前面一步：

> **手台手里有一大堆号码，控制信道（TSCC）到底在哪一个上？先试哪个？试到什么程度算找到？**

这件事在集群里每天发生无数次，只是用户看不见：

- **开机**：手台要先找到一个 TSCC，才能登记、才能打电话。  
- **通话结束**：手台从业务信道回来，要回到「刚才那个」TSCC。  
- **走出覆盖**：TSCC 听不清了，要换一个。  
- **网络命令**：网络发 C_MOVE 说「去另一个控制信道」。  
- **登记被拒**：这个站不收你，得另找一个站。

现场你一定听过这些话：

- 用户：「开机以后『搜索中』转了快半分钟才上网，别人的机子几秒就好。」——多半是**没有『上次在哪』的有效记录**，或**短名单里没有现在的控制信道号**，只能一路扫到「全范围猎」（§6、§10）。  
- 用户：「从地下车库开出来，要十几秒才有信号。」——手台在车库里**早已放弃原 TSCC**（`T_Nosig` 到期，§8.1），出来时正在别的号码上转圈（§6、§10）。  
- 网管：「新加了一个控制信道，老手台一部分就是不去。」——新号码**不在这些手台的短名单里**，网络也没用 **Ann_WD_TSCC 广播**把它加进去，或者它在全范围 Low…High 之外（§7、§10）。  
- 网管：「拆了旧控制信道以后，手台每次开机都先去旧频点空转一下。」——**手台记着『上次确认过的 TSCC』**，开机先去那儿（Commanded），失败才进短名单；短名单里还留着旧号就再白跑一趟（§6.2、§7.1）。  
- 优化：「在两个站交界的地方，手台登记被拒以后就在两个站之间来回跳，控制信道上全是登记请求。」——网络用的是 **Reg_Refused**（第 34 课 0x2A），规范明说这会让手台「找不到别的就回来再试」；想稳稳赶走，应该用 **Reg_Denied**（0x2B）（§8.2）。  
- 维护：「扫频仪上明明看见这个站的控制信道在发，手台就是不上去。」——手台**听到了**，但**验证没过**：模型 / 网号不对、站点授权表不含这个站、PAR 不放这一类手台、或这一片区刚被拒过登记（§4）。

培训台如果只背「手台会自动找控制信道」，后面排障会一直卡住：

> **猎站不是『自动的魔法』，是一套有顺序、有门槛、有记忆的流程。**  
> 顺序：**Resume → Commanded → Short → Comprehensive**。  
> 门槛：**验证（C_SYScode 对不对、我有没有资格）+ 确认（信号质量够不够）**。  
> 记忆：**上次确认的 TSCC 号、写频写进去的短名单和全范围、广播加进来的号、被拒登记的片区**。  
> 用户说「找网慢 / 找不到网 / 来回跳」时，就按这三样一样一样查。

本课目标：画出四段猎站的顺序和失败出口；说清**验证**和**确认**各查什么；**手拆一个 C_SYScode**（MODEL / NET / SITE / PAR / SYS_AREA）；说清**短名单**（≥ 50、建议 64 槽、可重复写来「偏置」）和**全范围**（Low_Comp_Ch…High_Comp_Ch，可被 Comp_Flag 关掉）；**手拆一条 Ann_WD_TSCC**；把 Adjacent_Site、Vote_Now、C_MOVE、P_CLEAR 放上猎站地图；列出**离开 TSCC 重新猎**的 9 种情况；说清**登记分岔**和**登记失败回哪一段**；能做现场分诊；为第 38 课「拨号与本地编址」留好边界。

**本课硬禁令（写进脑子）**：不 dump FEC/CRC/BPTC、不贴完整 SDL/MSC、不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/AnnexD猎站Hunt.md` **§0–§7**、`Announcement与其余枚举.md` **§3.1 / §3.3 / §3.7 / §5**、`Stun_DGNA_UDT与定时器.md` 定时器表、`总索引.md` **集群 / Tier III** 已有编号为准，本课新引用的条款都在 PDF 里逐条核过）；**不发明电平门限数值**（规范 Table A.7 明写「单位和数值由厂商自定」，本课不写任何 dBm 数字）；**本课所有频点、CHAN、网号、站号都是教学虚构**，实际以无线电管理部门批复和本单位规划为准；**不讲任何厂商私有的漫游算法**（规范说 Vote_Now 优先级怎么用「由厂商自定」）；**不重讲第 36 课的门牌表换算**（只用结论）、**不重 dump 第 32 课登记 MSC / Aloha 字段和第 34 课 Reason 全表**；**不讲拨号、本地编址、Stun/DGNA/UDT**（第 38–39 课）。本课只钉 **手台怎么找到并确认一个 TSCC，以及找到之后、丢了之后怎么办**。

## 2. 总图 / 故事：「走散的团员找导游」

### 2.1 一句话故事

你跟旅行团出来玩，在一个很大的景区里走散了。导游举着一块牌子（**TSCC**），牌子上写着团名。你要找到他，才能继续跟团（**登记、打电话**）。

景区有很多门，按 1、2、3……编号（**CHAN**）。你兜里有三样东西帮你找：

1. **记忆**：「刚才是在 **52 号门**分开的。」——先回那儿看看（**Resume / Commanded**）。  
2. **团里发的小卡片**：上面印着「本团常用集合点：37 号门、52 号门、101 号门……」，最多能印六十来个（**Short Hunt 短名单**）。导游还会用大喇叭广播「今天起 88 号门也是集合点」「101 号门不用了」（**C_BCAST Ann_WD_TSCC**）。  
3. **景区地图**：「本团活动范围是 1 号门到 160 号门。」——实在找不到，就从头到尾一个门一个门找（**Comprehensive Hunt 全范围**）。

每到一个门，看见有人举牌子，你还不能马上冲过去报到：

- **先看牌子上写的是不是自己的团**（**验证**：C_SYScode 的 MODEL、NET 对不对；这个站我能不能去；这一类团员能不能去；这一片刚才是不是拒绝过我）。  
- **再看自己是不是真看得清**（**确认**：信号质量够不够——看都看不清，过去也跟不住）。  
- 两样都过了，才走过去；导游说「新来的先报到」（**Reg = 1**），你就报到（**登记**）。导游说「你不是我们团的人」（**Reg_Denied**），你就把这片区域记在小本上「这里不要再来」，接着找。

整个过程里有一条铁律：**没确认之前，不许喊话。**——你没确认导游是谁就乱喊，会打扰别的团。手台在确认 TSCC 之前**绝不发射**。

把这张图记住四件事：

1. **顺序是有讲究的：越靠前越快、越窄。**Resume 和 Commanded 只试**一个**号；Short 试一张**短表**；Comprehensive 试**整个范围**。规范把 Comprehensive 称作「兜底」（contingency）。  
2. **两道关缺一不可。**「听到同步」只算候选；**验证**说的是「这是不是我该去的网」，**确认**说的是「这信号能不能用」。  
3. **确认之前绝不发射。**Annex D 每一段都重复这句话；正文 6.3.0 写得更死：手台**收到授权它接入的 C_SYScode 之前不得变为活跃，不活跃不得发射**。  
4. **失败有出口，登记失败也有出口。**Resume/Commanded 失败 → Short；Short 失败 → Comprehensive（除非被关掉）；Comprehensive 失败 → 再来一轮。登记被拒或超时 → **回到登记前所处的那一段**，不是从头来（6.3.3.1 f/g/h）。

## 3. 先把「听」这件事拆开（巩固弱项：调制与解调）

猎站说穿了就是**一个号一个号地「听」**。你最弱的是「频率与带宽」「调制与解调」，而「听」恰好要用到这两样。先花几分钟把它拆开，后面所有门限、判据才有着落。

### 3.1 手台「听一个号」时，物理上依次发生五件事

```text
  ① 查门牌表        ② 合成器调谐        ③ 量电平           ④ 4FSK 解调         ⑤ 读内容
  CHAN 37      →   本振跳到对应频率  →  在 12.5 kHz 的   →  把频率的四种    →  找 SYNC → 读 CACH
  （第 36 课）       等它锁定、稳住       窗口里量功率        偏移翻回成 2 bit     → 读 CSBK（C_SYScode）
                                        （RSSI）            的符号 → 比特流      → 数误码（BER）
```

- **①②是「频率」那一半**：把号码变成 MHz，把接收机「对准」那条 12.5 kHz 的车道。门牌表错了，后面全白听（第 36 课）。  
- **③是「带宽」那一半**：接收机只看 12.5 kHz 宽的窗口里的能量，窗口外再热闹也不算。  
- **④是「解调」**：DMR 用 4FSK——载波往上偏一点、偏多一点、往下偏一点、偏多一点，四种偏移各代表 2 个比特。**解调就是把『偏了多少』翻译回比特。**  
- **⑤是「协议」**：比特里先找同步字（「这是一个 TSCC 的突发」），再读内容（「这是谁家的网」）。

### 3.2 两种「信号好」：听得见 vs 听得清

| | 电平（RSSI） | 质量（误码率 BER） |
|---|---|---|
| 量的是什么 | 窗口里**有多少能量** | 解调出来的比特**错了多少** |
| 在哪一步量 | ③，解调之前 | ④⑤，解调之后 |
| 白话 | **听得见**（声音大不大） | **听得清**（话听不听得懂） |
| 会骗你的情况 | 同频干扰、邻道泄漏也算「能量」——电平高但全是噪声 | 很少骗你，但要先解调、要一点时间才数得准 |

打个比方：你在嘈杂的饭馆里，隔壁桌说话**声音很大**（电平高），但你**一句也听不懂**（误码高）——因为那不是在跟你说话，或者好几个人同时在说。

规范在这里很务实：Annex D.1.2.5 说采集门限可以是**接收机输入端的信号电平**，**也可以是等价的信号质量**；NOTE 还专门说「手台可能测不了电平，可以用误码测量等别的方法」。正文 6.3.2.3 也说质量可以是「误码率」或「射频信号强度」。**所以本课说「信号质量够不够」时，指的是电平或误码二者之一（厂商选）。**

### 3.3 一个物理信道，两个时隙一起听

DMR 一条 12.5 kHz 车道上有两个时隙（第 15 课）。Annex D.1.0 说：**因为两个逻辑 TDMA 信道占同一个物理信道，手台采样一个物理信道时可以同时评估两个逻辑信道。**一个物理信道上可以有一个或两个 TSCC（5.1.1；第二个 TSCC 用 PAR 区分，§4.4）。所以「试一个号」= 同时看两个时隙，不用试两次。

### 3.4 时间账：一次「听」大概多久？

规范**没有**规定猎一个信道最多花多久（6.3.2.2.0 原话：没有规定最大时间，但要尽快完成，尤其是那些很容易排除的信道）。但有几个**规范里的时间刻度**可以帮你建立感觉：

| 刻度 | 值 | 出处 | 意义 |
|------|----|------|------|
| 时隙 | 30 ms | Part 1 / 第 15 课 | 一个突发 |
| TDMA 帧 | 60 ms（两个时隙） | 5.0 Figure 5.1 | 两个时隙各轮一次 |
| CACH 送完一条 Short LC | 4 × 30 ms = **120 ms** | 5.1.0 | TSCC 每 120 ms 能送一次 C_SYS_Parms（含 C_SYScode 高 14 位） |
| Resume 要求 | **2 个 TDMA 帧**内能收到老 TSCC | D.1.1 | 2 × 60 = 120 ms（换算是本课算的） |
| Commanded 要求 | **3 个时隙**内能收到被点名的信道 | D.1.2.1 | 3 × 30 = 90 ms（同上） |

**粗算（教学估算，不是规范值）**：如果每个号光是「调谐 + 等一条 CACH」就要一两百毫秒，短名单 50 个号扫一遍就是好几秒；全范围扫 160 个号就是十几秒到几十秒——这就是「开机找网慢」的物理根源。所以**能用 CACH 快速排除的，就别傻等 CSBK**（§4.2）。

## 4. 第一道关：验证（Verification）——「这是不是我的网？我有没有资格？」

### 4.1 什么算「候选」

正文 6.3.2.2.0：手台在搜控制信道时，要检查收到的信号是否符合 TSCC 结构；**只要在某个信道上检测到 TSCC 的同步序列，就把它当作候选 TSCC**。

候选只是「这里好像有个导游」。接下来要读他的牌子：**C_SYScode（System Identity Code，系统识别码）**，16 bit。

### 4.2 牌子写在两个地方：CACH（快速版）和 CSBK（完整版）

| 位置 | 内容 | 出处 | 用途 |
|------|------|------|------|
| **CACH** 里的 Short LC **C_SYS_Parms** | C_SYScode 的**高 14 位**（不含 PAR）+ Reg + Common_Slot_Counter | 5.1.0 / 5.1.1 / 5.1.2 | **快速排除**：14 位都不对，就不用再等 CSBK |
| 部分 **CSBK**（如 C_ALOHA、C_BCAST） | **完整 16 位** C_SYScode | 6.3.2.2.1.0；Table 7.20 | 完整验证（含 PAR） |

为什么 CACH 里只有 14 位？因为 **CACH 是两个时隙共用的**，而一个物理信道上可能有两个 TSCC，各自用 2 bit 的 PAR 区分——共用的 CACH 没法同时写两个 PAR，所以干脆不写（5.1.1）。规范原话的意思：**手台在搜控制信道时，可以靠解 CACH 来放弃一个信道；不匹配就不必再等含 C_SYScode 的 CSBK。**

> **现场意义**：同频的别家网、邻市的同厂商网，手台靠 CACH 一两百毫秒就能排除，不会在上面耽误太久。如果你发现手台在某个「别人家的」频点上停留很久，值得怀疑它是不是没用上这个快速排除。

### 4.3 C_SYScode 的结构：MODEL 决定 NET 和 SITE 各占几位

规范定义了四种网络模型（Table 6.5），位分配见 Figure 6.15：

| 模型 | MODEL 码 | NET 位数 | 网络数 | SITE 位数 | 每网站数 | PAR | DMRLA 范围 |
|------|----------|----------|--------|-----------|----------|-----|-----------|
| Tiny | `00₂` | 9 | 512 | 3 | 8 | 2 | 1…3 |
| Small | `01₂` | 7 | 128 | 5 | 32 | 2 | 1…5 |
| Large | `10₂` | 4 | 16 | 8 | 256 | 2 | 1…8 |
| Huge | `11₂` | 2 | 4 | 10 | 1 024 | 2 | 1…10 |

每一行加起来都是 2 + NET + SITE + 2 = **16 bit**。白话：**小网多、大网少**——同一片地方可能有很多小网，但只有少数几个大网（6.3.2.2.1.1 原意）。所以小网把位数让给 NET（能区分更多网），大网把位数让给 SITE（一个网里能有更多站）。

- **NET**：哪一个集群网络。  
- **SITE**：网里的哪一个站。  
- **PAR**：同一个站有两个 TSCC 时，分流用（§4.4）。  
- **DMRLA**：不在 C_SYScode 里，是**写频写进手台**的数，表示「SITE 的高几位算一个登记片区（SYS_AREA）」（§4.6）。

### 4.4 验证四步（6.3.2.2.2，Figure 6.17）

| 步 | 查什么 | 对比对象（都在手台的固定非易失存储里，写频写入） | 不过的后果 |
|----|--------|------------------------------------------------|-----------|
| a | **MODEL** | 手台存的 MODEL | 视为**无权接入**此 TSCC |
| b | **NET** | 手台存的 NET | 同上 |
| c | **SITE** | 手台存的「站点接入授权数据」——**如果一条都没存，就不查**；存了至少一条，就要和其中某条匹配 | 同上 |
| d | **PAR** | 手台的**控制类别 ContCAT**（A 或 B） | 同上 |

PAR 的四个值（6.3.2.2.1.4）：

| PAR | 含义 |
|-----|------|
| `00₂` | 保留 |
| `01₂` | 只允许 **A 类**手台 |
| `10₂` | 只允许 **B 类**手台 |
| `11₂` | A 类、B 类都允许 |

规范举的例子（Figure 6.16）：一个站有两个 TSCC，第一个发 PAR = `01₂`，第二个发 PAR = `10₂`；写频时把全网手台大约一半写成 A 类、一半写成 B 类。到了这个站，A 类自动聚到第一个 TSCC，B 类聚到第二个——**负载分担**。到了只有一个 TSCC（PAR = `11₂`）的站，大家都能上。

> **现场意义**：一个双 TSCC 站上「一半手台在 TSCC-1、一半在 TSCC-2」是**设计如此**；如果「某批手台只认其中一个 TSCC、另一个死活不上」，先查这批手台写频里的 ContCAT。

### 4.5 第五步：SYS_AREA 不能在「被拒登记」名单里（6.3.2.2.3）

C_SYScode 过了四步以后，手台还要做一件事：用写频里的 **DMRLA** 去取 SITE 的**高 DMRLA 位**，得到 **SYS_AREA**（登记片区）。然后拿它去和手台里的「**被拒登记名单**」（list of denied registrations）比：

- 在名单里 → **无权接入**此 TSCC，接着猎。  
- 不在 → 通过。

这张名单从哪来？——在某个 TSCC 上登记时收到 **Reg_Denied**（第 34 课 0x2B），手台就把那个 SYS_AREA 记进去（6.4.4.1.4）。名单的规矩（Table 6.8 及 6.3.2.2.3.1）：

| 规矩 | 内容 |
|------|------|
| 容量 | **至少 8 个**不同的 SYS_AREA，按 FIFO 管理（满了挤掉最早的） |
| 关机 | **整张名单清空** |
| 寿命 | 定时器 **T_DENREG** 非 0 时每条有寿命：取值 1…1 000，**步长 10 s**（10 s…10 000 s）；T_DENREG = 0 表示不启用 |

> **现场意义**：「某个站拒了这批手台以后，它们很久都不再去那片」——这是 Denied 名单在起作用；**关机重开会清掉**。如果 T_DENREG 配了值，到时间也会自己解禁。

### 4.6 手拆一个 C_SYScode（教学虚构数值）

设某 **Large** 网，NET = 5，SITE = 19，PAR = `11₂`，手台写频 DMRLA = 6。

**正着拼**：

```text
  MODEL(2)   NET(4)    SITE(8)        PAR(2)
    10        0101     0001 0011        11
  ─────────────────────────────────────────
  1001 0100 0100 1111₂  =  0x944F
```

**CACH 里的高 14 位**：把最低 2 位（PAR）去掉 → `10 0101 0001 0011₂` = **0x2513**。手台在 CACH 里看到的就是它。

**取 SYS_AREA**：SITE = `0001 0011₂`（8 位），取高 6 位 → `0001 00₂` = **4**。所以这个站属于登记片区 **4**；SITE 18、17、16 也都在片区 4 里（它们的高 6 位相同），SITE 20 开始的高 6 位是 `000101₂` = 5，就是片区 5 了。

**倒着拆**（拿到 0x944F 时）：

1. 最高 2 位 `10` → **Large** → 后面 NET 4 位、SITE 8 位。  
2. 接下来 4 位 `0101` → NET = 5。  
3. 再 8 位 `0001 0011` → SITE = 19。  
4. 最低 2 位 `11` → PAR：A、B 类都允许。

> **纪律**：**先看 MODEL 再分段**。同样的 16 位，如果你（或某个工具）忽略 MODEL、硬按 Small（NET 7 位、SITE 5 位）去拆，就会拆出 NET = `0101 000₂` = 40、SITE = `10011₂` = 19 这种「看起来也挺像」的错数。分析仪如果没让你选模型，**先确认它是按哪个模型拆的**。

### 4.7 验证没过：马上走

正文 6.3.0 有一句很重要的话：**如果手台在多个候选信道上猎，一旦明显得不到服务，就应当马上离开所选信道。**也就是说，验证不过不要「再等等看」，立刻试下一个号。这是猎站速度的关键之一。

还有一个细节（6.3.2.2.1.0）：**验证通过之后、确认之前**，手台算是「在这个 TSCC 上活跃了」，可以**照办**收到的适用 PDU，但**不得发任何随机接入**，凡是要发射的事都不能做。

## 5. 第二道关：确认（Confirmation）——「我真听得清吗？」

### 5.1 规范怎么说（6.3.2.0 / 6.3.2.3，Figure 6.14）

TSCC 获取 = **先验证 C_SYScode**，**通过了再量信号质量（确认）**。Figure 6.14 画的就是这两步：验证失败 → 出；质量低于可接受门限 → 出；两样都过 → 「验证 + 确认」完成。

6.3.2.3 说：手台在控制信道上空闲时，要持续判断出站信号质量（可以看误码率，也可以量射频强度），并且**手台要持有两个门限**：

| 门限 | 什么时候用 |
|------|-----------|
| **猎站门限** | 确认**之前**，猎站时用 |
| **驻留门限** | 确认**之后**，空闲守在 TSCC 上时用 |

NOTE：手台进入**呼叫建立阶段**时，暂停对 TSCC 信号质量的测量。

为什么要两个门限？——**进门的门槛要高一点，赶你走的门槛低一点。**如果进门和离开用同一个数，信号在门槛附近抖一抖，手台就会「刚上去就下来、刚下来又上去」，这在无线里叫**乒乓**。两个门限之间留一段差距，就像空调的「回差」：26 °C 开、24 °C 停，而不是 25 °C 又开又停。（规范只要求「有两个门限」，**具体差多少由厂商定**。）

### 5.2 Annex A 的三条电平线（Table A.7）和 D.1.2.5

| 名字 | Table A.7 的意思 | 白话 |
|------|------------------|------|
| **L_Upper_SHort** | 短猎时**优先**采样的质量门限：高于它的先挑 | 「先找声音大的」 |
| **L_Lower_SHort** | 低于它，手台**不能**在该信道上变为活跃 | 「再小就别去了」 |
| **L_Squelch** | 低于它的物理信道因接收质量不足而被拒（静噪级） | 「基本听不见」的底线 |

D.1.2.5 补充两句：

- 手台**不应**试图在接收电平（或质量）低于规定采集门限的物理信道上变为活跃。  
- **采集门限 L_SHort** 设在 **L_Upper_SHort 到 L_Lower_SHort 之间**（在接收机输入端，或用质量的等价量）；L_Squelch 由**厂商**定。

Table A.7 的数值栏写的是：**单位和数值由厂商自定**。所以本课**一个 dBm 数字都不写**——你在任何资料上看到「L_Short = −xx dBm」，那是某个厂商或某个项目的值，不是 ETSI 的。

把三条线画在一根竖轴上（相对位置示意，**不代表任何数值**）：

```text
   信号强（或误码低）
        ▲
        │   ← 短猎第一遍：只挑这上面的（Fig D.1 写作 L_short / L_SigShort）
   ─────┼───── L_Upper_SHort
        │        L_SHort（采集门限）落在这一段里
   ─────┼───── L_Lower_SHort   ← 低于这里不得变为活跃
        │
   ─────┼───── L_Squelch       ← 全范围被关掉时，短猎改用这条线（D.1.2.4.1）
        │
        ▼
   信号弱（或误码高）
```

> 规范原文里这几个名字大小写不统一（L_SHort / L_Short / L_short / L_SigShort），**认概念、别抠拼写**。

### 5.3 确认之后马上做的两件事

1. **读色码**（6.3.2.4）：确认了控制信道后，手台要读出站正在发的 Colour Code，**之后这个 TSCC 分配的业务信道都用这个色码**。而网络在业务信道上会**丢弃色码不对的上行 PDU**。——这就是第 36 课 §10「号码、频率、色码三件套」里色码的来源之一。  
2. **记下「最近确认的 TSCC」**：下次开机或换回这个网，就能走 Commanded 单信道猎（§6.2）。D.1.0 b) 说这个号存在**非易失存储**里。

## 6. 四段猎站，一段一段拆（Annex D）

> **先说性质**：Annex D 是**资料性（informative）**附录，标题就叫 *Control Channel Hunting Procedures*。它给的是一个**框架**；NOTE 2 明说：**用别的或额外的做法并不禁止，只要满足本文的验证和确认要求。**所以不同厂商的手台猎站「手感」不一样是正常的；但**验证 + 确认 + 确认前不发射**这三条，谁都不能省。

### 6.1 ① Resume：回老地方（D.1.1）

**场景**：在业务信道上忙完了，回到 **Grant 之前最后确认过的那条 TSCC**。

**时限**：从下面四个时刻之一起，手台应当在 **2 个 TDMA 帧**内能收老 TSCC 的出站：

| # | 时刻 | 白话 |
|---|------|------|
| a | 收到要求离开业务信道的 **P_CLEAR** 结束时 | 网络清场 |
| b | 手台在业务信道上发出的**最后一条 P_MAINT（Maint_Kind = DISCON）**结束时 | 自己挂断 |
| c | 在业务信道上收到 **P_AUTH**，而其中地址**不是**当初 Grant 里的任何一个地址时 | 「这条信道上的授权不是给你的」 |
| d | 组呼中，**非主叫**用户按了「结束呼叫」时 | 自己退出组呼 |

**失败出口**：确认前应按 6.3.2.2.1 验证收到的 C_SYScode；**验证失败 → 本段失败 → 进入 Short Hunt。**

> 和第 36 课对上：P_CLEAR 的信道号写 **0** = 回上次确认的 TSCC——这就是 Resume；P_CLEAR 的 CONT 写了**别的号**，D.1.2.2 把它算作 Commanded 的「被点名信道」。（这是把 D.1.1 和 D.1.2.2 合起来读的教学归纳。）

### 6.2 ② Commanded：按命令 / 按记忆，单信道直调（D.1.2.1–D.1.2.2）

**场景**（D.1.2.1）：手台被**指向另一条** TSCC；或者**开机**时仍保有这个网之前活动的有效信息；或者用户**换网**、而手台对新网仍保有有效信息。

**时限**：从下面时刻起，手台应当在 **3 个时隙**内能收被点名的信道：

| # | 时刻 |
|---|------|
| a | 任何**适用于本手台**的有效 **C_MOVE** 结束时 |
| b | **开机**，且手台存有「最近确认过的信道号」的有效记录 |
| c | 用户**换网**，且手台存有新网「最近确认过的信道号」的有效记录 |

**被点名的信道是哪个**（D.1.2.2）：

| 来源 | 号码从哪来 |
|------|-----------|
| P_CLEAR | 它的 **CONT** 信息元素里的逻辑物理信道号 |
| C_MOVE | 它的 **CONT** 信息元素里的信道号（4095 时看 MV_AP 续块，第 36 课） |
| 手台读写存储 | 本网**最近确认过的 TSCC** 的号 |

**铁律 + 出口**：在按 6.3 确认之前**不得在该 TSCC 上发射**；确认失败 → 本段失败 → **进入 Short Hunt**。

> **现场意义**：「拆了旧控制信道，手台每次开机先去旧频点空转一下」——正是 b)：它记着旧号，开机先单信道猎它；失败后进 Short，这本身**无害但慢一点**。要让它彻底忘掉，靠的是：它在新 TSCC 上确认一次（记录被覆盖），以及短名单里撤掉旧号（§7.1）。

### 6.3 ③ Short Hunt：扫短名单（D.1.2.3）

**目的**：先扫这个网**最可能用作 TSCC** 的那些物理信道，尽快恢复服务。

**名单从哪来**（D.1.2.3.0 + D.1.0 c）：

| 项 | 规范怎么说 | 白话 |
|----|-----------|------|
| 初始内容 | 由「外部机构」指定，存在手台**固定非易失存储**里 | 写频 / 出厂写进去 |
| 规模 | D.1.0：存 **Nmax_Ch** 个可能的候选号；手台**应有最多 64 个**值的存储；Table A.6：Nmax_Ch = **50**，描述是「短猎列表中信道的**最少**数目」 | 读法：**至少能放 50 个，建议做到 64 个槽** |
| 空槽 | 未用的存储位置做标记，手台可以忽略 | 名单不必填满 |
| 重复写 | **同一个号可以写好几次**，给这个 TSCC 加「偏置」 | 想让它更常被先试到，就多写几格 |
| 动态加减 | 收到**所选网**的 **C_BCAST（Announce/Withdraw）**，把其中的号**加入**或**移出**猎站范围 | 网络广播「多了一个集合点 / 少了一个」 |

（为什么「重复写」能偏置？因为扫描起点是随机的（§6.6）——一个号占的格子越多，它被排在前面的机会就越大。）

**什么时候进入**（D.1.2.3.1 + 前两段的出口）：

| 入口 | 出处 |
|------|------|
| 开机，且**没有**这个网之前活动的有效信息 | D.1.2.3.1 a |
| 用户换网，且**没有**新网的有效信息 | D.1.2.3.1 b |
| Resume 时 C_SYScode 验证失败 | D.1.1 |
| Commanded 确认失败 | D.1.2.2 |
| Comprehensive 进行中，手台**自己决定**插一轮 | D.1.2.3.1 / D.1.2.4.1 |

**两种扫法**（规范举的例子，不是强制）：

| 做法 | 怎么扫 | 优点 |
|------|--------|------|
| **Figure D.1 那种** | 从名单里**随机位置**开始顺序扫，扫到最高再绕回最低；**扫两遍**——第一遍只找信号强度超过 **L_Short** 的 TSCC，第二遍放宽 | 先抓「够强的」，强站就在附近时最快 |
| **测完再挑** | 从头到尾扫一遍，**记下每个号的信号强度和/或误码率**，扫完再挑最合适的 | 不会因为「先碰到一个刚够格的」而错过更好的 |

**铁律 + 出口**：短猎中找到的 TSCC，在按 6.3 验证并确认之前**不应发射**。短猎**失败**（整张名单都试过没有一个过确认）→ **进入 Comprehensive**，**除非**写频把 Comprehensive 关掉了。

### 6.4 ④ Comprehensive Hunt：扫全范围（D.1.2.4）

**目的**（D.1.0 d）：采样这个网**可能在用的所有**物理信道号；是一个**兜底**：即使 TSCC 用了**平时不用作 TSCC 的号**，也能找到它。

> 为什么会有「平时不用作 TSCC 的号」？正文 6.3.0 提到网络可以用**专用控制信道**，也可以用**非专用控制信道**（NOTE：后者大概只适合信道很少的小型单站网）。控制信道不固定在某几个号上时，短名单就可能扑空，这时只有全范围猎能兜住。

| 项 | 内容 |
|----|------|
| 范围 | 写频（网络个性化）设定的最低号 **Low_Comp_Ch** 到最高号 **High_Comp_Ch** 之间的**每一个**号（D.1.2.4.0）；Table A.6：Low_Comp_Ch 取 1…4 095，High_Comp_Ch 取 Low_Comp_Ch…4 095 |
| 入口 | 短猎**失败**之后（D.1.2.4.1） |
| 失败 | 可以**重复**全猎，直到找到一个过确认的信道 |
| 插播 | 任何时候都可以插一轮短猎，或抽测「看起来可能成功」的信道；不成功再回全猎 |
| 关闭 | 写频可以**抑制**全猎（Table A.6 **Comp_Flag** = True）；此时手台**留在短猎**，采集门限改为 **L_Squelch**，直到找到一个过确认的信道 |
| 铁律 | 确认前不发射 |

**Comp_Flag 的取舍**（概念讨论，具体以项目为准）：关掉全猎，手台不会在一大片号上浪费时间，但**短名单一漏号，那个 TSCC 就永远找不到**（手台只会在短名单上用更低的门限转圈）；保留全猎，慢一点，但能兜住控制信道出现在不常用号上的情况。

### 6.5 Figure D.1：一种可能的实现（文字等价）

Figure D.1 是 Short + Comprehensive 的**一种可能实现**：先搜最可能的候选，**短猎扫两遍**，第一遍只找信号强度超过 L_SigShort 的。

```text
 START
   │
   ▼
 SHORT HUNT 第 1 遍：Sig > L_short             SHORT HUNT 第 2 遍：Sig < L_short
 ┌──────────────────────┐                      ┌──────────────────────┐
 │ Channel from BCAST   │                      │ Channel from BCAST   │   ← 广播加进来的号
 │ Channel #            │                      │ Channel #            │   ← 写频写进去的号
 │ Channel #            │   整表没有够强的      │ Channel #            │
 │ …………                 │ ───────────────────► │ …………                 │
 │ Null                 │                      │ Null                 │   ← 空槽，跳过
 │ Null                 │                      │ Null                 │
 └──────────────────────┘                      └──────────────────────┘
                                                          │ 整表仍失败
                                                          ▼
                                          COMPREHENSIVE HUNT
                                          Channel #, #+1, #+2, … #+…
                                          （Low_Comp_Ch … High_Comp_Ch 逐号）
```

图里「Channel from BCAST」和「Null」两种格子是本课最该记住的细节：**短名单 = 写频的号 + 广播加的号，中间夹着空槽**。

### 6.6 为什么要「随机起点」

D.1.0：多信道的猎站阶段**不规定**采样顺序；但为了**防止偏向某些物理信道**，手台**应当**保证顺序有随机性，二选一：

- 顺序猎（例如从低到高），但**从随机位置开始**；  
- 完全随机地猎。

白话：如果一个城市的手台**全都从名单第一格开始**找，一次全网重启以后，所有手台都会先挤到同一个 TSCC 上去登记，那个 TSCC 的随机接入就被挤爆了；而别的 TSCC 闲着。随机起点让大家**自然分散**。（这是本课对「防偏置」的解释，规范只写了要求。）

### 6.7 规范允许的「额外动作」

D.1.0 还允许：在 Comprehensive 中**完整插一轮别的猎站**、**随时抽测**看起来可能成功的信道；EXAMPLE 甚至说，找到一个过确认的 TSCC 以后**可以继续猎**，期待找到信号更好的。——所以「上网以后过一会儿自己换了个更强的站」，是规范允许的厂商行为。

## 7. 名单是活的：网络怎么帮手台猎（C_BCAST / C_MOVE）

前面说的都是手台自己的事。网络也有四种办法「帮」它：**改名单、报邻居、请你去看看、直接命令你去**。

### 7.1 Ann_WD_TSCC：给短名单加号 / 撤号（6.7.1.1；Table 7.69）

6.7.1.1 原意：这条公告**加入和/或撤销**一个广域系统里正在工作的 TSCC 无线信道；PDU 最多带**两个**逻辑物理信道号；只宣告一个时，另一个置 **CHNULL**；**手台应把这些号加入 / 移出自己的短猎名单**（见 Annex D）。

字段（Broadcast Parms 1 = 14 bit，Parms 2 = 24 bit；C_BCAST 外壳见 Table 7.20）：

| 段 | 字段 | 位 | 含义 |
|----|------|----|------|
| Parms 1 | Reserved | 4 | `0000₂` |
| | Colour code for CH_1 | 4 | 默认 `0000₂` |
| | Colour code for CH_2 | 4 | 默认 `0000₂` |
| | **AW_FLAG1** | 1 | `0` = 把 BCAST_CH1 **加入**猎站列表；`1` = **撤出** |
| | **AW_FLAG2** | 1 | 同上，针对 BCAST_CH2 |
| Parms 2 | **BCAST_CH1** | 12 | CHNULL 或逻辑物理信道号 |
| | **BCAST_CH2** | 12 | 同上 |

两个重要细节：

- **广播加进来的号，关机也不丢**：Table 6.4（猎站相关参数的易失性）把「从收到的公告里加入猎站列表的号（7.2.19.1）」列为**运行中会变、关机时保留**；而「逻辑信道猎站列表」本身是**写频时固定、关机保留**。  
- **绝对频率形式**：号写成 4095 时用 MBC + **BC_AP** 续块，一次只能宣告**一个** TSCC（第 36 课 §9.2；资料库 `Announcement与其余枚举.md` §3.1）。

### 7.2 手拆一条 Ann_WD_TSCC（教学虚构数值）

情境：网络要把 **CHAN 37**（色码 5）加入短名单；只宣告一个。系统码就用 §4.6 的 0x944F，Reg = 1，Backoff = 3（只当一个数，本课不展开退避）。

单块 CSBK 的 10 个字节（不含 CRC）：

```text
  A8 00 00 28 13 94 4F 02 50 00
```

一字节一字节拆：

| 字节 | 十六进制 | 二进制 | 拆出来 |
|------|---------|--------|--------|
| Oct0 | `A8` | `1 0 101000` | LB = 1（单块）、PF = 0、CSBKO = `10 1000₂` = 40 → **C_BCAST** |
| Oct1 | `00` | `0000 0000` | FID = 0（ETSI 标准） |
| Oct2 | `00` | `00000 000` | Announcement_type = `0 0000₂` → **Ann_WD_TSCC**；后 3 位是 Parms1 的前 3 位（Reserved） |
| Oct3 | `28` | `0 0101 000` | Reserved 最后 1 位 = 0；**CC_CH1 = `0101₂` = 5**；CC_CH2 的前 3 位 = 000 |
| Oct4 | `13` | `0 0 0 1 0011` | CC_CH2 最后 1 位 = 0（CC_CH2 = 0）；**AW_FLAG1 = 0（加入）**；AW_FLAG2 = 0；**Reg = 1**；Backoff = `0011₂` = 3 |
| Oct5–6 | `94 4F` | | System Identity Code = **0x944F**（§4.6：Large、NET 5、SITE 19、PAR 11） |
| Oct7–9 | `02 50 00` | `0000 0010 0101 │ 0000 0000 0000` | **BCAST_CH1 = 0x025 = 37**；BCAST_CH2 = 0 = **CHNULL** |

一句话读出来：「**NET 5 / SITE 19 的 TSCC 广播：把 37 号（色码 5）加进你的猎站短名单；这个系统要求登记。**」

> **跨字节纪律（第 34 课又来了）**：CC_CH2 横跨 Oct3 的最后 3 位和 Oct4 的第 1 位；AW_FLAG1 是 Oct4 的**第 2 位**，不是第 1 位。拆 C_BCAST 时最容易错的就是这一行。**一定先把 Oct2–Oct4 连成 24 位的二进制串，再按 5 / 4 / 4 / 4 / 1 / 1 / 1 / 4 切。**

### 7.3 Adjacent_Site：报邻居（6.7.1.7；Table 7.79）

6.7.1.7 原意：这条公告告诉手台**本 TSCC 附近其他站点正在用的 TSCC** 的信息，帮手台在**离开当前 TSCC 覆盖**时找到合适的 TSCC；PDU 同时带**被宣告 TSCC 的逻辑信道号和 C_SYScode**。

字段（Table 7.79）：Parms 1 = 邻站 C_SYScode **高 14 位**；Parms 2 = Active_connection 可用标志（1）+ Active_connection（1）+ 当前站优先级（3）+ 邻站优先级（3）+ Reserved（4）+ **CH_ADJ**（12，邻站 TSCC 的物理信道号，1…4 095）。

规范**没有规定**手台收到它要做什么，只给了一条建议：猎站时，手台**可以用 CH_ADJ 把搜索偏向更可能提供满意服务的信道**。——所以「邻站表」是给猎站的**提示**，不是命令；用不用、怎么用，看厂商。

### 7.4 Vote_Now：「请你过去看一眼」（6.7.1.3；Table 7.71 / 6.81）

6.7.1.3 原意：给**空闲**手台一个机会，去评估公告里指定的**另一个 TSCC** 的信号质量；PDU 带对方 C_SYScode 的子集（高 14 位）和对方的信道号 **CH_VOTE**。字段布局和 Adjacent_Site 几乎一样（CH_VOTE = 4095 时用 VN_AP 续块，第 36 课）。

**网络要「让路」**：手台去评估邻站时**收不到呼叫建立 PDU**，所以 TSCC 在 Vote_Now 之后的 **VOTE_BLK** 个 TDMA 帧里（Table A.6：2…10，本课换算 120…600 ms）只允许发 **MS Address = ADRNULL、Mask = 24 的 Aloha** 或 **C_WACKD**。

**两种策略**：**Radiated Preference**——在 Vote_Now 里**发**各站优先级，手台**应**把优先级和信号质量结合起来选站；**No Radiated Preference**——不发（填 0），手台按写频准则自己选（比如单纯比信号，或用写频里每个 TSCC 的优先级 **Ch_Pref**，Table A.6：50）。优先级值（Table 6.81）：**1 = 最高，2…6 依次，7 = 最低（都算优选站），0 = 非优选 / 不发优先级**。

规范还有三句要紧话：**具体选站算法是厂商私有的**；网络**要么所有 Vote_Now 都带优先级，要么都不带**，混着发可能导致**非常难以预测的行为**；另外 6.3.0 提醒，网络也许**故意**不让手台上信号最好的站（负载分担），而手台若**自己主动**离开 TSCC 去采样，可能错过 TSCC 上的事务。

### 7.5 C_MOVE：直接命令你去（7.1.1.1.3；Table 7.17）

字段（Table 7.17）：LB / PF / CSBKO（`11 1001₂` = 57）/ FID ｜ Reserved 9 ｜ **Mask** 5（与 Aloha 同类，可点名一部分手台）｜ Reserved 5 ｜ **Reg** 1（置 1 = 新 TSCC **要求**变为活跃前登记）｜ Backoff 4 ｜ Reserved 4 ｜ **Physical Channel Number** 12（0 无效；1…4094 单块；4095 → MV_AP）｜ MS address 24。

收到适用的 C_MOVE → 记下 CONT → 离开当前 TSCC（6.3.3.1 e）→ **Commanded 单信道猎**（3 个时隙内能收）→ 确认 → 看 Reg 决定要不要登记。

### 7.6 一句话收拢

**Ann_WD 改「地图」（手台应照办）；Adjacent_Site 给「提示」（怎么用不规定）；Vote_Now 发「邀请」（优先级怎么用厂商定）；C_MOVE 下「命令」（离开并单信道猎）。**

## 8. 丢了怎么办、找到以后怎么办：离开 TSCC 与登记分岔

### 8.1 什么时候离开 TSCC、重新猎（6.3.3.1）

手台在 TSCC 上「活跃但空闲」时，出现下面任何一条就回到猎站：

| # | 情况 | 回到哪一段 |
|---|------|-----------|
| a | 确认后误码率**劣于**驻留门限（§5.1） | 重新猎 |
| b | C_SYScode 与验证过的值**连续 NSYSerr 次**不同（Table A.6：1…3）；**只变了 PAR** 时，仅当本类手台不再被允许才必须走 | 重新猎 |
| c | **T_Nosig** 秒内收不到任何可解码 TSCC PDU（Table A.1：1…15 s） | 重新猎 |
| d | 用户换网 | 有记录走 Commanded，否则 Short |
| e | 收到适用于本手台的 **C_MOVE**，记下 CONT | Commanded |
| f | 登记收到 **C_NACKD(Reg_Denied)**（0x2B） | **登记前所处的那一段** |
| g | 确认后登记收到 **C_NACKD(Reg_Refused)**（0x2A） | **登记前所处的那一段** |
| h | 确认后登记随机接入超时（NRand_NR 次或 TRand_TC，2…60 s） | **登记前所处的那一段** |
| i | 确认后**非登记**业务的随机接入超时 | 离开 TSCC |

**f/g/h 那句「回到登记前所处的那一段」**是本课最容易被忽略的一点：如果手台是在 **Comprehensive 扫到第 80 号**时找到这个 TSCC、登记被拒，它就接着从全范围猎继续，**不是**回到 Resume 重新来。

**正在等信令时**（6.3.3.2，比如已经发了呼叫请求在等回音）：只有 **b、c、e** 三种情况才离开；而且在猎站和重新确认期间，**保持「等信令」状态和相关定时器**——换了个 TSCC，那次呼叫请求的「等待」还算数。

### 8.2 确认之后：三条岔路（6.4.3）

手台**确认 TSCC 之前不得做任何随机接入**。确认以后三条岔路：

| 岔路 | 条件 | 动作 |
|------|------|------|
| a | **Reg = 0**（C_ALOHA 和 CACH 里的 Reg 必须一致） | 不登记、不改登记记录，可直接发起呼叫 |
| b | 本片区 SYS_AREA 在**被拒登记名单**里 | 无权接入，继续猎 |
| c | 没有本片区的**成功登记记录** | 随机接入登记（第 32 课，可能带鉴权，第 35 课） |

c 的四种结局：

| 结局 | 手台怎么做 | 出处 |
|------|-----------|------|
| **Reg_Accepted** 0x62 | 记下 SYS_AREA，替换旧记录 ✔ | 6.4.4.1.2 |
| **Reg_Refused** 0x2A | 继续猎；确认 TSCC、收到合适 C_ALOHA 后重新登记 | 6.4.4.1.3 |
| **Reg_Denied** 0x2B | SYS_AREA 记入被拒名单，进入 TSCC 获取流程 | 6.4.4.1.4 |
| 等不到回音（TNP_Timer 到期） | 进入 TSCC 获取流程 | 6.4.4.1.6 |

几个必须记住的细节：

- **登记之前只许发两样**：登记随机接入请求，或对鉴权挑战的应答（6.4.3）。所以「手台在 TSCC 上、却打不出电话」，先看它是不是还没登记成功（网络会回 `MS_Not_Registered`，第 34 课）。  
- **Refused 会乒乓，Denied 才稳**：6.4.4.1.0 原意——终答是 Refused 时手台继续猎；**找不到别的允许接入的 TSCC，就回到这个 TSCC 重复登记**；系统负载高时这会造成**大量登记业务**。终答是 Denied 时，片区记入被拒名单，6.4.3 b) 禁止手台再向这个 TSCC 登记。所以规范说：**Registration Denied 是把手台从某个 TSCC 拒掉的首选终答。**  
- **登记记录关机保留，被拒名单关机清空**（Table 6.8）。另外 6.4.4.1.9：TSCC 要求登记时，手台在**开机或换网**时要登记。

## 9. 把整套流程走一遍（教学虚构情景）

**写频（虚构）**：短名单 = [37, 37, 52, 101, 空…]（37 写两遍＝偏置）；Low…High = 1…160，Comp_Flag = False；Large、NET 5、ContCAT A、站点授权表为空、DMRLA 6；门牌表用第 36 课的固定计划；「最近确认 TSCC」记录 = **52**。

| 步 | 发生了什么 | 对应 |
|----|-----------|------|
| 1 | 开机，有记录 52 → 3 个时隙内调到 CHAN 52 | Commanded（D.1.2.1 b） |
| 2 | 52 上有 TSCC 同步 → 候选；CACH 高 14 位 = `10 1010 0010 0100₂`（0x2A24）→ MODEL Large、NET `1010₂` = 10 ≠ 5 | 验证 b 不过 → **马上走** |
| 3 | Commanded 失败 → Short；随机起点落在第 4 格（101），第一遍只要「够强」 | D.1.2.3 |
| 4 | 101 低于 L_Short，第一遍跳过；绕回第 1 格 37：够强，CACH = 0x2513 | Fig D.1 |
| 5 | 等到 C_ALOHA：完整 C_SYScode 0x944F → a b c d 全过；SYS_AREA 4 不在被拒名单 | §4.6 |
| 6 | 质量过猎站门限 → **确认**；读色码 5；记「最近确认 = 37」 | 6.3.2.3 / 6.3.2.4 |
| 7 | Reg = 1、无片区 4 记录 → 登记 → Reg_Accepted → 记下 SYS_AREA 4 | 6.4.3 c |
| 8 | 收到 Ann_WD_TSCC：撤 52（AW_FLAG1 = 1），加 101（AW_FLAG2 = 0，色码 3）——就是自测题 5 那条 | §7.1 |
| 9 | 进地下车库，T_Nosig 内无可解码 PDU → 离开 TSCC 进入猎站 | 6.3.3.1 c |
| 10 | 出车库：短名单在 37 / 101 间转，37 先够强 → 确认；片区 4 已登记，**不用再登记** | 6.4.3 |

> 第 2 步的纪律：CACH 只有 **14 位**（去掉了 PAR），别把它当 16 位拆；读到 NET 就够判了。「**先确认位数再拆**」和第 34 课的跨字节坑是同一类错。

## 10. 现场分诊表：「找网慢 / 找不到网 / 来回跳」

| 症状 | 先怀疑 | 怎么核 | 本课 |
|------|--------|--------|------|
| 开机「搜索中」很久，别的机子几秒就好 | 没有「最近确认 TSCC」记录；短名单里没有当前 TSCC 号，一路扫到 Comprehensive | 读写频：短名单、Low/High、Comp_Flag；看手台上网后停在哪个号 | §6.2–§6.4 |
| **永远**上不去，扫频仪看到 TSCC 在发 | ① 号不在短名单且 Comp_Flag = True ② 门牌表把号算错了频率 ③ 验证不过：MODEL / NET / 站点授权表 / PAR 与 ContCAT ④ SYS_AREA 在被拒名单里 | 按 ①→④ 逐条；④ 关机重开即清 | §4、§6.4；第 36 课 |
| 只有**一部分**手台上不了某个 TSCC | **PAR 与 ContCAT**（双 TSCC 负载分担）；或这批手台站点授权表不含该站 | 读这批机的 ContCAT 和授权表 | §4.4 |
| 新加控制信道，老手台不去 | 短名单没有新号，网络没发 Ann_WD_TSCC 加号；或新号超出 Low…High | 分析仪看有没有 C_BCAST type `0 0000₂` 带这个号 | §7.1–§7.2 |
| 拆了旧控制信道，开机总先去旧频点 | 记着「最近确认 TSCC」= 旧号（Commanded），短名单也还留着 | 发 Ann_WD 撤号；让手台在新 TSCC 确认一次 | §6.2 |
| 两站交界，登记被拒后来回跳，控制信道登记请求暴增 | 网络用 **Reg_Refused**：找不到别的就回来再登记 | 看 C_NACKD Reason：0x2A 还是 0x2B；想赶走用 **Reg_Denied** | §8.2 |
| 被拒以后很久不再去那片 | Denied 名单 + T_DENREG | 看 T_DENREG；关机清空 | §4.5 |
| 出地下室 / 隧道后很久才恢复 | T_Nosig 到期后在别的号上转圈；短名单太长或起点随机落在远处 | 短名单精简、把本区 TSCC 多写几格做偏置 | §6.3、§8.1 |
| 手台在 TSCC 上，但打不出电话 | 还没登记成功（Reg = 1 时登记前只能发登记请求） | 看是否收到 `MS_Not_Registered` | §8.2 |

**分诊口诀**：**先问「它在试哪些号」（名单、范围、记录）→ 再问「号对应的频率对不对」（第 36 课门牌表）→ 再问「听到了为什么不认」（验证五步）→ 再问「认了为什么不留」（确认门限）→ 最后问「留了为什么不能用」（登记分岔）。**

**写频检查单（概念版，菜单名以厂商为准）**：短名单与重复次数｜Low / High｜Comp_Flag｜MODEL / NET｜ContCAT｜站点授权表｜DMRLA｜门牌表。**网络侧**：Ann_WD 是否随改造更新｜CH_ADJ 是否指向现役 TSCC｜Vote_Now 优先级「全带或全不带」｜拒登记用 Refused 还是 Denied｜T_DENREG。

## 11. 术语账本 / 口袋速查

| 速查项 | 值 / 出处 |
|--------|-----------|
| 四段顺序 | Resume → Commanded → Short → Comprehensive（D.1.0） |
| Resume / Commanded 时限 | 2 个 TDMA 帧 / 3 个时隙（D.1.1 / D.1.2.1） |
| 短名单 | Nmax_Ch = 50（最少）；建议存储 64；可重复；空槽可忽略 |
| 全范围 | Low_Comp_Ch 1…4 095；High_Comp_Ch Low…4 095；Comp_Flag = True 关闭 |
| 门限 | L_Upper_SHort / L_Lower_SHort / L_Squelch，单位数值厂商定（Table A.7） |
| C_SYScode | 16 bit = MODEL 2 + NET + SITE + PAR 2；CACH 只带高 14 位 |
| PAR | 00 保留 / 01 仅 A / 10 仅 B / 11 A+B |
| 离开 TSCC | NSYSerr 1…3；T_Nosig 1…15 s；TRand_TC 2…60 s |
| 被拒名单 | ≥ 8 条 FIFO；T_DENREG 0 或 1…1 000（× 10 s） |
| 广播 | C_BCAST CSBKO 40；Ann_WD `0 0000₂`、Vote_Now `0 0010₂`、Adjacent_Site `0 0110₂` |
| Vote_Now | VOTE_BLK 2…10 TDMA 帧；优先级 1 最高…7 最低，0 非优选；Ch_Pref 50 |
| C_MOVE | CSBKO 57；Reg 位；4095 → MV_AP |

## 12. 八则误区（看见就打回）

1. **「听到同步就上去。」**——那只是候选；要过验证和确认。  
2. **「找到 TSCC 就能发。」**——确认前绝不发射；Reg = 1 时登记成功前只能发登记请求。  
3. **「猎站失败就从头来。」**——登记失败回到**登记前那一段**；Resume / Commanded 失败进 Short。  
4. **「短名单越长越好。」**——越长扫一遍越慢；该做的是把本区 TSCC **多写几格**偏置。  
5. **「L_Short 是 −xx dBm。」**——规范只说单位数值厂商定。  
6. **「Adjacent_Site 是命令。」**——是提示；命令是 C_MOVE。  
7. **「Refused 和 Denied 差不多。」**——Refused 会让手台回来再试（可能乒乓），Denied 进黑名单。  
8. **「CACH 里就是完整系统码。」**——只有高 14 位，没有 PAR。

## 13. 自测题（含答案）

**题 1.** 手台刚开机，存有「最近确认 TSCC」记录。按顺序写出它可能经历的猎站段，以及每段失败去哪。

<details><summary>答案</summary>

Commanded（单信道猎记录的号）→ 失败进 Short → 失败进 Comprehensive（除非 Comp_Flag = True，则留在 Short、门限改 L_Squelch）→ 失败重复 Comprehensive，可插播 Short。

</details>

**题 2.** 「验证」五步各查什么？哪一步「没存就不查」？

<details><summary>答案</summary>

MODEL、NET、SITE（站点接入授权数据）、PAR（对 ContCAT）、SYS_AREA（不在被拒登记名单）。SITE 授权数据一条都没存时不查。

</details>

**题 3.** 拆 C_SYScode `0x5A6D`：模型、NET、SITE、PAR？若 DMRLA = 4，SYS_AREA 是多少？

<details><summary>答案</summary>

`0101 1010 0110 1101₂`：MODEL `01` = Small → NET 7 位 `0110 100` = 52，SITE 5 位 `11011` = 27，PAR `01` = 只允许 A 类。SYS_AREA = SITE 高 4 位 `1101₂` = 13。

</details>

**题 4.** Short Hunt 名单「至少多少、建议多少、能不能重复、怎么动态改」？

<details><summary>答案</summary>

Nmax_Ch = 50（Table A.6，最少数目）；D.1.0 建议存储最多 64 个值；同一号可重复写以偏置；收到本网 C_BCAST Ann_WD_TSCC 按 AW_FLAG 加入（0）或撤出（1），加入的号关机保留。

</details>

**题 5.** 拆这条单块 CSBK：`A8 00 00 01 D3 94 4F 03 40 65`。

<details><summary>答案</summary>

Oct0 `A8` → LB 1、CSBKO 40 → C_BCAST；Oct1 FID 0。Oct2–4 连起来 `00000 000 │ 0000 0001 │ 1101 0011`：type `0 0000₂` = Ann_WD_TSCC；Parms1 = Reserved `0000`、CC_CH1 `0000`、CC_CH2 `0011` = 3、AW_FLAG1 = **1（撤出）**、AW_FLAG2 = **0（加入）**；Reg = 1；Backoff = 3。系统码 0x944F。Oct7–9 `03 40 65` → BCAST_CH1 = 0x034 = **52**，BCAST_CH2 = 0x065 = **101**。意思：短名单撤掉 52、加入 101（色码 3）。

</details>

**题 6.** 手台在 Comprehensive 扫到某号，确认了 TSCC，登记收到 Reg_Refused。接下来呢？换成 Reg_Denied 呢？

<details><summary>答案</summary>

都回到登记前所处的那一段（Comprehensive）继续猎（6.3.3.1 f/g）。Refused：若找不到别的允许接入的 TSCC，会回来重新登记（负载高时可能造成大量登记）。Denied：该 SYS_AREA 记入被拒名单，之后验证第五步就把这个 TSCC 排除，直到关机或 T_DENREG 到期。

</details>

**题 7.** 正在等一次呼叫的回音，哪几种情况会让手台离开 TSCC？离开后那次「等待」怎么办？

<details><summary>答案</summary>

只有 6.3.3.1 的 b（C_SYScode 连续不符）、c（T_Nosig）、e（C_MOVE）。猎站和重新确认期间保持等信令状态和相关定时器（6.3.3.2）。

</details>

**题 8.** 一个站有两个 TSCC，PAR 分别是 `01₂` 和 `10₂`。某批手台只上第二个，另一批只上第一个，正常吗？若某批手台两个都上不去呢？

<details><summary>答案</summary>

正常：这是用 PAR + ContCAT 做负载分担，A 类上 PAR = 01 的、B 类上 PAR = 10 的。两个都上不去：先查这批手台的 ContCAT 写频（以及 MODEL / NET / 站点授权表），再查片区是否在被拒名单里。

</details>

**题 9.** Resume 和 Commanded 的时限各是多少？分别从什么时刻算起？

<details><summary>答案</summary>

Resume：从 P_CLEAR 结束、最后一条 P_MAINT(DISCON) 结束、地址不匹配的 P_AUTH 结束或非主叫按结束呼叫起，2 个 TDMA 帧内应能收到老 TSCC（D.1.1）。Commanded：从适用的 C_MOVE 结束、或带有效记录的开机 / 换网起，3 个时隙内应能收到被点名信道（D.1.2.1）。

</details>

**题 10（思考）.** 为什么规范要求随机起点？为什么要两个门限？

<details><summary>答案</summary>

随机起点：防止所有手台偏向同一个物理信道（例如全网重启后都挤到名单第一格的 TSCC 上登记）。两个门限：进门门槛高于离开门槛，留出回差，避免信号在门槛附近抖动时手台乒乓。

</details>
