# 第 38 课 · 拨号与本地编址

> DMR 深入学习 · **阶段 E · 集群 Tier III 第 8 课（约 10 课之八）**（接第 37 课「猎站 Hunt」）  
> 适合：已经能让手台找到控制信道、登记成功，也知道 C_RAND 里有 Target 和 Source 两个 24 位地址，但一被问到「**键盘上按的 `40125312` 和空口上跑的那个 24 位地址是什么关系？**」「**同事说他的号是 318，为什么解码器上看到的是 3444259？**」「**拨 `*9*934#` 和直接拨 `934`，C_RAND 里到底哪几个比特不一样？**」「**手台拨外线电话，那串电话号码是怎么送上去的？**」「**两家厂商的手台进同一个集群网，个呼为什么一边打得通一边打不通？**」就答不上来——说不出**用户看到的号码只是『翻译前』的样子，空口永远只认 24 位二进制；翻译规则写在哪、谁必须遵守、谁可以不遵守**——的人  
> 阅读量：约 **30–40 分钟** · **只讲映射规则和比特落点，不贴 FEC、不画完整 MSC** · 要把「**拨号 = 把人看的十进制串，按一套可逆算法翻成 24 位地址 + 几个业务比特；Annex E 是『建议的翻译表』（informative，厂商可以不用），Annex G 是『最低能力要求』（normative，必须能直接编到 1…16 776 415 里任何一个号）；号码长度和号段决定它是个号、组号还是调度台；`*` 开头的修饰符变成 C_RAND 的 Service_Options 比特；`01` / `02` 开头的外线号码不进地址字段，而是把 Target 设成 PSTNI / PABXI，号码本身用 BCD 装进 UDT 另外上传**」钉牢  
> **频谱 / 调制提醒**：RF 仍是 **12.5 kHz** 一条车道，调制仍是 **4FSK**（一个符号 2 bit，**4800 符号/秒 = 9600 bit/s**），时隙 **30 ms**。本课的「地址」在物理上就是 **24 个比特 = 12 个 4FSK 符号 ≈ 2.5 ms 的空口时间**（未计纠错编码）。号码再长、拨号串再花哨，**上了天线都要先变成这 24 个比特**——用户域多几位数字，不会多占一点带宽；真正多占空口的是外线号码那种「额外要上传的数据」（§10）。四句话原文见 `学习推送/加餐_频率带宽与调制解调.md`。

## 1. 为什么本课重要（动机）

第 37 课结尾我们说：**找到网之后，键盘上按的号码怎么变成地址。**前面 37 课里，你见过无数次「Target_address 24 bit」「Source_address 24 bit」，也在第 7 课学过「个呼 / 组呼」。但现场人手里拿的是**手台键盘和写频软件**，嘴上说的是「打 318」「切到 934 组」「按 `*9` 紧急」，没人会说「Target = 0x348E23」。这中间隔着一层**翻译**，而这层翻译恰恰是现场扯皮最多的地方：

- 用户：「我拨同事的号 `318`，手台说『号码无效』。」——多半是**短拨号依赖的『本车队号』没写进手台**，或者这个号在**号段规则外**（比如 IN 写成了 `150`，而合法 IN 从 `200` 开始），手台按规范**不许发起有歧义的呼叫**（§8）。  
- 网管：「解码器上看见 Source = 3444259，用户坚持说自己是 318 号。」——**两个都对**。`318` 是用户域的缩短拨号，`40125318` 是完整车队号，`3444259`（`0x348E23`）是空口地址。三者用一个公式互换（§5）。  
- 集成商：「A 厂手台进 B 厂集群，组呼正常，个呼一半打不到。」——一边按 **Annex E 车队号**换算，一边**直接用空口 ID**；两边对同一串数字的理解不一样（§11）。  
- 调度：「我按 `*1967` 想全呼，旁边站的手台没响。」——`*196x` 是**本站全呼 ALLMSIDL**，只到发起者所在站；要全网得拨 `*198x`（ALLMSID）（§9.4）。  
- 用户：「拨外线手机号，转了半天提示失败。」——外线号码不是一次发完的：先发一个 **Target = PSTNI** 的 C_RAND，网络回 **C_AHOY** 来「要号码」，手台再用 **UDT** 把 BCD 号码交上去；中间任何一步没过，网络回 **C_NACKD**（§10）。  
- 写频：「组号和某个人的个号都是 1001，软件报重复，是不是空口会冲突？」——**空口不冲突**：个号和组号是两套独立的地址空间，靠 Service_Kind（个呼 / 组呼）区分；报重复是**写频软件自己的限制**（§3.2）。

培训台如果只背「手台有个 ID，组有个组号」，后面排障会一直卡住：

> **号码有三副面孔：键盘上按的（拨号串）、屏幕上显示的（用户号码）、空口上发的（24 位地址）。**  
> 翻译规则：**Annex E**（建议性的车队编号与拨号计划，可逆算法）。  
> 底线要求：**Annex G**（强制：能把自己设成、也能呼叫 1…16 776 415 里任何合法地址）。  
> 用户说「打不通 / 号不对 / 显示怪」时，先问：**他按的是哪副面孔？手台用的是哪套翻译？对端用的又是哪套？**

本课目标：画出「用户域 ↔ 空口域」总图；复习 24 位地址空间里哪些号是谁的；拆开 **NAI 9 bit ‖ SSI / SGI 15 bit**，讲清 **NP = NAI + 296**；**手算**个号、组号、调度台号的换算（含反向）；用「位数 + 号段」判断一串数字是什么；把 `*9*` `*8*` `*11*` 等修饰符**落到 C_RAND 的 Service_Options 比特**并手拼几条 C_RAND；讲清外线拨号的 **PSTNI / PABXI + C_AHOY + BCD UDT** 流程和「20 位 / 44 位」两个门槛；讲清 Annex G 为什么是互通的底线；能做现场分诊；为第 39 课「Stun / DGNA / UDT」留好边界。

**本课硬禁令（写进脑子）**：不 dump FEC/CRC/BPTC、不贴完整 MSC/SDL、不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/AnnexE拨号.md` **§0–§9**、`AnnexG本地编址.md` **§0–§5**、`Stun_DGNA_UDT与定时器.md`、`集群协议字段速览.md`、`总索引.md` **集群 / Tier III** 已有编号为准；本课新引用的条款——E.1–E.3.7、G.1、4.3.1、6.6.1.7、6.6.2.1.2、Table 6.40、7.2.9 Table 7.46、7.2.13.1 Table 7.52、B.3.3 Table B.3、Table 7.25——都已在 PDF `TS102361-4_V1.12.1.pdf` 原文里逐条核对过）。**Annex E 是 informative**：本课讲的拨号串是「标准建议的写法」，**具体手台的按键和菜单以厂商说明书为准**。

## 2. 总图：同一个号码的三副面孔

先把整件事画成一张图。左边是人，右边是空口，中间是手台里的一段「翻译程序」（规范叫 MS Application，Figure E.2 叫它 **Bi-Directional Algorithm**，双向算法）：

```text
          用户域（User Interface domain）                     空口域（Air Interface domain）
   ┌──────────────────────────────────────┐            ┌──────────────────────────────────┐
   │ 变长 · 十进制 · CCITT 键盘 0–9 * #      │            │ 定长 · 二进制                       │
   │                                      │   双向算法   │                                  │
   │  318            （3 位短号）           │ ─────────► │  Target_address  24 bit           │
   │  25318          （5 位短号）           │            │  Source_address  24 bit           │
   │  40125318       （8 位完整车队号）      │ ◄───────── │  Service_Kind    4 bit（个/组）    │
   │  *9*934#        （修饰符 + 组号）       │            │  Service_Options 7 bit（紧急/广播/ │
   │  *1987          （全网全呼）           │            │                  优先级…）         │
   │  0113800138000  （外线电话）           │            │  Proxy Flag      1 bit            │
   │  通讯录「老王」   （别名，本质也是号码）  │            │  + 需要时：UDT 里的 BCD 号码        │
   └──────────────────────────────────────┘            └──────────────────────────────────┘
        ↑ 人看、人按、人记                                     ↑ 只认比特，不认「位数」
```

三条要记死的规则：

1. **空口只有 24 位。**不管用户按了 3 位、5 位还是 8 位，C_RAND / C_AHOY / Grant 里的地址字段永远是 24 bit。所以「号码多长」是**用户域**的事，「号码合不合法、属于谁」是**空口域**的事。  
2. **翻译必须可逆。**E.3.0 原文：映射用的是 *a number of reversible coding algorithms*。你按 `40125318` 能算出 `0x348E23`；手台收到来电 Source = `0x348E23`，也要能算回 `40125318`（或在同车队时显示 `318`）。来电显示就是反向翻译。  
3. **翻不出来就不许打。**E.1：如果用户按了一串**不属于任何拨号算法**的数字，手台**不应尝试建立呼叫**，要给用户提示（「号码无效」「业务不可用」之类）。原因很朴素：一串乱号在空口上可能恰好落在某个网关地址或保留地址上，会造成**不确定的呼叫建立**。

再把「两个附件」的分工钉牢——这是本课最容易混的地方：

| | **Annex E** 车队编号与拨号计划 | **Annex G** 原生编址（MS Native Addressing Plan） |
|---|---|---|
| 性质 | **informative**（信息性、建议） | **normative**（规范性、必须） |
| 管什么 | 用户按什么 ↔ 空口发什么（翻译表） | 手台**至少**要能直接编到哪些空口地址 |
| 内容 | NAI/SSI/SGI、NP、FIN/IN、FGN/GN、调度台、全呼串、修饰符、外线前缀 | 三条：本机地址可设在 1…16 776 415；被叫可编到 1…16 776 415；若支持全呼，能编 ALLMSIDL/Z/ID |
| 厂商能不能不照做 | **能**（E.1 明说尊重厂商设计独立性） | **不能** |
| 篇幅 | 约 10 页 | 约 1 页（只有 G.1） |

一句话：**Annex E 告诉你「推荐这样翻」，Annex G 告诉你「不管你怎么翻，空口上这些号都得够得着」。**

把它放回前几课的总图里，拨号发生在「守 TSCC → 登记」之后、「发 C_RAND」之前：

```text
开机 → 猎站（第37课）→ 验证+确认 → 登记（第32课）
     → 用户按键：拨号串 ──[本课：双向算法]──► Target(24) + Service_Kind + Service_Options (+Proxy)
     → C_RAND 随机接入（第32课 Aloha）
     → TSCC：C_WACKD / C_QACKD / C_NACKD（第34课 Reason）
             C_AHOY（查被叫 / 要外线号码 / 鉴权，第35课）
     → Grant（第33课）→ 业务信道频率 CHAN（第36课）→ 通话
```

## 3. 先复习：24 位地址空间里，哪些号是谁的

### 3.1 24 位有多大

24 bit 一共 \(2^{24} = 16\,777\,216\) 个值，十六进制 `000000`…`FFFFFF`，十进制 `0`…`16 777 215`。这些值**不是**全都能给手台用，规范把它切成了几块：

```text
十六进制          十进制              给谁用（Part 4 视角）
000000            0                  ADRNULL：空地址，不属于任何实体（列表空位、填充）
000001 … 0FFFFF   1 … 1 048 575       个号：Annex E 说保留给 MPT1327 迁移（E.3.1.1）
100000 … FFFCDF   1 048 576 … 16 776 415   DMR 个号 / 组号的主力区（Annex E 车队号都落在这里）
FFFCE0 … FFFEBF   …                  保留等（Part 1 Annex A 分区）
FFFEC0 … FFFED7   16 776 896 …        Tier III 网关 / 服务标识（Part 4 Table A.8）：PSTNI、PABXI、REGI、AUTHI、STUNI…
FFFED8 … FFFFFC   …                  保留 / 其他分区（Part 1 Annex A 还细分了系统网关、自定义、全呼等小区段，本课不展开）
FFFFFD            16 777 213         ALLMSIDL：本站全呼
FFFFFE            16 777 214         ALLMSIDZ：部分站点全呼
FFFFFF            16 777 215         ALLMSID：全网全呼
```

注意 Annex G 的上界 **16 776 415 = `FFFCDF`**，正好是「普通用户号」的最后一个值；再往上就进了保留区和网关区。**普通个号、组号都不该编到 `FFFCE0` 以上**——那一带的值在 Tier III 里有特殊意义（第 35 课鉴权用的 AUTHI 等服务 / 网关标识都在那里）。

> 小插曲：Annex E 说 `1…0FFFFF` 「保留给 MPT1327 迁移」，Annex G 却要求 `1…16 776 415` 全都能编。两句话不矛盾：E 说的是「**按我这套车队计划**，DMR 号从 `100000` 起编」；G 说的是「**手台能力上**，这些低号你也得能直接填进去」。现场很多常规网（Tier II）和业余网的号就是 `1001`、`3108128` 这种低于 `100000` 或者落在任意位置的号——Annex G 保证这些号在集群手台上也能用（§11）。

### 3.2 个号和组号是两套平行空间

clause **4.3.1** 的 NOTE 说得很清楚：**个体地址和 talkgroup 地址分属独立的地址空间**；数值可以相同，PDU 里用**个呼 / 组呼业务类型**区分，没有歧义。

```text
个号空间：  000001 ……… 3444259 ……… FFFCDF
组号空间：  000001 ……… 3444259 ……… FFFCDF
            ↑ 同一个数值，在两套空间里是两个不同的东西
区分靠：C_RAND 的 Service_Kind（IND_V_SRV = 0000 / GRP_V_SRV = 0001）
        Grant 的类型（第33课：PV_GRANT 个呼 / TV_GRANT 组呼 …）
```

所以「组号 1001 和张三的个号 1001 冲突吗？」——**空口不冲突**。写频软件拒绝重复，是软件为了防止用户在通讯录里选错，不是协议限制。Puget Sound DMR Coalition 的入门文章也特意提醒过：Private ID 和 Talkgroup ID 数值可以一样，但很多手台的写频软件**不接受**重复（见文末外链 4）。

### 3.3 地址在空口上是怎么「长」的

24 bit 在 PDU 里就是**连续 3 个字节，高位在前**（Big-endian）。比如 `0x348E23`：

```text
十六进制：  34        8E        23
二进制：    0011 0100 1000 1110 0010 0011
            └───────── 24 bit ─────────┘
十进制：    3×16^5+4×16^4+8×16^3+14×16^2+2×16+3 = 3 444 259
```

C_RAND 里 Target 在 **Octet 4–6**，Source 在 **Octet 7–9**（第 32 课登记时见过 C_RAND，本课 §9.3 会把它逐字节手拼出来）。

## 4. Annex E 的骨架：NAI ‖ SSI / SGI，以及 NP = NAI + 296

### 4.1 24 位地址的两段切法

E.3.1.1 规定：按车队计划编号时，24 位地址切成两段——

| 段 | 名称 | 比特 | 范围 | 白话 |
|---|---|---|---|---|
| 高 9 位 | **NAI**（Network Area Identity，网络区域标识） | 9 | DMR 用 **32…511**（0…31 留给 MPT1327 迁移） | 「区号」 |
| 低 15 位 | **SSI**（Short Subscriber Identity，短个体标识）或 **SGI**（Short Group Identity，短组标识） | 15 | 1…32 767（**0 无效**） | 「区内号」 |

```text
bit 23                 bit 15 bit 14                                   bit 0
 ┌──────────────────────────┬─────────────────────────────────────────────┐
 │      NAI（9 bit）          │          SSI 或 SGI（15 bit）                 │
 └──────────────────────────┴─────────────────────────────────────────────┘
 公式：AI 地址 = NAI × 2^15 + SSI = NAI × 0x8000 + SSI = (NAI << 15) | SSI
```

为什么是 9 + 15？因为 \(2^{15} = 32\,768\)，正好是一个「区」里能放的号数；\(2^9 = 512\) 个区。NAI 从 32 起，所以 DMR 号最小是 \(32 × 32768 = 1\,048\,576 = \texttt{0x100000}\)——这就是 E.3.1.1 说「DMR 个号从 `100000` 开始」的来历。**这不是巧合，是同一件事的两种说法。**

### 4.2 SSI 和 SGI 里的号段

| 值 | SSI（个号空间） | SGI（组号空间） |
|---|---|---|
| 0 | NULL，无效 | 保留 |
| 1 … 7 000 | 普通个号 | **组号**（每个 NP 最多 7000 个车队组号） |
| 7 001 … 32 200 | 普通个号 | 保留 |
| 32 201 … 32 767 | **特殊个号**（调度台就落在这里，§7） | 32 767 = **车队全呼**；其余保留 |

个号空间里 1…32 200 是给普通手台的（32 200 这个数怎么来的，§5.3 会算给你看）。

### 4.3 NP：给人看的「三位区号」

NAI 是二进制里的 9 位，人不好记。Annex E 给它配了一个**三位十进制的前缀 NP**（Network Prefix，网络前缀）：

$$
NP = NAI + 296
$$

- NAI 32 → NP **328**；NAI 510 → NP **806**。许可的 NP 是 **328…806，共 479 个**（E.3.1.2）。  
- **NAI = 511**（对应 NP 807）不给普通手台，**留给特殊网关**。  
- NP **200…327** 保留给 **MPT1327 迁移**。

为什么偏偏加 296？看一眼它的「祖宗」就明白了。英国 MPT1327 集群的编号标准叫 **MPT1343**，它的车队前缀（Fleet Prefix）范围恰好是 **200…327**（RadioReference 的 MPT-1327 词条写得很清楚，见文末外链 3）。DMR 把 **328 起**的前缀接着往后排，前面 200…327 原样留给老 MPT 网迁移过来的用户——**新老两套号码在用户眼里永远不会撞车**。296 就是为了让 NAI = 32 刚好对上 NP = 328 而凑出来的偏移量。

| 你看到的 | 它是什么 | 换算 |
|---|---|---|
| NP = 401 | 用户域三位前缀 | NAI = 401 − 296 = **105** |
| NAI = 105 | 地址高 9 位 | 105 × 0x8000 = **0x348000**（这个区的起点） |
| 这个区的号 | `0x348001` … `0x34FFFF` | 低 15 位就是 SSI / SGI |

后面所有例子都用 **NP = 401**（NAI = 105）这个**示例网络**，你会发现所有地址都以 `0x34…` 开头——因为它们都在同一个「区」里。

### 4.4 Annex E 的号码家族一览

先给全貌，后面三节一个个拆：

```text
                       ┌─ 个号（Individual）：NP ‖ FIN ‖ IN      8 位，例 401 25 312
                       │      FIN 20–41（大车队，每队 700 人）/ 42–89（小车队，每队 350 人）
用户号码（十进制）  ────┼─ 组号（Group）     ：NP ‖ FGN ‖ GN      8 位，例 401 25 934
                       │      FGN 20–89，GN 900–999（每队 100 个组）
                       ├─ 调度台（Dispatcher）：NP ‖ 10n         6 位，例 401 105
                       ├─ 全呼（All Call）  ：*196x / *197x / *198x
                       └─ 外线（Line）       ：01… PSTN / 02… PABX
缩短拨号：本网 NP 已预置 → 5 位（FIN‖IN / FGN‖GN）；本车队也预置 → 3 位（IN / GN / 10n）
```

**FIN**（Fleet Individual Number）= 车队号（个体用），**IN**（Individual Number）= 车队内个号；**FGN**（Fleet Group Number）= 车队号（组用），**GN**（Group Number）= 车队内组号。FIN 和 FGN 取同一个范围 20…89，规范说「每个 NP 有 70 个组车队，**与 FIN 对应**」——也就是说，**25 车队的人（FIN 25）一般就用 25 车队的组（FGN 25）**。

## 5. 个号：NP ‖ FIN ‖ IN ↔ 24 位地址

### 5.1 规范原文的两条公式（E.3.1.3.3）

完整个号 8 位：**NP（3 位）‖ FIN（2 位）‖ IN（3 位）**，例如 `401 25 312`。

| 车队类型 | FIN 范围 | IN 范围 | 每队人数 | 车队数 |
|---|---|---|---|---|
| **大车队** | 20 … 41 | 200 … 899 | 700 | 22 |
| **小车队** | 42 … 89 | 200 … 549 | 350 | 48 |

$$
\text{FIN } 20\ldots41:\quad AI = (NP-328)\times \texttt{0x8000} + (FIN-20)\times 700 + (IN-200) + \texttt{0x100001}
$$

$$
\text{FIN } 42\ldots89:\quad AI = (NP-328)\times \texttt{0x8000} + (FIN-42)\times 350 + (IN-200) + \texttt{0x103C29}
$$

（原文写作 `8 000₁₆`、`100 001₁₆`、`103C29₁₆`，下标 16 表示十六进制。外链 2 那篇 DJ0WH 的博客专门提醒过：**带 h / ₁₆ 的数先换成十进制再算**，混着算是最常见的错。）

### 5.2 公式背后的「隐藏结构」（看懂了就不用背）

把 `0x100001` 拆开：`0x100000 = 32 × 0x8000`，所以

$$
(NP-328)\times\texttt{0x8000} + \texttt{0x100000} = (NP-328+32)\times\texttt{0x8000} = (NP-296)\times\texttt{0x8000} = NAI \times \texttt{0x8000}
$$

也就是说，**公式的前半截就是「把 NAI 放到高 9 位」**，剩下的部分全是 SSI：

$$
\text{大车队：}\; SSI = (FIN-20)\times700 + (IN-200) + 1 \qquad (1 \ldots 15\,400)
$$

$$
\text{小车队：}\; SSI = 15\,401 + (FIN-42)\times350 + (IN-200) \qquad (15\,401 \ldots 32\,200)
$$

（`0x103C29 − 0x100000 = 0x3C29 = 15 401`。）

现在你能自己验证 E.3.1.3.1 里那个怪数 **32 200**：大车队一共 \(22 × 700 = 15\,400\) 个号，小车队一共 \(48 × 350 = 16\,800\) 个号，合计 **32 200**——正好是「普通 SSI」的上限。大车队用完 1…15 400，小车队从 15 401 接着排，一个空位都不浪费。**规范里的每一个常数都是算出来的，不是拍脑袋。**

```text
一个 NP（= 一个 NAI 区）里的 15 位 SSI 怎么分：
SSI   1 ─────────── 15 400 │ 15 401 ─────────── 32 200 │ 32 201 ─── 32 767
      大车队 FIN 20–41        │ 小车队 FIN 42–89           │ 特殊个号（调度台在 32 481–32 490）
      每队 700 人 × 22 队      │ 每队 350 人 × 48 队         │
```

### 5.3 手算：`40125312`

示例网络 NP = 401，车队 FIN = 25（大车队），个号 IN = 312。

| 步骤 | 计算 | 结果 |
|---|---|---|
| ① NAI | 401 − 296 | **105** |
| ② 区起点 | 105 × 32 768 | 3 440 640 = `0x348000` |
| ③ SSI | (25 − 20) × 700 + (312 − 200) + 1 = 3500 + 112 + 1 | **3 613** = `0x0E1D` |
| ④ AI | 3 440 640 + 3 613 | **3 444 253 = `0x348E1D`** |
| 核对（原公式） | 73 × 32 768 + 3500 + 112 + 1 048 577 = 2 392 064 + 3 612 + 1 048 577 | 3 444 253 ✓ |

同车队的 `318` 号：SSI = 3500 + 118 + 1 = 3 619 → **`0x348E23` = 3 444 259**。这就是 §1 那位「坚持自己是 318 号」的用户在解码器上的样子。

### 5.4 手算：小车队 `40157488`

FIN = 57（小车队），IN = 488：

| 步骤 | 计算 | 结果 |
|---|---|---|
| ① NAI | 401 − 296 | 105 → 区起点 `0x348000` |
| ② SSI | 15 401 + (57 − 42) × 350 + (488 − 200) = 15 401 + 5 250 + 288 | **20 939** = `0x51CB` |
| ③ AI | 3 440 640 + 20 939 | **3 461 579 = `0x34D1CB`** |

### 5.5 反向：解码器上看到 `0x34A0E0`，用户号码是多少？

这是现场最常用的方向——**抓到空口地址，要翻回人话**。

```text
① 高 9 位 NAI = 0x34A0E0 >> 15 = 105        → NP = 105 + 296 = 401
② 低 15 位 SSI = 0x34A0E0 & 0x7FFF = 0x20E0 = 8 416
③ 8 416 ≤ 15 400 → 大车队：k = SSI − 1 = 8 415
   FIN = 20 + ⌊8 415 / 700⌋ = 20 + 12 = 32
   IN  = 200 + (8 415 mod 700) = 200 + 15 = 215
④ 用户号码 = 401 32 215
```

手算小技巧：「>> 15」不好心算的话，先把 24 位地址写成十进制，除以 32 768 取整得 NAI，余数就是 SSI：3 449 056 ÷ 32 768 = 105 余 8 416。

若 SSI 落在 15 401…32 200，就按小车队：k = SSI − 15 401，FIN = 42 + ⌊k/350⌋，IN = 200 + (k mod 350)。若落在 32 201 以上，先看是不是调度台（§7）。

### 5.6 边界值表（排障时对照用）

| 用户号码 | 含义 | AI（十六进制） | AI（十进制） | NAI / SSI |
|---|---|---|---|---|
| `32820200` | 最小的号：NP 328、FIN 20、IN 200 | `100001` | 1 048 577 | 32 / 1 |
| `32841899` | 大车队最后一号 | `103C28` | 1 063 976 | 32 / 15 400 |
| `32842200` | 小车队第一号 | `103C29` | 1 063 977 | 32 / 15 401 |
| `80689549` | 最大的号：NP 806、FIN 89、IN 549 | `FF7DC8` | 16 743 880 | 510 / 32 200 |

最大的 Annex E 个号 `FF7DC8` 离 Annex G 上界 `FFFCDF` 还有一段——那一段（以及 `100000` 以下）Annex E 车队计划用不到，但 **Annex G 要求手台也能直接编进去**。

### 5.7 哪些号是「无效号」

手台按 E.1 应**拒绝**下面这些（例子都用 NP 401）：

| 拨号 | 为什么无效 |
|---|---|
| `40125150` | IN = 150 < 200 |
| `40125950` | 在个号位置上 IN = 950 > 899——但它其实是**合法组号**（GN 950），手台得按「组」翻（§6、§8） |
| `40157600` | FIN 57 是小车队，IN 最大 549 |
| `40190312` | FIN = 90，超出 20…89 |
| `20025312` | NP = 200，属于 MPT1327 迁移保留段，不是 DMR NP |

## 6. 组号：NP ‖ FGN ‖ GN ↔ 24 位地址

### 6.1 公式（E.3.1.4.3）

完整组号 8 位：**NP ‖ FGN ‖ GN**，FGN 20…89，**GN 900…999**（每个车队 100 个组；每个 NP 70 × 100 = **7 000** 个组号）。

$$
ID = (NP-328)\times\texttt{0x8000} + (FGN-20)\times100 + (GN-900) + \texttt{0x100001}
$$

同样拆出隐藏结构：**高 9 位还是 NAI**，低 15 位是

$$
SGI = (FGN-20)\times100 + (GN-900) + 1 \qquad (1 \ldots 7\,000)
$$

——和 E.3.1.4.1「SGI 1…7000 是组号」严丝合缝。组号**不分大小车队**，所有车队都是 100 个组。

### 6.2 手算：`40125934`

| 步骤 | 计算 | 结果 |
|---|---|---|
| ① NAI | 401 − 296 | 105 → `0x348000` |
| ② SGI | (25 − 20) × 100 + (934 − 900) + 1 = 500 + 34 + 1 | **535** = `0x0217` |
| ③ ID | 3 440 640 + 535 | **3 441 175 = `0x348217`** |

对比一下：同一个 25 车队，**个号 312 的 SSI 是 3 613，组号 934 的 SGI 是 535**——数值天差地别，但即使碰巧相等也不冲突，因为它们在两套空间里（§3.2）。

### 6.3 车队全呼：SGI = 32 767

E.3.1.4.1 还规定了一个特殊组号：**SGI = 32 767 = 整个车队的全呼**。在 NP 401 里就是 `(105 << 15) | 0x7FFF` = **`0x34FFFF`**（3 473 407）。

它和后面 §9.4 的三种「全呼」（ALLMSIDL / Z / ID）**不是一回事**：

| | 车队全呼（SGI 32 767） | ALLMSIDL / ALLMSIDZ / ALLMSID |
|---|---|---|
| 地址 | 每个 NAI 区各一个，如 `0x34FFFF` | 全系统固定的 `FFFFFD` / `FFFFFE` / `FFFFFF` |
| 怎么路由 | **按组呼路由**：送到这个车队有手台登记的所有站 | **按站点路由**：本站 / 一部分站 / 全部站 |
| 叫到谁 | 这个车队的人 | 覆盖范围内所有手台（不分车队） |

原文的说法是：车队全呼「本质上是一个 TG 呼叫，被路由到这个车队的 MS 已登记的所有站点」，不像另外三种按站点路由。

## 7. 调度台：NP ‖ 10n，以及单键短拨

### 7.1 六位调度台号（E.3.2 / Table E.3）

调度台用 **6 位**：**NP ‖ 10n**（n = 0…9），走**个号空间**：

$$
AI = (NP-328)\times\texttt{0x8000} + 32\,481 + n + \texttt{0x100000}
$$

拆开看：SSI = **32 481 + n**，即 32 481…32 490——落在 §4.2 说的「**特殊个号区 32 201…32 767**」里，永远不会和普通手台（≤ 32 200）撞号。

手算 `401105`（n = 5）：SSI = 32 486 = `0x7EE6`，AI = `0x348000 + 0x7EE6` = **`0x34FEE6`**（3 473 126）。

注意公式尾巴是 `+ 0x100000`（不是个号公式里的 `0x100001`），因为 32 481 本身已经是「从 1 数起」的 SSI 值了。**看公式尾巴的 1 有没有，是检验你是否抄对原文的好办法。**

本网 NP 已经预置时，调度台可以只拨 **3 位** `10n`。

### 7.2 单键短拨（E.3.3）

更省事的是**按一个数字键 0…9**：手台里最多存 **10 个预置个号**，每个键对应一个。呼叫类型是**普通优先级的个呼**。按了一个没设置的键，手台要提示「呼叫无法建立」。调度台那边如果想先把来电排队，可以进入 **callback**（回叫）状态。

现场对照：很多行业手台上的「一键呼调度」，在协议上就是这么回事——按键对应一个预存的 24 位个号，发出去的是一个**普通个呼 C_RAND**，没有任何「调度专用」比特。**调度台之所以是调度台，是因为它的号落在特殊 SSI 段、以及网络侧怎么对待它，不是因为手台发了什么特殊信令。**

## 8. 位数 + 号段 = 号码类型（手台怎么「听懂」你按的是什么）

### 8.1 判断树

用户按完数字、按 `#` 或 PTT 发起时，手台按下面的思路判断（这是把 E.3.1–E.3.7 的规则合在一起画的学习用判断树，**不是规范原图**；具体实现以厂商为准）：

```text
拨号串
 ├─ 以 * 开头 ───────────► 修饰符 / 功能串 / 全呼串（§9）
 ├─ 以 # 开头 ───────────► 取消类功能串（#41# #48# #0#）（§9.5）
 ├─ 以 01 开头且 ≥ 6 位 ──► 外线 PSTN（§10）
 ├─ 以 02 开头且 ≥ 6 位 ──► 外线 PABX（§10）
 └─ 纯数字，看位数：
     ├─ 1 位  0–9            → 单键短拨调度台（查预置表）
     ├─ 3 位  100–109        → 本网调度台 10n
     │        200–899        → 本车队个号 IN
     │        900–999        → 本车队组号 GN
     │        其他           → 无效，拒绝
     ├─ 4 位  1000–8999 / 9600–9699 → 规范保留（Table E.9），按规范不应解释
     ├─ 5 位  FIN‖IN 或 FGN‖GN（前两位 20–89；后三位 200–899 个号 / 900–999 组号）
     ├─ 6 位  NP‖10n         → 调度台（NP 328–806）
     ├─ 8 位  NP‖FIN‖IN 或 NP‖FGN‖GN
     └─ 其他 / 越界           → 无效，拒绝（E.1：不许发起有歧义的呼叫）
```

几个很漂亮的「不撞车」设计，值得体会：

- **3 位号段互不重叠**：100–109 调度台、200–899 个号、900–999 组号。所以缩短拨号时，手台**只看后三位就知道是人还是组**。  
- **以 0 开头的多位串永远不是本网号码**：NP 最小 328，FIN/FGN 最小 20，IN 最小 200——除了「单键 0」这个调度台短拨之外，没有任何合法用户号码以 0 开头。所以 `01`、`02` 拿来做外线前缀，**跟车队号永远不冲突**。  
- **8 位个号和 8 位组号靠最后三位区分**：`40125934` 是组（934 ≥ 900），`40125312` 是人。

### 8.2 缩短拨号依赖「预置」

| 用户按 | 手台需要预置 | 补全后 |
|---|---|---|
| `312` | 本网 NP = 401、本车队 FIN = 25 | `40125312` |
| `57488` | 本网 NP = 401 | `40157488` |
| `934` | 本网 NP = 401、本车队 FGN = 25 | `40125934`（组） |
| `105` | 本网 NP = 401 | `401105`（调度台） |

这就解释了 §1 第一条：**「拨 318 提示号码无效」，最常见的原因是写频里没填本车队号（或填错了 NP）**，手台补全不了，按规范只能拒绝。另外 E.1 允许厂商设**最短 / 最长拨号长度**（比如禁止 1 位拨号防误触），被这个参数挡住也会表现为「拨不出」。

### 8.3 来电显示：反向翻译 + 「能省就省」

收到来电时，手台拿 C_AHOY 或 Grant 里的 Source（24 位），按 §5.5 反算出 NP / FIN / IN。常见的显示策略是「**同车队只显示 IN，同网不同车队显示 FIN‖IN，跨网显示全 8 位**」——这是规范「缩短拨号」思路的自然延伸，**具体显示方式厂商自定**。

如果来电地址**不在 Annex E 能翻译的范围里**（比如 `0x000400`，或者一个 SSI 落在保留段的号），手台就只能显示原始数字——这正是下一节 Annex G 要求手台能处理的情况。

> 原文一处小出入：E.1 说「按本附件算法，一个个号可以用**七位**十进制完整表示」，但 E.3.1.3.2 定义的完整个号是 **8 位**（NP 3 + FIN 2 + IN 3）。资料库 `AnnexE拨号.md` §9 已标注：**以 E.3.1 的 8 位为准**。

## 9. `*` 开头的串：修饰符怎么变成 C_RAND 里的比特

### 9.1 语法（E.3.5）

```text
* <修饰码> * <目的号码> #
例：  *9*934#        紧急呼叫 → 本车队组 934
      *8*312#        高优先级呼叫 → 本车队个号 312
      *8*1*312#      优先级 1 呼叫 → 312
      *18*934#       高优先级广播呼叫 → 组 934（原文示例）
      *057*234#      状态投递：状态 57 → 个号 234
```

规则：`*` 是分隔符；用 `#` 或 PTT 发起。**双态功能**（如设 / 取消呼叫转移）用 `*` 开头表示「设」，用**同一个码但 `#` 开头**表示「清」（`*41*…#` / `#41#`）。不冲突的修饰符可以组合；**冲突的不许拨**——原文举的例子是 `*9`（紧急）不能和 `*8`（优先）连着用。

> 关于 `*18*`：原文示例把「高优先级广播」写成 `*18*934#`，看上去是把 `*11`（广播）和 `*8`（优先）合写成了 `*18`，但组合的书写规则原文**没有逐字说明**。现场以厂商说明书为准。

### 9.2 修饰符一览（Table E.8 + E.3.6）

| 拨号串 | 含义 | 在空口上落在哪 |
|---|---|---|
| `*11*nn…#` | 广播呼叫 Broadcast | Service_Options **BCAST_SV = 1**（只适用于组呼） |
| `*8*nn…#` | 优先呼叫（E.3.0：High Priority，PRIORTY_SV = 10₂） | **PRIORTY_SV = 10** |
| `*8*1*` / `*8*2*` / `*8*3*` | 优先级 1 / 2 / 3 | PRIORTY_SV = 01 / 10 / 11（Table 7.52：Priority 3 最高） |
| `*9*nn…#` | 紧急 Emergency | **EMERG = 1**，且按 Table 6.40 NOTE 3，PRIORTY_SV 置 00 |
| `*12*nn…#` | MS–MS 全双工个呼 | 另一种业务（Table 6.73），不是同一个 C_RAND 改一位 |
| `*0ss*nn…#` | 状态投递（状态 ss） | 状态业务（Table 6.57） |
| `*41*nn…#` / `#41#` | 本机呼叫转移 / 取消 | 呼叫转移业务（Table 6.61 / 6.64） |
| `*2*nn…*dddd#` | UDT 短数据 | UDT 业务（第 39 课） |
| `*7*i…*i…*i…*i…#` | 呼叫 IP 地址（前导零可省：`213.48.132.2`） | 目的为 IP 网关（IPI，Table A.8） |
| `*#` | 放弃 / 取消呼叫 | 还没发 C_RAND → 放弃；已发 → 取消；在业务信道上 → 取消 |
| `*47#` | 显示本机号码 | 不上空口 |
| `*48#` / `#48#` / `#0#` | 设回叫 / 取消回叫（仅语音）/ 取消回叫请求 | — |
| `#` 或 PTT | 振铃时接听 | — |
| `*46#` / `*461#` / `*462#` | 加密切换 / 关 / 开 | **NOTE：本 TS 不定义加密**（第 35 课说过，加密在 Part 4 之外） |

没拨任何优先级修饰时，默认 **Normal（low）**（E.3.0）。优先级的作用是：**TSCC 可以管理一个呼叫队列，让高优先级的呼叫更快「熟」**——但队列怎么管，规范**不规定**（E.3.0 原文：*procedures … are not prescribed*）。所以「加了 `*8` 也没快多少」不一定是故障，可能是网络侧根本没做优先级排队。

### 9.3 动手：把拨号串拼成 C_RAND（语音业务）

C_RAND（随机接入请求，CSBKO = `011111₂` = 31）的 10 个字节（Table 7.25 + Table 6.40；后面还有 2 字节 CRC，本课不算）：

```text
Octet 0 : LB(1)=1  PF(1)=0  CSBKO(6)=011111           → 1001 1111 = 0x9F
Octet 1 : FID(8) = 0000 0000                           → 0x00
Octet 2 : Service_Options(7) ‖ Proxy(1)
          Service_Options 从高到低：EMERG · Privacy · SUPED_SV · BCAST_SV · Reserved · PRIORTY_SV(2)
Octet 3 : SUPED_VAL(2) · ALS(1) · Reserved(1) ‖ Service_Kind(4)
          Service_Kind：IND_V_SRV = 0000（个呼）/ GRP_V_SRV = 0001（组呼）
Octet 4–6 : Target_address 或 Gateway（24 bit）
Octet 7–9 : Source_address（24 bit，主叫自己的个号）
```

假设主叫是 `40125312`（`0x348E1D`），本车队组 934 是 `0x348217`，318 号是 `0x348E23`：

| 用户拨 | Service_Options（7 bit） | Octet 2 | Octet 3 | 完整 Octet 0–9 |
|---|---|---|---|---|
| `318`（普通个呼） | 000 0000 | `00` | `00` | `9F 00 00 00 34 8E 23 34 8E 1D` |
| `934`（普通组呼） | 000 0000 | `00` | `01` | `9F 00 00 01 34 82 17 34 8E 1D` |
| `*9*934#`（紧急组呼） | **1**00 0000 | `80` | `01` | `9F 00 80 01 34 82 17 34 8E 1D` |
| `*8*934#`（高优先组呼） | 000 00**10** | `04` | `01` | `9F 00 04 01 34 82 17 34 8E 1D` |
| `*18*1*934#`（优先级 1 广播组呼） | 000 **1**0**01** | `12` | `01` | `9F 00 12 01 34 82 17 34 8E 1D` |

怎么从 7 bit 得到 Octet 2：**左移一位，再把 Proxy 放进最低位**。比如 `0001001₂` 左移得 `0010010₂` = `0x12`，Proxy = 0，所以 Octet 2 = `0x12`。

你会发现：**`934` 和 `*9*934#` 在空口上只差一个比特**（Octet 2 的最高位）。用户觉得「按了一串很长的东西」，手台发出去的只是把 EMERG 从 0 改成 1。这正是 Figure E.2 想表达的：**变长的用户串 → 定长的比特 + 修饰标志**。

### 9.4 全呼串：`*19{6|7|8}{1|2|4|5|7}`（E.3.4 / Tables E.4–E.7）

| 第三位 | 范围 | 目的地址 | 别名 |
|---|---|---|---|
| `*196x` | **本站**（发起者登记的站） | `FFFFFD` | ALLMSIDL |
| `*197x` | 系统内**一部分站**（哪些站由厂商决定） | `FFFFFE` | ALLMSIDZ |
| `*198x` | **全网所有站** | `FFFFFF` | ALLMSID |

| 最后一位 x | 业务 |
|---|---|
| 1 | 高优先级全呼 |
| 2 | 紧急全呼 |
| 3 | 保留 |
| 4 | 紧急数据全呼 |
| 5 | UDT 短数据全呼 |
| 7 | 普通全呼 |

全呼**占用组号空间**（E.3.4.0），并且按 6.6.1.7 **要当作「对 talkgroup 的广播呼叫」**来发：Service_Kind = 组呼，BCAST_SV = 1。普通全呼 `*1967`：

```text
Service_Options = 000 1000 → Octet 2 = 0x10，Octet 3 = 0x01
C_RAND = 9F 00 10 01 FF FF FD 34 8E 1D
```

按同样思路推（E.3.0 + Table 6.40，**本课推导，非原文逐字**）：`*1961`（高优先全呼）应是 BCAST + PRIORTY 10 → Octet 2 = `0x14`；`*1962`（紧急全呼）应是 EMERG + BCAST → Octet 2 = `0x90`。网络批准后发的是**广播组呼 Grant（BTV_GRANT）**一类（第 33 课 Grant 变体地图）。

现场对照：调度说「我按 `*1967` 全呼，隔壁站没响」——**`*196x` 本来就只到本站**。要跨站得用 `*197x`（站点子集，范围看厂商配置）或 `*198x`（全网）。另外 Annex G 说的是「**如果手台支持**全呼，就要能编这三个地址」——全呼本身**不是强制功能**，手台不支持、或者网络不给这个用户全呼权限，也会「没反应」。

## 10. 外线电话：号码不进地址字段，而是另外「交上去」

### 10.1 前缀规则（Table E.9 / E.3.7）

| 用户拨 | 含义 | C_RAND 的 Target |
|---|---|---|
| `01` + 至少 4 位（总长 ≥ 6，最多 44 位） | 打 **PSTN**（公网电话） | **PSTNI = `FFFEC0`** |
| `02` + 至少 4 位（总长 ≥ 6，最多 44 位） | 打 **PABX**（单位小交换机） | **PABXI = `FFFEC1`** |
| `1000`…`8999`（4 位） | 缩位拨号，**保留**待定义 | — |
| `9600`…`9699`（4 位） | **保留**待定义 | — |

**前导的 `01` / `02` 本身也要上传**：拨 `0112345`，上传的就是 `0112345`；拨 `021234`，上传 `021234`（E.3.7.1.1 / E.3.7.1.2 原文例子）。用 SIP 接外线时，PSTN 和 PABX 可以不区分（Table E.9 下的说明）。

为什么不直接把电话号码塞进 Target？因为 **24 bit 最多表示 8 位左右的十进制数**，一个手机号 11 位、国际号码更长，根本装不下。所以 DMR 的做法是「**两段式**」（规范叫 multi-part addressing，6.6.2.1.2）：

### 10.2 流程（学习用简化，不是完整 MSC）

```text
  MS（40125312）                                         TSCC
     │  ① C_RAND  Service_Kind=IND_V_SRV                   │
     │            Target=PSTNI(FFFEC0) Source=348E1D        │
     │            Proxy=0（号码 1–20 位） / 1（21–44 位）     │
     │ ───────────────────────────────────────────────────►│
     │                                                     │
     │  ② C_AHOY  Source=PSTNI  Target=348E1D               │  「请把号码交上来」
     │            UAB=00（Proxy=0 时） / 01（Proxy=1 时）     │
     │ ◄───────────────────────────────────────────────────│
     │                                                     │
     │  ③ UDT 头 + 附加数据块：BCD 号码（F 填充）             │
     │ ───────────────────────────────────────────────────►│
     │                                                     │  没收好：可以再发一次 C_AHOY，
     │                                                     │  或回 C_NACKD 宣告失败
     │  ④ C_WACKD / C_QACKD / C_NACKD … 进度或结果            │
     │ ◄───────────────────────────────────────────────────│
     │  ⑤ Grant → 业务信道（第33、36课）                     │
```

用 C_RAND 的 Proxy 比特预告「号码有多长」，TSCC 据此在 C_AHOY 里告诉手台「交几块」，这就是 6.6.2.1.2 的原文规则：**Proxy = 0 → 1…20 位，C_AHOY 的 UAB = 00；Proxy = 1 → 21…44 位，UAB = 01**。打 PABX / PSTN / 线路网关 / 调度网关（PSTNI、PABXI、LINEI、DISPATI）时，号码**一律是 BCD 数字**。

拨 `0112345` 时的 C_RAND（主叫 `0x348E1D`）：

```text
9F 00 00 00 FF FE C0 34 8E 1D
          │  │  └──────┘ Target = PSTNI
          │  └ Service_Kind = 0000 个呼（打电话是「个呼」到网关）
          └ Service_Options 全 0，Proxy = 0（7 位 ≤ 20）
```

### 10.3 BCD：一个数字占 4 bit（7.2.9 Table 7.46 + B.3.3）

| 字符 | 编码 | 字符 | 编码 |
|---|---|---|---|
| `0`…`9` | `0000`…`1001`（就是 0–9） | `*` | `1010`（A） |
| `#` | `1011`（B） | 1100 / 1101 / 1110 | 保留 |
| **DigitNULL**（填充） | **`1111`（F）** | | |

数字**按拨号顺序**放，最早拨的数字在第一个字节的**高 4 位**（B.3.3）。不够一整块的地方用 `F` 填满，填了几个 `F` 写在 UDT 头的 **Pad Nibble** 里。

**例 1：`0112345`（7 位）**——查 Table B.3：7 位 → **UAB = 0，Pad Nibble = 13**。

```text
数字：  0 1 1 2 3 4 5 + 13 个 F
字节：  01 12 34 5F FF FF FF FF FF FF      （共 10 字节 = 20 个半字节）
```

**例 2：一个 24 位的长号码**（示例号码，不是真实电话）`01` + `12345678901234567890` + `12`——查 Table B.3：24 位 → **UAB = 1，Pad Nibble = 20**；因为超过 20 位，C_RAND 里 **Proxy = 1**。

Table B.3 的规律：**1 块装 20 位，2 块装 44 位，3 块 68 位，4 块 92 位**（UDT 最多 4 块附加数据，所以 BCD 最多 92 位）。Table E.9 把外线号码上限定在 **44 位**，正好对上「Proxy 只有 1 bit：要么 1 块，要么 2 块」。

> **带宽直觉**（补你的弱项）：普通个呼的地址只花 24 bit；外线号码要额外走一轮 C_AHOY + UDT，**多占的是控制信道的时间**（每个 CSBK / 数据块都要占一个 30 ms 时隙里的一个突发）。所以「打外线比打对讲慢一拍」是协议结构决定的，不全是网关慢。

## 11. Annex G：为什么「原生编址」是互通的底线

### 11.1 G.1 原文三条

> 为确保不同厂商 MS 之间的互操作，**每台 MS 都应当能够呼叫 DMR 寻址范围内的全部有效 ID**。完整要求是：
> 1. 能把 MS 自己的地址（见 4.3）个性化成可寻址范围 **000 001 … 16 776 415** 内的**任意值**；
> 2. 对 MS 支持的所有呼叫业务，能把被叫（**个体或 talkgroup**）编址到 **00 000 001 … 16 776 415**；
> 3. **如果 MS 支持**，能编址 ALLMSIDL（16 777 213）、ALLMSIDZ（16 777 214）、ALLMSID（16 777 215）。

翻成白话：**不管你的拨号界面多花哨（或者干脆没有键盘），写频软件和通讯录必须允许直接填一个 1…16 776 415 的原始数值。**一台「只会按 Annex E 车队号翻译」的手台，是打不到 `100000` 以下、也打不到 SSI 保留段里的号的——它就**不满足 Annex G**。

这里的 **Native（原生）**指「相对于拨号计划的、原汁原味的 24 位地址」，**不是**「只能编本站的地址」。中文资料把 Annex G 叫「本地编址」时，要按这个意思理解。

### 11.2 同一个空口地址，在两种手台上显示得不一样

这是本课最大的坑，务必亲手算一遍。业余无线电 DMR 网普遍用 **7 位十进制 ID**，格式 `XXXYZZZ`（国家 3 位 + 州 / 省 1 位 + 序号 3 位），比如美国科罗拉多州的前缀是 `3108`（DMR-MARC 编号规则页，见外链 5）。假设某人的 ID 是 `3108128`：

```text
空口：3 108 128（十进制）= 0x2F6D20
用「直接显示原生 ID」的手台看：      3108128
用「按 Annex E 车队号显示」的手台看：
    NAI = 3 108 128 ÷ 32 768 = 94 余 27 936   → NP = 94 + 296 = 390
    SSI = 27 936（> 15 400，小车队）：k = 27 936 − 15 401 = 12 535
    FIN = 42 + ⌊12 535 / 350⌋ = 42 + 35 = 77
    IN  = 200 + (12 535 mod 350) = 200 + 285 = 485
    → 显示 39077485
```

**同一部对讲机、同一个空口地址，一边显示 `3108128`，一边显示 `39077485`。**两边都没错，只是用了不同的「翻译表」。反过来，我们示例网的 `40125312` 在原生显示的手台上就是 `3444253`。

外链 2 的 DJ0WH 博客讲的正是这个场景：把 **MOTOTRBO** 手台接入**别家**的 DMR Tier III 系统时，要先把分配到的车队号（他写作 `FFFGGNNN`）按 Annex E 公式换算成空口 ID；他还提到 **Capacity Max 不用车队号，而是直接用空口地址**——和常规信道上用的是同一个 ID。

### 11.3 互通排障的「一句话原则」

> **对号的时候，永远对空口 24 位地址（十六进制或十进制都行），不要对屏幕上的号码。**

- 写频交接单上，每个号码同时写「用户号码」和「空口 ID（十进制 + 十六进制）」两列。  
- 混合厂商的网里，先确认每家手台用的是哪种显示 / 拨号方式（Annex E 车队号、原生 ID，还是厂商自己的方案）。  
- 解码器、网管日志里出现的永远是空口地址；拿着用户报的号码去搜之前，先换算。

### 自测答案

1. SSI = (25−20)×700 + (318−200) + 1 = 3 619；AI = 105×32 768 + 3 619 = **3 444 259 = `0x348E23`**。  
2. 3 462 305 ÷ 32 768 = 105 余 21 665 → NP 401；SSI 21 665 > 15 400 → 小车队，k = 6 264，FIN = 42 + 17 = **59**，IN = 200 + 314 = **514** → **`40159514`**。（`0x34D4A1` = 3 462 305。）  
3. `950` → 本车队**组号** GN 950；`105` → 本网**调度台** n = 5；`150` → 不属于任何号段，**拒绝**并提示（E.1）。  
4. 让 NAI = 32（DMR 最小区）正好对应 NP = 328；200…327 是 MPT1343 / MPT1327 的车队前缀，保留给迁移用户，新老号码在用户眼里不撞车。  
5. Octet 2 = **`0x80`**（EMERG = 1，其余 0，Proxy = 0），Octet 3 = **`0x01`**（组呼）。Table 6.40 NOTE 3 规定 EMERG = 1 时 PRIORTY_SV 置 00——紧急本身就优先于一切（E.3.0：紧急呼叫可以抢占资源）。  
6. `*1967` → `FFFFFD` 本站全呼，按站点路由，只到发起者所在站；`*1987` → `FFFFFF` 全网全呼，到所有站；车队全呼 → 每个 NAI 区一个（NP 401 是 `0x34FFFF`），**按组呼路由**到这个车队有人登记的站，只叫这个车队的人。  
7. Target = **PSTNI `FFFEC0`**，Service_Kind = **IND_V_SRV 0000**，Proxy = **0**；UAB = **0**，Pad Nibble = **13**；BCD = `01 12 34 5F FF FF FF FF FF FF`。  
8. 30 位：Proxy = **1**，UAB = **1**，Pad Nibble = **14**（Table B.3）。50 位：超过 Table E.9 的 44 位上限，**不能作为外线号码拨**（UDT 本身能装到 92 位，但 Proxy 只有 1 bit，外线最多 2 块）。  
9. **Annex G 是强制（normative）**，Annex E 是建议（informative）。只支持车队号、不能编 1…16 776 415 任意值的手台**不满足 G.1**。  
10. 显示 **`39077485`**（NAI 94 → NP 390，SSI 27 936 → FIN 77、IN 485）。说明**屏幕上的号码依赖翻译表**，跨厂商、跨网对号必须对空口 ID。  
11. **不冲突**：个号和组号是两套独立空间（4.3.1 NOTE），靠 Service_Kind 区分；写频软件报重复是软件限制。

   - Annex E 的「祖宗」：MPT1327 用 20 bit 地址（7 bit 前缀 + 13 bit ident），用户看到的是 **MPT1343** 编号：前缀 200…327、个号 20…89 / 200…899、组号 90…99 / 900…998——和 DMR 的 NP 保留段、IN / GN 号段一脉相承。**怎么用**：只读 Numbering Schemes，体会 §4.3「为什么 +296」。

4. **[Puget Sound DMR Coalition · DMR 102（呼叫类型与通讯录）](https://www.pugetsounddmr.org/lc/digital-mobile-radio-dmr/dmr-100/102)**  
   - 从常规 / 业余视角讲个呼、组呼、全呼、紧急呼叫；明确写了通讯录 ID 是 **0…16 776 415** 的十进制数，个号和组号可以数值相同但类型不同，很多手台软件不接受重复。**怎么用**：对照本课 §3.2、§11.1 读。注意它讲的是 Tier II 常规网，不涉及集群拨号计划。

5. **[DMR-MARC · Subscriber and Repeater Numbering Scheme](https://dmr-marc.net/FAQ/GSM-ID.html)**  
   - 业余网的号码规则：用户 ID 7 位 `XXXYZZZ`（国家 + 州 / 省 + 序号），中继 ID 6 位。这是一种「十进制层面」的编号约定，和 Annex E「比特层面」的车队编号是两种思路。**怎么用**：拿任意一个 ID 按 §11.2 换算，看它在 Annex E 手台上会显示成什么。

6. **[Ham Radio DX · Get Started with DMR - An Introduction for Beginners（视频，约 76 分钟）](https://www.youtube.com/watch?v=yAuPruMvlgw)**  
   - 澳大利亚 AREG 的入门讲座：先讲 DMR 基础，再由 Ben VK5BB 讲 DMR 术语以及它们怎么对应到写频（ID、通话组、通讯录等），最后讲没有中继覆盖时的其他接入方式。**怎么用**：重点看中间讲术语和写频的部分，建立「号码填在哪、手台怎么用它」的直觉。**讲的是业余 Tier II 常规网，不涉及 Annex E 车队拨号。**

## 本课收束

阶段 E 第八站：**键盘上的号码，怎么变成空口上的 24 个比特。**  
三副面孔：拨号串（人按的）、用户号码（人看的）、空口地址（天线发的）；对号永远对空口地址。  
骨架：24 bit = NAI 9 ‖ SSI / SGI 15；NP = NAI + 296（328…806）；200…327 留给 MPT1327。  
个号：大车队 SSI = (FIN−20)×700 + (IN−200) + 1；小车队 SSI = 15 401 + (FIN−42)×350 + (IN−200)；组号 SGI = (FGN−20)×100 + (GN−900) + 1；调度台 SSI = 32 481 + n。  
号段不重叠：100–109 调度、200–899 个号、900–999 组号；以 0 开头的多位串是外线。  
修饰符变比特：`*9` → EMERG，`*8` → PRIORTY_SV，`*11` → BCAST_SV；全呼 `*196x/7x/8x` → FFFFFD/E/F。  
外线两段式：C_RAND(Target=PSTNI/PABXI, Proxy) → C_AHOY → UDT 交 BCD 号码（20 / 44 位门槛）。  
Annex E 是建议，Annex G 是底线：1…16 776 415 必须能直接编。
