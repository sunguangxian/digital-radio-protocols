> **手册模式 · 岗位深挖（运维 / 网管）第 1 篇**（接第 40 课收官 · **不是第 41 课**）

## 1. 为什么要写这篇手册（动机 + 现场对话）

第 40 课收官时，运维路线的 **第 1 周** 写得很清楚：

> Reason 高频码 + **登记失败三问** → 交付《本网 10 个 Reason 剧本》草稿。

课程编号停在第 40 课。从今天起，同一套材料按**症状 / 岗位**继续推——这是手册模式的第一篇，专门把 Week‑1 那一行展开成可值班用的厚文。

现场你一定听过这些对话：

- 调度：「他开机了，网管显示『注册失败』。」——你问「Reason 码值？」对方回「就写着失败啊。」——中文提示是线索，**不是证据**。  
- 写频同事：「系统码、CC、频率都对，怎么还登不上？」——可能空口身份对了，但 **C_RAND(登记) 根本没发出去**；也可能发出去了，回的是 `0x2B Reg_Denied`。三问没问完就改写频，等于在猜。  
- 新站开通当天：「一半手台登不上。」——日志里 `0x2A` 和 `0x2B` 混着出现。一个是 **Reg_Refused（可换站再试）**，一个是 **Reg_Denied（被本 TSCC 否决、进 Denied Registration List）**，处理剧本完全不同（第 34 课钉子；本篇 §4、§6 再钉）。  
- 用户：「手台一直转圈，说排队。」——有人当「登记失败」开单，其实看见的是 **`0xE0 Wait`（WACK，中间态）**，后面还应有最终 ACK/NACK；别把「稍等」当成终局拒绝。  
- 监听员：「我看见 Grant 了啊！」——登记成功路径**不是**语音 Channel Grant；登记成功常见是 **`C_ACKD` + Reason=`0x62 Reg_Accepted`（或 `0x65` 登记+组订阅）**。把登记回条跟语音小票搞混，三问第二问就答错。  
- 分析仪新人：「字节里明明有个 `2A`……」——直接念 `0x2A Reg_Refused`，结果真正 Reason 可能是跨字节拼出来的别的码（第 34 课 §3.3 阴坑；本篇 §4.4 提醒）。

培训台如果只背「集群要先登记」六个字，值班会卡在同一处：

> **会背「要登记」≠ 会分诊。**  
> 分诊 = 每次工单强制三问：  
> **① C_RAND 发出去了吗？（有没有按铃 / Service_Kind=登记类）**  
> **② 回来的是 Grant 还是哪条确认族 ACK？**（登记成功走 ACK Reason，不是语音 Grant）  
> **③ Reason 码值是多少？**（整 8 位；重点 `0x62 / 0x2A / 0x2B / 0x2D / 0xE0` 与鉴权相关名字指针）  
> 三问答不清，不许升级为「设备故障」或「射频坏了」。

本篇目标：能画出「守 TSCC → 读 Aloha → C_RAND(登记) →（可选 WACK）→ ACK(Reg_Accepted) / NACK(Reg_Refused|Reg_Denied|…)」总图，并与语音 Grant 路径对照；会用三问 +「日志三联单」接单；会精读登记相关 Reason（不是把第 34 课全表再 dump 一遍）；会区分写频/CC/Hunt 问题与真登记拒绝的先后顺序；能填完《本网 10 个 Reason 剧本》模板；自测过关后，回库翻 `ReasonCode与Grant变体.md` 把本网真实高频码补进剧本。

**本篇硬禁令（写进脑子）**：不发明 ETSI 条款号（入口锚点以资料库 `04-集群协议/ReasonCode与Grant变体.md`、`集群协议字段速览.md`、`总索引.md` 集群关键词、第 32/34/35/40 课已有编号为准）；**不重 dump Grant 全变体地图**（第 33 课）；**不重 dump Hunt 状态机**（第 37 课）；**不讲鉴权算法 / RC4 细节**（第 35 课；本篇只认鉴权相关 Reason **名字**当指针）；**不写攻击面 Stun/Kill 内容**（若提及仅保留第 39 课网络管理口径）；不把厂商中文提示当成 ETSI 正式名；本篇不写下一篇手册正文。

## 2. 总图 / 故事：登记回条 vs 语音 Grant

### 2.1 一句话：登记是「入住」，Grant 是「房卡」

继续旅馆比喻（第 31–34、40 课）：

| 旅馆 | 空口 | 成功长什么样 |
|------|------|--------------|
| 前台告示牌 | **C_ALOHA**（Reg / Mask / Backoff…） | 能读懂「要不要先登记」 |
| 入住按铃 | **C_RAND**，Service_Kind=登记类（学习口径 `1110₂`） | 分析仪上**看见这台机的登记按铃** |
| 入住回条 | **确认族** C_ACKD / C_NACKD / C_WACKD… + **Reason** | 成功常见 `0x62 Reg_Accepted`；失败 `0x2A/0x2B`…；中间 `0xE0 Wait` |
| 点餐要房 | 再发 **C_RAND**（语音/数据类） | 与登记按铃 **Service_Kind 不同** |
| 房卡小票 | **Channel Grant**（PV/TV/…） | **Grant 本身不带 Reason**；失败才走 NACK |

口诀：**先读告示 → 再办入住（登记 RAND + ACK Reason）→ 再点餐要房（语音 RAND + Grant）→ 最后进客房说话。**  
把「登记成功」说成「收到 Grant」，是本篇最常见的口误。

### 2.2 大图：登记路径（本篇主线）

```text
  ┌─────────────────────────────────────────────────────────┐
  │  MS 守在 TSCC（控制前台）                                 │
  │  听 C_ALOHA：Reg / Mask / Backoff / NRand_Wait / SF …   │
  └───────────────────────────┬─────────────────────────────┘
                              │
              Reg=1（须登记后才活跃）时
                              ▼
  ┌─────────────────────────────────────────────────────────┐
  │  ① 按铃：C_RAND（Service_Kind = 登记类 `1110₂`）          │
  │     ← 三问第 1 问：这枪发出去了吗？                        │
  └───────────────────────────┬─────────────────────────────┘
                              │
          （可选）网络忙着办手续
                              ▼
  ┌─────────────────────────────────────────────────────────┐
  │  C_WACKD · Reason = Wait `0xE0`                         │
  │     ← 中间态：已收下，后面还有信令；≠ 登记成功；≠ 登记失败 │
  └───────────────────────────┬─────────────────────────────┘
                              │
              最终回条（确认族，看 Reason 的 tt）
                              ▼
        ┌─────────────────────┴─────────────────────┐
        │                                           │
        ▼                                           ▼
  C_ACKD（tt=ACK）                            C_NACKD（tt=NACK）
  · Reg_Accepted `0x62`                       · Reg_Refused `0x2A`
  · Reg_Subscription… `0x65`（登记+组附着）    · Reg_Denied  `0x2B`
  · （鉴权相关名字 → 第 35 课指针）            · （其它网络拒因，见第 34）
        │                                           │
        ▼                                           ▼
  入住办成 → 可再发语音/数据 C_RAND            按码值选剧本：
                                               2A→可换站再试
                                               2B→本站否决/Denied List
                                               …
  三问第 2 问：回来的是确认族 ACK/NACK，
               不是语音 Channel Grant！
  三问第 3 问：Reason 整 8 位码值是多少？
```

旁路指针（本篇认形状，不展开）：

- **C_AHOY 点名**也可驱动登记后续（第 32 课路径 B）——仍要落到确认族 Reason，不是 Grant。  
- **MassReg**（大规模重登记）会让控制面「挤」——先查是不是策略性重登记窗，别先换机柜（第 32 课）。  
- 未登记却直接发**语音** C_RAND → 常见 `0x2D MS_Not_Registered`（这是「业务被拒」，根因仍是没办成入住）。

### 2.3 对照图：语音呼叫成功路径（只为对比，不 dump Grant 地图）

```text
  （已登记）MS --C_RAND(语音类)--> TSCC
       │
       ├─ 成功 → Channel Grant（重复发送常见）→ 双方进 Payload 说话
       │         ※ Grant 无 Reason
       │
       └─ 失败 → C_NACKD + Reason（权限/对方不在/拥塞/…）
                 ※ 这里的 Reason 是「呼叫被拒」，不是「登记被拒」
                 ※ 若 Reason=`0x2D`：先回去办登记，别在 Grant 变体里找原因
```

对照口诀：

| 你想确认的事 | 成功长什么样 | 失败长什么样 |
|--------------|--------------|--------------|
| **登记办成了吗？** | 确认族 **ACK** + `0x62`/`0x65`… | 确认族 **NACK** + `0x2A`/`0x2B`… |
| **房间派出去了吗？** | **Channel Grant** | **NACK** + 呼叫类 Reason |
| **只是让你等？** | **WACK** `0xE0` 或 **QACK** `0xA0`/`0xA1` | 后面还有最终条；别当终局 |

## 3. 登记失败三问 + 「日志三联单」

### 3.1 三问工作流（每次工单照念）

把下面三行贴在网管值班屏边上（第 40 课 §5.2 原文加厚）：

```text
① C_RAND 发出去了吗？
   → 有没有「按铃」？Service_Kind 是不是登记类？
   → 没有 RAND：先查终端是否在发、Aloha Mask/Backoff、写频系统身份、射频能否守住 TSCC
   → 有 RAND：进入第 ② 问

② 回来的是 Grant 还是哪条确认族 ACK？
   → 登记场景：期望看见 C_ACKD / C_NACKD / C_WACKD（同一 Opcode 壳，靠 Reason 的 tt 区分）
   → 若同事说「看见 Grant 了」：先确认是不是把登记回条误叫成 Grant；
     登记成功通常是 ACK+Reg_Accepted，不是语音小票
   → 若只有 WACK/QACK：记「中间态」，等最终条再结案

③ Reason 码值是多少？（整 8 位十六进制）
   → 优先记码值，再对 ETSI/笔记名字；厂商中文提示只做线索
   → 登记高频：0x62 / 0x65 / 0x2A / 0x2B / 0x2D / 0xE0
   → 鉴权味道的名字 → 指针第 35 课，本篇不展开算法
```

**结束条件**：三问都有证据（空口或可靠解码日志）写入工单，才能谈「下一步动作」。只有中文「注册失败」四个字 = 线索不足。

### 3.2 决策树（口述版）

```text
工单：登不上 / 注册失败 / 开机无网
        │
        ▼
  先问①：看见本机 C_RAND(登记) 了吗？
        │
   没有 ─┬─► 空口身份（SYNC/CC/是否在正确 TSCC）→ 写频系统码/频率计划
        │    → Aloha Reg/Mask/Backoff → 终端是否禁用开机登记
        │    → 仍无 RAND 再怀疑射频/天线（最后一刀）
        │
   有了 ──► 问②：回条是确认族还是（误认的）Grant？
                │
           只有 WACK 0xE0 ──► 等最终 ACK/NACK；勿结「失败」单
                │
           ACK 0x62/0x65 ──► 登记其实成功；投诉可能在「下一步语音」
                │
           NACK ──────────► 问③：码值？
                              0x2A Reg_Refused → 可换站/查本站策略
                              0x2B Reg_Denied  → 本站否决/Denied List/号段授权
                              0x2D （若出现在语音 RAND 后）→ 回去办登记
                              鉴权相关名字 → 第 35 课 / 钥匙与挑战
                              其它 → 回第 34 课全表与 ReasonCode 笔记
```

### 3.3 日志三联单（强制三栏）

第 40 课 §5.2b 建议网管工单强制三栏。本篇把它写成可复制模板：

| 栏 | 必填 | 合格例子（教学虚构） | 不合格例子 |
|----|------|----------------------|------------|
| **空口 / 信令** | 有无登记类 C_RAND；回条族（ACK/NACK/WACK）；**Reason 十六进制**；时间戳 | 「10:02:11 C_RAND SK=登记；10:02:12 C_NACKD Reason=0x2B」 | 「网管显示注册失败」 |
| **终端侧** | 型号/写频版本；个号（可脱敏）；是否刚换站/换写频；开机登记开关 | 「机型X，写频包 2026-09；个号末四 …1234；今早改过邻站表」 | 「用户说机子坏了」 |
| **网络侧** | 站点/TSCC 标识（脱敏）；时间窗；本站是否开鉴权；近期 MassReg/改授权 | 「站B TSCC；鉴权开；今日 09:30 有 MassReg 窗」 | 「系统有问题」 |

规则：**三联单填齐之前，不升级为「设备故障」。**  
三联单填齐且三问指向同一结论之后，才进入 §5 的分诊顺序（先空口身份，再信令，再写频/Hunt，最后射频）。

### 3.4 「中文提示 → 先问码值」对照心态

| 网管 / 终端常见中文（厂商各异） | 你开口第一句 | 可能落到的码（举例，以空口为准） |
|--------------------------------|--------------|----------------------------------|
| 注册失败 / 登记拒绝 | 「Reason 十六进制是多少？0x2A 还是 0x2B？」 | `0x2A` / `0x2B` / 其它 |
| 未注册 / 请先登记 | 「是业务 RAND 被 0x2D 打回，还是根本没发登记 RAND？」 | 常 `0x2D` 或「无登记 RAND」 |
| 排队中 / 请稍候 | 「是 WACK 0xE0 还是 QACK 0xA0？最终条来了吗？」 | `0xE0` / `0xA0`… |
| 鉴权失败 | 「空口是哪条鉴权相关 Reason 名？钥匙批次对过吗？」 | 名字指针 → 第 35 课 |
| 注册成功但仍无法呼叫 | 「登记 ACK 是 0x62 吗？语音 RAND 的 Reason/Grant 呢？」 | 登记已过，问题在呼叫链 |

**永远：中文是线索，码值与空口字节是证据。**（第 40 课分诊口诀）
