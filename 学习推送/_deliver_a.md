# 第 7 课 · 寻址直觉：谁在跟谁说话（个呼 / 组呼）

> DMR 深入学习 · 阶段 A 通信地基  
> 适合：已懂「半双工 / 中继上下行 / 直通」，但还不清楚「空中这么多电台，怎么只叫到该叫的人」的人  
> 阅读量：约 30–40 分钟 · 几乎不推公式 · 要把「个号 vs 组号」「呼叫类型」「联系人 / 发射联系人 / 接收组」钉死

## 0. 开课前：加餐四句话复习（带新例子）

若你已读过 `学习推送/加餐_频率带宽与调制解调.md`，下面四句应能脱口而出。本课**不照抄加餐与第 2–6 课**，换成「调度台要叫某一个人，还是叫整个作业组」的场景再钉一遍：

| # | 一句话 | 本课用的新例子 |
|---|--------|----------------|
| 1 | **频率** = 信号抖得有多快 | 个呼与组呼**通常共用同一对中继频率**（同一 RX/TX、同一色码、同一时隙）。谁被叫到，**不是换了一个频点**，而是空口里「目的地址 + 呼叫类型」不同 |
| 2 | **带宽** = 频谱尺子上占多宽的一条带子 | 无论你叫一个人还是叫一组人，这一路语音仍占那条 **12.5 kHz** 载波上的**一个 30 ms 时隙**。组呼不会「占更宽的频谱」；它只是让更多接收机决定「开喇叭」 |
| 3 | **调制** = 把信息装进适合发射的高频波 | 按住 PTT：声码器比特仍用 **4FSK** 装进载波。变的是链路控制（LC）里写的 **Destination ID** 与 **FLCO（组呼或个呼）**——装的「收件人标签」不同，装车方式没变 |
| 4 | **解调** = 从收到的高频波把信息卸下来 | 同频同色码同时隙上的电台都能解调出比特；但电台软件还会看：这是个呼且目的是不是我？还是组呼且这个组我在接收列表里？**解调成功 ≠ 一定开喇叭** |

再补一句和本课主线钉死的对照：

- **信道参数**（频率、色码、时隙）回答：「我们能不能听到同一条数字车道？」  
- **寻址参数**（本机 ID、目的 ID、个呼/组呼类型、接收组）回答：「听到之后，要不要把声音放出来、以及我一按 PTT 打给谁？」

若这四句仍糊：先打开加餐文，再回本课。本课主线是：**谁在跟谁说话、地址写在协议哪一层直觉、写频软件里的联系人/接收组怎么对应**。

## 1. 为什么本课重要（动机）

现场与写频软件里你会反复撞到这些说法：

- 「本机 Radio ID / DMR ID 填多少？」  
- 「联系人类型选 Group Call 还是 Private Call？」  
- 「发射联系人」与「接收组 / RX Group List」各干什么？  
- 「个呼听不见 / 组呼别人听得到我听不到」  
- 「全呼 / All Call」「广播呼叫」什么时候用？  
- 文档里：**Source ID / Destination ID**、**Talkgroup**、**FLCO = Grp_V_Ch_Usr / UU_V_Ch_Usr**

若只背「组呼就是一群人、个呼就是一个人」两句空话，后面排障会卡在同一处：

> **同一个数字（比如 1001），既可以是某个电台的个号，也可以是某个对讲组的组号——空口靠「呼叫类型」把它们分开。写频里若把类型选错，等于寄错了信封。**

本课目标是让你能自己讲清八件事（仍不推公式）：

1. **寻址**在 DMR 里解决什么问题（在频率/时隙之上再筛「谁」）；  
2. **24 bit 地址**、个号空间与组号空间**分立**；  
3. **个呼（Individual / Private / Unit-to-Unit）** vs **组呼（Group / Talkgroup）** vs **全呼/广播**；  
4. 空口里谁是 **Source**、谁是 **Destination**；  
5. 写频四件套：**本机 ID、联系人、发射联系人、接收组**；  
6. 为什么「频率对了仍无喇叭」常常是接收组/呼叫类型问题；  
7. 个呼有时会多一步「存在性检查」（先问对方在不在）；  
8. 常见误区：以为数字相同就是同一对象、以为个呼等于加密保密、把接收组当成发射目标。

第 8 课才会专讲「从模拟到 DMR 为什么要标准化」；本课到「寻址直觉与写频落点」为止。

## 2. 总图 / 故事：同一条车道上的「信封」

先把整课装进一张故事图。想象你已经站在正确的中继信道上（频率、色码、时隙都对）：

```text
同一条数字车道（例：中继下行 460.xxx / 上行 450.xxx，CC=1，Slot=1）
        │
        │  空中飞过的语音突发里，还贴着一张「信封」
        ▼
┌─────────────────────────────────────────────┐
│  呼叫类型：组呼 或 个呼（协议用不同 FLCO）     │
│  目的地址 Destination：组号 或 对方个号（24 bit）│
│  源地址 Source：主叫自己的个号（24 bit）       │
└─────────────────────────────────────────────┘
        │
        ├─ 组呼、目的=作业组A → 凡把「作业组A」放进接收组的电台开喇叭
        ├─ 个呼、目的=张三的ID → 只有本机ID=张三的电台开喇叭
        └─ 全呼/广播（特殊目的或业务选项）→ 按系统约定，可能几乎人人听 / 只听不回

类比（帮助记，不是协议定义）：
  · 频率+色码+时隙  ≈  走进正确的会议室
  · 组呼 + 组号      ≈  对着会议室麦克风喊「A组注意」
  · 个呼 + 个号      ≈  点名「张三，请回话」
  · 本机 ID          ≈  你胸牌上的工号
```

三句话记牢：

| 层 | 回答的问题 | 典型参数 |
|----|------------|----------|
| **射频 / 接入** | 我们能不能解调到同一路比特？ | 频率、频差、色码、时隙、直通/中继 |
| **寻址 / 业务** | 解调之后，该不该开喇叭？打给谁？ | 本机 ID、目的 ID、个呼/组呼类型、接收组 |
| **人机界面** | 用户按一下 PTT 默认打谁？ | 发射联系人、信道绑定的联系人、键盘拨号 |

DMR 日常排障，经常是「射频层都对了，寻址层写错了」。

## 3. 白话术语表

| 术语 | 白话 | 现场你会碰到 |
|------|------|----------------|
| **寻址 Addressing** | 用数字身份标明「谁发、打给谁」 | 写频、调度、抓包看 Source/Dest |
| **DMR ID / Radio ID / Unit ID / 个号** | 一台（或一个逻辑用户）在**个体地址空间**里的号码 | CPS「Radio ID」；业余侧常 7 位十进制 |
| **Talkgroup / TG / Group ID / 组号** | 在**组地址空间**里的号码；代表「一群该一起听的人」 | 联系人类型 Group Call；规划表里的组号 |
| **个呼 / 单呼 / Private Call / Individual / UU** | 一对一：目的是某个 Unit ID | Private Call 联系人；FLCO 个呼类 |
| **组呼 / Group Call** | 一对多：目的是某个 Talkgroup ID | 日常作业组、车队组、应急组 |
| **全呼 All Call / 全体** | 尽量叫到系统上「所有相关终端」的约定用法 | 特殊 ID（如 `FFFFFF` 一类约定）或厂商全呼开关；专业系统常见，部分业余网络禁用 |
| **广播 Broadcast（组业务选项）** | 组呼的一种业务形态：常用于「只听不回」 | Service Options 里的 Broadcast；领导发通知场景 |
| **Source ID** | 空口信封上的「寄件人」：主叫个号 | 对方屏幕上显示的来电 ID / Talker Alias 相关 |
| **Destination ID** | 空口信封上的「收件人」：个号或组号 | 决定谁应该响应 |
| **24 bit 地址** | 空口上 Source/Dest 各占 24 比特 | 约 1670 万量级编号空间（分区后可用区间见下） |
| **分立地址空间** | 个号表与组号表是两本通讯录；**数字可以撞车，类型不同则对象不同** | 1001 个呼 ≠ 1001 组呼 |
| **联系人 Contact** | 写频里一条：别名 + 类型 + ID | Digital Contacts |
| **发射联系人 Tx Contact** | 本信道一按 PTT，默认打给谁 | 信道属性里绑定的联系人 |
| **接收组 / RX Group List** | 本信道额外愿意听哪些**组呼** | 「能发 A 组，也能旁听 B、C 组」 |
| **FLCO** | 特性集内的功能码：区分组语音用户 LC vs 个语音用户 LC 等 | `Grp_V_Ch_Usr` / `UU_V_Ch_Usr` |
| **Full LC** | 完整链路控制，携带 Source/Dest 等 | Voice LC Header、Terminator with LC |
| **Null 地址 `000000`** | 非法源/目的，不要当地址用 | 规划与测试时避开 |

## 4. 先分清两件事：信道对了，不等于「该你听」

### 4.1 模拟习惯带来的坑

模拟同频对讲：亚音/静噪对了，喇叭里往往就是「谁大声谁上」。  
数字 DMR：就算频率、色码、时隙全对，电台仍可能**静默**——因为它还要匹配寻址规则。

### 4.2 一张对照表

| 检查项 | 作用 | 错了会怎样 |
|--------|------|------------|
| 频率 / 频差 | 能不能落到正确载波 | 完全无声或噪声 |
| 色码 Colour Code | 同频系统门禁 | 解调异常或忽略 |
| 时隙 Slot | 听/说哪 30 ms 片 | 听错另一路业务 |
| 呼叫类型 | 个呼还是组呼 | 同数字却打错对象 |
| 目的 ID | 打给谁 | 对方不开喇叭 |
| 本机 ID | 你是谁 | 个呼永远接不到「打给你的」 |
| 接收组 | 你愿意听哪些组 | 「别人组里聊得很欢，你这边死寂」 |

现场一句话：

> **先确认「在正确的会议室」，再确认「点名方式与胸牌」对不对。**

## 5. 24 bit 地址与「两本通讯录」

### 5.1 空口规矩（Part 1 Annex A 直觉）

- Full LC **必须**带 **Source ID**（发送方个体）与 **Destination ID**（接收方或组）。  
- Source / Destination **恒为 24 bit**。  
- **个号空间**与 **组号空间分立**：数值可以相同，靠**业务/呼叫类型**区分，不会在协议里糊成一个对象。

学习用分区摘要（细节与保留区以 ETSI 原文为准）：

**Talkgroup 空间（组）**

| DMR ID（hex） | 含义（直觉） |
|---------------|--------------|
| `000000` | Null，非法 |
| `000001`–`FFFCDF` | 可用对讲组地址（数量很大） |
| `FFFCE0`–`FFFFDF` | 保留等 |
| `FFFFE0`–`FFFFEF` | 特殊「未寻址」类组 |
| `FFFFF0`–`FFFFFF` | 「全体组」分区方案 |

**Individual 空间（个）**

| DMR ID（hex） | 含义（直觉） |
|---------------|--------------|
| `000000` | Null，非法 |
| `000001`–`FFFCDF` | 可用个体地址 |
| 其后保留 / 网关 / 定制 / 全体个体分区 | 网关、全呼个体方案等 |

### 5.2 全体呼叫约定（先建立地图，细节后课再抠）

- **未**采用分区「All * Idn」方案的系统：常用 **`FFFFFF`** 一类约定呼叫系统上所有人。  
- **采用**分区方案：用 `FFFFF0`…`FFFFFF` 等分别呼叫各分区全体。  
- **同一系统内只允许一种**全体方案。  
- Tier III 还有 ALLMS* 等网关/全员相关赋值，与上表衔接；本课只需知道「全呼不是普通组号随手填」。

### 5.3 十进制你会怎么看见

写频与业余网络里，地址常显示成十进制。例如 24 bit 全 1 的 `FFFFFF` 对应十进制 **16777215**。  
业余 BrandMeister 等生态里，个人 ID 常见 **7 位**十进制；专业系统可能是内部规划的短号、车队号、经拨号附录映射后的 AI 地址。  
**本课记原则**：界面上的十进制，最终要落到空口 24 bit；映射规则看系统与 Part 2 Annex C / Part 4 Annex E（信息性拨号建议），不要假设「屏幕上 7 位数永远等于空口原样」。

## 6. 个呼、组呼、全呼、广播：行为差异

### 6.1 组呼（一对多）——日常主力

- **目的** = Talkgroup ID。  
- 空口典型：组语音用户 LC（`Grp_V_Ch_Usr`，FLCO=`000000`）：带 Group address + Source address。  
- 谁开喇叭：本机认为「我是这个组的成员」——在常规写频里，通常体现为：该组是当前信道的发射联系人，**或**在该信道的 **RX Group List** 里。  
- 谁可以回话：一般组内成员都能在挂起时间内抢 PTT（具体权限、禁发、优先级看系统与配置）。

### 6.2 个呼（一对一）

- **目的** = 对方 Unit ID。  
- 空口典型：个语音用户 LC（`UU_V_Ch_Usr`，FLCO=`000011`）：Target + Source。  
- 谁开喇叭：目的 ID **等于本机 Radio ID** 的那一台（集群/联网场景下还涉及登记与路由，后文点到为止）。  
- 专业系统里，个呼有时先走 **UU_V_Req → UU_Ans_Rsp / NACK** 一类「对方在不在」信令，再进语音；组呼过程与个呼过程在 Part 2 里是分开描述的。

### 6.3 全呼 / 全体

- 意图：尽量让系统内相关终端都听到。  
- 实现：特殊目的地址约定，或厂商「All Call」能力开关；**不是**「随便建一个组号人人自动加入」。  
- 业余网络常限制或禁用全呼；专业调度、应急通知更常见。

### 6.4 广播（Broadcast）组呼

- 仍是组业务的一种形态：强调「主叫说，其他人听」，被叫侧常**不能回传**（屏幕可能提示无法发射）。  
- 与「全呼」相关但不是同一概念：广播描述的是**业务选项行为**，全呼描述的是**叫到多大范围**。

### 6.5 一张对比卡

| | 组呼 | 个呼 | 全呼/全体 | 广播组呼 |
|--|------|------|-----------|----------|
| 目的是什么 | 组号 | 个号 | 特殊全体约定 | 通常仍是组号 + 广播选项 |
| 典型听众 | 组成员 | 一个终端 | 系统约定范围内几乎所有人 | 组内听众（常不可回） |
| 写频类型 | Group Call | Private / Individual | All Call 或特殊 ID | 组联系人 + 业务选项/信道能力 |
| 保密吗？ | 否 | **否**（见误区） | 否 | 否 |

## 7. 写频现场对照：四件套怎么摆

下面用「常规 Tier II 中继信道」的常见 CPS 逻辑说明（厂商菜单名可能略有不同：Digital Contact、TX Contact、RX Group List、TG List…）。

### 7.1 本机 Radio ID

- 每台终端至少一个**个体** ID。  
- 个呼打给你，靠的就是它。  
- 两台机器误写成同一 Radio ID：个呼、短消息、部分补充业务会乱套。

### 7.2 联系人（Contacts）

每条联系人至少三要素：

1. **别名**（给人看：`作业一组`、`张三`）；  
2. **类型**：Group Call / Private Call /（可能还有 All Call 等）；  
3. **号码**：组号或个号。

**致命点**：类型选错时，同一个号码是完全不同的空口对象。

### 7.3 发射联系人（信道上的 Tx Contact）

- 决定：**这个信道上一按 PTT，默认信封寄给谁**。  
- 组作业信道 → 通常绑「作业一组」组呼联系人。  
- 需要固定个呼信道 → 绑对方的 Private 联系人。  
- 也可在机上临时选联系人/拨号，再 PTT（视机型）。

### 7.4 接收组（RX Group List）

- **只影响接收，不改变你默认打给谁。**  
- 典型用法：信道发射联系人是 TG 101，但接收组里放了 101、102、103 → 你仍默认打 101，却也能听到 102/103 的组呼（前提是中继/系统真的在把这些组送到你的时隙上）。  
- 个呼一般**不靠**接收组匹配；个呼看目的是否等于本机 ID。

SharkRF 论坛对接收组有一句很干净的归纳（业余热点语境，机制可借）：  
电台开喇叭，常见是——个呼且目的是你；或组呼且目的等于当前发射联系人，**或**目的在当前信道的 RX group list 里。

### 7.5 完整小例子（建议你对照自己的 CPS 点一遍）

假设：

- 中继：RX `460.125 MHz`，TX `450.125 MHz`，CC=1，Slot=1（数字仅为课堂例子，**以你单位执照规划为准**）  
- 本机 Radio ID = `10086`  
- 联系人：  
  - `作业A`，类型 **Group**，ID=`2001`  
  - `巡线B`，类型 **Group**，ID=`2002`  
  - `张三`，类型 **Private**，ID=`10010`

**信道「作业A」建议配置**

| 项 | 值 |
|----|-----|
| 频率/色码/时隙 | 如上 |
| 发射联系人 | `作业A`（组 2001） |
| 接收组 | 至少含 2001；若要旁听巡线，加入 2002 |

**行为**

- 你 PTT → 空口组呼目的 2001，源 10086。  
- 同事把 2001 放进接收组（或同样以 2001 为发射联系人）→ 能听你。  
- 有人用个呼打 `10086` → 只有你的机器应开喇叭（同信道射频条件满足时）。  
- 你临时选中联系人`张三`再 PTT → 变成个呼目的 10010；此时旁人即使接收组很全，也**不应**当组呼去听（除非开启了某些监听/promiscuous 模式，那是特例，不是标准作业默认）。
