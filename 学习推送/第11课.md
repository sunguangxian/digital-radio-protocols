## 1. 为什么本课重要（动机）

第 9 课钉死了 DMR 与 Tier；第 10 课钉死了 12.5 格子与 6.25e 效率账。下一关不是再背一个技术词，而是学会**打开正确的书**：

- 新人被甩来五本 PDF，点开最厚的那本（常常是 Part4），从 Aloha、Grant、Reason Code 开始啃——其实他做的是工厂常规中继（Tier II），根本还没到集群。  
- 销售把 **TR 102 398** 当「合同级规范」引用，和工程师拿 **TS** 条款对质时对不上号。  
- 同事在群里贴「Part1 V2.6.1」，资料库里其实已经是 **V2.7.1（2026-05）**；两边各说各话。  
- 语音不通，有人只翻 Part2「业务名字」，从不下沉看 Part1 的同步/色码/时隙；数据丢包只骂应用层，从不打开 Part3 的 PDP。  
- 搜到中文旧文或协会网页上的版本号，就当成「全球最新」，忘了 **ETSI deliver 链接**才是可下载发布版的锚点。

若只背「DMR 有五本标准」五个字，后面会卡在同一处：

> **TR 是导读与系统设计总览（不是规范性 TS）；Part1–4 才是要遵守的技术规范。现场问题先对 Tier 与岗位，再选对 Part；版本冲突时 TS > TR > 手册笔记，PDF 以 ETSI 为准。**

本课目标是让你能自己讲清十件事：

1. **为什么**需要文档地图（开错书比读不懂更浪费时间）；  
2. 一张总图：TR 在上作导读，Part1 空口、Part2 语音、Part3 数据、Part4 集群；  
3. 白话术语：TR / TS / Part / Annex / Version / AI / PDP / TSCC 等；  
4. 五本书各自**管什么、不管什么**；  
5. 现场角色怎么映射到书架（产品/射频/语音/数据/集群）；  
6. 本地资料库 `/workspace/dmr-protocol/` 怎么用（先中文笔记，后官方 PDF）；  
7. 四个完整例子（开错书、版本滞后、排障路径、把 TR 当金科玉律）；  
8. 常见误区清单；  
9. 自测能闭卷答对「该翻哪本」；  
10. 为第 12 课「协议分层 L1/L2/L3」准备好「书从哪来」的直觉。

## 2. 总图 / 故事：五本书怎么摆在一张书架上

先把整课装进两张故事图。精神与《DMR整合学习手册》§0 一致：TR 是入口导读，四本 TS 是按主题切开的规范。

### 2.1 书架总图（请在脑子里贴墙上）

```text
                    ┌─────────────────────────────┐
                    │  TR 102 398 系统设计导读     │  ← 新人 / 采购 / 运营入口
                    │  （不是规范性 TS）           │     建立全貌，不替代 Part1–4
                    └─────────────┬───────────────┘
                                  │
         ┌────────────────────────┼────────────────────────┐
         ▼                        ▼                        ▼
   TS 102 361-1              TS 102 361-2            TS 102 361-3
   Part 1 · 空中接口 AI       Part 2 · 语音与通用      Part 3 · 数据协议 PDP
   「管道怎么切、比特怎么飞」 「谁跟谁说话、补充业务」 「数据怎么打包」
         │                        │                        │
         └────────────┬───────────┴────────────┬───────────┘
                      ▼                        ▼
                 常规系统 Tier I/II        TS 102 361-4
                 （主要啃 1+2，数据再+3）   Part 4 · 集群协议 Tier III
                                          「控制器怎么派信道」
                                          （仍要 Part1/2 地基）
```

### 2.2 一句话故事

| 书 | 一句话故事 | 你什么时候打开 |
|----|------------|----------------|
| **TR 102 398** | 「DMR 整栋楼的导览图」 | 建立概念、写标书总述、和客户讲系统能力 |
| **Part 1** | 「无线电管道与比特怎么在空中飞」 | 同步失败、时隙乱、帧结构、接入、物理/链路 |
| **Part 2** | 「语音呼叫与补充业务怎么定义」 | 个呼/组呼行为、迟后进入、补充/通用设施 |
| **Part 3** | 「短数据与分组数据怎么封装」 | 短信、确认/非确认数据、IP/头压缩 |
| **Part 4** | 「集群控制器怎么登记、派发、拒绝」 | Tier III：控制信道、Aloha、Grant、Reason Code |

三层 Tier 与书架的关系（再钉一次，避免串台）：

```text
Tier I / II（常规）  → 主战场多在 Part1 + Part2（+ 需要时 Part3）
Tier III（集群）    → 必须上 Part4，但仍要 Part1 空口 + Part2 语音地基
TR                  → 所有人都可以先翻；不能拿它盖过 TS 条款
```

口诀：**先导读（TR），再按岗位进 Part；集群别跳过空口与语音地基。**

## 3. 白话术语表

| 术语 | 白话 | 现场你会碰到 |
|------|------|----------------|
| **TR（Technical Report）** | 技术报告 / 导读；讲设计意图与总览，**一般不当成硬性互操作条款** | `TR 102 398`；「先看导读」 |
| **TS（Technical Specification）** | 技术规范；实现与互操作要遵守的硬文本 | `TS 102 361-1` … `-4` |
| **Part 1 / 2 / 3 / 4** | 同一标准族切成的四本分册 | 「去翻 Part1」「这是 Part4 的事」 |
| **Annex（附录）** | 规范正文后面的专题附件（编址、定时器、拨号、猎站……） | 手册里的 AnnexD/E/G 等笔记 |
| **Version（V x.y.z）** | 版本号；**x.y.z + 发布年月**一起记 | `V2.7.1 (2026-05)` |
| **ETSI** | 欧洲电信标准协会；DMR 空口系列的发布方 | etsi.org/deliver/… |
| **DMRA / DMR Association** | 产业协会；便于浏览与推广，**网页版本可能滞后** | dmrassociation.org |
| **AI（Air Interface）** | 空中接口；Part1 的核心舞台 | 「空口问题先看 Part1」 |
| **PDP** | 分组数据协议（Packet Data Protocol）；Part3 主线 | 确认/非确认数据、短数据 |
| **TSCC** | 集群系统控制信道（Trunked Station Control Channel 一类说法）；Part4 舞台 | 「听控制信道」「登记上线」 |
| **CCL / L3** | 控制/呼叫相关的高层（后续第 12 课细讲分层）；本课先记「业务与集群信令常落在更高层」 | 以后对照 L1/L2/L3 |
| **Normative / Informative** | 规范性 vs 资料性；TS 条款多为要遵守的；TR 与许多导读段落偏资料性 | 争论「必须」时先问：TS 哪一节？ |
| **冲突裁决** | **TS > TR > 手册/笔记/中文旧文/厂商白皮书** | Wiki、标书、代码注释都要写清版本 |
| **Tier II 常规** | 直通或中继，无集群控制器派信道 | 工厂、物业、大量专业对讲 |
| **Tier III 集群** | 有控制器自动分配业务信道 | 大型专网、调度中心 |

口诀：**TR 导游，TS 法典；Part 分册，Annex 专题；版本写全，ETSI 为准。**

## 5. 深挖一：TR 102 398 —— 导读，不是法典

**官方身份**：ETSI **TR** 102 398《DMR General System Design》  
**本库版本**：**V1.5.1（2023-11）**，PDF 在 `00-入门/TR102398_V1.5.1_系统设计总览.pdf`

### 5.1 它是写给谁的

- 采购、运营商、系统规划、产品经理、新入职要建立「整栋楼印象」的人；  
- 也适合工程师在啃 TS 之前，先知道「有哪些业务分类、编号大概怎么想、系统构件叫什么」。

### 5.2 它通常覆盖什么（导读级）

- 系统设计总览与目标（为何在 **12.5 kHz** 信道上做数字化、用 **2 时隙**换 **6.25e** 效率叙事）；  
- 业务与能力的鸟瞰（语音、数据、补充类能力从系统视角怎么摆）；  
- 编号 / 编址的引导性说明（让你知道「地址很重要」，细表仍要回 TS Annex）；  
- 网管、架构、省电、接入、功率等**概述性**附录话题（本库有中文摘记：`00-入门/TR附录_省电接入功率.md`）。

### 5.3 它明确不替代什么

- **不替代** Part1 的突发、同步、信道接入比特级规则；  
- **不替代** Part2 的呼叫过程与补充业务规范性定义；  
- **不替代** Part3 的 PDP PDU 与确认机制；  
- **不替代** Part4 的集群控制信令与 Reason/Grant；  
- 与 TS **文字冲突时，以 TS 为准**（手册扉页那句冲突规则，就是为这种情况写的）。

### 5.4 现场怎么用 TR

| 正确用法 | 错误用法 |
|----------|----------|
| 给客户讲「DMR 整栋楼有哪些房间」 | 在争议条款上甩 TR 页码当终审判决 |
| 标书「系统综述」章节的概念来源 | 实现互操作测试只引用 TR、不打开 TS |
| 新人第一周建立词汇 | 「TR 更新了所以 Part1 旧条款作废」——未必，要查对应 TS 版本 |

一句话：**TR 是导游图；走路（实现与排障）要靠 TS 交通法规。**

## 6. 深挖二：Part 1 —— 管道怎么切、比特怎么飞

**官方身份**：ETSI **TS** 102 361-1《Air interface (AI) protocol》  
**本库版本**：**V2.7.1（2026-05）** ⭐ 当前公开最新大更新  
**路径**：`01-空中接口/TS102361-1_V2.7.1.pdf` + 中文 `帧结构与字段定义.md`、`CSBK与LC字段详表.md` 等

### 6.1 Part1 管什么

用白话记四块（细节留给阶段 C 空口课，本课只建立「该翻这里」的肌肉记忆）：

1. **时间管道**：约 **30 ms** 一时隙、2 时隙组成 TDMA 帧、语音超帧 A–F 等时间结构；  
2. **突发与字段骨架**：突发怎么切块、中间嵌入什么、CACH / SYNC 等「找齐队伍」的标记；  
3. **物理与链路层面的规则**：信道接入、校验与保护的**原则性**要求（本课不贴 FEC 矩阵）；  
4. **空口公共积木**：Colour Code、LC/CSBK 外壳、许多业务都要骑在上面跑的「比特高速公路」。

### 6.2 Part1 不管什么（常见误会）

- 不管「这个组呼业务在用户体验上叫什么名字、补充业务清单怎么列」——那是 **Part2** 的主场；  
- 不管「短数据确认重传、IP 头怎么压」——那是 **Part3**；  
- 不管「集群控制器如何 Aloha、如何 Grant、Reason Code 表」——那是 **Part4**；  
- 但请注意：**Part2/3/4 描述的业务，最终都要落到 Part1 定义的空口管道上**。排障时常出现「业务文看懂了，空口同步却是错的」。

### 6.3 版本特别提醒（本课必记）

- Part1 曾长期常见 **V2.6.1（2023-05）**；现已公开 **V2.7.1（2026-05）**。  
- DMR Association 标准页**有时仍列旧号**——这不是你资料库错了，而是协会页可能滞后。  
- **引用、Wiki、代码注释请写：`TS 102 361-1 V2.7.1 (2026-05)`**，并以 ETSI deliver PDF 为准。

现场口播：

> 「空口不同步、时隙听错、色码不对、帧对不齐——先别扯集群，打开 Part1。」

## 7. 深挖三：Part 2 —— 谁跟谁说话、补充业务

**官方身份**：ETSI **TS** 102 361-2《Voice and generic services》  
**本库版本**：**V2.5.1（2023-05）**  
**路径**：`02-语音业务/TS102361-2_V2.5.1.pdf` + `语音业务字段速览.md`

### 7.1 Part2 管什么

- **语音呼叫过程**的规范性描述：个呼、组呼等「谁跟谁说」在协议里如何建立与结束（直觉课已在第 7 课铺过，这里对上标准分册）；  
- **补充业务 / 通用设施**：例如迟后进入、各类与语音伴生的能力——以 Part2 字段与过程为准；  
- 与空口信令的衔接点（许多信息元素会映射回 Part1 的 LC/CSBK 世界）。

### 7.2 Part2 不管什么

- 不管突发里每一个比特怎么排、SYNC 图案细节——回 **Part1**；  
- 不管 PDP 数据包头、确认数据窗口——去 **Part3**；  
- 不管 Tier III 控制信道上的登记与信道授出——去 **Part4**（集群语音仍常要 Part2 的业务理解作地基）。

### 7.3 现场对照

| 现象 | 优先路径 |
|------|----------|
| 「能同步听到噪声状数字声，但组呼逻辑不对」 | Part2 → 必要时回 Part1 看地址/嵌入 |
| 「个呼显示主叫不对 / 迟后进入没有」 | Part2 字段速览 + Service Options 一类概念 |
| 「中继双时隙正常，但某补充功能两家终端不一致」 | Part2 条款 + 厂商实现差异；别先骂 Part4 |

口播：

> 「Part2 回答：这场语音通话在业务上被定义成什么样；Part1 回答：这些定义怎么坐上约 30 ms 的比特车。」

## 8. 深挖四：Part 3 —— 数据怎么打包

**官方身份**：ETSI **TS** 102 361-3《Data protocol》  
**本库版本**：**V1.3.1（2017-10）**（公开版较「老」，但仍是当前学习与实现常用锚点）  
**路径**：`03-数据协议/TS102361-3_V1.3.1.pdf` + `数据协议字段速览.md`

### 8.1 Part3 管什么

- **PDP**：分组数据怎么在 DMR 空口业务里承载；  
- **确认数据 vs 非确认数据**：要不要回执、失败了怎么理解（排障时先分清模式）；  
- **短数据**及相关头；  
- **IP 相关与头压缩**等（本库笔记与 Annex 有 IPv6 策略等摘记）。

### 8.2 和 Part1/2/4 的边界

```text
应用想发一条短消息 / 一小段 IP
        │
        ▼
   Part3：怎么打包成 PDP / 短数据语义
        │
        ▼
   Part1：这些块如何塞进时隙突发飞出去
        │
        ▼
（若在集群系统）Part4：控制面可能先帮你要到业务信道 / 相关许可
```

### 8.3 现场对照

| 现象 | 优先路径 |
|------|----------|
| 短信有时成功有时丢，且模式是非确认 | 先降低「每次必达」预期；再查覆盖与空口 |
| 确认数据重传打满仍失败 | Part3 过程 + 回 Part1 看信道质量/同步 |
| 「集群上数据」异常 | Part4 控制/业务信道状态 + Part3 载荷 |

口播：

> 「Part3 是快递员怎么封箱；Part1 是货车怎么跑；Part4（若有）是调度台给不给车道。」

## 9. 深挖五：Part 4 —— 集群怎么派信道

**官方身份**：ETSI **TS** 102 361-4《Trunking protocol》  
**本库版本**：**V1.12.1（2023-07）**  
**路径**：`04-集群协议/` 下 PDF 与多篇加厚中文笔记（Reason/Grant、Hunt、拨号、本地编址……）

### 9.1 Part4 管什么（Tier III 主场）

用一张「调度台故事」记住：

```text
终端开机 → 找控制信道（TSCC）→ 登记上线
        → 想说话 → 随机接入 / Aloha 一类机制
        → 系统同意或拒绝 → Grant / Reason Code
        → 去业务信道通话或传数据
        → 还有鉴权、猎站、动态组、遥毙等集群能力……
```

Part4 正是把上面这些**控制与集群业务信令**写成规范的地方。

### 9.2 Part4 不管什么 / 仍要什么地基

- **不管**「常规 Tier II 中继双时隙怎么配」——那不是 Part4 的日常主场；  
- **仍要** Part1：没有可靠空口，控制信令飞不到；  
- **仍要** Part2：集群里的语音业务语义仍建立在语音/通用业务理解上；  
- 数据面常还要 **Part3**。

### 9.3 千万别犯的错

> 做工厂 **Tier II 常规中继**项目时，把 Part4 当入门第一本——会把 Aloha/Grant 学成「宇宙真理」，却解释不了现场其实只是固定信道 + 时隙。

口播：

> 「Part4 回答：谁有权在什么时候占用哪条业务信道；只有系统里真有集群控制器时，你才主要靠它吃饭。」

## 12. 完整例子（三个正例路径 + 一个反例）

### 例子 A · 新人开错书：工厂 Tier II 中继却啃 Part4

- **场景**：某工厂上数字中继，两组话分 Slot1/Slot2；新同事被发「把标准学一下」，直接打开最厚的 Part4，卡在 Aloha、TSCC、Grant。  
- **诊断**：项目是 **Tier II 常规**，没有集群控制器派信道；Part4 不是他的第一本。  
- **正确路径**：TR 或整合手册建立全貌 → Part1（时隙/色码/同步）→ Part2（组呼行为）→ 需要短信再 Part3。  
- **一句话**：**Tier 选错，书就整架拿错。**

### 例子 B · 版本滞后：有人引用 DMRA 上的 Part1 V2.6.1

- **场景**：评审材料写「遵循 TS 102 361-1 V2.6.1」；本库与 ETSI deliver 已是 **V2.7.1（2026-05）**。  
- **正确做法**：打开 ETSI PDF 核对封面；材料改为 V2.7.1；若必须兼容旧终端，单独写「互通基线」而不是假装最新是 2.6.1。  
- **教训**：**协会页便于浏览，发布版以 ETSI deliver 为准。**

### 例子 C · 语音排障路径：Part2 → Part1

- **场景**：组呼「有时只有部分人能进」、迟后进入异常；有人只在调度台业务配置里打转。  
- **路径**：  
  1. Part2 / `语音业务字段速览.md`：业务选项、呼叫过程是否符合预期；  
  2. 回到 Part1：色码、时隙、SYNC/嵌入地址是否一致；  
  3. 仍不解再查覆盖与干扰（射频），而不是跳去 Part4 Reason Code（除非确认是集群系统）。  
- **一句话**：**业务语义在 Part2，比特管道在 Part1；先分清是「业务定义」还是「空口没坐稳」。**

### 例子 D · 反例：把 TR 当绑定规范，压过 TS

- **错误做法**：实现争议时甩 TR 某段概述：「导读里就是这么画的，所以必须……」；同时忽略 Part1/2 更精确的条件与例外。  
- **后果**：联调双方各执导读与条款，项目延期；或做出「导读友好、条款不合」的半吊子实现。  
- **纠正**：导读用于对齐意图；**写进合同与测试用例的，应是 TS 版本 + 条款定位**；冲突时 TR 让位。  
- **教训**：**导游图不能当判决书。**

## 13. 常见误区（请逐条用自己的话复述）

1. **「TR 和 TS 反正都是 ETSI 出的，效力一样。」**  
   错。TR 是报告/导读；Part1–4 的 TS 才是规范性技术规格主战场。

2. **「五本书随便从哪本开始都行。」**  
   不推荐。先全貌（TR/手册），再按岗位与 Tier 选 Part；集群别当常规入门第一课。

3. **「做 Tier II 也要先把 Part4 啃完。」**  
   错。Part4 是 Tier III 集群主场；常规中继优先 1+2（+3）。

4. **「做集群只要 Part4，Part1/2 可以跳过。」**  
   错。没有空口与语音地基，控制信令无处落脚。

5. **「协会网站列的版本号一定是全球最新。」**  
   不保证。可能滞后；以 ETSI deliver PDF 为准（Part1 V2.7.1 就是典型例子）。

6. **「中文网页写得清楚，可以代替 TS。」**  
   错。可作入门；条款与数字冲突时回 ETSI。

7. **「手册/笔记写了就等于标准原文。」**  
   错。本库明确：TS > TR > 手册。

8. **「语音问题只看 Part2，空口不用看。」**  
   危险。大量「业务怪」其实是同步、色码、时隙、地址在 Part1 层就错了。

9. **「数据问题属于 IT，与 DMR 标准无关。」**  
   错。短数据/PDP/IP 承载规则在 Part3，常还要 Part1（与集群时 Part4）。

10. **「Part3 版本号比较老（V1.3.1），说明数据部分不用学了。」**  
    错。老不等于作废；以当前公开 TS 为学习与实现锚点，并关注是否另有更新发布。

11. **「Annex 都是可忽略附录。」**  
    过分。许多编址、定时器、拨号、猎站关键内容在 Annex；本库用「附录覆盖清单」管理。

12. **「文档地图学完就可以不记版本号。」**  
    错。没有版本的引用等于没引用；Wiki 与标书必须写 `文档号 + Vx.y.z + 年月`。
